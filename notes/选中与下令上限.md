# 选中与下令的两道硬上限（500 / 128）

> 结论来自 `G:\motest\gamemd.exe` 反汇编。YRpp / Ares / Phobos 均未声明这两处 ——
> 它们是 YR 自己的 `static` 定长数组和队列容量。标「实证」附地址，「推断」另注。

## 0. 一句话

- **500** = 框选候选池（`Unsorted::TacticalSelectables`），不是选中集合；
  选中集合 `CurrentObjects` 是动态向量，**无上限**。
- **128** = 每逻辑帧联机事件数（`EventClass::OutList`）。一个单位一条令 = 一条事件，
  框 500 个右键只动前 128 个。

两道限制互相独立。

---

## 1. 框选候选池 500

| 项 | 地址 | 说明 |
|---|---|---|
| 数组 | **`0xB0CEC8`** | 500 项 × 12 字节 `{Object*; X; Y}`（对 YRpp `TacticalClass.h:13`）|
| 计数器 | **`0x8880D4`** | 实例 `0x887324` + `0xDB0`，每帧重建（`0xDB0` 从二进制读出；YRpp 只声明了数组 `Unsorted.h:652`）|

两处写死 `cmp eax,0x1F4 / je 丢`（实证）：`TacticalClass::AddSelectable` @
`0x6D9EF0`（`6d9ef0/6d9ef7/6d9efd`），另一处同款 @ `0x6D9CE0`（`6d9e54/6d9e5c/6d9e61`，
调用点 `0x6D461A`）。

- **填**（每帧，屏内可见对象自登记）：`0x73CF6B`、`0x5192E6`、`0x519609`、
  `0x4148CC`、`0x74D558`（皆 `call 0x6D9EF0`）。
- **读**：`Tactical_MakeFilteredSelection` @ `0x6D9FF0`（Phobos 整函数换掉）、
  框选命中 @ `0x6DA080`（调用点 `0x4ABCCB`），都遍历 `[0, SelectableCount)`。

选中集合本身无 500：`CurrentObjects` @ `0xA8ECB8` 是动态向量，`ObjectClass::Select`
@ `0x5F45FD` 经虚表 `+0x8` 扩容（`5f462d~5f467a`）。**P / T / Shift 加选都不受限，
只有拖框选受**（600 个进池 500，其余静默不进）。

没动它：`0xB0CEC8` 后紧邻别的全局（直到 `0xB0FE54 NavCycleMode`），无原地扩容空间；
要改须换基址 + 改 `AddSelectable` / `MakeSelection` / `0x6DA080` / 全部调用点，
高风险低收益。`MindSelect.cpp` 直接扫 500 项原始数组绕开计数器。

## 2. 每帧 128 条联机事件

`EventClass::OutList` = `QueueClass<EventClass, 128>`（YRpp `EventClass.h:14,16`，
布局 `QueueClass.h:52-59`）：

| 偏移 | 地址 | 内容 |
|---|---|---|
| +0 | **`0xA802C8`** | `Count` |
| +4 | `0xA802CC` | `Head` |
| +8 | **`0xA802D0`** | `Tail`（`& 0x7F`）|
| +12 | **`0xA802D4`** | `Array[128]`，每项 `sizeof(EventClass)=111=0x6F` |
| +12+128×111 | **`0xA83A54`** | `Timings[128]` |

`Add`（YRpp `QueueClass.h:80-92`）：`Count<size` 则写入、`Tail=(Tail+1)&(size-1)`，
否则 `false`（满 → 静默丢）。后继同构队列：`MegaMissionList` @ `0xA83ED0`（256，
`& 0xFF`）、`DoList` @ `0x8B41F8`（16384，`& 0x3FFF`）；组包侧
`MegaMissionTargets[8][8][128]` @ `0xAFA468`（计数 `0xAC50FC`），组包器 `0x64BFxx`
一包最多 128 个 `Whom`。

**关键粒度：一个单位一条事件**（易错点）：下令循环 `0x4AE750` 遍历
`CurrentObjects`，每单位各调一次派发 → `TechnoClass::ClickedMission` @ **`0x6FFBE0`**
（虚表槽 `0x378`）末尾 `call 0x646E90` → 构造 `MEGAMISSION{Whom; Mission; …}` 并
`OutList.Add`。**500 单位 = 500 条，`Whom` 即目标单位**，不存在批量语义。

抛点都带 `cmp …,0x80 / jge`（`646ef0~646f58` 构造→判满→丢；同形：
`0x646F70 MEGAMISSION_F`、组命令 `0x730D60/0x730EA0/0x730FE0`；组包器
`0x64C739 cmp [0xA83ED0],0x100`、`0x64C191 cmp [0x8B41F8],0x4000`）。

## 4. 超限后三条路径行为不一（易踩坑）

### (a) 右键 / 热键逐单位派发：**完全静默**

`0x4AE750`（调用点 `0x4ABFA9`）扫完整个选区，`ClickedMission` 返回值**完全不看**
（`4ae844 call [edx+0x144] / 4ae84a~4ae85a inc+cmp+jl`）。超限单位无语音无提示，就是不动。

### (b) S / G / F 组命令：**第一条失败就整段跳出**

`GuardCommandClass::Execute` @ `0x730D60`（Ares 挂 `0x730DB0`）：
`730deb call [edi+0x378] / 730df1 bl,al / 730df5 je 0x730e8f`（走函数尾，剩下全不管）；
`StopCommandClass` @ `0x730EA0`（`730e5e/730e60`，Ares 挂 `0x730EE5`）、第三个 @
`0x730FE0`（`731025/731027`）同形。`bl` = 至今全成功标志 → 「按 S 只有前 N 个停下」。

### (c) 一处明确拒绝 + 播语音的 128 检查

`0x639130`（调用点 `0x4ABF7F`，前置 `0x639040` 判同类选中）：读标志 `0xAC4CF4`
（语义未查清，见 §7），遍历 `CurrentObjects` 统计同类数 + 玩家计数 `0xAC4B84`，
`add ebp,edi / cmp ebp,0x80 / jle 放行`，否则播警告语音让调用方放弃下单。

其它抛点：`QueueClass::Add` 返回 `false`，调用方多直接忽略（同 (a) 静默丢）。

## 5. 联机影响：**没有**

1. **本机事件只归本机**：别家操作是收进来的，本机不代发。延迟与否只取决于本机输入 + 本机水位。
2. **补发仍是原版事件**（带原版帧号，走 `OutList → DoList`），各端同一串事件同一执行序；
   「晚几帧发」≡「网络晚几帧到」。帧 CRC（`LatestFramesCRC[256]` @ `0xB04474`、
   `CurrentFrameCRC` @ `0xAC51FC`）算的是这串字节，相同即不同步不报。
3. **被挤掉的事件所有端一起缺**（没进 OutList = 没上网），是 YR 原版玩法 bug，不是不同步。
4. **峰值不超原版**：补发每帧同样 ≤128 条 × 111B ≈ 14KB，只把丢掉的摊到后续帧。

`MPEnable` 默认 0 纯粹保守，挡的是 §7 未验证的 Winsock 下一层缓冲。单机（战役 0 / 遭遇战 5）直开。
`GameMode` @ `0xA8B238`：`Campaign=0 / LAN=3 / Internet=4 / Skirmish=5`。

## 6. 已实施：`OrderThrottle`（源码 `src/OrderThrottle.cpp`，配置见 §6.4）

钩点（`.text` 直接补丁，不进 `.inj`）：`0x6FFBE0: 81 EC 88 00 00 00 53 55 56 57`
（`sub esp,0x88` + push，偷 10B 无相对跳转，跳板重放安全；回跳 `0x6FFBEA`，
尾声 `ret 0x10`，返回值只保证 AL）。入口栈形 `[esp+4]=Mission, +8=pTarget,
+0xC=TargetCell, +0x10=NearestCell`，`ECX=this`。冲突核对：Phobos 只钩 `0x6FFD4C`
（体内 +0x16C 的 VoiceSpecialAttack），Ares 只钩 `0x6FF860`/`0x6FFEC0`/`0x6FFF9E`，
无 `0x6FFBE0`，不重叠。

判定（**原版能发的发，原版会丢的不丢**，无额外阈值）：
```c
if (s_QCount <= 0 && *(unsigned*)ADDR_OUT_COUNT < EVT_CAP) return 0;  /* 放行 */
... 否则入队 (返回 1) ...
if (s_QCount >= OT_QCAP) return 2;  /* 队列满: 与原版同形地失败 */
```

补发（挂 `PowerDrawBoth` 每逻辑帧）：`cnt=OutList 现有数; cnt>=128 return;`
`while (队非空 && cnt<128)` 校验后调**跳板**（非补丁入口，不递归），`cnt++`
（一条令恰推进 1）。`cnt` 是上界：原版中途拒收只会令其高估，高估 = 少发方向，
本帧必不溢出，无需预留。补发还原入队瞬间 `MoveFeedback`（`0x822CF2`），语音不变。

兜底：换图/读档（`ScenarioClass::Instance` @ `0xA8B230` 变）整队丢弃；单条等超
600 帧（~10s）丢弃；补发前校验（`IsPlausiblePtr` + 虚表落 exe 映像 + `IsAlive`(+0x90)
且非 `InLimbo`(+0x81)，cell 只验指针）；装钩幂等 + 目标点被占则 `OFF` 不覆盖。

### 6.4 配置

```ini
[OrderThrottle]
Enable=1      ; 总开关 (默认 1)。0 = 完全旁路, 与原版逐位相同
MPEnable=0    ; 联机是否启用。默认 0, 见 §5
```
