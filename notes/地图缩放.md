# 地图缩放 (ScaleBar)

代码：`src/GUI/ScaleBar.cpp` + `src/GUI/FullMap.cpp`（视口几何）+ `src/MOExperience.cpp`（两个鼠标折算钩 +
`GScreenClass::Render` 入口钩）。 配置：`[ScaleBar]`。9 档：0.25=4 倍 / 1/3=3 倍 / 0.5=2 倍 / 2/3=1.5 倍 / 1=原样 /
1.25 / 1.5 / 2.0 / MAX=整图。 放大档（scale<1）与缩小档（scale>1）都实现（缩小档见 §11）。

---

## 0. 一句话

引擎只会 1:1 逐格画地图，所以"缩放" = **视口 R 改成视图区 A 的 scale 倍，引擎照旧 1:1 画进 Composite 的 R，呈现时把 R 最近邻放大铺回 A**。

## 1. 引擎侧事实（gamemd.exe 反汇编实证）

| 事实 | 地址 / 依据 |

## 2. 两个矩形与不变量

```
A = 满视图区 (侧栏模式决定宽, 高 = winH-32), FullMap 每循环写死
R = 引擎实际视口 = A * scale, 恒有 ViewBounds.X = ViewBounds.Y = 0
```

- **ViewBounds.xy 缩放时必须恒为 0**：渲染落点是 `ViewBounds.xy + (mapPos - T)`，
所以 R 永远落在渲染面的 (0,0)。而引擎自己的两条查格路（`CoordsToCell` / `ClientToCoords`）只在 X=0 时一致，非 0 会让下单击与 hover 差
`2·X`。
- **`[0xB0CE28/2C/30/34]` 必须始终等于 R**（不是 ViewBounds）。`Fm_ApplyViewWidth`
有一处**故意**拿 **A** 调 `DisplayClass::Set_View_Dimensions`（那个函数末尾会 `InitGUI`，侧栏一次性写入的偏移全按传入矩形算，传 R
会把侧栏摆坏），顺手就把缓存 留成了 A。而 `sync()` 只在几何变化那一帧跑 ⇒ **缓存永远停在 A** ⇒ `TacticalPos` 按 A 算而渲染按 R ⇒ 恒定偏移
`(A-R)/2`，放大档下 = 视野整体偏左上 （左上出界、右下少一圈）+ 引擎悬浮提示错位（与自己那份重影）。 `Fm_SyncViewCache`
负责纠正，且放在"几何没变"的早退之前也跑，让不变量自愈。

## 3. 档位表

固定九档 `0.25 / 1/3 / 0.5 / 1/1.5 / 1.0 / 1.25 / 1.5 / 2.0 / MAX`（`s_LevAll`，最右 `SB_LEV_MAX` 那档表里
scale 留 0 = 现算）。`[ScaleBar] Level` 是档位序号：

| # | scale | 标签 | 含义 |
|---|-------|------|------|
| 0 | 0.25  | 4x   | 4 倍放大 |
| 1 | 1/3   | 3x   | |
| 2 | 0.5   | 2x   | |
| 3 | 2/3   | 1.5x | |
| 4 | 1.0   | 1x   | 原样（默认） |
| 5 | 1.25  | 0.8x | 视野 1.25 倍 |
| 6 | 1.5   | 0.7x | 视野 1.5 倍 |
| 7 | 2.0   | 0.5x | 视野 2 倍 |
| 8 | MAX   | max  | 整张地图塞进视图区 |

刻度条上的文字是"相对 1x 的倍率" `1/scale`（`Sb_Fmt1`，一位小数）。**常显的只有 `4x / 1x / 0.5x` 三档**（下标 0 / `s_LevOne` /
`s_NLev-2`），其余（含 `max`）只有鼠标 悬在其上时才画（`SB_Poll` 每帧算 `s_HoverLev = Sb_OverBar ? Sb_LevelAt(mx) :
-1`）。

**MAX 档**（`Sb_CalcMaxScale`）：`scale = max(图宽/A.Width, 图高/A.Height)` —— 取更松的那轴，
两轴才都装得下；另一边留余量（图外深灰）。地图像素矩形走 `Sb_MapPx`（与
`Clamp_Center` 同一套换算）。R 长边超 `[ScaleBar] LimitFallback`（缺省 8192，可配，0=不限）时钳到限制上
（能装多少装多少）；低于 320x240（同 `SB_EnsureBig`
下限）或地图尺寸读不到才判为不支持 ⇒ 点那一档时退到**最高那一档**（scale 2.0） 并打一条日志，不静默变 1x。倍率随窗口/地图尺寸变，`SB_NoteWindowSurface` 与
`SB_Poll` 里各自 `Sb_DropMax()` 让它重算（只在 MAX 档才算）。

刻度条控件的几何：上面一条档位文字带（`FontPx+2`）+ 1px 缝 + 下面 12px 的滑条带 + 2px 底边留白（`SB_BOT_PAD`），`FontPx=12` 时整
**29px**。滑条带（相对滑条带顶 `rowY`）里的摆法：

```
刻度线    2..8  (7px, SB_TICK_H, 下挪 SB_TICK_DY=2, 坐在横条正上方)
黄色滑块  1..9  (9px, SB_KNOB_H/SB_KNOB_DY —— 高度不跟刻度线走, 下移 1px 压住横条第一行)
贯穿横条  9..11 (3px, SB_LINE_H, 贴控件底, 左端向左多画 2px = SB_LINE_X0=-2, 右端不动)
```

`+/-` 画在刻度带里居中（`SB_SIGN_C/SB_SIGN_BAR/SB_SIGN_STEM`），不骑横线。
当前档的黄色滑块比刻线高（9px vs 7px）、只比刻度宽一点，当前档一眼可辨。

纵向定位：`[ScaleBar] Y` 是**下边距**（控件底边到窗口底边多少像素），`Sb_Place` 算 `s_BarY = gh - s_Y -
s_WidgetH`，`Y=-1` 才贴**带顶** （`gh - 32`，与 `FullMap.cpp` 的 `winH-32` 同一条）。

- 几何变了会在日志里打一条 `sbar: geom x=.. y=.. w=.. h=.. win=..`。
横向基准恒为"侧栏列左缘"（窗口宽 − 168），**与 F11 侧栏显隐无关**，条右端再往左让 `[ScaleBar] X`（默认 32）。

- **放大档**（scale<1）：视口收小，引擎照旧画进 Composite 的 (0,0,R)，呈现时把 R
最近邻放大铺回 A（`SB_CompositeMagnify`）。
- **缩小档**（scale>1）：视口放大，需要一张 R 那么大的离屏面。本模块自建两张 R 大的
DSurface，只在 `GScreenClass::Render` 期间临时换进 `[0x88731C]`(Composite)/ `[0x8872FC]`(地图面)，渲染完还原并把 R
降采样铺回 A（`SB_CompositeDemagnify`）。 受 ddraw 大面内存限制，建面失败时自动退回 A（等于 1x），不会越界。见 §11。

## 4. 时序（钩点与理由）

```
prepare 0x4F42F0 (每循环)  → PowerDrawBoth : ... SB_Poll（摆条 + 点击换档）

  0x4F4502  call [edx+0x40]   → chrome pass 0x6D0A20（底栏 [0xB0FC58] + 侧栏 + 悬停提示）
  0x4F4505  ChromePostEntry   → 装回大面   (SB_RenderResume)

  0x4F451B  AfterMapEntry     → 还原窗口面 + 铺图外 + R 降采样铺回 A (SB_RenderAfterMap)
```

**放大写 Composite 而不是 Primary**：它是后面每次上屏 blit 的**源**，在它上面改， 后续多少次 blit 都把放大结果原样搬上屏（写 Primary 会被随后的
blit 覆盖）。

凡是"按 ViewBounds 定位"的引擎代码都会跟着视口缩小的量挪位置 —— 除了地图光栅化， 还有超武列表（`PowerBarClass::Draw`
0x6DA9D0）、边缘卷屏（`Scroll_Map`）、框选橡皮线 （0x6D5030）。新增缩放功能时按这条核一遍。

## 5. 缩放在 Composite 上的两条不变量

1. **呈现阶段不许动 Composite 的地图区以外的任何东西**，且放大只做一次、位置固定在
视图区 A —— 引擎是**增量**重绘（只重画标脏的格），任何"缩放一次、事后补一次"的 做法都会在同一帧内被引擎重画盖掉。
2. `[0xB0CE2x]` 缓存必须等于 R（见 §2）。

## 5.1 放大档残影：就地放大把引擎视口 R 换成放大像素

**症状**：2x / 4x（`SB_In()`）下缓慢移动时，新露出来的地方出现别的东西的残影（该出现建筑的地方是别的内容的轮廓）。1x 正常；静止不闪。

**根因 = 呈现顺序里"源"和"目标"重叠，而源是引擎的增量光栅。**

1. `SB_GetViewRect` 恒返回 `R = {0,0,w,h}`（原点固定、不超过 A）⇒ **R ⊆ A**。
2. `SB_CompositeMagnify` 是**就地**放大：`copy R -> scratch; resample scratch -> A`。盖住 R 是必须的——它就是本帧要呈现的图。于是**引擎的视口 R 每帧被换成放大像素**。
3. 引擎光栅是**增量**的（§11.15：视口一动先整幅 `CopyFromPart` 位移拷贝，再只画新空出来那条；没标脏的格子谁也不碰）。

⇒ 放大像素被下一帧的位移拷贝当成地图内容搬走。4x 时一个源像素放大成 4×4 块，1x 只有
1px —— 放大档一眼看出来的原因。

**修法 = 还原 R + 按位移拷贝门控标脏**，见 §5.1.2。

⚠️ **呈现之前不要往 R 写 1:1 内容**（R ⊆ A，会在左上角露出没放大的方块）。

光标画在 **Primary** 上，与 Composite 上的放大无关（反汇编见 `WWMouseClass` 0x7B8730；
`flag=1` 的分支读 `ViewBounds.Width`，须与条带上屏的 `dst.X` 同源，见 隐藏侧栏.md §4.11）。

### 5.1.1 呈现开销：整数快路 / 快拷 / 列映射

放大档每帧的固定开销 = 重采样（A 的整幅）。

| 档位 | R → A | 重采样通用路 | 整数倍快路 |
|---|---|---|---|
| 4x | 438×262 → 1752×1048 | 0.76 ms/帧 | **0.17 ms**（4.4×）|
| 2x | 876×524 → 1752×1048 | 0.76 ms/帧 | **0.30 ms**（2.6×）|
| 1.3x | 1348×806（比例非整数）| 0.76 ms/帧 | 走通用路 |

（1920×1080 / 态0；单机测量，只看量级。）

1. **整数快路**（`Sb_ResampleNx`）：n 倍放大只需把源行横向铺 n 次、铺好的行纵向重复 n 次，
   写入量约 1/n。横向按 4 字节成对写，写次数减半。
   只在 n 是 2 的幂时走（通用路 16.16 步长在 n=3 时差一格）。两条路逐位相同，
   见 `test/scalebar_resample_test.c`（2/4/8 倍、各种对齐、奇数行宽）。
2. **快拷**（`Sb_CopyPx`）：本工程无 CRT（`memcpy` 是逐字节循环），每帧数 MB 的搬运
   走它比采样本身还贵，故按 dword 搬。纵向重复、R 快照、清面/铺底色全走它，只改本模块。
3. **列映射**（`Sb_Resample`，非整数倍与所有缩小档走它）：每帧算一次表，
   内层只剩两次访存。表按目标绝对列建（起点 `x0`）。
4. **精确 2:1 步幅**（0.5x 档的降采样）：`rw == 2*dw` 且 `rh == 2*dh` 时直读
   `src[y*2][x*2]`，不要乘法也不要查表。与通用路逐位相同，同上测试锁住。

**测试**（`test/scalebar_resample_test.c`）：两条路逐位比对。写越界测试的两点：
目的不用常量预填（用随机图案），表尾接一页 `PAGE_NOACCESS` 让越界当场崩。

### 5.1.2 帧率：还原 R 代替整块标脏

放大档曾比 1x 还慢：每帧整块标脏逼引擎重画整幅 R（逐格光栅，单位像素比内存搬运贵一个量级），
而 1x 不标脏。

**改成自己还原 R**（`SB_ViewPreRender`）：`SB_CompositeMagnify` 重采样前本来就得把 R 拷进
`s_Scratch`，那份快照逐位就是引擎本帧的输出。呈现后 R 里是放大像素，下一帧引擎动 R 之前
按行拷回去即可，增量光栅照旧。代价 = 一次 R 大小的行拷贝（4x 约 230KB）。

**标脏按"这一趟会不会跑位移拷贝"门控**（位移拷贝的源就是 R，只在 `delta ≠ 0` 时跑）：

| 相机 | 引擎这一趟 | R 里的放大像素 | 结论 |
|---|---|---|---|
| 静止 | 增量早退，**不读 R** | 无害 | 只还原就够，**零额外开销** |
| 移动 | `CopyFromPart` 位移拷贝，**读 R** | 被搬成残影 | 必须整块标脏 |

判据 = 视口原点（`TacticalClass+0xB0/+0xB4`）与上次呈现记下的值是否不同；
读不到按"动过"处理。还原不论动不动都先做一遍。换档后连催 4 帧标脏（`s_ViewDirtyN`）。

**实现约束：**

- 还原只认 pitch 与 R 的几何，**不认面指针**（引擎双缓冲轮换，快照那块未必是下帧要画的那块）。
- 同帧第二遍按"引擎帧号 + armed"去重，否则把放大像素再拍成"干净 R"。
  暂停时帧号冻结，迷你循环每遍 Render 都会还原（armed 清零），此时同帧也必须重放。
- `s_Scratch` 归这条链独占。

### 5.1.3 刻度条：按需刷一次底栏带

换档/悬停切档后，旧的黄色指示条和字会留在底栏带上（刻度条只画不擦，
而底栏带归引擎 chrome 管，脏缓存命中就整段跳过）。

**修法 = 按需刷一次。** `Sb_Paint` 开头：

```c
sig = s_Level * 2 + (s_HoverLev + 1);
if (sig != s_BarSig) { s_BarSig = sig; *(unsigned*)0xB0CD44 = 0; }
```

只在切换档位或悬停切档这两个时刻清一次，让引擎下一次 chrome 重画底栏带。
绘制照常每帧进行，档位文字不透明。不要写成每帧清（等于逼引擎每帧重画整段 chrome）。

### 5.1.4 每帧两处重复劳动

- **条带抹黑跑两遍**：`FM_BlitSb`（chrome pass）与 `FM_DrawRadarTo`（消息帧）算出的 keep 完全相同，而两次之间没有任何代码写条带（小地图自绘之后才是 `PowerDisplay_DrawSb`）⇒ 第二次纯浪费，态1 下是每帧最多 4 次整幅 `FillRect`。已按引擎帧号去重（`Fm_ClearStripOnce`）。
- **侧栏列起点算三遍且已经漂移**：`Fm_BlitSb` / `FM_DrawRadarTo` / `FM_Poll` 各写了一份兜底链，其中 `FM_Poll` 那份的兜底值与另两份不同（`vb->X+vb->Width-sbW` vs `winW-sbw`）。三处必须同值，否则条带上屏位置与小地图自绘位置会错开。已收成 `Fm_ColumnPlace()` 一处。

## 5.2 悬停提示在放大档下的两个毛病

放大档下悬停提示（建筑名 / 电量串 / 侧栏 gadget 名）有两个症状，都出在"放大前那次绘制"和"拿视口当界面"上。

**① 重影：同一帧画了两遍，大那份被放大**

`ToolTipManager::Draw`（虚表 +0x0C）全二进制只有两个调用点：

| 调用点 | 位置 | 相对 `SB_CompositeMagnify` |
|---|---|---|
| `0x4F4564` | `GScreenClass::Render`，实参 0 | **之后** |
| `0x6A7081` | `SidebarClass::Draw`（`0x6A6C30`），实参 1 | **之前** |

- 字形尺寸来自全局字体 `[0x89C4D0]`（经 `GetTextDimension` `0x433CF0`），**永不随缩放变** ⇒ 字号大一倍那份只能是 `SB_CompositeMagnify` 的重采样产物。
- 不是残影：`TacticalClass::Render` 每帧重画整个视口（`0x6D3E2F` 那几条"无变化"分支是跳回 `0x6D4582` **继续画**）⇒ R 每帧干净。
- ⇒ 放大档挡掉 `0x6A7089`（抢 7B = `8B 11 6A 01 FF 52 0C`），留 `0x4F4564` 那次。Entry 见 `MOExperience_TipPreDrawEntry`，安装见 `VecText_Install`。
- Entry 里必须自己跑 `ToolTipManager::Process`（`0x724AD0`）：`Draw(1)` 第一件事就是它，刷 `Dimension` 与 LifeTime/Sticky 计时，跳掉之后放大后那次会画空框。只跳绘制，`0x6A7090` 之后的 `BlitSidebar` 判据一字不改。门控 `SB_In() && !SB_Safe()`，与 `SB_CompositeMagnify` 一致 ⇒ 1x 与 Safe 档零行为变化。

**② 偏移：拿视口 R 当界面，提示盒被整体拽走**

放大档下凡"拿 ViewBounds 当界线"的地方都会按视口缩小的量误判。三处，全部改成用满视图区 A（`ScaleBar.cpp` 的 `g_AView` 影子，每循环
`SB_PublishAView()` 抄一次）：

| 位置 | 拿 R 当什么 | 后果 |
|---|---|---|
| `ToolTip_Clamp`（`0x478FDC` 钩） | 钳制右界 | **盒子连字整体往左拽**，位移最多一整个视口宽（2x 876px / 4x 1314px）⇒ 提示飞到离光标很远 |
| `ToolTipManager::Update`（`0x478BD1/0x478BD7/0x478C17`） | 选面比较 + `GetTextDimension` 的 maxWidth + 居中基准 | 误判"在侧栏上"、长文本按 876 而不是 1752 提前折行 |
| `CCToolTip::DrawText`（`0x478E4A/0x478E50`） | 选面右界 | 误走侧栏面那支（`0x478E7E` 还会 `x -= 右界`） |

- 后两处：指令里写死的 imm32 改指到影子（`VecText.cpp` 的 `rep[]`），指令长度不变、只换数据来源；`ToolTip_Clamp` 自己算，按 `SB_In()` 取。
- 改址必须先全验完再动手：`A1`/`BF` 形态第 2 字节已是立即数，误当 opcode 会留半改状态。
- 侧栏两处 `SidebarBounds`(`0x886F90/0x886F98`) 不动。**1x 时 A == R ⇒ 与原版逐位相同。** 不写回 ViewBounds 本身（引擎状态）。

**③ 一条看着像 bug 但不要动**：`ToolTipManager::Process`（`0x724AD0`）把 `Dimension` 锚在
`CurrentMousePosition`，而后者由 `ProcessMessage`（`0x724200` → `GetCursorPos` +
`ScreenToClient`）写成**物理**点，不经我们折算的 `WWMouse` +0x34 也不经 `0x6930A0` 的 lParam。看着像漏折算，其实是对的：放大前那次已被
① 挡掉，剩下那次画在放大之后的 Composite 上，而那时的 Composite 像素 1:1 对应屏幕 ⇒ 物理点正好落在光标处。折了反而偏到 1/zoom。

## 6. 鼠标

引擎里"鼠标在哪"有**两个数据源**，两条都必须折算，否则口径不一致 ⇒ 放大档下 "按下时的点"与"每帧读到的点"差 `A/R` 倍。 （提示框那条 `GetCursorPos`
路径是第三个数据源，它**不需要**折，见 §5.1③。）

### 6.1 每帧轮询：`WWMouseClass` 虚表 +0x34

`v = (p - A.xy) * R.size / A.size`（p 在 A 内才折，A 外原样放行）。

11 个消费点（全二进制扫 `mov ecx,[0x887640]` 附近 `call [reg+0x34]` 的全集）：

| 调用点 | 消费者 |
|---|---|
| 0x4A56CE | 单位矩形命中 |
| 0x4A91EF / 0x4A9232 / 0x4A9284 | `DisplayClass::Scroll_Map` 边缘卷屏 |
| 0x4AAC6D / 0x4FB405 | `ClientToCoords` → `ProcessClickCoords` |
| 0x4AE538 | 框选（<900px）→ `ProcessClickCoords` |
| 0x4B8FAA | 地图像素区判定 |
| 0x692F5E | 点选下单击 |
| 0x6D0ABA | 地形判定 |
| 0x6D5068 | **框选橡皮线**（0x6D5030，第三趟 0x4F4515 调） |

**为什么必须挑"数据源"而不是消费者**：挂在 `ClientToCoords` (0x6D2280) / `CoordsToCell` (0x6D6590) 上按调用点白名单折是不可行的
—— 它们的入参绝大多数是 引擎自己的地图像素，折算等于替引擎改数据（一折就崩）；而只挑"看着像鼠标"的少数 调用点又必然漏（0x6D5068 橡皮线、0x692F5E
点选都漏过）。源头只有虚表 +0x34 一处。

安全性：gadget 命中链（`GadgetClass::Input` 0x4E1640）用虚表 **+0x2C/+0x30**， 不是 +0x34 ⇒
侧栏/工具栏/雷达命中一点不变；光标绘制走 +0x3C/+0x40 读实例原始坐标 ⇒ 光标仍停在物理位置；**1x 时 A == R，折算恒等**；只读内存 + 只算坐标，联机安全。

本项目里自己走 `ProcessClickCoords` 的三处（`OU_MouseCellPx` / `OU_MouseCellTarget` / `DP_MouseCellZ`）拿的是
`GtMouseGameXY` 的物理点，喂之前 必须自己调一次 `SB_MapPoint`。按引擎投影画图元的三处走 `SB_ViewToScreen` /
`SB_MapDeltaToScreen`。

### 6.2 鼠标按钮消息：窗口过程的 `lParam`

```
窗口过程 0x7775C0 → 0x777640 call 0x6930A0 (this=MouseClass::Instance=0x87F7E8)
       第4实参 = &lParam
```
`0x6930A0` 用 `eax = Msg-0x201` 查 6 项跳转表（0x693410），落地的只有五个鼠标按钮， 开头同一段：`mov eax,[edx]`（x）+ `movsx
ecx,word [esp+36]`（y）`- ViewBounds.xy`。

| Msg | 跳转 | 干什么 |
|---|---|---|
| 0x201 LBUTTONDOWN | 0x693126 | 点选下令 + `LeftMouseButtonClick` 0x4AC310 **记框选锚点**（DisplayClass+0x11DC/+0x11E0）|
| 0x202 LBUTTONUP | 0x6931F9 | `0x63A8E0(x,y)` 滚屏判据 → 点选收尾 |
| 0x203 LBUTTONDBLCLK | 0x6932A4 | 同上 |
| 0x204 RBUTTONDOWN | 0x693366 | `0x63AB00(x,y)` 边缘卷屏开关；左键还按着则结束框选 |
| 0x205 RBUTTONUP | 0x6933E6 | 左键还按着才收尾 |

**钩法**：`MOExperience_WndMouseEntry` 把**第4实参那个指针**换成折算好的副本 （`s_WndLp`），尾跳跳板。

- **只能换指针，不能改 lParam 的值**：同一个槽后续还要原样交出去更新鼠标位置；
改了不还原 ⇒ 光标跑偏、gadget 命中全歪、`GtMouseGameXY` 还会再折一次。 第4实参槽在 0x6930A0 自己栈帧上（`ret 0x10` 弹掉）⇒
换指针不影响调用者。
- 副本须是**打包好的 lParam**（`(y<<16)|x`）：引擎按高/低 16 位取 y/x，
放 `Point2D` 则 y 恒 0。
- 入口 `ecx` = this（跳板当 DisplayClass 用），cdecl 调用前后手动 `push/pop ecx`。

不修的症状：单击被判成拖框、橡皮线起点偏到 2 倍远、点选落格偏一档。

## 10. 两条把游戏打崩过的坑（结论保留）

**① 跳板偷的字节数必须落在完整指令的末字节上。** 跳板把 `[at, at+n)` 原样搬走再跳回 `at+n`；`at+n` 落在某条指令中间就会从半个指令开始重新反汇编 →
执行到莫名其妙的指令 直接飞掉（能写任意内存 / 跳去任何地方）。用法：先反汇编确认末字节再填 `n`。

**② 写引擎内存的每个循环都要同时按"目标对象的实际尺寸"夹。** 只按调用方给的矩形夹， 一旦该矩形超出目标面（改分辨率/建面的瞬间）就会整片写出界 ⇒ 堆被写坏 ⇒ 之后某个虚表
/函数指针变野，跳到堆地址崩。往 DirectDraw 面写之前还要查 `pitch >= 2*width` （不是 16bpp 的面会每行越过行尾）。

## 11. 缩小档（scale>1，扩大视野）

放大档把视口收小，引擎画得少；缩小档反过来，视口 R=A*scale 比窗口大，引擎必须画进一张 R 那么大的面。`GScreenClass::Render` 只会把视口 1:1 画进
`[0x88731C]`（三趟 Render 的 面参数），而 `TacticalClass::Render`（0x6D3D10）内部在 0x6D4057 把 `[0x88731C]` 与
`[0x8872FC]`（持久地图面）**互换**，所以两张面必须同尺寸 —— 这是"只换 Composite 不够" 的原因。

### 11.1 面从哪来、什么时候换

引擎自己的 CreateAll 只在建面/改分辨率时跑，且本模块明确不钩它（会崩）。所以：

1. `SB_GetViewRect`（FullMap 每循环调）在 scale>1 时先 `SB_EnsureBig(w,h)` 自建两张 R 大
的 DSurface（`0x4BA5A0` 构造，对象 0x24 字节，flags `1,1`）。建不出（ddraw 内存不够 / Render 钩没装上）就返回 0 ⇒ FullMap 用
A，行为等于 1x，**绝不**按 R 往窗口面里画。
2. Render 入口钩（`0x4F4480`，首 8B=`83 EC 08 A1 1C 73 88 00`）在缩小档把
`[0x88731C]`/`[0x8872FC]` 换成大面（`SB_RenderSwapIn`）。
3. 三趟地图画完、**引擎 UI 之前**（`GScreenClass::Render` 内 `0x4F451B`，钩
`MOExperience_AfterMapEntry`）`SB_RenderAfterMap`：还原 `[0x88731C]`/`[0x8872FC]` **以及 "当前绘制面"
`[0x887314]`** 成窗口面，再把大面的 R 区域降采样铺回窗口 Composite 的 A（`SB_CompositeDemagnify`，源/目标两张面不重叠，可直接读写、无需
暂存），之后引擎原生 UI（侧栏 `0x4F4547`、MessageList `0x4F455D`）与本项目 UI 链 全部 1:1 落在窗口 Composite 上。见 §11.5。
4. 离开缩小档（`SB_PrepareSurface` 见到 `!SB_Out`）销毁大面。

大面只在一次 `GScreenClass::Render` 内出现，窗口期的其它代码（prepare/侧栏/DoBlit）看到的
仍是窗口面。`g_RenderTramp==NULL`（钩子装不上）时整块停用。

### 11.2 ZBuffer/ABuffer —— 只能借它的构造/析构，**不能走 Set_View_Dimensions**

`[0x887644]`(ZBuffer) / `[0x87E8A4]`(ABuffer) 每像素 2 字节、被 Render 每帧整块清零并按 屏幕坐标写。**缩小档必须**按 R
重建这两块缓冲（TacticalClass::Render 用 ViewBounds=R 的 坐标 z-fill/z-test），否则越过行尾/缓冲末尾读/写到野地址。

`DisplayClass::Set_View_Dimensions` (0x4A8960) 的第 3/5 步就是"按 ViewBounds 释放+重建
这两块缓冲"，但那个正门**顺带**做了四件在缩小档下全是坏事的事：

| 步骤 | 副作用 | 缩小档后果 |
|---|---|---|
| 0x4A8987-0x89A1 | 覆写 ViewBounds 四字段 | 缩放的不变量被它改掉 |
| 0x4A89BD `call 0x6D5F60` | 同步 `[0xB0CE28/2C/30/34]` 缓存 | 缓存被留成传入值 |
| 0x4A89CA `call [edx+0x0C]` / 0x4A8B0B `[edx+0x10]` | 按 ViewBounds 重建 WWMouse 视口 | 鼠标视口变成 R，死区/光标判据全错 |
| **0x4A8B13 `call 0x6ABD30` = `DisplayClass::InitGUI`** | 侧栏页签/cameo 行/小地图/底部工具栏的**一次性**布局写入全按传进去的矩形算 | **崩溃 + 侧栏点不动**（见下） |
| 0x4A8BB8 `call 0x5D3A60` / 0x4A8BC9 `call 0x5D4AD0` | 按 `[0x886FA8]` 重设 MessageList 区 | 消息框被摆到屏幕外 |

**⇒ `SB_ResizeBufs` 只借构造/析构自己重建两块缓冲** （`0x7BC970` / `0x7BCAE0` / `0x410CE0` /
`0x410E50`，`operator new/delete` = `0x7C8E17` / `0x7C8B3D`，对象 `0x30` 字节，布局 `+0x28=宽
+0x2C=高`，ZBuffer 构造完补 `+0x24=0x8000`）。 不碰 ViewBounds、不碰缓存、不碰 WWMouse、不碰侧栏布局。
顺序上**先建新的再放旧的**：分配失败时引擎手里仍是完好的旧缓冲 （宁可尺寸不匹配，也不能让 `[0x887644]` 变空指针 —— Render 每帧无条件解引用它）。

**调用约定一律按 `ret N` 核实**（矩形按值传的构造是 `ret 0x10`，传指针砸栈）：

| 函数 | 结尾 | 约定 | 调用要点 |
|---|---|---|---|
| `0x7C8E17` `operator new` | `6A 01 / FF 74 24 08 / E8 .. / 59 59 / C3`（净栈变化 0） | cdecl 1 参 | 参数留给调用方 |
| `0x7C8B3D` `operator delete` | `push [esp+4] / call .. / pop ecx / ret` | cdecl 1 参 | 同上 |
| `0x7BCAE0` / `0x410E50` 析构 | 裸 `ret` | thiscall，无栈参数 | — |
| `0x7BC970` / `0x410CE0` 构造 | **`ret 0x10`**（`0x7BCA46` / `0x410DB3`） | thiscall + **矩形按值传**（入口按 `[esp+4]/[+8]/[+0xC]/[+0x10]` 读） | `ct(p, *r)`，**不能传指针** |

构造 `ct(p, *r)` 必须按值传矩形（传指针被 callee 多弹 12 字节砸栈）。

**这条同时修掉了三个症状**（同一个根因）：

1. **F11 切侧栏崩**。日志现场：`MOE: phase=applyview`（= `Fm_ApplyViewWidth`），
`eip=0x6BA643`（`mov [ecx],dx`，通用拉伸 blit 的内层写循环），`ecx=0x0FFD911E`， 栈上是 `0x6B600D` ←
`0x6A9A43`。时序完全对上： `F11 → mode->radar → A 变 → R 变 → SB_ResizeBufs(R) → Set_View_Dimensions(R) →
InitGUI(R) → 侧栏图标按 R 几何摆 → 往 168 宽的侧栏面 x=3474 处拉伸 → 越界 → 崩`。
2. **超武侧栏按钮点一下就崩（F4 显隐不崩）**。同一个根因：点按钮会下单 → 加 cameo →
`RepaintSidebar` → 侧栏图标拉伸 → 越界。F4 只切显隐，不碰 cameo，所以不崩。
3. **原版侧栏点击失效**。`InitGUI` 那批一次性写入同时把侧栏按钮的**命中区**按 R 摆歪，
点下去落在按钮外面。

`Fm_ApplyViewWidth` 里那条 `setDims(A)` 也加了 `&& !SB_Out()`：缩小档下缓冲归缩放独占， 否则两边来回抢（ScaleBar 按 R
建、FullMap 按 A 建），且它每次都会拖一次 InitGUI。

- **缩小档恒按 R 重建**（必须，见上）；其余档按 A。
- 日志：`sbar: zbuf <- WxH`（每次重建）、`sbar: zbuf alloc FAILED -> zoom-out off`，
换档行里的 `zbuf=WxH zref=WxH` 是"从引擎对象读出的真实尺寸 / 我们记的"，两者一致才算装好了。
- 别加 `[ScaleBar] GrowZBuf`（让 1x/放大档也按 R 重建）：1x 时 R==A 无事可做，缩小档恒开管不到，
放大档 R<A 开了反而把缓冲**缩小** —— 三档里两个天然是空操作。

### 11.2b 缩小档的"分辨率上限"：自设长边限制 + 内存

`[ScaleBar] LimitFallback`（缺省 8192，可配长边像素；0=不限；非 0 小于 3820 按 3820）：

| 限制 | 位置 | 性质 |
|---|---|---|
| R 长边 > LimitFallback ⇒ 钳到限制上（长边=限制值，能看多少看多少） | `Sb_CalcMaxScale` / `SB_GetViewRect` / `SB_ResizeBufs` 三处同线 (`Sb_OverLimit` + `Sb_ClampScale`) | **自设安全线，不是引擎硬上限**。实测缓冲能建出更大。三处必须同线，否则 R 与缓冲错配 ⇒ 野读崩（见 §11.18） |
| `DSurface::DSurface` (0x4BA5A0) 不夹尺寸 | 反汇编 | 只 `operator new(0x6C)` + 填描述符 + `CreateSurface`，失败由它返回 |
| `CreateSurface` 失败（显存/系统内存不够） | ddraw | 项目记 `sbar: zoom-out surface FAILED -> off` 退回 1x |
| R 宽 < 320 / 高 < 240 ⇒ 不建大面 | `SB_EnsureBig` | 反向（太小），不是上限 |
| `VisibleCells[800]`（0x6DA93E `cmp eax,0x31F`） | 引擎 | **不是分辨率上限**，是"同帧要重画的有物体格子数"硬截断；缩小档视野越大越容易撞 799，后面的单位不画 |

**实际瓶颈是内存，不是分辨率。** 缩小档每帧常驻：`2 张 R 大面 + 2 块 R 裁剪器`，都是 2 字节/像素 ⇒ 约 **8 × W × H 字节**。

| 窗口 (态0) | A | 0.75x 的 R / 占用 | 0.5x 的 R / 占用 |
|---|---|---|---|
| 1920×1080 | 1752×1048 | 2336×1397 / 26 MB | 3504×2096 / **59 MB** |
| 2560×1440 | 2392×1408 | 3190×1878 / 48 MB | 4784×2816 / **108 MB** |
| 3840×2160 | 3672×2128 | 4896×2837 / 111 MB | 7344×4256 / **250 MB** |

⇒ 1080p 两档都没问题；1440p 的 0.5x 约 108 MB；**4K 的 0.5x 约 250 MB**，能不能跑取决于 ddraw 驱动给不给得出来（给不出来就是
`FAILED -> off` 退回 1x，不会崩）。 长边限制缺省 8192，R 长边 > 8192 才钳（约窗口宽 ≳ 4952，5120 宽那档）；MAX 档 R 最大，超限和性能开销都先撞它。

⚠️ 另外换档瞬间 `Sb_ClearSurf` 会把两张大面整块写一遍（4K/0.5x 是 2×62 MB），是一次可见的卡顿；`s_BigCapW` 只增不减就是为了不每帧重建。

### 11.3 新面要催重画

引擎的地图是**增量**画的（只有标脏的格子重画），换视口宽度/换面都不标脏。新建的 R 大面是 空白的，所以 `SB_EnsureBig` 成功后连续 4 帧把整块 R 推进
`RegisterDirtyArea`（帧号门控）， 否则缩小后大半屏是黑的。

### 11.4 已改的消费点（scale>1 与 scale<1 共用）

`SB_MapPoint` / `SB_ViewToScreen` / `SB_MapDeltaToScreen` 的门从 `SB_In()` 改成 `SB_Zoomed()`（两者都是
`v=(p-A.xy)*R.size/A.size`，方向都成立）；`MOE_MousePos`、 `MOE_WndFixLParam`、`MessageDrawHook`
同步改；`ToolTip_Clamp` 的 A 影子判据也从 `SB_In()` 改成 `SB_Zoomed()`（缩小档下 ViewBounds=R>A，拿 R 当界同样会错）。放大档专属的
`SB_CompositeMagnify`、提示框重影修复（`TipPreDraw`）仍只判 `SB_In()`。

新增日志：`sbar: zoom-out surface ON WxH` / `sbar: zoom-out surface FAILED -> off` / `sbar: zoom-out
off (render hook missing)` / `vtext: render hook ON/OFF`。

### 11.5 还原点必须早于引擎 UI（底栏残影 + 侧栏崩溃的根因之一）

`GScreenClass::Render` 在三趟地图之后、`MessageList::Draw` 之前还有一段引擎原生 UI：

| 地址 | 内容 |
|---|---|
| `0x4F451B` | 光标恢复（`[0xB0B519]`）——**本模块的还原钩就抢这 5 字节** |
| `0x4F452D-0x4F4540` | `WWMouse::vt+0x40([0x887300] 侧栏面, 1)` + 清 `[0xB0B519]` |
| `0x4F4547` | `[[0xA8EF54]->vt+0x2C](0)` |
| `0x4F455D` | `MessageList::Draw` (0x5D49A0，全二进制**唯一**调用点) |

还顺带明确：`SidebarClass::Draw` 把 `[0x887314]` 换成侧栏自己的面再画，不往当前面画； "侧栏画进大面"不是它的锅（真凶见 §11.9）。 还原
`[0x887314]` 这一步仍然必须（`TacticalClass::Render` 把它写成换过之后的地图面）。

⚠️ `SB_RenderSuspend(1)` 目前无调用点（光标擦除那条只接了 Suspend(0)）：`0x4F4492` 的 `[0x887314]=eax`
拿到的是大面，光标在上面存取像素自洽，不致命；但 `g_PreCurWin/g_PreCurSurf` 恒 0，别误以为 `0x4F4492` 真的在让面。

### 11.6 边缘卷屏死区按屏幕空间算

`0x692B60` 把传入点当视口坐标再和面的宽高比死区；缩放后拿到的是视口点 ⇒ 死区跟缩放。入口换回物理鼠标（`SB_EdgeScrollPointFix`），1x 恒等。

### 11.7 ZBuffer/ABuffer 须匹配渲染面（换档崩溃根因之一）

两块缓冲被当成行步进/裁剪用，须与当前渲染面同尺寸（缩小档=R，平时=A）。 离开缩小档须缩回 A；记账以对象 `+0x28/+0x2C` 为准（引擎也会重建）；
先建新再放旧（`[0x887644]` 不能空，Render 每帧解引用）。

### 11.8 通用拉伸 blit 守卫（cameo 越界的兜底，判据见 §25）

缩放档下 cameo/图标拉伸（`0x6BA580`）会拿到坏面/坏矩形（`0x6BA643` 越界写）。 守卫只在 `SB_Zoomed()`
检查（指针+虚表+尺寸/pitch+矩形落界），非法返回 0， 合法走跳板。矩形落界按"两张面（s1/s2）都不沾才跳过"判：只认一张会误杀 "往 cameo
合成图标"的那类调用（矩形是另一张面的坐标，如 `(22,228,60,48)` 落在 strip 里而 s2 是 60x48 cameo），缩放档侧栏图标全空 就是这么来的（`blit:
skip unclipped dst=60x48 rect=22,228,60,48`）。 1x 零变化。日志：`vtext: blitguard hook ON` / `blit: skip
…`。

### 11.9 底栏残影（画面中部闪出底栏）—— 根因是 **chrome pass 在三趟地图中间按窗口坐标画**

现象：缩小档下大面 R=A*scale 里 `y ∈ [A.Height, winH)`（1.43 倍档时 = R.y 1048..1080）那条**窗口底栏带**的内容，被降采样映射到
A.y **733..756** —— 正好是画面 正中的那一条。即：残影不在窗口 Composite 上，而是**混在降采样的源（大面）里**。

#### 画它的是哪一笔

`GScreenClass::Render` (0x4F4480) 里除了三趟地图，还在**第二趟与第三趟之间**有一笔：

```
0x4F44F9  mov eax,[esp+0x10]      ; 实参 = 打包的两个 mode 标志
0x4F44FD  mov edx,[esi]          ; ← 本轮的挂点
0x4F44FF  push eax
0x4F4500  mov ecx,esi
0x4F4502  call [edx+0x40]        ; 虚表 +0x40 = 0x6D0A20 = chrome pass
0x4F4505  mov ecx,[0x88731C]     ; ← 本轮的挂点
0x4F450B  push 2 … call 0x6D3D10 ; 第三趟地图
```

`0x6D0A20` 那一趟：

| 地址 | 内容 |
|---|---|
| `0x6D0AC2` / `0x6D0BF8` / `0x6D0CDC` | 取 `[0xB0FC58]` = **底栏矩形**（1x = `(0, H-32, W-168, 32)`）|
| `0x6D0C3B` / `0x6D0D29` / `0x6D0DC8` | 往 `[0x887314]` blit 底栏条与侧栏图标（`0x6D0CFC..0x6D0D4B` 是逐个按钮的循环）|
| `0x6D0D7A` / `0x6D0E38` 一带 | `SidebarClass::Draw` (0x6A6C30)，内含 `ToolTipManager::Draw(1)`（**悬停提示盒**，0x6A708D）|

`0x6D0A20` 在 **`vt+0x40`**（紧挨 Render 的 `vt+0x3C`），夹在两趟地图中间。

#### 修法：把"让出窗口面"扩成两段

| 挂点 | 原指令 | 动作 |
|---|---|---|
| `0x4F4492` | `A3 14 73 88 00` | `SB_RenderSuspend(1)`：三个全局换回窗口面（**不动** `s_CurC/s_CurM/s_LastFinal`），并把**入口 eax** 换成窗口面（`0x4F44A2` 的光标擦除直接吃 eax，不读全局）|
| `0x4F44CB` | `A1 1C 73 88 00` | `SB_RenderResume()`：装回大面，原指令照跑重读全局 |
| **`0x4F44FD`** | **`8B 16 50 8B CE`** | **`SB_RenderSuspend(0)`：再让回窗口面**（不碰 `g_PreCur*`，chrome pass 走虚表不吃渲染面）|
| **`0x4F4505`** | **`8B 0D 1C 73 88 00`** | **`SB_RenderResume()`：装回大面** |

⇒ 大面被暴露的窗口真的只剩"三趟地图"这一段。

顺带修掉的两个症状（都出自这一笔）：

- **悬停提示显示两次**：chrome pass 里那次画进大面、降采样后缩小并上移，
随后 `0x4F4564` 又正确画一遍。现在只剩正确的一份。 所以缩小档**不能**学放大档挡 `0x6A7089`（`TipPreDraw` 仍只判 `SB_In()`）： 挡掉它
`ToolTipManager::Process` 计时不刷新。
- **选中单位时底部底栏"点不动"**：chrome 脏缓存 `[0xB0CC00..(n)]`（n=`[0xB0CD44]`）
记的是**大面**，`0x6D0B3C..0x6D0B57` 拿 `[0x887314]`（当时也是大面）比对命中 ⇒ `bl=0`，**整段 chrome
每帧跳过**。于是窗口面上那条底栏再也不会重画（只剩进档前 的死像素），而按钮的按下/悬停反馈全落在中部那条"错误底栏"上 ⇒ 看着就是"点了 底部却映射到地图中间"。

#### 另外两条配套

1. **新大面清零**。`DSurface` 像素缓冲内容未定义，图外/半格区会把堆残留当画面。
`SB_EnsureBig` 成功后两张面立即 `Sb_ClearSurf`。
2. **大面尺寸只增不减**。按 R 精确重建连按 F11 就是每帧建面+清零 ⇒ 整屏黑。
新 R 塞得下就复用（引擎只读写 `(0,0,R)`），切模式 R 变了推 4 帧整块脏区。
3. **换面泄漏自愈 + 本项目图层不画进大面**。`SB_RenderSwapIn` 记住真正的窗口面。

日志：`sbar: WARN composite leak from last frame -> re-armed` ⇒ 上一帧换面泄漏，已自愈； `vtext:
chrome-pre/post hook ON/OFF` ⇒ 让出/装回挂点状态。

### 11.10 视口 gadget 的 Y/Height 也收窄（否则缩小档侧栏点不动）

命中测试读 gadget 四个 int 当屏幕坐标比。容器摆在 ViewBounds 上；缩小档 R 高超窗口，只收 X/Width 仍盖住整屏高度。四个字段一起按 A 写。

### 11.11 超武列表的"画布判据"必须同时认大面（否则自定义面板整块消失）

`VecText` 把原版超武列表摘下来靠的是"面尺寸 == 主画布尺寸"这一句： `VecSimpleEntry`（0x4A5EB0 的 7B 钩）里 `b[1]==g_SWCompW &&
b[2]==g_SWCompH`， `g_SWCompW/H` 每帧由 `MOE_DrawUILayers` 写成**窗口 Composite** 的尺寸。

缩小档下三趟地图期间渲染面 = R 大面，于是 `inband` 整批判 false ⇒ 放行 ⇒ 原版名/计时器/底色条画进大面，降采样后挤在画面右缘，而自定义面板因收不到行消失。

⇒ `ScaleBar.cpp` 出两个判据：
- `SB_IsBigSurface(void*)`：**指针**判定"这块面是不是本模块自建的大面"。VecText 的
`VecSimpleEntry`（`0x4A5EB0` 的 7B 钩）与 `VecSWCapture`（Print 层兜底）改用 `VecIsCanvas(surf,w,h) =
主画布尺寸命中 || SB_IsBigSurface(surf)`。指针判定不受 将来窗口改尺寸影响，也不必赌"窗口面尺寸 = 画布尺寸"。
- `SB_CanvasH(int w)`：按**宽度**认同一张面、返回它的高（0 = 不认）。只给"手上只有
pitch"的场合用（`VecRender` 的空裁剪哨兵）；认不出时退回原版 1bpp 光栅，只退化 外观不出错。窗口面尺寸由
`SB_NoteWindowSurface(surf,w,h)` 每帧从消息帧钩喂进来 （**不依赖 `[ScaleBar] Enable`**），`SB_EnsureBig`
里另有一份兜底。

y 侧的裁剪上界也跟着换成**这块面自己的高**（`b[2]` / `sh`），不再写死 `g_SWCompH`。

1x/放大档下大面不存在 ⇒ 三处判据逐位等价于原来的写法。

### 11.12 缩小档下"点底部底栏 = 对画面中部下令"（A 外的点被当成视口内）

现象：**选中单位**后点底部底栏，命令落到**画面中部**那个地图像素上（单位朝正中跑）。 1x / 放大档没有；只有 `scale > 1` 有。

根因是一句话：**`SB_MapPoint` 对 A 之外的点原样放行，而缩小档下 R 比窗口大。**

| 档 | R | 底栏带物理 y = 1049..1080 | 原样放行后 | 结果 |
|---|---|---|---|---|
| 1x | 1048 | 1049..1080 | 落在 R **之外** | 引擎的 ViewBounds 边界判定拒掉 ✓ |
| 放大 (0.5) | 524 | 1049..1080 | 落在 R **之外** | 同上 ✓ |
| 缩小 (1.43) | 1497 | 1049..1080 | 落在 R **之内** | ✗ 当成"地图上 y≈1060 那一带" |

那个像素呈现在屏幕上的位置是 `1060 * A.H/R.H ≈ 742` ⇒ 正是**画面正中**。 而 `DisplayClass::ProcessClickCoords`
(0x692300) 的全部判据只有两条：

```
0x69234B  mov eax,[ebp]   ; test eax,eax ; jl 0x6925FC   → X<0 拒
0x692356  mov ebx,[ebp+4] ; test ebx,ebx ; jl 0x6925FC   → Y<0 拒
```

**没有上界判定** —— "点在视口之外"引擎自己根本不管，1x/放大档是靠别的几处 ViewBounds 边界判定（`ClientToCoords` / 橡皮线 0x6D5030 /
`Scroll_Map`）兜住的， 那些在缩小档同样失效（它们比的是 R）。

修法两半：

1. **`SB_MapPoint`：缩小档下 A 之外的**窗口内**点也走同一个线性变换**。
物理 `≥ a.Y+a.Height` ⇒ 视口 `≥ r.Height`，折完必然出界 ⇒ "不是地图上的点" 这件事在视口坐标里也成立。窗口外的点（拖出窗口）维持原样。屏幕空间的卷屏判据
不受影响（`SB_EdgeScrollPointFix` 入口会把那个点换回物理鼠标）。 **只判 `SB_Out()`** ⇒ 1x / 放大档逐位不变。
2. **`ProcessClickCoords` 入口钩（0x692300, 7B `8B 44 24 10 83 EC 18`）**：
入口用 `SB_PtInView(vx,vy)` 判一次，不在视口内就自己 `ret 0x18` 返回 0。 0x201/0x203 两条分支本来就 `test al,al; je
0x693408` 直接跳出， `LeftMouseButtonClick` (0x4AC310) 也就不会记框选锚点，`DecideAction` 无从下手。

**gadget 命中链可排除**：`GadgetClass::Input` 取 `WWMouse::vt+0x2C/+0x30` （物理坐标），不经过折算，天生与缩放无关。

日志：`sbar: click outside view X,Y`（2 秒一条，只在真拒掉时打）； 安装：`vtext: clickcoords hook ON/OFF/mismatch`。

#### 11.12.1 缩小档点小地图没反应 —— 拒点门把自己人拦了 + 地图格矩形取不到

**症状**：缩放档（1x 之外任何档）点小地图，视角不跳。

**三个独立原因叠在一起**（日志逐条对上）：

**① 入口那道拒点门先把自己人拦了。** `SB_MapPoint` 的缩小档分支把 **A 之外**的 窗口内点也做线性变换（§11.12 的修法，`v=(p-A.xy)*R/A` 再钳到
R 外），雷达那个 物理点 (1800,80) 变成 (2571,1498) —— 落在 R 之外。紧接着 `ProcessClickCoords` 入口 那道 `SB_PtInView`
门判"点在视口外"直接 `ret 0x18`。而**认得出这是小地图点击的 那道门**（`FullMap_RadarClickGate`，Syringe 钩在
`ProcessClickCoords` 内部 0x692406， 正好在这道门**之后**）根本没机会跑。日志 `sbar: click outside view 2573,1498`
（物理点反算回去正好在 `colX=1752` + 雷达 `{X=11,Y=20,W=145,H=137}` 里）就是现场。

结论:

★ 原生链是**活的**: `[0x880C98]` 与 `[0x880C94]` 运行时就是 1, 前置条件满足 (旧注释断言"全二进制只有读没有写 = 死代码"是错的, 已删)。
* **命脉是 `FM_Install` 里那五处 imm32 补丁** —— 把 `mov r32,[0x886FA8]`

实测装上 4/5 (`route` 那处运行时被别的东西改了字节, 装不上, 但小地图照样通)。
* **必须逐处安装。** 原先是"五处字节全部匹配才一起打", 一处对不上就一处都不打 ——
`0x478BD7` 对不上, 于是 `0x653A3F` 被连坐, 原生链整条死掉, 症状就是点小地图完全 没反应。现在逐处装 + 逐处复核, `fullmap: verify <name>
ok|BAD` 一眼能看出谁坏了。

原生链内部就是"映射到原本那块地图矩形"这件事, 一个换算都不用我们写 (0x653A89..0x653B0B): `0x656750(Radar, &{绝对X,绝对Y}, &cellXY,
&tmp)` 出等距格 → `{格*256+0x80}` → 视口跳格。输入绝对屏幕点、参照框是雷达矩形, 那个矩形永远在 1x 位置 (1763,20,145x137), 与缩放无关。

**⚠️ 别自己换算格坐标。** 两条硬规矩:

1. **拿到一个"地图矩形"先量宽高比, 跟源的比例对不上就别往里映射。** 小地图是俯视
网格图 145x137 ≈ **1.06**; `Clamp_Center` 那个等距矩形 7800x4035 ≈ **1.93** —— 不是同一个投影, 硬拉必偏。
2. **`X/Y/Z` 的单位只能从"调用点后面跟着谁"确认。** `0x6D6070` 里
`cdq/sub eax,edx` 是取整, 真正的除法是末尾的 `sar eax,8`(/256); 带 `sar ...,8` 的才是 1/256 空间。`{格*256+0x80}`
本身一直是对的。

**改动一个"已验证可用"的点击链之前, 先 `git show` 那个提交, 看清它到底靠什么成立 —— 注释里写的结论可能和代码实际依赖的东西矛盾。**

**吞没范围 = "侧栏顶部那一块"**（`Fm_KeepTopRect` = `{0,0,列宽,SidebarBounds.Y}`）， **不能**用 `Fm_KeepRect`：态0
那是**整条**侧栏面，缩放档开门后会把页签/cameo 一起吞 掉 —— 那两样点了是要下单的。也不加 `s_ExtraH`：那是呈现偏好，会把页签那一行最上面 几像素也吞掉。

### 11.13 视口比地图大：来回抖动 + 一侧残影 ⇒ 居中 + 图外填深灰

现象（缩小档，小图上 R 比地图大）：横向移动地图时画面左右来回抖，一侧留残影； 地图之外纯黑一片，读起来像渲染坏了。抖动根因是 Clamp 的 min > max（下节），
残影根因是增量拷贝的旧像素没人覆盖（§11.15）。

修法：退化轴直接钉地图正中（`SB_ClampFix`，与 §11.15 同口径）；图外填深灰 （`[ScaleBar] VoidR/G/B`，默认 0x20/0x20/0x28，全 0
回纯黑），且必须**每帧**重铺。

日志：`sbar: view > map, center-pinned x …` / `sbar: view <= map, normal clamp …` （状态翻转或 4 秒一条）。

### 11.14 引擎函数指针的调用约定：先看原版结尾是 `ret N` 还是 `ret`

原版 `Clamp_Center` 结尾裸 `ret 4`（被调方清栈），探针却声明成 `__cdecl` （调用方清栈）⇒ 每调一次丢 4 字节栈，返回地址变垃圾，崩在数据段。

**项目口径**：调引擎一律"被调方清栈"（统一 `__attribute__((thiscall))`）； 只有"ecx 不用、纯栈参"的函数才用 `__stdcall`；原版裸
`ret`（cdecl）才用 `__cdecl`。写新指针先确认原版结尾。

### 11.15 图外底色必须**每帧**重铺 + 边界的完整解码

残影与视口移动无关（中心钉死不动时残影仍在），真正机制是增量位移拷贝搬出来的旧像素 没人再覆盖 —— 建面时铺的底色同样会被后续拷贝搬走。地图光栅是**增量**的：
`TacticalClass::Draw` (0x6D4560，`pusha`) 在 0x6D45A9/0x6D45AF 把当前原点存进 `+0xB8/+0xBC` 当"上一帧原点"；下一帧
0x6D3D55 拿它减当前原点算 delta：

```
6d3d55: mov ebx,[ebp+0xb8]   ; prev
6d3d5b: mov esi,[ebp+0xb0]   ; cur
6d3d6e: sub ebx,esi          ; deltaX = prev - cur
```

按 delta 做 `CopyFromPart` 位移拷贝 ⇒ **视口一动，整幅图被搬一次**；而**新空出来的 那一条没有任何地图格子会再去覆盖它**（光栅器只画它有的格子）⇒
那一块永远留着"搬过来 的旧像素"。它跟视口稳不稳无关：视口早就钉死了，残影仍在，因为它是**过去某一帧**搬过来 的，之后谁也不会去碰它。建面时铺的底色同样会被后续的位移拷贝搬走。

⇒ **正解是每帧把图外那块重铺一遍**，而不是"建面时铺一次"。铺满整面太贵 （3504x2096 一帧 14MB），只铺图外的四条带（实测两条，几十万像素，可以忽略）。

`MapClass` 实例是一个**全局对象**在 `0x87F7E8`（不是指针），它 `+0x34` 的 Rectangle 由 `0x6E21E0`（唯一写点）抄进四个全局：

| 全局 | MapClass 偏移 | 含义 |
|---|---|---|
| `0x87F8DC` | `+0xF4` | 恒为 0（唯一写点 0x68555A 写 0） |
| `0x87F8E4` | `+0xFC` | 地图左上角 格X |
| `0x87F8E8` | `+0x100` | 地图左上角 格Y |
| `0x87F8EC` | `+0x104` | 地图宽（格） |
| `0x87F8F0` | `+0x108` | 地图高（格） |

`0x6D8640` 的 px 换算（X 60px/格、Y 30px/格，外加原版两个历史常数）：

```
minX = W/2 + 30*(2*格X - [0x87F8DC])      W = [0x886FA8]
maxX = minX + 60*格W - W            ⇒  地图宽 = 60*格W
minY = 15*([0x87F8DC] + 2*格Y - 5) + H/2  H = [0x886FAC]
maxY = minY + 30*格H + 135 - H       ⇒  地图高 = 30*格H + 135
```

（60x30 一格是 RA2 的 Iso 尺寸 ⇒ 64x64 图 = 3840x1920，与 §11.13 的数字对得上； 那两个 `-5` / `+135`
是原版自带的边界余量，抄过来即可，不必理解。）

**⇒ 地图中心 `(min+max)/2 = (60*格X + 30*格W, 30*格Y - 75 + 15*格H + 67)`， 完全不含视口尺寸。**
这一条很关键：它意味着"图外那一圈在哪"只由地图矩形与视口决定， **与历史无关** ⇒ 每帧重铺天然自愈。

视口：`TacticalClass*` 在 `0x887324`，原点 = `+0xB0/+0xB4`，尺寸 = ViewBounds `0xB0CE30/34`（`Set_Viewport`
0x6D5F60 从 `0x886FA0` 那个 rect 抄； `Update_Tactical_Position` 就是 `origin = center -
ViewBounds.size/2`）。

于是 `SB_ClampFix` 不再需要跳板回调原版，探针与 `g_ClampTramp` 一起删掉 —— §11.14 那个"双重清栈踩烂栈"的崩溃类别就此归零。

原版 `0x6D86B3..0x6D86FB` 的真实控制流（**注意 Y 夹完是 `jmp` 去夹 X，不是返回**）：

```
edx = arg->Y ;  if (edx >= Ymin) goto upper
                 arg->Y = Ymin ; bl = 1 ; goto X_part     ← 这里 jmp 0x6D86D2
upper:         if (edx <= Ymax) goto X_part
                 arg->Y = Ymax ; bl = 1 ; goto X_part
X_part:        eax = arg->X ;  if (eax >= Xmin) goto xupper
                 arg->X = Xmin ; return 1
xupper:        if (eax <= Xmax) return bl
                 arg->X = Xmax ; return 1
```

原版 Y 夹完是 `jmp` 去夹 X（不是返回），照抄 fall-through 即可。

退化判据也从 `min > max` 换成 `mapW < ViewBounds.w`（两者等价，但后者不含舍入）。 关键性质：退化时钉住的值 =
正常夹位在边界处会给的值（`mapW==VB.w` 时 `min==max==center`）⇒ **判据翻转的那一帧不会跳**，天然连续。

图外 = 大面 `[0,0]-[vw,vh]` 减去"地图落在大面里的矩形"，后者 = 地图 px 矩形 − 视口原点。大面坐标 → 窗口坐标用现成的 `a.xy + v * a.size /
r.size` （与 `SB_MapPoint` 同一个变换，那里是反着用的）。

**只铺本帧最终面**（`SB_RenderAfterMap` 里 SwapOut 之后、降采样之前一次）。
三趟地图此时已画完，第三趟只画地图不碰图外，所以一次就够；
另一张面轮到它显示的那帧自会铺。面与 ViewBounds 对不上就跳过。
纯渲染面写入，不碰模拟状态 ⇒ 联机安全。

### 11.16 离开/切回 1x 崩溃（两起，同一切换时序）

- **UAF**：切回 1x 当帧崩在 `0x6D493E`（`ecx` 是已释放的大面）。引擎把面指针缓存在
自己结构里。修法：`SB_SurfaceDestroy` 推迟一代释放（`s_RetComp/s_RetMap`）。
- **同轮遗漏**：`SB_RenderResume` 漏还原 `0x887314`（引擎当当前渲染面用），已补。
- **差一帧**：切回 1x 当帧崩在 `0x494BF9`（旧 R 裁剪配窗口小面）。`Sb_SetLevel` 改档

### 11.17 换档当帧 R 变了、裁剪器还是旧尺寸

**根因**：`SB_PrepareSurface()` 每循环只在开头跑一次，处理的是**旧档**尺寸；
`Sb_SetLevel` 换档当帧即调 `FM_SyncViewNow()` 把 R 改成新尺寸，ZBuffer/ABuffer
还停在旧尺寸。缩小档引擎拿 **R 坐标**寻址这两块，尺寸对不上即野读写
（例：`R=2400x1310` 而 `zbuf=1920x1048`，崩在 16 位 blit 内层循环）。

**修法**：换档当帧 `FM_SyncViewNow()` 之后再跑一趟 `SB_PrepareSurface()`，
让裁剪器在 Render 之前跟上新 R（幂等，`SB_BufIs` 对得上零开销）。
该不变量与 F11 无关，任何换到缩小档的操作都适用。

### 11.18 R 与裁剪器错配：三处取 R 必须同线（已验证缓冲能建出更大）

**根因 = R 与缓冲错配，不是建不出。** 例：MAX 档按 F11 后的 A 算出 `R=8548x4666`，
当时预检把缓冲退回 A（`1920x1048`），而 ViewBounds 留着 8548 ⇒ 引擎拿 **R 坐标**
寻址小尺寸缓冲野读崩。`SB_GetViewRect` 只问大面成不成、不问缓冲，两者的差值
就是事故窗口。

**修法**（限制现为可配 `[ScaleBar] LimitFallback`，三处经 `Sb_OverLimit` 同线、超限经 `Sb_ClampScale` 钳制）：

1. `SB_GetViewRect` 超限走钳制（`Sb_ClampScale`：长边=限制值），prepare 拿到的
本来就是限制内的 R，R 与缓冲天然同线。MAX 档的隐患也顺带解决：MAX 的 scale
是按当时的 A 算的，F11 一换 A.Width（1752→1920），R 就可能顶穿限制
（7800 → 8548），钳到 8192（8192x4471）接着看，不跳回 1x。
2. `SB_PrepareSurface` 的失败分支（内存不够那条）补上 `Sb_SetLevel(s_LevOne)` +
`FM_SyncViewNow()` —— 那条注释本来就写着"宁可退回 1x"，但当时只退了面和缓冲， **没退档位**，所以 ViewBounds 还留着那个超限的
R。`SB_GetViewRect` 里的 `s_SurfFail` 兜底是**下一趟**才生效，本帧 Render 已经在栈上了。

(0xAC4848) 的 0x6BA580, key=0xF81F。 崩不崩看越界后那页映射了没 ⇒ "并不总是崩"; 寄存器每次不同, 越界量级相同。
- 崩时五个引擎全局全健康且没指着我们的大面 (面快照已验证), 旧守卫逐项放行。
- 修法: BlitGuard 加矩形落界检查 (矩形两张面都不沾才跳过, 本循环无裁剪,
出界必坏), 越界跳过 + 一行带数日志 (`blit: skip unclipped s1=.. s2=.. rect=..`)。 只在缩小档检查, 1x 零变化。注意矩形坐标系:
cameo 合成那笔的矩形落在源面 （strip）坐标里, 只按 DST 一张判会误杀整列图标（见 §11.8）。
- 根因（坐标哪来的）待查：看 `skip unclipped` 日志的几何，或对照 1x / 去 DLL。

### 25.1 同一个守卫把**侧栏图标整块吃掉**了（判据写错）

`0x6BA580` = `DSurface::BlitImage(rect, src)`，**一个矩形给两张面共用，但两边用法 完全不同**（照它的指令抄）：

| | 怎么用 `rect` | 出处 |
|---|---|---|
| 源 `s2` | `ebp = src->Lock(0,0)` 之后**线性**走，每行 `src += 2*w`、行数 `h` | 0x6BA5B8 / 0x6BA637 / 0x6BA62B |
| 目标 `s1` | `destRow = dest->Lock(0,0) + (x+y)*2`，行步进 = 目标 pitch | 0x6BA628 / 0x6BA653 |

⇒ **源的 x/y 根本没用，只有 `w ≤ w2 && h ≤ h2` 才安全**；目标才必须 `x,y,w,h` 整个落在 `s1` 内（否则就是 0x6BA643 那起越界写）。

旧守卫（`MOExperience.cpp` `BlitGuardC`）用"**两张面都容得下整个矩形**"当放行条件：

```
in2 = (x>=0 && y>=0 && x <= w2 - w && y <= h2 - h)      // ← 源只看尺寸就够
```

侧栏图标那笔正是 `s1 = 168x1080` strip、`s2 = 60x48` cameo、`rect = (x, 228, 60, 48)`
（`x` 只需对 168 宽的 strip 成立，在 60x48 的源上必然"不沾"）⇒ 缩放档下整笔被
跳过 ⇒ 侧栏图标全空（1x 下守卫不跑，正常绘制）。

**修法**：
1. 源只按尺寸判：`okSrc = (w>0 && h>0 && w<=w2 && h<=h2)`。
2. 目标不合而源合 ⇒ **把 `x/y` 夹进 `s1` 再照画**（w/h 超面就先缩），绝不越界，
也绝不整块不画。
3. 两张都不合才跳过（保留 0x6BA643 那起崩溃的防护）。

⚠️ 判据必须照被守卫的那条指令抄：源只看尺寸（`w<=w2 && h<=h2`），目标才看落界。
直觉写法（两张面都容得下整个矩形）错判方向是"宁可少画"，症状是静默失效，极难察觉。

侧栏按钮落点本身是对的（`f(行,列) - SidebarBounds.X`，1x 排布 `1774/1837` 验证过），
乱的是拷贝落点那组派生锚点（见 隐藏侧栏.md §4.3b），别去动按钮位置。

## 26. 读档后侧栏图标不按位摆 / 1x 下错乱

`DisplayClass::InitGUI` (0x6ABD30) 里那批写入全是**一次性**的，而且全都按 **当时的 `ViewBounds`** 算：页签/cameo
的位置与滚动偏移 `-SidebarBounds.X` （0x6ABE37 / 0x6ABE67 / 0x6ABE9E / 0x6ABEDF）、三个 radar gadget 的位置
（0x6ABD39 → `0x6403A0` → `0x654320`）、`[0xB0B3E4]`/`[0xB07E3C]` 等。 ⇒
视口几何一变就必须拿**正确**的矩形重跑一次，否则侧栏一直用上一次宽度算出来的 位置，读档最明显（`CreateAll` 走 `Fm_ViewRectStub`，视口宽是全宽的
clientW）。

**① 缩小档没人替我们重跑（`FullMap.cpp` `Fm_InitGuiForA`）**

唯一会重跑 `InitGUI` 的路是 `Set_View_Dimensions` (0x4A8960) 的末尾，而 `Fm_ApplyViewWidth` 里那条路带 `&&
!SB_Out()`（缩小档禁调，见 §11.2：它按传入 矩形重建 ZBuffer/ABuffer / WWMouse 视口 / 消息区）。⇒ 缩小档换挡、只改高度的 换挡、以及
`s_SyncViewFrame` 帧门挡住的那几次，侧栏布局**一次都没重算**。

修法：不再借 `Set_View_Dimensions`，单独调 `InitGUI`： `ViewBounds := A` → `call 0x6ABD30`（`this =
0x87F7E8`，无栈参）→ `ViewBounds := R`， 列起点由 `InitGUI` **入口钩**（`FM_SyncSidebarColumn`）纠。它只写布局量，不碰
ViewBounds / 缓存 / 裁剪器 / 缓冲，正是我们要的。`s_LayoutDirty` 由几何变化置位， `Fm_ConsumeLayoutDirty`
消费（**真跑成了才清**，跑不成就留着下一趟再试）； `setDims` 成功那趟直接清掉（它末尾已经按 A 跑过）。

**② 引擎重建了面（读档/改分辨率）后没人补（`Fm_NoteSurfaceRebuild`）**

`CreateAll` 换掉 `[0x887300]`（侧栏面）⇒ 新面是**空白**的，而上面那批一次性布局
还停在旧几何上，引擎不会自己重算。判据用**面指针换人**（比尺寸硬：尺寸可能碰巧 一样）。命中时：`s_RadarLockOk = 0`（小地图矩形锁作废，新面尺寸可能不同）、
`s_LayoutDirty = 1`、`s_ForceRedraw = 8`（置三个侧栏重画脏标记，走的正是引擎 `SidebarClass` 的全量重画分支）、`s_DirtyFrames
= 3`。 ⚠️ 判据要在 `Fm_ApplyViewWidth` **之前**跑（好让这一趟就把布局刷了），且 Apply 早退那条分支之后要再消费一次脏标记。

**③ ZBuffer/ABuffer 与视口不同源（`ScaleBar.cpp` `SB_PrepareSurface`）**

非缩小档分支必须以对象里的**真实**尺寸为准（`SB_BufIs`，对上零开销），不能只记
我们自己重建过的尺寸 —— 读档后引擎按建面用的全宽矩形重建的那两块缓冲，
否则永远不会被纠正（长期"视口 1752 / 裁剪器 1920"，见 隐藏侧栏.md §4.8）。

日志：`fullmap: sidebar layout refreshed for A`（每次真的重跑）、 `fullmap: surfaces rebuilt <old> ->
<new>`（读档/改分辨率）、 `sbar: zbuf <- WxH`（缓冲尺寸纠正）。

## 27. 读档后侧栏图标错乱: 换面时缩放退 1x

`Fm_InitGuiForA` 把锚点写对之后，又被换面后压的 `s_ForceRedraw = 8` 覆盖回去，
所以"补一遍"补不上（读档后整列 cameo 挤成窄条 + 绿红竖条）。

### 27.1 根因: `s_ForceRedraw` 那几帧里 `ViewBounds` 是 R，锚点被 `ComputeLayout` 重推

§26② 换面后压了 `s_ForceRedraw = 8`，逼 `SidebarClass::Draw` 走全量重画分支 （`0x6A6CFD`）。**那条路会调
`SidebarClass::ComputeLayout` (`0x6A5130`， 调用点 `0x6A5326`）**，而它的 `flag != 0` 分支照**当时的
`ViewBounds`** 重算 `SidebarBounds.X` 并重推 cameo 落点那组派生锚点（`[0xB0B4F4] = X + 0x16` 等，见 隐藏侧栏.md
§4.3b）。

这 8 帧里 `ViewBounds` 已是 R（同一个 `FM_Poll` 趟里 `Fm_ApplyViewWidth` 在 `Fm_NoteSurfaceRebuild` 之后跑，已经把
R 写进去了）⇒ 锚点被写成 `R.Width + 22` ⇒ 拷贝落点 `R.Width + 22 - colX` 越出 168 宽的侧栏条带。

**实证**：落点 `773 = 2525 − 1752`，`2525 = 2503 + 22`（R.Width 2503）—— 正是
`ComputeLayout` 按 R 口径重推的锚点（§25.1 挡住的只是 blit 越界这个症状）。
⇒ `Fm_InitGuiForA` 写对的锚点，紧接着又被这 8 帧覆盖回去。

平时切档不走全量重画分支（只有 F11 切模式和换面才压 `s_ForceRedraw`），1x 下
`ViewBounds = A` 本来就是对的 —— 所以只在读档 + 缩小档叠加时犯。

### 27.2 修法: 换面时缩放退回 1x（`SB_ResetZoom1x`）

按"**侧栏无论什么缩放下都该 1x，读档不该影响侧栏**"的口径，**换面时直接把 档位退回 1x**，不做冻结窗口、不记忆读档前挡位、也不做事后补偿：

- `Fm_NoteSurfaceRebuild` 命中时调 `SB_ResetZoom1x()`（`FM_Poll` 的第一个动作，
赶在 `Fm_ApplyViewWidth` 之前 —— 位置必须如此）。
- 于是同一个 `FM_Poll` 趟里 `Fm_ApplyViewWidth` 的 `SB_Scale()` 拿到 1.0，
`ViewBounds` 被写回 **A**；`!SB_Out()` 成立 + 宽度从 1920 变 1752 ⇒ 顺带走 一次 `Set_View_Dimensions(A)`，把裁剪器 /
WWMouse 视口 / `InitGUI(A)` 全部按 A 重建一次 —— 这本来就是读档后该做的事。
- 之后那 8 帧强制全量重画**全程跑在 A 口径上**，`ComputeLayout` 重推的锚点
就是正确的 `1752 + 22 = 1774`，落点 22，落在 168 宽条带内。

1x 时 `SB_ResetZoom1x` 空转 ⇒ **原本 1x 读档的行为逐位不变**（无回归）。

顺带被这个改动一起解决的（都是"1x 口径下引擎本来就该做的事"）： 读档后 ZBuffer/ABuffer 与视口同源（§26③ / 隐藏侧栏.md §4.8）； 缩小档那两张 R
大的离屏大面在同一个 `FM_Poll` 趟里被 `SB_PrepareSurface` 的 `!SB_Out()` 分支退休（里面是**上一局**的地图像素，引擎增量渲染只补脏格）。

### 27.3 为什么不用"载入期冻结"那套

"载入期把缩放冻结在 1x"不可靠且多余：进度屏相位判据在局内读档时根本不置位
（读档走另一条路径），且正常游戏里会抖动刷屏；"换面退 1x"是一次性动作，
不依赖帧计数，还顺带走掉 `setDims(A)` 正门。

⇒ **判据必须挑"事件发生"而不是"状态维持"**：换面是一次性事件（面指针比对），进度屏相位是维持状态（会抖）。
