# 地图缩放 (ScaleBar)

代码：`src/GUI/ScaleBar.cpp` + `src/GUI/FullMap.cpp`（视口几何）+ `src/MOExperience.cpp`（两个鼠标折算钩）。
配置：`[ScaleBar]`。只有放大档（0.25 = 4 倍 / 0.5 = 2 倍 / 1 = 原样）。

---

## 0. 一句话

引擎只会 1:1 逐格画地图，所以"缩放" = **视口 R 改成视图区 A 的 scale 倍，引擎照旧
1:1 画进 Composite 的 R，呈现时把 R 最近邻放大铺回 A**。

## 1. 引擎侧事实（gamemd.exe 反汇编实证）

| 事实 | 地址 / 依据 |
|---|---|
| 地图逐格 1:1 光栅化，格子恒 60x30，行步进 30px、列 60px | `TacticalClass::Render` 0x6D3D10 → 格循环 0x6D6D10（按 ViewBounds 高/30、宽/60 迭代）；**没有任何缩放/采样路径** |
| 画哪一格由 ViewBounds (0x886FA0) + TacticalPos (+0xB0) 决定，落点 = `ViewBounds.xy + (mapPos - TacticalPos)` | 格循环起点 |
| 地图画三趟，渲染面是参数（三趟都 push [0x88731C] = Composite）；之后 0x4F455D 才是 `MessageList::Draw` | `GScreenClass::Render` 0x4F4480，调用点 0x4F44DF/0x4F44F4/0x4F4515 |
| `TacticalPos = 视口中心 - 视口尺寸/2` | `Update_Tactical_Position` 0x6D8B30，**尺寸取自缓存 `[0xB0CE30/34]`**，不是 ViewBounds |
| 屏幕点 → 格 | `DisplayClass::ProcessClickCoords` 0x692300 → `CoordsToCell` 0x6D6590 |
| 屏幕点 → 地图像素（hover 那条） | `ClientToCoords` 0x6D2280 = `map = p + TacticalPos`（**不减 ViewBounds**）|
| 视口尺寸/范围判定读的是缓存副本 | 0x6D5F60 把 ViewBounds 抄到 `[0xB0CE28/2C/30/34]`；`Update_Tactical_Position` / `ClientToCoords` 都读它 |
| 引擎钳位 | `TacticalClass::Clamp_Center` 0x6D8640：只读 ViewBounds 宽高 + 场景全局，把中心钳到"视口完整落在图内" |
| 引擎"重画哪块"的信号 | `RegisterDirtyArea` 0x6D2790（60+ 调用点），矩形是**视口系** |
| ZBuffer/ABuffer 每帧清零 | 0x6D3F9A `ZBuffer::Fill(0xFFFF)` + 0x6D3FA7 `ABuffer::Fill(0x7F)` |

## 2. 两个矩形与不变量

```
A = 满视图区 (侧栏模式决定宽, 高 = winH-32), FullMap 每循环写死
R = 引擎实际视口 = A * scale, 恒有 ViewBounds.X = ViewBounds.Y = 0
```

- ★ **ViewBounds.xy 缩放时必须恒为 0**：渲染落点是 `ViewBounds.xy + (mapPos - T)`，
  所以 R 永远落在渲染面的 (0,0)。而引擎自己的两条查格路（`CoordsToCell` /
  `ClientToCoords`）只在 X=0 时一致，非 0 会让下单击与 hover 差 `2·X`。
- ★ **`[0xB0CE28/2C/30/34]` 必须始终等于 R**（不是 ViewBounds）。`Fm_ApplyViewWidth`
  有一处**故意**拿 **A** 调 `DisplayClass::Set_View_Dimensions`（那个函数末尾会
  `InitGUI`，侧栏一次性写入的偏移全按传入矩形算，传 R 会把侧栏摆坏），顺手就把缓存
  留成了 A。而 `sync()` 只在几何变化那一帧跑 ⇒ **缓存永远停在 A** ⇒
  `TacticalPos` 按 A 算而渲染按 R ⇒ 恒定偏移 `(A-R)/2`，放大档下 = 视野整体偏左上
  （左上出界、右下少一圈）+ 引擎悬浮提示错位（与自己那份重影）。
  `Fm_SyncViewCache` 负责纠正，且放在"几何没变"的早退之前也跑，让不变量自愈。

## 3. 档位表

固定三档 `0.25 / 0.5 / 1.0`（`s_LevScale`），`[ScaleBar] Level` 是档位序号（0 = 4 倍放大）。
文字由 `scale` 现算（`4x` / `2x` / `1x`）。

缩小档（scale>1）**整块停用**：它需要一张"整张图那么大"的 DirectDraw 面
（7800x4035 的图 ⇒ 7928x4163 = 66MB），实测 ddraw 内部扛不住（引擎自己只碰过几 MB
的面）。要更大视野只能换"自己 malloc 的马赛克 + 分条渲染"那套。

## 4. 时序（钩点与理由）

```
prepare 0x4F42F0 (每循环)  → PowerDrawBoth : ... SB_Poll（摆条 + 点击换档）
                                      → FM_Poll → Fm_ApplyViewWidth → 写 ViewBounds + Fm_SyncViewCache
render  0x4F4480 三趟之后    → SB_CompositeMagnify：把 Composite 的 R 放大覆盖到 A
                                 ⇒ 引擎 UI 与本项目 *_Draw 全都照旧 1:1 画在 Composite 上
pre-tip 0x6A7089             → MOExperience_TipPreDrawEntry（放大档只跑 Process 不画，见 §5.1①）
鼠标    WWMouse 虚表 +0x34   → MOE_MousePosEntry       （每帧轮询）
        窗口过程 0x6930A0   → MOExperience_WndMouseEntry（鼠标按钮消息，见 §7.2）
```

**放大写 Composite 而不是 Primary**：它是后面每次上屏 blit 的**源**，在它上面改，
后续多少次 blit 都把放大结果原样搬上屏（写 Primary 会被随后的 blit 覆盖）。

⚠ 凡是"按 ViewBounds 定位"的引擎代码都会跟着视口缩小的量挪位置 —— 除了地图光栅化，
还有超武列表（`PowerBarClass::Draw` 0x6DA9D0）、边缘卷屏（`Scroll_Map`）、框选橡皮线
（0x6D5030）。新增缩放功能时按这条核一遍。

## 5. 缩放在 Composite 上的两条不变量

1. **呈现阶段不许动 Composite 的地图区以外的任何东西**，且放大只做一次、位置固定在
   视图区 A —— 引擎是**增量**重绘（只重画标脏的格），任何"缩放一次、事后补一次"的
   做法都会在同一帧内被引擎重画盖掉。
2. `[0xB0CE2x]` 缓存必须等于 R（见 §2）。

## 5.1 悬停提示在放大档下的两个毛病（已修）

放大档下悬停提示（建筑名 / 电量串 / 侧栏 gadget 名）有两个症状，都出在"放大前那次绘制"和"拿视口当界面"上。

**① 重影：同一帧画了两遍，大那份被放大**

`ToolTipManager::Draw`（虚表 +0x0C）全二进制只有两个调用点：

| 调用点 | 位置 | 相对 `SB_CompositeMagnify` |
|---|---|---|
| `0x4F4564` | `GScreenClass::Render`，实参 0 | **之后** |
| `0x6A7081` | `SidebarClass::Draw`（`0x6A6C30`），实参 1 | **之前** |

- 字形尺寸来自全局字体 `[0x89C4D0]`（经 `GetTextDimension` `0x433CF0`），**永不随缩放变** ⇒ 字号大一倍那份只能是 `SB_CompositeMagnify` 的重采样产物。
- 不是残影：`TacticalClass::Render` 每帧重画整个视口（`0x6D3E2F` 那几条"无变化"分支是跳回 `0x6D4582` **继续画**）⇒ R 每帧干净。
- ⇒ 放大档挡掉 `0x6A7089`（抢 7B = `8B 11 6A 01 FF 52 0C`），留 `0x4F4564` 那次。Entry 见 `MOExperience_TipPreDrawEntry`，安装见 `VecText_Install`。
- ⚠ Entry 里必须自己跑 `ToolTipManager::Process`（`0x724AD0`）：`Draw(1)` 第一件事就是它，刷 `Dimension` 与 LifeTime/Sticky 计时，跳掉之后放大后那次会画空框。只跳绘制，`0x6A7090` 之后的 `BlitSidebar` 判据一字不改。门控 `SB_In() && !SB_Safe()`，与 `SB_CompositeMagnify` 一致 ⇒ 1x 与 Safe 档零行为变化。

**② 偏移：拿视口 R 当界面，提示盒被整体拽走**

放大档下凡"拿 ViewBounds 当界线"的地方都会按视口缩小的量误判。三处，全部改成用满视图区 A（`ScaleBar.cpp` 的 `g_AView` 影子，每循环 `SB_PublishAView()` 抄一次）：

| 位置 | 拿 R 当什么 | 后果 |
|---|---|---|
| `ToolTip_Clamp`（`0x478FDC` 钩） | 钳制右界 | **盒子连字整体往左拽**，位移最多一整个视口宽（2x 876px / 4x 1314px）⇒ 提示飞到离光标很远 |
| `ToolTipManager::Update`（`0x478BD1/0x478BD7/0x478C17`） | 选面比较 + `GetTextDimension` 的 maxWidth + 居中基准 | 误判"在侧栏上"、长文本按 876 而不是 1752 提前折行 |
| `CCToolTip::DrawText`（`0x478E4A/0x478E50`） | 选面右界 | 误走侧栏面那支（`0x478E7E` 还会 `x -= 右界`） |

- 后两处：指令里写死的 imm32 改指到影子（`VecText.cpp` 的 `rep[]`），指令长度不变、只换数据来源；`ToolTip_Clamp` 自己算，按 `SB_In()` 取。
- ⚠ 改址**必须先全验完再动手**：`mov eax,[imm32]`(`A1`) / `mov edi,imm32`(`BF`) 形态第 2 字节已经是立即数，当 opcode 校验会在第 2 个点 break，留下只改了第 1 个点的半改状态。
- 侧栏两处 `SidebarBounds`(`0x886F90/0x886F98`) 不动。**1x 时 A == R ⇒ 与原版逐位相同。** 不写回 ViewBounds 本身（引擎状态）。

**③ 一条看着像 bug 但不要动**：`ToolTipManager::Process`（`0x724AD0`）把 `Dimension` 锚在 `CurrentMousePosition`，而后者由 `ProcessMessage`（`0x724200` → `GetCursorPos` + `ScreenToClient`）写成**物理**点，不经我们折算的 `WWMouse` +0x34 也不经 `0x6930A0` 的 lParam。看着像漏折算，其实是对的：放大前那次已被 ① 挡掉，剩下那次画在放大之后的 Composite 上，而那时的 Composite 像素 1:1 对应屏幕 ⇒ 物理点正好落在光标处。折了反而偏到 1/zoom。

## 6. 鼠标

引擎里"鼠标在哪"有**两个数据源**，两条都必须折算，否则口径不一致 ⇒ 放大档下
"按下时的点"与"每帧读到的点"差 `A/R` 倍。
（提示框那条 `GetCursorPos` 路径是第三个数据源，它**不需要**折，见 §5.1③。）

### 6.1 每帧轮询：`WWMouseClass` 虚表 +0x34

`v = (p - A.xy) * R.size / A.size`（p 在 A 内才折，A 外原样放行）。

11 个消费点（全二进制扫 `mov ecx,[0x887640]` 附近 `call [reg+0x34]` 的全集）：

| 调用点 | 消费者 |
|---|---|
| 0x4A56CE | 单位矩形命中 |
| 0x4A91EF / 0x4A9232 / 0x4A9284 | `DisplayClass::Scroll_Map` 边缘卷屏 |
| 0x4AAC6D / 0x4FB405 | `ClientToCoords` → `ProcessClickCoords` |
| 0x4AE538 | 框选（<900px）→ `ProcessClickCoords` |
| 0x4B8FAA | 地图像素区判定 |
| 0x692F5E | 点选下单击 |
| 0x6D0ABA | 地形判定 |
| 0x6D5068 | **框选橡皮线**（0x6D5030，第三趟 0x4F4515 调） |

**为什么必须挑"数据源"而不是消费者**：挂在 `ClientToCoords` (0x6D2280) /
`CoordsToCell` (0x6D6590) 上按调用点白名单折是不可行的 —— 它们的入参绝大多数是
引擎自己的地图像素，折算等于替引擎改数据（一折就崩）；而只挑"看着像鼠标"的少数
调用点又必然漏（0x6D5068 橡皮线、0x692F5E 点选都漏过）。源头只有虚表 +0x34 一处。

安全性：gadget 命中链（`GadgetClass::Input` 0x4E1640）用虚表 **+0x2C/+0x30**，
不是 +0x34 ⇒ 侧栏/工具栏/雷达命中一点不变；光标绘制走 +0x3C/+0x40 读实例原始坐标
⇒ 光标仍停在物理位置；**1x 时 A == R，折算恒等**；只读内存 + 只算坐标，联机安全。

本项目里自己走 `ProcessClickCoords` 的三处（`OU_MouseCellPx` /
`OU_MouseCellTarget` / `DP_MouseCellZ`）拿的是 `GtMouseGameXY` 的物理点，喂之前
必须自己调一次 `SB_MapPoint`。按引擎投影画图元的三处走 `SB_ViewToScreen` /
`SB_MapDeltaToScreen`。

### 6.2 鼠标按钮消息：窗口过程的 `lParam`

```
窗口过程 0x7775C0 → 0x777640 call 0x6930A0 (this=MouseClass::Instance=0x87F7E8)
       第4实参 = &lParam
```
`0x6930A0` 用 `eax = Msg-0x201` 查 6 项跳转表（0x693410），落地的只有五个鼠标按钮，
开头同一段：`mov eax,[edx]`（x）+ `movsx ecx,word [esp+36]`（y）`- ViewBounds.xy`。

| Msg | 跳转 | 干什么 |
|---|---|---|
| 0x201 LBUTTONDOWN | 0x693126 | 点选下令 + `LeftMouseButtonClick` 0x4AC310 **记框选锚点**（DisplayClass+0x11DC/+0x11E0）|
| 0x202 LBUTTONUP | 0x6931F9 | `0x63A8E0(x,y)` 滚屏判据 → 点选收尾 |
| 0x203 LBUTTONDBLCLK | 0x6932A4 | 同上 |
| 0x204 RBUTTONDOWN | 0x693366 | `0x63AB00(x,y)` 边缘卷屏开关；左键还按着则结束框选 |
| 0x205 RBUTTONUP | 0x6933E6 | 左键还按着才收尾 |

**钩法**：`MOExperience_WndMouseEntry` 把**第4实参那个指针**换成折算好的副本
（`s_WndLp`），尾跳跳板。

- ★ **只能换指针，不能改 lParam 的值**：同一个 lParam 槽在 0x777645 之后还要原样
  交给 `0x778030` 和 0x7779B9 → `0x54F790`，后者靠 lParam 更新 `WWMouseClass` 的
  位置。改了值不还原 ⇒ 光标跑偏、gadget 命中全歪、`GtMouseGameXY` 还会**再折一次**。
  而第4实参那个槽在 0x6930A0 自己的栈帧上（`ret 0x10` 会弹掉）⇒ 换指针不影响调用者。
- ★ 副本里必须放**打包好的 lParam**（`(y<<16)|x`），不能放 `Point2D`：引擎先把整个
  dword 抄进自己的栈槽，再 `movsx ax` 取低 16 位（x）、`movsx word [esp+36]` 取那个
  dword 的**高 16 位**（y）。放 `Point2D` 的话 y 恒等于 X 的高 16 位（0）。
- ★ 入口 `ecx` = this，跳板里 `mov esi,ecx` 把它当 DisplayClass 用 ⇒ 中间那个 cdecl
  调用的前后必须手动 `push/pop ecx`（`ebx/esi/edi/ebp` 是 callee-saved，不用管）。
- 抄 8B = `A0 78 E3 A8 00` + `83 EC 1C`，跳板跳回 0x6930A8。

不修的症状：单击被判成拖框、橡皮线起点偏到 2 倍远、点选落格偏一档。

## 7. 超武列表在放大档下会漏出来

原版超武列表由 `PowerBarClass::Draw` (0x6DA9D0) 画，那批行的 x 是
`ViewBounds.Width - 30`（名）/`-3`（计时器），1x 下视口右缘 1752 ⇒ 名 1722 / 计时器
1749。放大档下这批行跟着视口缩到**视口右缘**（2x 下 846/873），随后被放大两倍 ⇒
原版列表又大又偏，正好压在自定义面板上。

⇒ 横向拦截带必须跟着 `ViewBounds` 走（`VecText.cpp` 的 `VecSWBand`：
`[ViewBounds.X+Width-160, +16]`）。同理 `Print` 层的计时器兜底用同一条带。

## 8. 已知限制

- **放大档下光标看不见**：我们把 Composite 的视图区整块重采样盖掉了引擎画上去的光标。
  别去调 0x4F4583 那两个虚表槽（`+0x3C` 是 `RemoveMouse(surface,flag)`，
  `DisplayClass +0x44` 的参数还压在栈上语义不明）。要恢复得走"从 Composite 里按光标
  矩形拷一小块到 Primary"的路子。
- 视口大于窗口时，引擎有几处按窗口尺寸建的临时面会拿到超界 blit（DDraw 会裁剪）。
- `VisibleCells[800]` 有硬上限（0x6DA93E `cmp eax,0x31F`）：缩小档下同一帧超过 799 个
  "有对象的格子"要重画时，后面的单位可能不画。
- 缩放档下卷动步长仍按地图像素走（看起来比 1x 快/慢 scale 倍）。

## 10. 两条把游戏打崩过的坑（结论保留）

**① 跳板偷的字节数必须落在完整指令的末字节上。** 跳板把 `[at, at+n)` 原样搬走再跳回
`at+n`；`at+n` 落在某条指令中间就会从半个指令开始重新反汇编 → 执行到莫名其妙的指令
直接飞掉（能写任意内存 / 跳去任何地方）。用法：先反汇编确认末字节再填 `n`。

**② 写引擎内存的每个循环都要同时按"目标对象的实际尺寸"夹。** 只按调用方给的矩形夹，
一旦该矩形超出目标面（改分辨率/建面的瞬间）就会整片写出界 ⇒ 堆被写坏 ⇒ 之后某个虚表
/函数指针变野，跳到堆地址崩。往 DirectDraw 面写之前还要查 `pitch >= 2*width`
（不是 16bpp 的面会每行越过行尾）。
