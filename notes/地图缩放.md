# 地图缩放 (ScaleBar)

代码：`src/GUI/ScaleBar.cpp` + `src/GUI/FullMap.cpp`（视口几何）+ `src/MOExperience.cpp`（两个鼠标折算钩 + `GScreenClass::Render` 入口钩）。
配置：`[ScaleBar]`。6 档：0.25=4 倍 / 0.5=2 倍 / 0.769=1.3 倍 / 1=原样 / 1.43=0.7 倍视野 / 2=半数视野。
放大档（scale<1）与缩小档（scale>1）现在都实现（缩小档见 §11）。

---

## 0. 一句话

引擎只会 1:1 逐格画地图，所以"缩放" = **视口 R 改成视图区 A 的 scale 倍，引擎照旧
1:1 画进 Composite 的 R，呈现时把 R 最近邻放大铺回 A**。

## 1. 引擎侧事实（gamemd.exe 反汇编实证）

| 事实 | 地址 / 依据 |
|---|---|
| 地图逐格 1:1 光栅化，格子恒 60x30，行步进 30px、列 60px | `TacticalClass::Render` 0x6D3D10 → 格循环 0x6D6D10（按 ViewBounds 高/30、宽/60 迭代）；**没有任何缩放/采样路径** |
| 画哪一格由 ViewBounds (0x886FA0) + TacticalPos (+0xB0) 决定，落点 = `ViewBounds.xy + (mapPos - TacticalPos)` | 格循环起点 |
| 地图画三趟，渲染面是参数（三趟都 push [0x88731C] = Composite）；之后 0x4F455D 才是 `MessageList::Draw` | `GScreenClass::Render` 0x4F4480，调用点 0x4F44DF/0x4F44F4/0x4F4515 |
| `TacticalPos = 视口中心 - 视口尺寸/2` | `Update_Tactical_Position` 0x6D8B30，**尺寸取自缓存 `[0xB0CE30/34]`**，不是 ViewBounds |
| 屏幕点 → 格 | `DisplayClass::ProcessClickCoords` 0x692300 → `CoordsToCell` 0x6D6590 |
| 屏幕点 → 地图像素（hover 那条） | `ClientToCoords` 0x6D2280 = `map = p + TacticalPos`（**不减 ViewBounds**）|
| 视口尺寸/范围判定读的是缓存副本 | 0x6D5F60 把 ViewBounds 抄到 `[0xB0CE28/2C/30/34]`；`Update_Tactical_Position` / `ClientToCoords` 都读它 |
| 引擎钳位 | `TacticalClass::Clamp_Center` 0x6D8640：只读 ViewBounds 宽高 + 场景全局，把中心钳到"视口完整落在图内" |
| 引擎"重画哪块"的信号 | `RegisterDirtyArea` 0x6D2790（60+ 调用点），矩形是**视口系** |
| ZBuffer/ABuffer 每帧清零 | 0x6D3F9A `ZBuffer::Fill(0xFFFF)` + 0x6D3FA7 `ABuffer::Fill(0x7F)` |

## 2. 两个矩形与不变量

```
A = 满视图区 (侧栏模式决定宽, 高 = winH-32), FullMap 每循环写死
R = 引擎实际视口 = A * scale, 恒有 ViewBounds.X = ViewBounds.Y = 0
```

- ★ **ViewBounds.xy 缩放时必须恒为 0**：渲染落点是 `ViewBounds.xy + (mapPos - T)`，
  所以 R 永远落在渲染面的 (0,0)。而引擎自己的两条查格路（`CoordsToCell` /
  `ClientToCoords`）只在 X=0 时一致，非 0 会让下单击与 hover 差 `2·X`。
- ★ **`[0xB0CE28/2C/30/34]` 必须始终等于 R**（不是 ViewBounds）。`Fm_ApplyViewWidth`
  有一处**故意**拿 **A** 调 `DisplayClass::Set_View_Dimensions`（那个函数末尾会
  `InitGUI`，侧栏一次性写入的偏移全按传入矩形算，传 R 会把侧栏摆坏），顺手就把缓存
  留成了 A。而 `sync()` 只在几何变化那一帧跑 ⇒ **缓存永远停在 A** ⇒
  `TacticalPos` 按 A 算而渲染按 R ⇒ 恒定偏移 `(A-R)/2`，放大档下 = 视野整体偏左上
  （左上出界、右下少一圈）+ 引擎悬浮提示错位（与自己那份重影）。
  `Fm_SyncViewCache` 负责纠正，且放在"几何没变"的早退之前也跑，让不变量自愈。

## 3. 档位表

固定六档 `0.25 / 0.5 / 1.0/1.3 / 1.0 / 1.0/0.7 / 2.0`（`s_LevAll`），`[ScaleBar] Level`
是档位序号（0 = 4 倍放大，3 = 1x，5 = 半数视野）。文字由 `scale` 现算
（`4x` / `2x` / `1.3x` / `1x` / `0.7x` / `0.5x`）。

- **放大档**（scale<1）：视口收小，引擎照旧画进 Composite 的 (0,0,R)，呈现时把 R
  最近邻放大铺回 A（`SB_CompositeMagnify`）。
- **缩小档**（scale>1）：视口放大，需要一张 R 那么大的离屏面。本模块自建两张 R 大的
  DSurface，只在 `GScreenClass::Render` 期间临时换进 `[0x88731C]`(Composite)/
  `[0x8872FC]`(地图面)，渲染完还原并把 R 降采样铺回 A（`SB_CompositeDemagnify`）。
  受 ddraw 大面内存限制，建面失败时自动退回 A（等于 1x），不会越界。见 §11。

## 4. 时序（钩点与理由）

```
prepare 0x4F42F0 (每循环)  → PowerDrawBoth : ... SB_Poll（摆条 + 点击换档）
                                      → FM_Poll → Fm_ApplyViewWidth → 写 ViewBounds + Fm_SyncViewCache
render  0x4F4480 三趟之后    → SB_CompositeMagnify：把 Composite 的 R 放大覆盖到 A
                                 ⇒ 引擎 UI 与本项目 *_Draw 全都照旧 1:1 画在 Composite 上
pre-tip 0x6A7089             → MOExperience_TipPreDrawEntry（放大档只跑 Process 不画，见 §5.1①）
鼠标    WWMouse 虚表 +0x34   → MOE_MousePosEntry       （每帧轮询）
        窗口过程 0x6930A0   → MOExperience_WndMouseEntry（鼠标按钮消息，见 §7.2）

缩小档 (scale>1) 的 Render 内部时序（GScreenClass::Render 0x4F4480）:
  0x4F4480  RenderEntrySwap   → 换成 R 大离屏面 (SB_RenderSwapIn)
  0x4F4492  PreCurEntry       → 让回窗口面 (SB_RenderSuspend(1)，含入口 eax)
  0x4F44CB  MapEntry          → 装回大面   (SB_RenderResume)
       ...  第一趟 / 第二趟 TacticalClass::Render ...
  0x4F44FD  ChromePreEntry    → 让回窗口面 (SB_RenderSuspend(0)) ★底栏/提示盒就画在这里
  0x4F4502  call [edx+0x40]   → chrome pass 0x6D0A20（底栏 [0xB0FC58] + 侧栏 + 悬停提示）
  0x4F4505  ChromePostEntry   → 装回大面   (SB_RenderResume)
  0x4F4515  第三趟 TacticalClass::Render (含 PowerBarClass::Draw 原版超武列表)
  0x4F451B  AfterMapEntry     → 还原窗口面 + R 降采样铺回 A (SB_RenderAfterMap)
       ...  0x4F455D MessageList::Draw → MOExperience_MessageDrawHook → 本项目 *_Draw ...
  0x4F4564  ToolTipManager::Draw(0)  ← 正确的悬停提示（唯一一份）
  0x4F459A  call [edx+0x44]   → 0x4F45B0 呈现
```

**放大写 Composite 而不是 Primary**：它是后面每次上屏 blit 的**源**，在它上面改，
后续多少次 blit 都把放大结果原样搬上屏（写 Primary 会被随后的 blit 覆盖）。

⚠ 凡是"按 ViewBounds 定位"的引擎代码都会跟着视口缩小的量挪位置 —— 除了地图光栅化，
还有超武列表（`PowerBarClass::Draw` 0x6DA9D0）、边缘卷屏（`Scroll_Map`）、框选橡皮线
（0x6D5030）。新增缩放功能时按这条核一遍。

## 5. 缩放在 Composite 上的两条不变量

1. **呈现阶段不许动 Composite 的地图区以外的任何东西**，且放大只做一次、位置固定在
   视图区 A —— 引擎是**增量**重绘（只重画标脏的格），任何"缩放一次、事后补一次"的
   做法都会在同一帧内被引擎重画盖掉。
2. `[0xB0CE2x]` 缓存必须等于 R（见 §2）。

## 5.1 悬停提示在放大档下的两个毛病（已修）

放大档下悬停提示（建筑名 / 电量串 / 侧栏 gadget 名）有两个症状，都出在"放大前那次绘制"和"拿视口当界面"上。

**① 重影：同一帧画了两遍，大那份被放大**

`ToolTipManager::Draw`（虚表 +0x0C）全二进制只有两个调用点：

| 调用点 | 位置 | 相对 `SB_CompositeMagnify` |
|---|---|---|
| `0x4F4564` | `GScreenClass::Render`，实参 0 | **之后** |
| `0x6A7081` | `SidebarClass::Draw`（`0x6A6C30`），实参 1 | **之前** |

- 字形尺寸来自全局字体 `[0x89C4D0]`（经 `GetTextDimension` `0x433CF0`），**永不随缩放变** ⇒ 字号大一倍那份只能是 `SB_CompositeMagnify` 的重采样产物。
- 不是残影：`TacticalClass::Render` 每帧重画整个视口（`0x6D3E2F` 那几条"无变化"分支是跳回 `0x6D4582` **继续画**）⇒ R 每帧干净。
- ⇒ 放大档挡掉 `0x6A7089`（抢 7B = `8B 11 6A 01 FF 52 0C`），留 `0x4F4564` 那次。Entry 见 `MOExperience_TipPreDrawEntry`，安装见 `VecText_Install`。
- ⚠ Entry 里必须自己跑 `ToolTipManager::Process`（`0x724AD0`）：`Draw(1)` 第一件事就是它，刷 `Dimension` 与 LifeTime/Sticky 计时，跳掉之后放大后那次会画空框。只跳绘制，`0x6A7090` 之后的 `BlitSidebar` 判据一字不改。门控 `SB_In() && !SB_Safe()`，与 `SB_CompositeMagnify` 一致 ⇒ 1x 与 Safe 档零行为变化。

**② 偏移：拿视口 R 当界面，提示盒被整体拽走**

放大档下凡"拿 ViewBounds 当界线"的地方都会按视口缩小的量误判。三处，全部改成用满视图区 A（`ScaleBar.cpp` 的 `g_AView` 影子，每循环 `SB_PublishAView()` 抄一次）：

| 位置 | 拿 R 当什么 | 后果 |
|---|---|---|
| `ToolTip_Clamp`（`0x478FDC` 钩） | 钳制右界 | **盒子连字整体往左拽**，位移最多一整个视口宽（2x 876px / 4x 1314px）⇒ 提示飞到离光标很远 |
| `ToolTipManager::Update`（`0x478BD1/0x478BD7/0x478C17`） | 选面比较 + `GetTextDimension` 的 maxWidth + 居中基准 | 误判"在侧栏上"、长文本按 876 而不是 1752 提前折行 |
| `CCToolTip::DrawText`（`0x478E4A/0x478E50`） | 选面右界 | 误走侧栏面那支（`0x478E7E` 还会 `x -= 右界`） |

- 后两处：指令里写死的 imm32 改指到影子（`VecText.cpp` 的 `rep[]`），指令长度不变、只换数据来源；`ToolTip_Clamp` 自己算，按 `SB_In()` 取。
- ⚠ 改址**必须先全验完再动手**：`mov eax,[imm32]`(`A1`) / `mov edi,imm32`(`BF`) 形态第 2 字节已经是立即数，当 opcode 校验会在第 2 个点 break，留下只改了第 1 个点的半改状态。
- 侧栏两处 `SidebarBounds`(`0x886F90/0x886F98`) 不动。**1x 时 A == R ⇒ 与原版逐位相同。** 不写回 ViewBounds 本身（引擎状态）。

**③ 一条看着像 bug 但不要动**：`ToolTipManager::Process`（`0x724AD0`）把 `Dimension` 锚在 `CurrentMousePosition`，而后者由 `ProcessMessage`（`0x724200` → `GetCursorPos` + `ScreenToClient`）写成**物理**点，不经我们折算的 `WWMouse` +0x34 也不经 `0x6930A0` 的 lParam。看着像漏折算，其实是对的：放大前那次已被 ① 挡掉，剩下那次画在放大之后的 Composite 上，而那时的 Composite 像素 1:1 对应屏幕 ⇒ 物理点正好落在光标处。折了反而偏到 1/zoom。

## 6. 鼠标

引擎里"鼠标在哪"有**两个数据源**，两条都必须折算，否则口径不一致 ⇒ 放大档下
"按下时的点"与"每帧读到的点"差 `A/R` 倍。
（提示框那条 `GetCursorPos` 路径是第三个数据源，它**不需要**折，见 §5.1③。）

### 6.1 每帧轮询：`WWMouseClass` 虚表 +0x34

`v = (p - A.xy) * R.size / A.size`（p 在 A 内才折，A 外原样放行）。

11 个消费点（全二进制扫 `mov ecx,[0x887640]` 附近 `call [reg+0x34]` 的全集）：

| 调用点 | 消费者 |
|---|---|
| 0x4A56CE | 单位矩形命中 |
| 0x4A91EF / 0x4A9232 / 0x4A9284 | `DisplayClass::Scroll_Map` 边缘卷屏 |
| 0x4AAC6D / 0x4FB405 | `ClientToCoords` → `ProcessClickCoords` |
| 0x4AE538 | 框选（<900px）→ `ProcessClickCoords` |
| 0x4B8FAA | 地图像素区判定 |
| 0x692F5E | 点选下单击 |
| 0x6D0ABA | 地形判定 |
| 0x6D5068 | **框选橡皮线**（0x6D5030，第三趟 0x4F4515 调） |

**为什么必须挑"数据源"而不是消费者**：挂在 `ClientToCoords` (0x6D2280) /
`CoordsToCell` (0x6D6590) 上按调用点白名单折是不可行的 —— 它们的入参绝大多数是
引擎自己的地图像素，折算等于替引擎改数据（一折就崩）；而只挑"看着像鼠标"的少数
调用点又必然漏（0x6D5068 橡皮线、0x692F5E 点选都漏过）。源头只有虚表 +0x34 一处。

安全性：gadget 命中链（`GadgetClass::Input` 0x4E1640）用虚表 **+0x2C/+0x30**，
不是 +0x34 ⇒ 侧栏/工具栏/雷达命中一点不变；光标绘制走 +0x3C/+0x40 读实例原始坐标
⇒ 光标仍停在物理位置；**1x 时 A == R，折算恒等**；只读内存 + 只算坐标，联机安全。

本项目里自己走 `ProcessClickCoords` 的三处（`OU_MouseCellPx` /
`OU_MouseCellTarget` / `DP_MouseCellZ`）拿的是 `GtMouseGameXY` 的物理点，喂之前
必须自己调一次 `SB_MapPoint`。按引擎投影画图元的三处走 `SB_ViewToScreen` /
`SB_MapDeltaToScreen`。

### 6.2 鼠标按钮消息：窗口过程的 `lParam`

```
窗口过程 0x7775C0 → 0x777640 call 0x6930A0 (this=MouseClass::Instance=0x87F7E8)
       第4实参 = &lParam
```
`0x6930A0` 用 `eax = Msg-0x201` 查 6 项跳转表（0x693410），落地的只有五个鼠标按钮，
开头同一段：`mov eax,[edx]`（x）+ `movsx ecx,word [esp+36]`（y）`- ViewBounds.xy`。

| Msg | 跳转 | 干什么 |
|---|---|---|
| 0x201 LBUTTONDOWN | 0x693126 | 点选下令 + `LeftMouseButtonClick` 0x4AC310 **记框选锚点**（DisplayClass+0x11DC/+0x11E0）|
| 0x202 LBUTTONUP | 0x6931F9 | `0x63A8E0(x,y)` 滚屏判据 → 点选收尾 |
| 0x203 LBUTTONDBLCLK | 0x6932A4 | 同上 |
| 0x204 RBUTTONDOWN | 0x693366 | `0x63AB00(x,y)` 边缘卷屏开关；左键还按着则结束框选 |
| 0x205 RBUTTONUP | 0x6933E6 | 左键还按着才收尾 |

**钩法**：`MOExperience_WndMouseEntry` 把**第4实参那个指针**换成折算好的副本
（`s_WndLp`），尾跳跳板。

- ★ **只能换指针，不能改 lParam 的值**：同一个 lParam 槽在 0x777645 之后还要原样
  交给 `0x778030` 和 0x7779B9 → `0x54F790`，后者靠 lParam 更新 `WWMouseClass` 的
  位置。改了值不还原 ⇒ 光标跑偏、gadget 命中全歪、`GtMouseGameXY` 还会**再折一次**。
  而第4实参那个槽在 0x6930A0 自己的栈帧上（`ret 0x10` 会弹掉）⇒ 换指针不影响调用者。
- ★ 副本里必须放**打包好的 lParam**（`(y<<16)|x`），不能放 `Point2D`：引擎先把整个
  dword 抄进自己的栈槽，再 `movsx ax` 取低 16 位（x）、`movsx word [esp+36]` 取那个
  dword 的**高 16 位**（y）。放 `Point2D` 的话 y 恒等于 X 的高 16 位（0）。
- ★ 入口 `ecx` = this，跳板里 `mov esi,ecx` 把它当 DisplayClass 用 ⇒ 中间那个 cdecl
  调用的前后必须手动 `push/pop ecx`（`ebx/esi/edi/ebp` 是 callee-saved，不用管）。
- 抄 8B = `A0 78 E3 A8 00` + `83 EC 1C`，跳板跳回 0x6930A8。

不修的症状：单击被判成拖框、橡皮线起点偏到 2 倍远、点选落格偏一档。

## 7. 超武列表的拦截带与"画布判据"

原版超武列表由 `PowerBarClass::Draw` (0x6DA9D0) 画，那批行的 x 是
`ViewBounds.Width - 30`（名）/`-3`（计时器），1x 下视口右缘 1752 ⇒ 名 1722 / 计时器
1749。放大档下这批行跟着视口缩到**视口右缘**（2x 下 846/873），随后被放大两倍 ⇒
原版列表又大又偏，正好压在自定义面板上。缩小档下反过来撑到 ~2473/2500，画进 R 大面、
降采样后挤在画面右缘。

⇒ 横向拦截带必须跟着 `ViewBounds` 走（`VecText.cpp` 的 `VecSWBand`：
`[ViewBounds.X+Width-400, +8]`）。同理 `Print` 层的计时器兜底用同一条带。

⇒ **"这块面是不是主画布"的判据必须同时认大面**（缩小档，见 §11.11：
`VecIsCanvas` / `SB_IsBigSurface`）。

## 8. 已知限制

- **放大档下光标看不见**：我们把 Composite 的视图区整块重采样盖掉了引擎画上去的光标。
  别去调 0x4F4583 那两个虚表槽（`+0x3C` 是 `RemoveMouse(surface,flag)`，
  `DisplayClass +0x44` 的参数还压在栈上语义不明）。要恢复得走"从 Composite 里按光标
  矩形拷一小块到 Primary"的路子。
- 视口大于窗口时，引擎有几处按窗口尺寸建的临时面会拿到超界 blit（DDraw 会裁剪）。
- `VisibleCells[800]` 有硬上限（0x6DA93E `cmp eax,0x31F`）：缩小档下同一帧超过 799 个
  "有对象的格子"要重画时，后面的单位可能不画。
- 缩放档下卷动步长仍按地图像素走（看起来比 1x 快/慢 scale 倍）。

## 10. 两条把游戏打崩过的坑（结论保留）

**① 跳板偷的字节数必须落在完整指令的末字节上。** 跳板把 `[at, at+n)` 原样搬走再跳回
`at+n`；`at+n` 落在某条指令中间就会从半个指令开始重新反汇编 → 执行到莫名其妙的指令
直接飞掉（能写任意内存 / 跳去任何地方）。用法：先反汇编确认末字节再填 `n`。

**② 写引擎内存的每个循环都要同时按"目标对象的实际尺寸"夹。** 只按调用方给的矩形夹，
一旦该矩形超出目标面（改分辨率/建面的瞬间）就会整片写出界 ⇒ 堆被写坏 ⇒ 之后某个虚表
/函数指针变野，跳到堆地址崩。往 DirectDraw 面写之前还要查 `pitch >= 2*width`
（不是 16bpp 的面会每行越过行尾）。

## 11. 缩小档（scale>1，扩大视野）

放大档把视口收小，引擎画得少；缩小档反过来，视口 R=A*scale 比窗口大，引擎必须画进一张
R 那么大的面。`GScreenClass::Render` 只会把视口 1:1 画进 `[0x88731C]`（三趟 Render 的
面参数），而 `TacticalClass::Render`（0x6D3D10）内部在 0x6D4057 把 `[0x88731C]` 与
`[0x8872FC]`（持久地图面）**互换**，所以两张面必须同尺寸 —— 这是"只换 Composite 不够"
的原因。

### 11.1 面从哪来、什么时候换

引擎自己的 CreateAll 只在建面/改分辨率时跑，且本模块明确不钩它（会崩）。所以：

1. `SB_GetViewRect`（FullMap 每循环调）在 scale>1 时先 `SB_EnsureBig(w,h)` 自建两张 R 大
   的 DSurface（`0x4BA5A0` 构造，对象 0x24 字节，flags `1,1`）。建不出（ddraw 内存不够 /
   Render 钩没装上）就返回 0 ⇒ FullMap 用 A，行为等于 1x，**绝不**按 R 往窗口面里画。
2. Render 入口钩（`0x4F4480`，首 8B=`83 EC 08 A1 1C 73 88 00`）在缩小档把
   `[0x88731C]`/`[0x8872FC]` 换成大面（`SB_RenderSwapIn`）。
3. 三趟地图画完、**引擎 UI 之前**（`GScreenClass::Render` 内 `0x4F451B`，钩
   `MOExperience_AfterMapEntry`）`SB_RenderAfterMap`：还原 `[0x88731C]`/`[0x8872FC]`
   **以及 "当前绘制面" `[0x887314]`** 成窗口面，再把大面的 R 区域降采样铺回窗口
   Composite 的 A（`SB_CompositeDemagnify`，源/目标两张面不重叠，可直接读写、无需
   暂存），之后引擎原生 UI（侧栏 `0x4F4547`、MessageList `0x4F455D`）与本项目 UI 链
   全部 1:1 落在窗口 Composite 上。见 §11.5。
4. 离开缩小档（`SB_PrepareSurface` 见到 `!SB_Out`）销毁大面。

大面只在一次 `GScreenClass::Render` 内出现，窗口期的其它代码（prepare/侧栏/DoBlit）看到的
仍是窗口面。`g_RenderTramp==NULL`（钩子装不上）时整块停用。

### 11.2 ZBuffer/ABuffer（GrowZBuf）—— 只能借它的构造/析构，**不能走 Set_View_Dimensions**

`[0x887644]`(ZBuffer) / `[0x87E8A4]`(ABuffer) 每像素 2 字节、被 Render 每帧整块清零并按
屏幕坐标写。**缩小档必须**按 R 重建这两块缓冲（TacticalClass::Render 用 ViewBounds=R 的
坐标 z-fill/z-test），否则越过行尾/缓冲末尾读/写到野地址（实测 `0x49741E` 的
`mov dx,[eax]`，eax 是按 R 步进、按 A 尺寸回绕算出来的垃圾堆指针）。

`DisplayClass::Set_View_Dimensions` (0x4A8960) 的第 3/5 步就是"按 ViewBounds 释放+重建
这两块缓冲"，但那个正门**顺带**做了四件在缩小档下全是坏事的事：

| 步骤 | 副作用 | 缩小档后果 |
|---|---|---|
| 0x4A8987-0x89A1 | 覆写 ViewBounds 四字段 | 缩放的不变量被它改掉 |
| 0x4A89BD `call 0x6D5F60` | 同步 `[0xB0CE28/2C/30/34]` 缓存 | 缓存被留成传入值 |
| 0x4A89CA `call [edx+0x0C]` / 0x4A8B0B `[edx+0x10]` | 按 ViewBounds 重建 WWMouse 视口 | 鼠标视口变成 R，死区/光标判据全错 |
| **0x4A8B13 `call 0x6ABD30` = `DisplayClass::InitGUI`** | 侧栏页签/cameo 行/小地图/底部工具栏的**一次性**布局写入全按传进去的矩形算 | **崩溃 + 侧栏点不动**（见下） |
| 0x4A8BB8 `call 0x5D3A60` / 0x4A8BC9 `call 0x5D4AD0` | 按 `[0x886FA8]` 重设 MessageList 区 | 消息框被摆到屏幕外 |

**⇒ `SB_ResizeBufs` 只借构造/析构自己重建两块缓冲**
（`0x7BC970` / `0x7BCAE0` / `0x410CE0` / `0x410E50`，`operator new/delete` = `0x7C8E17` /
`0x7C8B3D`，对象 `0x30` 字节，布局 `+0x28=宽 +0x2C=高`，ZBuffer 构造完补 `+0x24=0x8000`）。
不碰 ViewBounds、不碰缓存、不碰 WWMouse、不碰侧栏布局。
顺序上**先建新的再放旧的**：分配失败时引擎手里仍是完好的旧缓冲
（宁可尺寸不匹配，也不能让 `[0x887644]` 变空指针 —— Render 每帧无条件解引用它）。

**⚠ 调用约定一律按 `ret N` 核实，别照"像是指针"去猜**（本项目已栽两次）：

| 函数 | 结尾 | 约定 | 调用要点 |
|---|---|---|---|
| `0x7C8E17` `operator new` | `6A 01 / FF 74 24 08 / E8 .. / 59 59 / C3`（净栈变化 0） | cdecl 1 参 | 参数留给调用方 |
| `0x7C8B3D` `operator delete` | `push [esp+4] / call .. / pop ecx / ret` | cdecl 1 参 | 同上 |
| `0x7BCAE0` / `0x410E50` 析构 | 裸 `ret` | thiscall，无栈参数 | — |
| `0x7BC970` / `0x410CE0` 构造 | **`ret 0x10`**（`0x7BCA46` / `0x410DB3`） | thiscall + **矩形按值传**（入口按 `[esp+4]/[+8]/[+0xC]/[+0x10]` 读） | `ct(p, *r)`，**不能传指针** |

第一版图省事写成 `(void*, const RectangleStruct*)` 传 `&t`：矩形的四个
dword 恰好被当值读走（所以缓冲尺寸看着仍然是对的，`SB_BufIs`
也过），但被 callee **多弹掉 12 字节 ⇒ 栈被砸**。表现是 `eip=0xB`、
`eax=1`、`edx=1`、`ebp=0x89`，栈上还留着半截日志文本（`MOE: phase=applyview`，
紧挤着的上一条日志正是 `sbar: zbuf <- 2503x1497`）——正好指向
`SB_ResizeBufs` 之后那几条语句。

**这条同时修掉了三个症状**（同一个根因）：

1. **F11 切侧栏崩**。日志现场：`MOE: phase=applyview`（= `Fm_ApplyViewWidth`），
   `eip=0x6BA643`（`mov [ecx],dx`，通用拉伸 blit 的内层写循环），`ecx=0x0FFD911E`，
   栈上是 `0x6B600D` ← `0x6A9A43`。时序完全对上：
   `F11 → mode->radar → A 变 → R 变 → SB_ResizeBufs(R) → Set_View_Dimensions(R)
   → InitGUI(R) → 侧栏图标按 R 几何摆 → 往 168 宽的侧栏面 x=3474 处拉伸 → 越界 → 崩`。
2. **超武侧栏按钮点一下就崩（F4 显隐不崩）**。同一个根因：点按钮会下单 → 加 cameo →
   `RepaintSidebar` → 侧栏图标拉伸 → 越界。F4 只切显隐，不碰 cameo，所以不崩。
3. **原版侧栏点击失效**。`InitGUI` 那批一次性写入同时把侧栏按钮的**命中区**按 R 摆歪，
   点下去落在按钮外面。

`Fm_ApplyViewWidth` 里那条 `setDims(A)` 也加了 `&& !SB_Out()`：缩小档下缓冲归缩放独占，
否则两边来回抢（ScaleBar 按 R 建、FullMap 按 A 建），且它每次都会拖一次 InitGUI。

- `GrowZBuf=1` 只是让 1x/放大档也按视口重建（一般不需要）；缩小档恒开。
- 日志：`sbar: zbuf <- WxH`（每次重建）、`sbar: zbuf alloc FAILED -> zoom-out off`。

### 11.3 新面要催重画

引擎的地图是**增量**画的（只有标脏的格子重画），换视口宽度/换面都不标脏。新建的 R 大面是
空白的，所以 `SB_EnsureBig` 成功后连续 4 帧把整块 R 推进 `RegisterDirtyArea`（帧号门控），
否则缩小后大半屏是黑的。

### 11.4 已改的消费点（scale>1 与 scale<1 共用）

`SB_MapPoint` / `SB_ViewToScreen` / `SB_MapDeltaToScreen` 的门从 `SB_In()` 改成
`SB_Zoomed()`（两者都是 `v=(p-A.xy)*R.size/A.size`，方向都成立）；`MOE_MousePos`、
`MOE_WndFixLParam`、`MessageDrawHook` 同步改；`ToolTip_Clamp` 的 A 影子判据也从 `SB_In()`
改成 `SB_Zoomed()`（缩小档下 ViewBounds=R>A，拿 R 当界同样会错）。放大档专属的
`SB_CompositeMagnify`、提示框重影修复（`TipPreDraw`）仍只判 `SB_In()`。

新增日志：`sbar: zoom-out surface ON WxH` / `sbar: zoom-out surface FAILED -> off` /
`sbar: zoom-out off (render hook missing)` / `vtext: render hook ON/OFF`。

### 11.5 还原点必须早于引擎 UI（底栏残影 + 侧栏崩溃的根因之一）

早期版本把 `SB_RenderSwapOut` + 降采样放在消息帧钩（`0x5D4A94`）。但 `GScreenClass::Render`
在三趟地图之后、`MessageList::Draw` 之前还有一段引擎原生 UI：

| 地址 | 内容 |
|---|---|
| `0x4F451B` | 光标恢复（`[0xB0B519]`）——**本模块的还原钩就抢这 5 字节** |
| `0x4F452D-0x4F4540` | `WWMouse::vt+0x40([0x887300] 侧栏面, 1)` + 清 `[0xB0B519]` |
| `0x4F4547` | `[[0xA8EF54]->vt+0x2C](0)` |
| `0x4F455D` | `MessageList::Draw` (0x5D49A0，全二进制**唯一**调用点) |

⚠ **修正旧结论**：`SidebarClass::Draw` (0x6A6C30) 在 0x6A6C59 把 `[0x887314]` 存起来、
0x6A6C74 把它换成 **`[0x887300]`（侧栏自己的面）**，画完再还原 —— 它**不**往当前绘制面画。
所以"侧栏画进大面"不是它的锅；真正把窗口坐标 UI 写进大面的是别的东西（见 §11.9）。
还原 `[0x887314]` 这一步仍然必须（`TacticalClass::Render` 0x6D4076 把它写成换过之后的
地图面），保留。

### 11.9 底栏残影（画面中部闪出底栏）—— 根因是 **chrome pass 在三趟地图中间按窗口坐标画**

现象：缩小档下大面 R=A*scale 里 `y ∈ [A.Height, winH)`（1.43 倍档时 = R.y
1048..1080）那条**窗口底栏带**的内容，被降采样映射到 A.y **733..756** —— 正好是画面
正中的那一条。即：残影不在窗口 Composite 上，而是**混在降采样的源（大面）里**。

#### 画它的是哪一笔（`BlitImage` 目标面探针 0x4AED70 取证）

`GScreenClass::Render` (0x4F4480) 里除了三趟地图，还在**第二趟与第三趟之间**有一笔：

```
0x4F44F9  mov eax,[esp+0x10]      ; 实参 = 打包的两个 mode 标志
0x4F44FD  mov edx,[esi]          ; ← 本轮的挂点
0x4F44FF  push eax
0x4F4500  mov ecx,esi
0x4F4502  call [edx+0x40]        ; ★ 虚表 +0x40 = 0x6D0A20 = chrome pass
0x4F4505  mov ecx,[0x88731C]     ; ← 本轮的挂点
0x4F450B  push 2 … call 0x6D3D10 ; 第三趟地图
```

`0x6D0A20` 那一趟（BlitImage 探针打到的返回地址 `0x6D0D30` / `0x6D0DCD` 就落在它里面）：

| 地址 | 内容 |
|---|---|
| `0x6D0AC2` / `0x6D0BF8` / `0x6D0CDC` | 取 `[0xB0FC58]` = **底栏矩形**（1x = `(0, H-32, W-168, 32)`）|
| `0x6D0C3B` / `0x6D0D29` / `0x6D0DC8` | 往 `[0x887314]` blit 底栏条与侧栏图标（`0x6D0CFC..0x6D0D4B` 是逐个按钮的循环）|
| `0x6D0D7A` / `0x6D0E38` 一带 | `SidebarClass::Draw` (0x6A6C30)，内含 `ToolTipManager::Draw(1)`（**悬停提示盒**，0x6A708D）|

⚠ **旧结论修正**：之前以为 `vt+0x44 = 0x6D0A20` 是错的。运行期探针打出来的是
`t44 = 0x4F45B0`（呈现那一趟）。0x6D0A20 在**`vt+0x40`**（紧挨着 Render 的
`vt+0x3C`），所以它夹在两趟地图中间，肉眼看 Render 的反汇编很容易漏掉。

#### 修法：把"让出窗口面"扩成两段

| 挂点 | 原指令 | 动作 |
|---|---|---|
| `0x4F4492` | `A3 14 73 88 00` | `SB_RenderSuspend(1)`：三个全局换回窗口面（**不动** `s_CurC/s_CurM/s_LastFinal`），并把**入口 eax** 换成窗口面（`0x4F44A2` 的光标擦除直接吃 eax，不读全局）|
| `0x4F44CB` | `A1 1C 73 88 00` | `SB_RenderResume()`：装回大面，原指令照跑重读全局 |
| **`0x4F44FD`** | **`8B 16 50 8B CE`** | **`SB_RenderSuspend(0)`：再让回窗口面**（不碰 `g_PreCur*`，chrome pass 走虚表不吃渲染面）|
| **`0x4F4505`** | **`8B 0D 1C 73 88 00`** | **`SB_RenderResume()`：装回大面** |

⇒ 大面被暴露的窗口真的只剩"三趟地图"这一段。

顺带修掉的两个症状（都出自这一笔）：

- **悬停提示显示两次**（实测图2）：chrome pass 里那次画进大面、降采样后缩小并上移
  （`y × A.H/R.H`），随后 `0x4F4564` 那次又按窗口坐标正确画一遍。现在那次画在窗口
  Composite 上，随即被 `0x4F451B` 的降采样整块覆盖掉 A ⇒ 只剩正确的一份。
  ⚠ 所以缩小档**不能**学放大档那样去挡 `0x6A7089`（`TipPreDraw` 仍只判 `SB_In()`）：
  挡掉它会让 `ToolTipManager::Process` 的计时不刷新。
- **选中单位时底部底栏"点不动"**：chrome 脏缓存 `[0xB0CC00..(n)]`（n=`[0xB0CD44]`）
  记的是**大面**，`0x6D0B3C..0x6D0B57` 拿 `[0x887314]`（当时也是大面）比对命中 ⇒
  `bl=0`，**整段 chrome 每帧跳过**。于是窗口面上那条底栏再也不会重画（只剩进档前
  的死像素），而按钮的按下/悬停反馈全落在中部那条"错误底栏"上 ⇒ 看着就是"点了
  底部却映射到地图中间"。

#### 另外三条配套

1. **新大面清零**。`Sb_NewSurf` 里 `DSurface` 的像素缓冲是 `operator new` 出来的，
   内容未定义；地图光栅化只覆盖它认为该覆盖的格子，图外/半格区会把堆里
   上一块内存的残留直接当成画面。`SB_EnsureBig` 成功后两张面立即 `Sb_ClearSurf`。
2. **大面尺寸只增不减**。侧栏模式(F11)与缩放档都会改 R；若按 R 精确重建，连按 F11
   就是"每帧建两张新面 + 每帧清零"，而新面在引擎重画之前是黑的 ⇒ **连按侧栏键时
   整屏黑**（实测图2）。新 R 只要塞得下就复用：引擎只往 `(0,0,R)` 画、降采样也只读
   `(0,0,R)`，多出来的边角永远没人碰。切模式时 R 变了还要推 4 帧整块脏区
   让新露出的那圈重画。
3. **换面泄漏自愈 + 本项目图层不画进大面**。`SB_RenderSwapIn` 记住"真正的窗口面"
   （`s_WinComp/s_WinMap`）；入口若看到 `[0x88731C]` 已经是自己的面（上一帧还原漏了），
   就改用记住的窗口面当还原目标。`SB_PrepareSurface` 每循环补一次 `if (s_RenderSwapped)
   SB_RenderSwapOut()`。`SB_DrawToComposite` / `SB_CompositeDemagnify` 目标若还是大面就跳过（`Sb_IsBigSurf`）。

⚠ **一度走错过的路（已剔）**：曾经试过"每帧把 R 里 `y∈[A.Height,winH)` 那 32 行抹掉"，
屏障是底栏残影带在 R 里混进来的。错在两处：**(a)** 那条带在 R 里是**地图**，抹了会留黑带
（地图是增量画的，不保证每帧重覆）——实测图1 那条黑带就是它；**(b)** 它本身就是"藏痕"而不是"治病"，
底栏在底部画是完全正常的（`y ∈ [A.Height, winH)` 那条带在窗口面上从不被地图覆盖）。
用正解让它根本不可能被画进大面，底部那条仍然完好。

日志：`sbar: WARN composite leak from last frame -> re-armed` ⇒ 上一帧换面泄漏，已自愈；
`sbar: WARN demagnify target still big -> skipped` ⇒ 降采样目标还是大面，已跳过；
`sbar: diag comp=… cur=… final=…` ⇒ 每 ~2 秒一次的面指针诊断；
`vtext: chrome-pre hook ON/OFF` + `vtext: chrome-post hook ON/OFF` ⇒ 上面那两个挂点。

### 11.11 超武列表的"画布判据"必须同时认大面（否则自定义面板整块消失）

`VecText` 把原版超武列表摘下来靠的是"面尺寸 == 主画布尺寸"这一句：
`VecSimpleEntry`（0x4A5EB0 的 7B 钩）里 `b[1]==g_SWCompW && b[2]==g_SWCompH`，
`g_SWCompW/H` 每帧由 `MOE_DrawUILayers` 写成**窗口 Composite** 的尺寸。

缩小档下三趟地图期间渲染面 = R 大的离屏大面（2503x1497），于是
`inband` 整批判成 false ⇒ `return g_OrigSimple(...)` 放行 ⇒ 原版名/计时器/底色条
原样画进大面，降采样后挤在画面右缘（实测图4：自定义面板没了，变成引擎原本那串
压扁的列表）。`VecSWCapture`（Print 层兜底）与 `VecRender` 的空裁剪哨兵同理。

⇒ `ScaleBar.cpp` 出两个判据：
- `SB_IsBigSurface(void*)`：**指针**判定"这块面是不是本模块自建的大面"。VecText 的
  `VecSimpleEntry`（`0x4A5EB0` 的 7B 钩）与 `VecSWCapture`（Print 层兜底）改用
  `VecIsCanvas(surf,w,h) = 主画布尺寸命中 || SB_IsBigSurface(surf)`。指针判定不受
  将来窗口改尺寸影响，也不必赌"窗口面尺寸 = 画布尺寸"。
- `SB_CanvasH(int w)`：按**宽度**认同一张面、返回它的高（0 = 不认）。只给"手上只有
  pitch"的场合用（`VecRender` 的空裁剪哨兵）；认不出时退回原版 1bpp 光栅，只退化
  外观不出错。窗口面尺寸由 `SB_NoteWindowSurface(surf,w,h)` 每帧从消息帧钩喂进来
  （**不依赖 `[ScaleBar] Enable`**），`SB_EnsureBig` 里另有一份兜底。

y 侧的裁剪上界也跟着换成**这块面自己的高**（`b[2]` / `sh`），不再写死 `g_SWCompH`。

1x/放大档下大面不存在 ⇒ 三处判据逐位等价于原来的写法。

### 11.12 缩小档下"点底部底栏 = 对画面中部下令"（A 外的点被当成视口内）

现象：**选中单位**后点底部底栏，命令落到**画面中部**那个地图像素上（单位朝正中跑）。
1x / 放大档没有；只有 `scale > 1` 有。

根因是一句话：**`SB_MapPoint` 对 A 之外的点原样放行，而缩小档下 R 比窗口大。**

| 档 | R | 底栏带物理 y = 1049..1080 | 原样放行后 | 结果 |
|---|---|---|---|---|
| 1x | 1048 | 1049..1080 | 落在 R **之外** | 引擎的 ViewBounds 边界判定拒掉 ✓ |
| 放大 (0.5) | 524 | 1049..1080 | 落在 R **之外** | 同上 ✓ |
| 缩小 (1.43) | 1497 | 1049..1080 | 落在 R **之内** | ✗ 当成"地图上 y≈1060 那一带" |

那个像素呈现在屏幕上的位置是 `1060 * A.H/R.H ≈ 742` ⇒ 正是**画面正中**。
而 `DisplayClass::ProcessClickCoords` (0x692300) 的全部判据只有两条：

```
0x69234B  mov eax,[ebp]   ; test eax,eax ; jl 0x6925FC   → X<0 拒
0x692356  mov ebx,[ebp+4] ; test ebx,ebx ; jl 0x6925FC   → Y<0 拒
```

**没有上界判定** —— "点在视口之外"引擎自己根本不管，1x/放大档是靠别的几处
ViewBounds 边界判定（`ClientToCoords` / 橡皮线 0x6D5030 / `Scroll_Map`）兜住的，
那些在缩小档同样失效（它们比的是 R）。

修法两半：

1. **`SB_MapPoint`：缩小档下 A 之外的**窗口内**点也走同一个线性变换**。
   物理 `≥ a.Y+a.Height` ⇒ 视口 `≥ r.Height`，折完必然出界 ⇒ "不是地图上的点"
   这件事在视口坐标里也成立。窗口外的点（拖出窗口）维持原样。屏幕空间的卷屏判据
   不受影响（`SB_EdgeScrollPointFix` 入口会把那个点换回物理鼠标）。
   **只判 `SB_Out()`** ⇒ 1x / 放大档逐位不变。
2. **`ProcessClickCoords` 入口钩（0x692300, 7B `8B 44 24 10 83 EC 18`）**：
   入口用 `SB_PtInView(vx,vy)` 判一次，不在视口内就自己 `ret 0x18` 返回 0。
   0x201/0x203 两条分支本来就 `test al,al; je 0x693408` 直接跳出，
   `LeftMouseButtonClick` (0x4AC310) 也就不会记框选锚点，`DecideAction` 无从下手。

**为什么不是 gadget 命中链的问题**（排查时确认过，别再往那边找）：
`GadgetClass::Input` (0x4E1640) 的命中测试取的是
`WWMouse::vt+0x2C/+0x30`（0x4E16AA / 0x4E16BF ⇒ **物理**坐标），不经过我们折算的
+0x34，所以那条链天生与缩放无关；而 `FM_TrimViewGadget` 收窄视口容器 gadget
（§11.10）只是额外保险。

日志：`sbar: click outside view X,Y tick=…`（2 秒一条，只在真拒掉时打）——
**这条打不出来就说明底栏点击根本没走 `ProcessClickCoords`**，那才需要往别的路径查；
安装：`vtext: clickcoords hook ON/OFF/mismatch`。

### 11.6 边缘卷屏的死区必须按屏幕空间算

引擎的边缘自动卷屏是 `DisplayClass` 的 `0x00692B60`（每帧由 `0x00692F30` 驱动，唯一
调用点 `0x69304E`）。它把传入点当**视口坐标**（`pt + ViewBounds.xy`），再拿结果和**面的
宽高**（vt `+0x7C/+0x80`）比算死区/方向 —— 这是**屏幕**空间的判据。

缩放后 `WWMouse` 虚表 `+0x34` 返回的是视口点（物理 `* R/A`），直接喂进去死区就跟着
缩放：缩小档（R>A）光标还没到屏幕边就出死区 ⇒ "鼠标在画面中部就能卷动"，而左右/上下
仍按物理边判 ⇒ "判定还在左上角"。

修法：在 `0x692B60` 入口（钩 `MOExperience_EdgeFixEntry`，7B）把那个 `Point2D*` 换回
**物理**鼠标（`WWMouse` 实例 `+0x1C/+0x20`，`SB_EdgeScrollPointFix`）。1x 时本来就是
物理点 ⇒ 恒等；只在 `SB_Zoomed()` 动手。`0x692B60` 只有这一个调用点，且它是整条驱动里
**最后**用这个点的地方（`ProcessClickCoords` 在那之前已用完）⇒ 不影响 hover/点击。

### 11.7 ZBuffer/ABuffer 必须始终匹配"渲染面尺寸"（换档崩溃的根因）

`[0x887644]`(ZBuffer) / `[0x87E8A4]`(ABuffer) 被地图/单位光栅化用来做 z-test 与 alpha，
并且它们的宽高会被当成**渲染面的行步进/裁剪**用。所以它们必须与当前渲染面匹配：

| 档位 | 渲染面 | 缓冲应匹配 |
|---|---|---|
| 缩小档 | 自建大面 `R` | `R` |
| 1x / 放大档 | 窗口 Composite (`GtGameW/H`) | `A`（引擎默认，`A ≤` 面宽） |

早期版本只在缩小档**放大**缓冲，离开缩小档时直接 `return`（只把 `s_BufW=0`），于是
缓冲**停在 R 大的尺寸**。渲染面已回到窗口 Composite，但光栅化按旧的大尺寸步进 ⇒
`[edi]` 走出界 ⇒ 崩（`phase=blitsidebar`、`eip=0x494BF9` 的 `mov [edi],ax`）。

**而且记账不能只信自己**：`Fm_ApplyViewWidth` 换宽度时会调引擎的 `Set_View_Dimensions`，
那会把缓冲按 A 重建一遍 —— 我们记的 `s_BufW/s_BufH` 就与实际脱节了。所以
`SB_BufIs(w,h)` 直接读 ZBuffer 对象里的 `+0x28/+0x2C` 交叉验证，对不上就重建。

重建顺序：**先建新的再放旧的**（`Sb_BuildBuf` 成功才 `Sb_DropBuf` 旧的）。分配失败时
引擎手里仍是完好的旧缓冲 —— 宁可尺寸不匹配，也不能让 `[0x887644]` 变空指针，Render
每帧无条件解引用它。

### 11.8 通用拉伸 blit 的野面守卫（cameo 崩溃的兜底）

缩放档下引擎的 cameo/图标拉伸（`0x6BA580`，`SHP`/`PCX` 透明拉伸）在侧栏重画时
（SWS 隐藏→`AddCameo`×78→`RepaintSidebar`、F11 切态、刚进缩小档）会拿到野面指针，
`0x6BA643` 的 `mov [ecx],dx` 直接崩（`ecx=0xFFxxxxxx`）。

**注意**：这是**兜底**，不是修法。真正让这里拿到野面指针的是 §11.2 里
`Set_View_Dimensions(R) → InitGUI(R)` 那条链（参数 R 被侧栏布局当成屏幕宽度）。
根因修掉之后这条守卫保留，只在 `SB_Zoomed()` 时检查两个面实参（`IsPlausiblePtr` +
虚表 + 尺寸/pitch 离谱否），非法就返回 0（调用方本来就有失败分支），合法走跳板。
1x 零行为变化。日志：`vtext: blitguard hook ON` / `blit: skip wild surf`。

守卫的判据（本轮补齐）：
- `ecx` 是野的**原因**是 `ebx = destBuf + 2*(rect.Y*(destPitch/2) + rect.X)` 里
  `rect` 或 `pitch` 离谱 —— 所以除了指针还查 `pitch ∈ [w*2, w*2+1024]`
  （16bpp 面 pitch 恒为 `width*2` 按 4 对齐）和 `rect` 四个 int 都 `|v| ≤ 32767`。

### 11.10 视口 gadget 的 Y/Height 也必须收窄（缩小档侧栏点不动）

`GadgetClass::Input` (0x4E1640) → `ExtractGadgetAt` (0x4E15A0) 的命中测试读 gadget 的
`+0x0C=X / +0x10=Y / +0x14=Width / +0x18=Height` 四个 int 当**屏幕坐标**比。引擎把横跨
整个视口的容器 gadget 摆在 ViewBounds 上；`FM_TrimViewGadget` 原先只改 X/Width。

缩小档下 ViewBounds = R，**高度 R.Height（2x 时 2096）远超窗口 1080** ⇒ 只改 X/Width 的
话这个容器仍盖住整屏高度，侧栏那一列的点被判成"在视口上"。现在四个字段一起按
`s_ViewA`（满视图区，不跟缩放走）写。`FM_NoteGadgetInput` 的"这是不是那个容器"的判据
仍然只比 X/Width（Y/Height 随 R 变，拿来当判据会在换挡那帧认不出自己）。
