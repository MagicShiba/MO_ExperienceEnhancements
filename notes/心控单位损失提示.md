# 单位损失提示与语音播报

功能：`[Features] MCLossMute`（默认 1）静音心控单位的"单位损失"提示，实现见 `src/misc/MCLoss.cpp`。

## 1. 原生链路（gamemd.exe 反汇编，ImageBase 0x400000）

`FootClass::Destroyed` 入口就是 `0x4D98C0`，函数尾 `0x4D9918 = ret 4`。原版整段只做"损失播报"：

```
0x4D98C4  Owner -> HouseClass::IsControlledByCurrentPlayer (0x50B6F0)
0x4D98D1  不是当前玩家控制 -> 0x4D9916 直接返回
0x4D98DD  类型 +0xD54 标志为真 (不重要单位) -> 返回
0x4D98F0  取 GetMapCoords (vtable +0x1B8)
0x4D98F9  ecx = 7 (RadarEventType::UnitLost)
0x4D98FE  call 0x65FA70 RadarEventClass::Create
0x4D9905  失败 -> 返回
0x4D990C  ecx = "EVA_UnitLost", edx = -1, 栈 -1
0x4D9911  call 0x752700 VoxClass::Play
```

雷达事件对象是唯一来源：雷达上的闪烁圈、左下"单位遭到损失"文本（`MsgText` 的 `RadarEventType=7` 行）都由它派生。挡住 Create 就同时挡住两者。

## 2. Ares 3.0 重写

`Ares.dll.inj:799` = `4D98C0 = FootClass_Destroyed, A`。参考源码
`references/ares(Antares)/src/Ext/Techno/Hooks.cpp:1579-1599` 是 complete rewrite：
在 `!DontScore && !Insignificant && !Spawned && Owner->IsControlledByCurrentPlayer()`
且 `EVA.Lost` 索引 >= 0 且 `!SuppressLossMessage` 时，依次调
`RadarEventClass::Create(UnitLost, cell)` 与 `VoxClass::PlayIndex(idx,-1,-1)`，
最后 `return 0x4D9918`（跳过原版整段）。

判据里**没有心控检查**。心控单位 `Owner` 已被 `SetOwningHouse` 改成控制方，
于是每个心控单位阵亡都算"我方损失"——心控流战役里这类死亡远多于自有单位。

建筑走另一条：`Ares.dll.inj:105` = `44D760 = BuildingClass_Destroyed_UnitLost, 7`，
只播 `VoxClass::PlayIndex`，不建雷达事件。

### Ares 内部的调用包装（0x10000000 基址）

| 地址 | 作用 |
|---|---|
| `0x10049080` | `FootClass_Destroyed` 导出；`edi = pThis` 全程保留 |
| `0x10011780` | `RadarEventClass::Create` 的 jmp thunk，不改 EDI |
| `0x10013CB0` | `VoxClass::PlayIndex` 的 jmp thunk，不改 EDI |
| `0x10013F10` | `BuildingClass_Destroyed_UnitLost` 导出 |

`0x10049117` 调 Create、`0x10049123` 调 PlayIndex，两条 call 紧邻（中间只有
`push -1 / or edx,-1 / mov ecx,esi`），且 idx<0 时两条都不调。所以"Create 被抑制 ⇒
紧跟的第一次 PlayIndex 一定是同一单位的 EVA"，一次性标记可以精确消费。

## 3. 拦截点

`0x4D98C0` 已被 Ares 用终止式 hook 占用，同址叠加的链式顺序不可控，不用。
改钩两个 Ares 与本项目都未占用的纯表现层入口：

| 站点 | 长度 | 字节 | 抑制时跳到 |
|---|---|---|---|
| `0x65FA70` RadarEventClass::Create | 6 | `push ebp / mov ebp,esp / and esp,~7` | `0x65FB47` (`ret 4`) |
| `0x752480` VoxClass::PlayIndex | 5 | `mov eax,[0xB1D4CC]` | `0x752581` (`ret 4`) |

站点都在函数入口、序言未执行、栈上只有一个 4 字节参数，直接 `ret 4` 时寄存器与栈
都保持调用者状态。两处入口字节均无相对跳转、落在指令边界上。

单位判据：`REGISTERS.EDI` 是 Ares hook 留着的 `pThis`，调用栈 `[esp+8]` 是同一函数
压栈保存的副本，两条路径任一命中即可。再做指针/虚表/`WhatAmI`/`Owner` 校验，
最后只读查询 `TechnoClass::IsMindControlled (0x7105E0)`
（`[+0x2C0] MindControlledBy || [+0x2C4] MindControlledByAUnit`，临时与永久心控都算）。
取不到单位一律走原版，绝不误伤其它 EVA。

只写本地：不创建本地雷达事件对象、不播放本地 EVA，不改模拟状态、不发事件；
联机各客户端自行决定是否显示，不会不同步。

## 4. 为何不用 Ares 现成开关

- `EVA.Lost=`（`TechnoType/Body.cpp:388`，默认 `EVA_UnitLost`，可写 `none`）：类型级，装载期按类型读一次。
- `UnitLost.Suppress=`（弹头级，`WarheadType/Body.cpp:118`）：`ReceiveDamage` 时按弹头给
  `TechnoExt::SuppressLossMessage` 置位（`Hooks.Damage.cpp:195`），只有被该弹头命中才触发。

## 5. 判据

启动日志 `mcloss: MCLossMute=ON/OFF`；前 5 次抑制各记一行 `mcloss: radar/eva frame=...`。
心控单位阵亡不再出现"单位遭到损失"行、雷达圈与 EVA 语音，自有单位照常播报。
ESC 设置页"游戏控制 → 杂项"可现读现改。
