# 游戏速度（GameSpeed）

代码 `src/GameSpeed.cpp` / `.h`，配置 `MOExperience.ini [GameSpeed] Enable / FPS / FixEngineFps`。
UI：ESC → GUI功能 →「游戏控制」组（开关 + 拖动条）。
钩子：`0x55D79E = GameSpeed_TickHook, 6`（速度）、
`0x55E3B5 = GameSpeed_EngSettleHook, 5`（帧率计数器的口径修正）。

## 1. 帧率就是这个引擎的"游戏速度"

| 地址 | 含义 |
|---|---|
| `0xA8EB60` | `GameOptionsClass::Instance.GameSpeed`，**0~6 的整数档** |
| `0xA8B238` | `SessionClass::Instance` 首成员 = GameMode（3/4 = 联机，5 = 遭遇战） |
| `0x887348` / `0x887350` | 帧定时器 StartTime / **TimeLeft**，单位 = tick = 1/60 秒 |
| `0x6C8C40` | `timeGetTime() >> 4`（tick） |
| `0x832CEC` | 动画除数表，索引 = `GameSpeed + rate*8`，**只有 7 组** |

每帧（遭遇战 GameMode 5 必走）：

```
0x55D440 GameMode 判定 → 0x55D79E: mov esi,[0xA8EB60]   ← 挂钩处
0x55D7A4 lea ecx,[esp+0x14] / call 0x6C8C40
0x55D7BC mov [0x887350], esi      ; TimeLeft = 档位值
0x55D854 call 0x55E160            ; 按 tick 睡
```

`0x55E160` 里 `while (elapsed_tick < TimeLeft) Sleep(剩余tick)`，帧时长 = `TimeLeft` tick。

| GameSpeed | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| TimeLeft | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| FPS | 不限速 | 60 | 30 | 20 | 15 | 12 | 10 |

**引擎是帧锁定的：一帧 = 一次逻辑步进。** 帧率降 → 逻辑、动画、游戏内计时器全都同比变慢。
所以"调到 120"实际是"游戏跑两倍速"，不是"画面更流畅"。（旁证：Phobos 同功能 `CustomGS`
就是改 `FrameTimer.TimeLeft`。）

`0xA8E314` 常被误当成逻辑时钟：全镜像只有 2 处引用，都在 `0x55E160` 内（`+= 本帧还要等的
tick`），没有任何读者。

## 2. 绝不能写 `0xA8EB60`

`GetAnimSpeed`（`0x5FB2E0`）：

```
mov ecx,[0xA8EB60]        ; 整个 dword 直接参与地址运算
lea edx,[ecx+eax*8]
mov eax,[edx*4+0x832CEC]  ; 表只有 7 组
```

写 35 → 索引远超表尾 → 读 .data 垃圾 → 除数 0 → **除零崩**；`rate>=5` 分支 `idiv ecx`
（ecx = GameSpeed+1）写 -1 也直接除零。所以自定义值只存在 MOE 的 `s_Fps` 里。

## 3. 与原版速度页共存：只读、不回写

原版滑块没被禁用（那页还有滚屏/音量等其它项），它的处理器 `0x4E1E1B` 非联机时只做
`0x4E1EBA mov [0xA8EB60], ecx`。MOE 每帧比对 `0xA8EB60` 与快照，变了就把档位换算成
FPS 抄进 `s_Fps`（0 → MAX，1..6 → 60/30/20/15/12/10）。

于是"最后拖哪个以哪个为准"**天然成立**：两个控件最终只落到 `s_Fps` 这一个变量，不存在
两个写入源互相覆盖，也不需要仲裁标志。

- 开局引擎会从 `spawn.ini` 写一次 `GameSpeed`，那不是玩家操作，所以**第一次只建立基线**，
  否则 ini 里的自定义值一进游戏就被冲掉。
- 菜单打开时主循环停摆，`GameSpeed_Frame` 不会被调 → 面板绘制前补一次 `GameSpeed_Poll()`。

不回写档位的附加好处：动画除数不变，动画/逻辑的比例（`1/D`，只由档位决定）完全保持，
自定义帧率就是整体等比快放/慢放。

## 4. 实现

### 4.1 钩子返回的是绝对地址，不是偏移

`0x55D79E: 8B 35 60 EB A8 00`（`mov esi,[0xA8EB60]`，正好 6 字节），下一条是 `0x55D7A4`。

```c
if (不接管) return 0;          /* Syringe 重放原指令后继续 */
R->ESI = 自己算的 tick;         /* REGISTERS + 0x0C */
return 0x0055D7A4;             /* 跳过原指令，绝对地址 */
```

参考同 DLL 里的 `PV_LOOP_EXIT = 0x55DEDB`。写成 `6`（相对偏移）会跳到 0x00000006 直接崩。

### 4.2 5~60：Bresenham 摊 tick

每帧应得 `60/FPS` 个 tick，整数除法的余数摊到后续帧：

```c
s_Acc += 60;
t = s_Acc / fps;  s_Acc -= t * fps;   /* 35 → 1,2,2,1,2,2,2，平均 1.714 */
```

5/10/15/20/30/60 是整除点无抖动；25/35/40/45/50/55 有 ±1 tick（±16.7 ms）抖动，
和 Phobos 的 `CustomGS` 同性质。这档不需要动系统定时器精度。

### 4.3 61~120：绕开 tick，自建毫秒节拍

一个 tick 是 16.67 ms，装不下 8 ms 的帧。而且 `0x55E2D4 cmp esi,0 / je 0x55E33B` ——
`TimeLeft=0` 时引擎跳过整个等待循环。

一帧的完整结构（GameMode 5 正常帧）：

```
0x55D7C2  判定 GameMode
0x55D830  call 0x5D4D50 / 0x48D080 / 0x53B560     逻辑
0x55D847  call [vtbl+0x5C]
0x55D84F  call 0x4F4480                           渲染
0x55D854  call 0x55E160                           等待（TimeLeft=0 时立即返回）
0x55D877  ret
```

所以 `0x55D360`（一帧入口，`PV_MainGate`）是**唯一限速点**，帧周期 = 我们的等待 + 整帧体；
`0x55E33B` 之后那段的帧计数不含任何 Sleep。于是让引擎 `TimeLeft=0` 全速跑，再由
`GameSpeed_Frame` 用 QPC 绝对时刻限速。

- **`timeBeginPeriod(1)`**：单机路径引擎自己不调（`0x5D5870` 只有联机分支用），系统粒度
  15.6 ms，8 ms 的 Sleep 根本睡不出来。MOE 自己 `LoadLibrary("winmm")` 调，只开不关。
- **自旋收尾**：Sleep 即便 1 ms 粒度也会过冲，剩不到 2 ms 就自旋；绝不能让算出的毫秒数
  为 0 还调 `Sleep(0)`（那是让出时间片，多线程进程里可能等满 15.6 ms 片）。
- **追帧**：目标时刻严格按 `period` 累加（不是每帧从当前时刻重算），偶发过冲由后续帧少等
  补回来；偏离超过 200 ms（读盘/切窗口/系统睡眠）才重新对时。

→ 该档实际帧率 = `min(设定, 1/帧体耗时)`，设定值是上限，不是保证值。

### 4.4 引擎 FPS 计数器为什么比设定值低 4%

引擎计数器（YRpp `FPSCounter`）：

| 地址 | 含义 |
|---|---|
| `0xABCD40` | 本窗口累计帧数，每渲染帧 +1（`0x55AFB0` 入口 `inc`） |
| `0xABCD44` | `CurrentFrameRate`，每次结算写入；Ares 的 `FPS:` 就是它 |
| `0xABCD48` | `TotalFramesElapsed`（Ares 的 `Avg` 分子，`0x55E3AC add ecx, eax`） |
| `0xABCD4C` | `TotalTimeElapsed`（分母，每个窗口 +1） |

结算在 `0x55E372`：`0x6C8C40()` 与快照差 **≥ 60** 就结算，再把快照设成"当前 + 60"。
而 `0x6C8C40 = timeGetTime()>>4`，单位 16 ms → 引擎的"一秒"是 **960 ms**，
它数的是"每 60 tick 的帧数"：

```
显示值 = 墙钟帧率 × 0.96        100→96   110→105   120→115   60→57
```

原版里看不出来（60 档每帧 1 tick，960 ms 正好 60 帧），我们按墙钟设定就暴露了。

**处理**：挂在结算写入点 `0x55E3B5`（`mov [0xABCD44], eax`，5 字节）。此处 `EAX` 正是引擎
刚数完的本窗口帧数，用 QPC 量出同一窗口的真实墙钟换算成每秒帧数写回 `EAX`，**返回 0 让
引擎自己执行那条 `mov`**：

- 内存里没有中间态 —— `0xABCD44` 同时是低帧率降效判定的输入（6 处 `cmp [0xABCD44], eax`，
  阈值来自带滞回的 `GameSpeed::GetMinFrameRate()` `0x55AF60`），不能每帧临时改再改回；
- MOE 一个字节都不写游戏内存，只是把寄存器里的数改对；
- `dt` 必须实测而非写死 960 ms：窗口条件是"tick 差 ≥ 60"，tick 只在帧边界推进，实际窗口是
  `960 ms + 最多一帧`，低帧率时误差很大（5 fps 时写死 960 会算成 5.2）。
- `dt` 不在 0.85~1.5 s 内（暂停/读盘/失焦）这一轮不接管，沿用引擎原值。

**Ares 不需要改**：`Ares(old)/src/Misc/Surfaces.cpp` 只有一行
`swprintf_s(L"FPS: %-4u Avg: %.2f", FPSCounter::CurrentFrameRate, ...)`，它自己不做任何
统计，改数据源就等于"和 Ares 对齐"。

**`Avg` 不改**：`0x55E3AC add ecx, eax` 在挂点之前，用的是引擎原值，仍是 0.96 口径。
要一起改得把钩子挪到 `0x55E39B`，代价是 `TotalFrames` 语义从"帧数"变成"累计 fps"，没必要。

### 4.5 MAX 与下限

- 121 = MAX：引擎不限速（`TimeLeft=0`），我们的节拍器也不开，即原版 0 档行为。
- 下限 5：要完全静止有底栏的暂停/帧进（`PauseView`），不需要速度 0。

### 4.6 菜单控件：拖动条（`EG_SLIDE`）

只有 GUI功能 页的"游戏速度"行走这个类型，其它行仍是开关/分段/步进。

```
游戏速度      [===============O===============]   [ 100 ]
            ← 轨道 (右端贴到数值框前 10px) →     数值框 96px
```

- **数值框没有 +/- 按钮**，直接占满右侧控件区（`ESC_STEP_W`），右边缘与其它行一样留
  `ESC_CTL_RIGHT`。几何三处必须同源，统一走 `Esc_NumBoxFor(item)`：绘制、命中
  （`Esc_StepMid`）、编辑光标（`Esc_EditCurAt`），改一处漏一处就会光标飘或点不到框。
- 只显示设定值（在框内），不另画实测帧率。
- 轨道摊 116 个档位（5..121）≈ 2.6 px 一档；**拖动值按 `ESC_SPEED_STEP`(5) 吸附**，
  只有最右端一档是 MAX。点数值框手输不受吸附限制（可输非 5 的倍数），>121 钳 MAX、<5 钳 5。
- 交互：点/拖轨道立即跳值并 `SetCapture`，`WM_MOUSEMOVE` 连续改；点数值框进编辑；
  `WM_CAPTURECHANGED` 与关菜单都会清拖动标志。
- MAX 档数值框显示 `MAX`，滑块停在最右端。

**行高必须收紧**：GUI 页有 23 行，用默认 `ESC_GROUP_H 28` + `ESC_BLOCK_GAP 12` 在 1024x768
下总高 670 px，超出可用 652 px → 底部"阵营 UI"被裁掉。这一页单独用 `ESC_GUI_GROUP_H 26` +
`ESC_GUI_GAP 6`（总高 628 px），绘制与命中用同一套常量。

`Enable=0` 时两个钩子都不接管（TickHook 返回 0 跑原指令、SettleHook 直接返回 0 用引擎原值），
等于完全回原版行为。日志只有初始化时一条 `gamespeed: on`。

## 5. 联机：广播的是档位，不是帧数/毫秒

ESC 滑块处理器 `0x4E1E1B`：

```
非联机            → 0x4E1EBA mov [0xA8EB60], ecx   (纯本地写)
联机(GameMode 3/4) → push ecx(新档位) / push 0xd / call 0x4C6720
```

事件名表 `0x82091C` 第 13 项 = `GAMESPEED`，YRpp `EventClass::GAMESPEED { int GameSpeed; }`，
载荷在 `EventClass+7`（DataBuffer）——**就是 0~6 的档位整数**。

各端本地节奏另走一套：`RequestedFPS (0xA8B558)` → 帧定时器 `60/fps` tick（`0x55D4FB`）
+ 网络定时器 `1000/fps` 毫秒（`0x55D51C`）。这也是联机档位表多一个 45 FPS 的原因
（单机 tick 做不出 45）。

→ 自定义 FPS 在这条协议里**无法表达**，所以 `GameSpeed_Ticks`/`GameSpeed_Frame`
第一件事就是 `GameMode == 3/4 → 不接管`。

## 6. 已知限制

1. **战役（GameMode 0）不生效**：那条路走 `0x55D767`，没有 `-SPEEDCONTROL` 时引擎直接把
   `GameSpeed` 强制成 2 并写 `TimeLeft=2`，根本不经过 `0x55D79E`。MO 是启动器直接进遭遇战，
   不受影响。
2. **ESC 菜单打开期间不生效**：主循环停摆，`GameSpeed_Frame` 不会被调，改完要关菜单。
3. **GUI功能 页在低分辨率下可能显示不全**：该页没有滚动（文本页有），超出面板底部的部分
   会被裁掉。这是既有布局的约束，800x600 下本来就放不下。
4. **退出时引擎会把 `GameSpeed` 写回 `RA2MO.ini`**（那是原版档位）；自定义值单独存
   `MOExperience.ini [GameSpeed] FPS`，两者互不干扰。
5. >60 档每帧 ~1 ms 自旋收尾，占一点 CPU；5~60 档零额外开销。
