# 截图 (视口原图)

代码: `src/gui/Shot.cpp` + `ScaleBar.cpp` (`SB_RawView` / `Sb_CropVoid`) +
`PauseView.cpp` (`PV_SlotGeom` 槽 3) + `EscMenu.cpp` (`GUI_ITEM_SHOT`)。
配置: `[BottomBar] ShotEnable` (按钮显示)。输出目录固定 `<游戏目录>\Screenshots`,
就是游戏自带截图用的那个文件夹, 不开放配置 (目录不可改)。

## 1. 原生截图 (游戏自带)

热键命令对象 (`PageUserCommandClass` 派生) 的第 8 号虚函数: 虚表 `0x7EBF04`,
槽 8 (+0x20) = `0x537BC0`, GetName = `"ScreenCapture"`, 热键读
`KeyboardMD.ini [Hotkey]` (值编码 = 高字节修饰 | 低字节 VK, 现值 `339` = Ctrl+S)。

函数全程只碰 `DSurface::Primary` (`0x88730C`): 窗口矩形按面尺寸夹一遍后隐藏光标、
Lock 整面、逐行写出 —— **截的是整个屏幕, 含侧栏/底栏/战役框/tooltip/光标**,
且是缩放之后的像素。原版写 `SCRN%04d.pcx`; 本作 Ares 覆盖了这个函数, 实测输出
`SCRN.<yyyyMMdd-HHmmss-mmsss>.png`, 截取范围不变。

## 2. 本项目落点: 未缩放的视口原图

| 档位 | 屏上呈现 | 原图来源 | 截图分辨率 |
|---|---|---|---|
| 1x | Composite 的 A | Composite 的 R (== A) | = 视图区 |
| 放大 (`SB_In`) | R 就地放大铺满 A | Composite 的 R (放大之前) | < 视图区 |
| 缩小 (`SB_Out`) | R 降采样铺回 A | 大面 `s_LastFinal` 的整面 R | = R > 视图区 |

标签是 `1/scale`: 标 `0.5x` 时 scale=2, 截图宽高正好是屏上的两倍。

插入点 = `MOExperience_MessageDrawHook` 里 `SB_RenderSwapOut()` 之后、
`SB_CompositeMagnify` / 降采样之前。此刻各档原图都齐了, 且还没有任何 UI ——
tooltip 在 `0x4F4564` 才画, 光标画在 Primary 上。

## 3. 实现

| 位置 | 改动 |
|---|---|
| `Shot.cpp/.h` | 相机按钮 / 点击排队 / 取图 / 起线程编码 |
| `ShotPng.cpp/.h` | 565/555 → 8 位 RGB PNG (调系统 gdiplus.dll) |
| `ScaleBar.cpp` `SB_RawView` | 给出原图所在面 + 矩形 (只读), 顺带裁图外底色 |
| `PauseView.cpp` `PV_SlotGeom` | 4 槽: 0 格网 / 1 暂停 / 2 步进 / 3 截图 |
| `EscMenu.cpp` `GUI_ITEM_SHOT` | GUI 页一行开关, 写回 `[BottomBar] ShotEnable` |

- 面恒 16bpp, `pitch >= w*2` 必须先校验。纯读面 + 写本地文件 ⇒ 联机安全。
- 点击只在 `Shot_Poll` (prepare 钩) 排队, 取图在消息帧钩里做一次; 未开局
  (`0xA8ED5C == 0`) 忽略。
- 按钮 22x22 (`PV_BS`), 恒占槽 3 = 紧贴刻度条; 它显示时三键整体左移
  `PV_BS + PV_GAPB`。点击后立刻描 12 帧黄边 (不等编码结果)。
- 编码在 `CreateThread` 起的线程里跑 (`Shot_Worker`), 4 个槽轮转; 都在编时
  丢掉这次点击, 不排队积压。线程只碰自己的像素缓冲与目标文件, 日志和黄边
  反馈由主线程 `Shot_ReapJobs` 每帧收 (引擎日志句柄没锁, 两个线程同时写会串行)。

### 3.1 裁掉图外灰边

视口伸到地图外时 `Sb_PaintVoidOn` 会按"大面矩形 - 地图矩形"铺 `[ScaleBar] Void`
(默认 `0x202028`), 那是补边不是画面。MAX 档恒有一边留余量 (scale 取两轴较松的
那个), 缩小档地图不够大时四边都留。

`Sb_CropVoid` 两步: 先与地图矩形求交 (`SB_MapPx` - `Sb_ViewPx`, 与 `Sb_PaintVoidOn`
同一口径), 再按底色削掉"整行/整列全底色"的行列 —— 引擎地图矩形自带 `-5/+135`
余量, 纯几何裁会在底边留一条。地图完全盖住视口时为无操作。

地图在屏幕上是等距菱形, 而裁的是矩形 ⇒ 菱形四角的小三角仍带一点底色, 要剪只能
剪成菱形, 会切掉地图内容。

### 3.2 输出

`SCRN.<yyyyMMdd-HHmmss-mmm>.PNG` (与 Ares 同名口径), 8 位 RGB 非隔行。

编码交给系统的 `gdiplus.dll`。自己写 deflate 走过一遍 (构建链 `-nostdlib`,
工具链里只有 `zlib1.dll` 没有 `libz.a`, 链不上 zlib, 所以当初手写了一份固定
Huffman + 哈希链 LZ77), 但同一张 1920x1048 的三方实测是:

| 编码器 | 耗时 | 体积 |
|---|---|---|
| GDI+ | 105 ms | 2.33 MB |
| 自写 (固定 Huffman + 15 位哈希链) | 155 ms | 3.09 MB |
| WIC (`IWICBitmapEncoder`) | 176 ms | 3.64 MB |

0.5x 档的 6120x3735: GDI+ 1.24 s / 25.6 MB, 自写 1.64 s / 33.4 MB。
GDI+ 在抖动画面上找到的重复比自写那份多, 于是又快又小 —— 那就没必要再维护
一份 deflate, 改成 5 个 `GetProcAddress` 的薄封装, 净删约 300 行。

`gdiplus.dll` 是 XP SP1 起的系统组件, 但仍**动态加载**: 万一没有, 只该让截图
功能不可用, 不该让 `MOExperience.dll` 整体加载失败。PNG 编码器的 CLSID 直接
写常量 (`{557CF406-1A04-11D3-9A73-0000F81EF32E}`), 不枚举 `GdipGetImageEncoders`。
DLL 的导入表里没有 gdiplus —— 用 `objdump -p` 可以核对。

`ShotPng_Init` 在按钮出现的第一次 (`Shot_EnsureInit`) 预热, 日志里会留一行
`shot: png=gdiplus` 或 `shot: png unavailable (no gdiplus)`。

编码耗时 (单线程): 1920x1048 约 0.11 s, 3504x2096 约 0.4 s, 0.5x 档的
6120x3735 约 1.24 s —— 所以必须异步, 否则那一下屏幕冻住。

内存是 GDI+ 直接引用的 BGR 缓冲 `h*align4(w*3)`, 最大档约 69 MB, 编完即还。

目录 `<游戏目录>\Screenshots` 写死 (与游戏自带截图同一个文件夹), 由
`Shot_BuildTarget` 用 `GetModuleFileNameA` 取 exe 目录再拼 `\Screenshots`,
`CreateDirectoryA` 一次。**不做可配置目录** —— 原来的 `[BottomBar] ShotDir`
(相对/绝对/空三路分支) 已删, 那三路里只有"相对游戏目录"这一个是有意义的。
拷贝在锁内, 编码与写盘在解锁之后。

> 历史结论 (自写编码器时测的, 若哪天又要自己编码可以参考): 行滤波必须恒用
> `None` —— 游戏画面是 16 位抖动色, 同一图案短距离反复出现, LZ77 靠"原样重复"
> 吃饭, Sub/Up/Paeth 一减就把它抹掉。同一张 1920x1048: 不滤波 3.09 MB,
> None+Sub+Up 里选 3.91 MB, 五档全选 4.91 MB。

> 16 位 `BI_BITFIELDS` BMP 的写出 (`Shot_WriteBmp565`) 只剩存档缩略图在用。

> 语言文件在 `dist/MOExperienceResources`, 构建脚本负责拷到游戏目录; 缺键的行
> 会渲染成空行。
