# 存档缩略图 (SaveShot)

代码 `src/gui/SaveShot.cpp` + `SaveShot.h`; 钩子注册在 `src/core/SyringeHooks.cpp`;
绘制入口挂在 `0x622396` (`EscMenu_OnPaintSurface` 第一行)。
配置 `[SaveShot]`: `Enable` / `Width=320` / `PreviewWidth=200` / `EditHook`。
输出 `<存档目录>\Thumbs\<存档名>.bmp` (旁挂文件, 存档本体不动)。

硬约束:

- **只在按 ESC 那一刻截屏** —— 存档瞬间前台是对话框, 抓到的是对话框本身。
- **只能画在 `0x622396` 的整屏面上**; 子窗口的像素会被面板 blit 盖掉。
- 面板固定 **800x600**, 改模板无效 (见 §4.0)。
- 只读渲染面 + 写本地文件 ⇒ 联机安全。

## 1. 存档文件

`.SAV` 是 OLE 复合文档 (`D0CF11E0`), 根存储下全是扁平流: `CONTENTS`(世界) /
`Version` / `Scenario Description` / `Player House` / `Player Name` / `Start Time` /
`Last Save Time` / `Play Time` / `Campaign` / `Scenario Number` / `GameType` /
`Executable Name` / `\x05SummaryInformation`, 与 YRpp `SavegameInformation` 逐字段对得上。
缩略图选了旁挂文件 (内嵌流可行: 往副本追加流, `CONTENTS` 长度不变)。

## 2. 写档钩点

```
0x67CEF0(ECX=ANSI 日志串, EDX=同)
  → MultiByteToWideChar(…, [esp+0x2c], 0x40)
  → StgCreateDocfile(W, STGM 0x1012)        直接写最终文件, 无临时文件
  → 填 SavegameInformation → CreateStream("CONTENTS") → 0x67D300 写世界
  → Commit → Release → 尾部 0x67D2F1 (BL=1 成功)
```

| 钩子 | 长度 | 原指令 | 用途 |
|---|---|---|---|
| `0x67CF42` = `SaveShot_SaveBegin` | 6 | `FF 15 C8 15 7E 00` | 取 EDX 的完整路径 |
| `0x67D2F1` = `SaveShot_SaveEnd` | 5 | `5F 5E 8A C3 5D` | BL=1 时写 BMP |

路径不在 `0x67CEF0` 取 (那里 ECX 是 ANSI 串), `0x67CF42` 的 EDX 才是转换后的缓冲。
API 名是 `StgCreateDocfile` (非 W), 所以按"第 2 字节是否为 0"两种都认。
`0x67D2F1` 在三条 `Release` 之后 ⇒ 文件已关闭。

## 3. 取图

调用点 `Esc_OnShow` → `SaveShot_CaptureNow`, 钩在 `0x4F1140` (引擎建好对话框、
`ShowWindow` 之前): 此刻视口里还是刚渲染完的战场。晚一步 (`0x622396` 或首个
`WM_PAINT`) 抓到的就是菜单 —— 菜单和对话框画在 Composite 上, 正盖住视口那块。

- 源: `SB_RawView()` 的视口原图 (本来就没有侧栏/底栏/消息/tooltip), 盒式降采样到
  `Width` 宽, 高度按视口比例。
- 门控: `Enable` / `0xA8ED5C` 已开局 / 不在读档中 / `FrameCap_ActiveDlg()` 为空
  (最后一条挡"菜单里再开子页"那次)。
- `SaveShot_Tick` 只剩兜底: 只在 `s_Pix` 为空时抓一张, 防"开局没弹过对话框就存档"。

## 4. 存/读档界面

| 模式 | 模板 | 列表 | 主按钮 | 标题 |
|---|---|---|---|---|
| Load (`0x558A30`) | 183 | `1317` | `1039` (GUI:Load) | `1036` |
| Save (`0x558B90`) | 692 | `1319` | `1735` (GUI:Save) | `1036` |
| Delete (`0x558CB0`) | 693 | `1320` | — | — |

模板统一 `533x369` DLU, 按引擎单位 (6,13) 换算 = **800x600 px, 居中**。
实测: 列表在屏幕 `(679,367)`, 面板原点 `(560,240)`。

### 4.0 窗口层级

`0x622650` = `CreateDialogIndirectParamA` + `ShowWindow`。**对话框窗口是整屏的**,
客户区坐标 = 屏幕坐标; 只有 800x600 那块面板被 blit 上屏。

- `0x622396` 里 `[esp+0x10]` 是主窗口不是对话框。认对话框只能靠"有没有我们的列表
  控件": 枚举 `#32770` → `GetDlgItem(h, 1317/1319)`。没对话框时这个钩点仍每帧进,
  枚举节流 200ms。
- **改模板 cx/cy 不生效**: 引擎按自己的尺寸摆控件、也按自己的尺寸 blit 面板。
- 面板内可用空间: 列表原宽 380, 右边余 280, 下面余 170。

### 4.1 排版 (`SS_Layout`)

```
panel  = MapDialogRect(hDlg, {0,0,533,369})   // 800x600
panelX = (clientW - panelW) / 2, panelY = (clientH - panelH) / 2
listX  = panelX + 12
sbW    = 列表右侧那个独立滚动条子窗口的宽 (id=0, 通常 20px, 找不到算 0)
colW   = PreviewWidth (默认 200, 夹 120~420, 且给列表至少留 380)
listW  = 面板右缘 - pad - sbW - colW - listX      // 不缩只长; 挤不下就 colW=0
```

判据全来自实测, 别"顺手优化"。

- **滚动条是独立子窗口** (id=0, 紧贴列表右缘、同高同顶), `MoveWindow` 列表不会带着
  它走; 引擎刷新时还会把它摆回去, 所以每帧对一次 (`SS_KeepScroll`)。
- **高度拉到面板底**。列表下方压着的可见小控件 (存档名输入框, 高 <60) 推到面板底,
  列表停在它上面 8px。
- 左缘对齐、贴列表下沿的子控件跟着平移 + 加宽, 右缘不越过 `band.left - pad`
  (否则主按钮压上去)。两个"挪小控件"的循环必须 `continue` 掉 `s_HWndLoad/s_HWndDel`。
- 标题 `1036` 跟列表同左缘同宽; 主按钮从模板位置挪到面板底部那条带, 与输入框垂直
  居中: `[存档名输入框……][储存]`。
- `SS_LayoutDrift` 检查列表矩形/面板尺寸, 不对就重排 (每个对话框最多 3 次, 防互抢)。
- `GUI:Back` (`1670`) 钉在面板右下角, 与主按钮那一列视觉重叠是引擎本来的排法。

### 4.2 行重绘: 控件不画

```
引擎把面板画进临时面 → 0x622396 (present 前最后一跳, 我们在这画) → 上屏
                    → 之后 Windows 才异步派发子窗口 WM_PAINT (控件的 GDI 像素)
```

控件自画晚于我们 (两套文字), 赶在 blit 前画又被整块盖掉 ⇒ **控件一个像素都不画**:

```c
SS_ListProc:  WM_PAINT      -> BeginPaint/EndPaint (只为让刷新区失效) + SS_RequestPanel
              WM_ERASEBKGND -> 1
              WM_NCDESTROY  -> 还原原 proc
              其它          -> CallWindowProc (点击/滚轮/键盘/滚动条一概不变)
SS_DrawRows(surf, list) : 0x622396 里画整块列表客户区
```

- 字体跟随 `[VecText]` (`VecText_ResolvedPx/FontFace/Bold`, 与标题/按钮同源),
  槽位用主字号槽 **2**, 画法同 VecText (`RenderLine` → `BlitCoverage`)。
- **行距按墨迹**, 不能用字体 cell (`g_G->adv` 含 ~6px leading): `SS_MeasureInk`
  渲染一次 `国Gg` 扫 DIB 得 `inkH/inkTop` (同字号只量一次),
  `LB_SETITEMHEIGHT = inkH + 3`, 绘制 `y = 行顶 + (rh-inkH)/2 - inkTop`;
  行高每个控件只设一次 (`s_RhList`), 每帧设会让控件反复重排。
- 行区域从 `y0 + 2 + 3` 起算, 否则首行墨迹压在上边框上。
- 字体拿不到也要照画底色/边框 (控件已不画, 直接 return 会露出面板原像素)。
- **外框**: 面板美术那圈 2px 灰边随列表变高后对不上, 由 `SS_DrawRows` 自己画。

```
FileEntry*  = LB_GETITEMDATA(i)
档名        = +0x000 (wchar_t[0x80])    文件名 = +0x100 (char[0x20])
时间        = +0x1AC (FILETIME → Local → System → "YYYY-MM-DD HH:MM:SS")
valid/wrong = +0x1B4 / +0x1B5            (假/版本不符画灰)
```

- 左 = 档名 (按剩余宽度截断), 右 = 完整时间右对齐。色 (239,235,239) / 时间
  (214,210,218) / 假档 (128,126,134), 选中底 (123,32,123)。
- 引擎把日期列写死 (~55px, 永远 `2026...`), 加宽列表只多出空白 ⇒ 只能整块重画。
- **刷新**: 控件 `WM_PAINT` 比 `LB_GETCURSEL/LB_GETTOPINDEX` 与面板上次画的
  (`s_DrawnCur/s_DrawnTop`), 不同就 `InvalidateRect(对话框)`, 30ms 节流。

### 4.3 两个截图框

| 位置 | 内容 |
|---|---|
| 上 (`s_PicA`) | **当前画面** —— 缓存 `s_Pix` 现缩放, 不读文件 |
| 下 (`s_PicB`) | 选中那一档的 `Thumbs\*.bmp`; 换选择才重读 |

- 一个缩放函数 `SS_Shrink`: 缩小时对目标像素覆盖的源矩形取平均, 放大退化成最近点;
  `flip=1` 表示源自底向上 (BMP 的 `biHeight > 0`)。
- 等比放进框内 (`SS_PicFit`) 居中, 尺寸一变就 `SS_PicFree` 重分配, 不做容量复用。
- 色调按引擎位宽重新打包 (`g_GBits==6` 走 565, 否则 555)。
- 框内有深底 + 1px 边; 没图画 `无截图`。**框高 = 图高 + 2**。
- **缓存与记认必须同一个函数清**: `s_PicB` 与 `s_ThumbName` 只由 `SS_ThumbReset`
  一起清。`s_ThumbName` 在加载**失败**时也要记下, 否则每帧重读一次磁盘。

## 5. 载入 / 删除: 三个页面是一套代码

```
0x558DD0  屏幕状态机 (this+0x04 = 页面: 1 读档 / 2 存档 / 3 删除,
                      this+0x18 = 动作: -1 空闲, 1 本页按钮, 0x40F 载入, 2 返回)
  ├ 建对话框: 0x622650(ecx=模板id, edx=DlgProc)  183→0x558a30 692→0x558b90 693→0x558cb0
  └ 每帧看 this+0x18: 非 -1 就 GETCURSEL/GETITEMDATA 再按页面执行
      页面1 → 0x5594AE 读档 (跳过 +0x1B5 版本不符, 用 +0x100 文件名, call vtable[1])
      页面2 → 0x5591A6 存档        页面3 → 0x559095 删除
```

- `vtable[1] = 0x559D60` (屏幕对象 vtable `0x7ED2E4`, **不用 this**) 才是真读档:
  push 屏幕栈 → 建 `0x41C` 载入框 → pop → `0x67E440` LoadGame → 恢复栈深 → 销毁框。
  它**不销毁**存读档对话框 (那一步在 `0x5594AE` 返回后), 所以读档期间旧对话框还活着。
- 三个 DlgProc 都从 `GetWindowLong(dlg, DWLP_USER)` 拿 `ctx`, 只往 `ctx+0x18` 写动作码
  —— 与状态机读的是同一字段, 即 ctx 就是那个屏幕对象。
- **空闲动作是 -1 不是 0**。动作分派 (`0x559030`) **只按页面**决定干什么, 动作值只过
  "是不是本页按钮"那道门 ⇒ 点载入必须**同时**写 `页面=1` + `动作=0x40F`; 只写动作
  会在存档页上执行一次**存档**。所以写之前核对 `ctx+4 == 2 && ctx+0x18 == -1`。
- 动作码只在 `while ([esi+0x18] == -1) { 0x623120(); [esi+0x14](); 0x532100(); }`
  (`0x558FF8`) 这个循环里被消费; 选不中行就直接复位回 -1
  (**"储存"在列表没有选中行时就是彻底没反应**)。

### 5.1 两个按钮: 引擎原生美术

自建按钮进不了引擎的自绘表, 只能像素复刻 —— 正确做法是让引擎自己认领, 关键是**时机**:

```
0x558B90 = 存档页 DlgProc (stdcall, ret 0x10), 前 5B 53 8B 5C 24 10 (无 rel32)
  → 换成 SS_SaveDlgProc (跳板回原过程)
  WM_INITDIALOG:
    1) CreateWindowExW(0, L"Button", L"GUI:Load", WS_CHILD|WS_VISIBLE|BS_OWNERDRAW, …)
       **必须在调原过程之前** —— 引擎的 WM_INITDIALOG 会遍历子控件, 给自绘按钮挂
       0x610CA0 子类并注册进 0xAC1B00 表; 事后建的永远进不去。
       文本必须是 CSF 键 (`GUI:Load` / `GUI:Delete`), 引擎把窗口文本当键查
       StringTable, 查不到就显示 MISSING:<ANSI>。初始坐标 -2000,-2000。
    2) 调原 DlgProc
    3) 从"储存"(1735) 的 ownerdraw 元素复制 +0xB0 (底图 band) 与字体给新按钮。
  点击就是普通 WM_COMMAND(BN_CLICKED), id 0x540 载入 / 0x541 删除。
```

不能换对话框的 `GWLP_WNDPROC` (会把对话框管理器拆掉); patch DlgProc 函数头是另一回事,
因为里面原样调回原过程。`0xAC1B00` 是 HWND → ownerdraw 元素表, 表项
`{ HWND, elem, …, next@+0x204 }`。

### 5.2 自绘按钮的崩溃与守卫

`0x6071E0` 一进门就假定 UI 主题资源 `[0xB0FC14..0x2C]` 非空 (`0x607369` 读
`[0xB0FC20]` 直接解引用)。`LoadGame` 把这组资源释放并置 0, 而旧对话框还可见, 之后
任意一次 `WM_PAINT` 都会空指针崩溃。

**别靠隐藏窗口躲**: 外层收尾依赖状态机正常销毁对话框, 藏起来会让读档完成后停在设置页、
鼠标消失。改成挂守卫: `0x6071E0` 前 6B `81 EC 8C 01 00 00` → `SS_BtnDrawGuard`,
`s_Loading` 期间整函数跳过, 平时只在主题指针真的为空时拦。

### 5.3 载入完成后按"真载入"收尾

```
0x51E 载入 (0x4F1348): ShowWindow(菜单, SW_HIDE) → 0x5587F0(页面=1) →
      **看返回值** al!=0 → [ebp]=0x51e 后直接 ret (不显示菜单)
0x51F 存档 (0x4F13BD): ShowWindow(菜单, SW_HIDE) → 0x558810(页面=2) →
      **不看返回值** → 落 0x4F14BF: ShowWindow(菜单, SW_SHOW) + UpdateWindow
```

从存档页发起读档, 外层永远走**存档**分支 ⇒ 世界换新档、菜单又被显示出来
("停在设置页, 鼠标消失, 要盲点才回游戏")。

修法: 在 `0x4F14BF` (5B `6A 05 56 FF D7`, 无 rel) 挂桩, `s_TailLoad` 为真时照
`0x4F1389` 做: `[ebp]=0x51e` + `xor eax,eax` + pop edi/esi/ebp/ebx + `add esp,0x614`
+ `ret 0x10`, 跳过 ShowWindow; 否则原样 `push 5; push esi; call edi` 再跳回 `0x4F14C4`。
`ebp` = `GetWindowLongA(hDlg, DWLP_USER=8)` (`0x4F12B1`) = 屏幕对象。
标志在 `WM_NCDESTROY` 里校验: `ctx+0x18` 仍是 `0x40F` 才留, 否则当取消/失败清掉。

**触发前 `SS_Forget(0)` + 立 `s_Loading`**: 读档会重建整个世界, 之后的旧控件、
旧 FileEntry 都是野指针。之后 `SaveShot_PaintDialog` 看 `s_Loading` 空转, 直到旧对话框
真的被销毁才恢复 (带 90 秒看门狗)。

### 5.4 删除

照 `0x559095` 自己干 (`DeleteFileA` + `LB_DELETESTRING`), 人留在存档页 —— 走引擎删除页
会被弹走。不可逆, 第一下只"上膛" (4 秒超时), 第二下才真删。

- **空白档位不能上膛**: 没有文件名 (`SS_EntryFile` 失败) 就直接返回, 否则按钮停在
  "确认删除"却什么都删不掉。
- 删完借一次"选中变化"让引擎自己重画面板 (`SS_BumpSel`: 选到邻居再选回来) ——
  面板重绘只由引擎自己的控件通知带出来。

### 5.4.1 空白档位不能载入

`[空白 栏位]` 占位行没有文件名, 交给引擎 = 去 `LoadGame` 一个不存在的文件: 弹错误框,
而那条失败路径把屏幕栈拆掉, 世界没了而面板还在画 = 花屏 + 卡死。
所以要求 `SS_EntryFile` 成功**且** `GetFileAttributesA` 存在, 否则一步都不走。

### 5.5 按钮动态文字

按钮文字**只在初始化时**从窗口文本走一遍 CSF (`0x6102EA` → `0x734E60` → `0x623560`
存进对象字段, 引擎自己 malloc 的副本)。绘制 `0x6071E0` 既不查 CSF 也不读窗口文本,
直接读那份副本 ⇒ `SetWindowTextW` 改不动字。

- 打开对话框时用"储存"按钮反查偏移 (`SS_ProbeTextOff`): 扫元素 `+0x04..+0x200` 的每个
  DWORD, 找指向 `L"储存"` 的指针 → `s_TxtOff` (实测 `0x40`)。探不到就不改字。
- 换字 (`SS_SetBtnText`) 必须用**引擎自己的 malloc `0x7C8E17`** 分新块再改字段 ——
  按钮销毁时引擎会 `free` 这个字段, 指到 DLL 静态串就是崩溃。旧块直接泄漏。
- 上膛时换 `L"确认删除"`, 4 秒落回 `L"删除"`, 只在状态变化时设。

CSF 里现成的空串键: `GUI:Blank` / `TXT_NONE` (要"有美术没文字"时用)。

## 6. 存档名输入框: 接管引擎的 NewEdit

界面那几块的通用实现 (编辑会话/剪贴板/逐字几何/输入法定位) 在 `src/gui/LineEdit.h`,
本节只写存档框特有的部分。

**控件身份**: 模板 692 的 `id 1318` 是名字框 (rect 80,253,266,14 DLU), 类名不是 `EDIT`
而是原子 `ord:129` —— 引擎自己 `RegisterClassA` 的 `"NewEdit"` (`0x60D4DB` 的
`WNDCLASSA`: style `0x83`, `lpfnWndProc = 0x60D520`, `lpszClassName = 0x833720`)。
**运行期 id 不可信**: `GetDlgItem(dlg, 1318)` 拿到的是 `ListBox` (引擎初始化时对调过
`GWL_ID`), 控件还会被我们的排版挪走。找控件只有一个办法: 用 `SS_Layout` 顺手挑出来的
那一个 (判据="列表下方、可见、宽高都小"), 记进 `s_BoxHwnd`, `SS_EdAttach` 只认它。

**文字在哪**: 不在窗口文本, 在 ownerdraw 元素 `+0x28` (由 `0x610CA0` 的子类维护),
只能过控件消息读写:

- `0x4B3` 取文字 (`wParam` = 字符容量, `lParam` = `wchar_t*`, 处理在 `0x611AD4`)
- `0x4B2` 设文字 (`lParam` = `wchar_t*`, 处理在 `0x611BC1`: 先 free 旧块再
  `malloc(2*(len+1))` 拷入, 新旧不同才发 `EN_CHANGE`)

**文字的唯一真相在引擎控件里, 不存第二份**: `SS_EdText` 每次现读, 改完整段写回
(`SS_EdCommit`)。引擎换档/写默认名时不需要任何同步动作。
代价是每次改字多一对 `0x4B3`/`0x4B2` (设置界面, 不用管性能)。

**`0x4B2` 会把动作码顶成 1**: 引擎设完文字发自定义消息 `0x4DA` (`0x558C1A`),
处理只有一条 —— `[ctx+0x18] = 1`, 即"存档"。被顶成 1 之后"储存"点下去值没变化、
"上一页"被吞、我们自己的载入因要求 `-1` 而跳过。所以写完立刻放回 `-1`
(`SS_EdClearAct`), 且只清这一个值 (载入/上一页不是我们造成的)。

**接管方式**:

| 事 | 怎么做 |
|---|---|
| 认领 | `SetWindowLongPtrA(ed, GWLP_WNDPROC, SS_EdProc)`; 先 `0x4B3` 读一次, 读不到就不接管 (字不在这类窗口里, 硬画等于抹掉它) |
| 焦点 | 不做焦点门控: 所有消息照常转给原过程, 只吞绘制类 (`WM_PAINT/WM_ERASEBKGND/WM_NCPAINT/WM_PRINTCLIENT`), 原生灰框一个像素都不出现。按钮/列表/命令一律原生 |
| 一行字 | 按"名字框是对话框的**直接**子窗口"写: `GetParent(s_Ed)` 当对话框用 (`SS_EdClearAct` 读它的 `DWLP_USER`, `SS_EdRepaint` 置脏, `SS_EdDraw` 用 `MapWindowPoints` 转坐标) |
| 边框 | 画在控件矩形**外侧** 2px: 内沿压在控件矩形上, 内容区 = 控件真实大小, 文字与原生框同一基线 |
| 定位 | 单击**和** `WM_LBUTTONDBLCLK` 都处理 (双击第二下不是 `LBUTTONDOWN`)。命中按字中点分界, Shift+点击以原插入点补锚 |
| 绘制 | 控件不画: 底板/文字/选中/光标/组字全由 `SS_EdDraw` 画在 `0x622396` 上, 位置直接 `GetWindowRect(s_Ed)` 取 (我们的排版会挪控件) |
| 系统光标 | 原过程会 `CreateCaret` 出一道亮条, 但**不能 DestroyCaret** (输入法拿它当锚点): 只 `SetCaretPos` 挪位置, 视觉光标自己画 (530ms 闪) |
| 组字 | `WM_IME_SETCONTEXT` 清 `ISC_SHOWUICOMPOSITIONWINDOW`; `GCS_COMPSTR/GCS_CURSORPOS` 画黄字+下划线; `WM_IME_COMPOSITION` 里**当场**读 |
| 候选窗 | 每帧显式钉 (不靠插入符猜): `面坐标 * 呈现区 / 面尺寸`, 上下文取**主窗** `[0xB73550]`, 拿不到才退名字框 |
| 收字 | `GCS_RESULTSTR` 插入并记时刻; 系统收尾会按老路把同一串回一遍 `WM_IME_CHAR`, **200ms 内的回声一律吃**; 更晚的是"直接输入"(全角不发 composition), 必须收 |
| 节拍 | `SetTimer` 在这个对话框里不响。两路代替: 120ms 后台线程 (只在名字框有焦点时置脏) 负责光标闪; `0x622396` 每次刷新调 `SS_EdPoll` (插入符 + 组字 + 候选窗) |
| 焦点判定 | 一律走 `SS_EdFocused()`: `GetFocus()` 是"调用线程"的焦点, 心跳线程里恒为 NULL; 跨线程用 `GetGUIThreadInfo(0,&gi).hwndFocus` |

**三条硬约束**:

1. **退格只在一处处理。** `WM_KEYDOWN(VK_BACK)` 与 `WM_CHAR(0x08)` 成对来, 两边都删
   就是"按一次删两个字"。文本变动只认 `WM_CHAR`; `WM_KEYDOWN` 只做方向键/Home/End/
   Delete 与 Ctrl 组合。组字中 (`SS_EdComposing()`) 的退格与 ASCII 都要吐掉。
2. **改完文字/改完插入点必须主动请重画, 且 `InvalidateRect` 后跟一次 `UpdateWindow`**。
   画面是在 `0x622396` 拼的, 只有对话框收到 `WM_PAINT` 才会跑; 光置脏不会自己冒出来。
   少了它 = 打字没反应 / 点一下光标停在原处。
3. **候选窗位置只有一个正确算法**: 送给**持有上下文那个窗口**的上下文, 按它自己的
   客户区坐标。给子控件上下文送屏幕坐标 = 再叠一次窗口原点 = 飞出屏幕。也不能只推
   一次: IME 每次按键都可能按插入符改回去。

## 7. 已知取舍

- 老存档没有 bmp ⇒ 下框显示"无截图"; 重新存一次就好。
- 行绘制是硬替换: 控件不再画任何像素, 引擎以后在行里加图标/换主题我们都不会画。
- 删除存档时 `Thumbs` 里的 bmp 一并删; 被外部删掉的档留下孤儿 bmp, 不清理。
- 名字框只有单击定位 + Shift 选中, 没有双击选词/拖选; 上限跟引擎
  `EM_LIMITTEXT(0x4f)` = 79 字; `0x4B3` 读不到文字就整套退出 (退回原生框)。
- 列表项若不再存 `FileEntry*` 到 item data, 预览会整块消失 (安全失败, 不崩)。
- ESC 菜单 GUI 页没有这个开关, 只有 ini。
