# 存档缩略图 (SaveShot)

代码: `src/gui/SaveShot.cpp` + `SaveShot.h`; 钩子注册在 `src/core/SyringeHooks.cpp`;
绘制入口挂在 `EscMenu_OnPaintSurface` (0x622396) 的第一行。
配置: `[SaveShot] Enable=1` / `Width=320` / `PreviewWidth=200`。
输出: `<存档目录>\Thumbs\<存档名>.bmp` (旁挂文件, 存档本体不动)。

约束:

- **不要在存档瞬间截屏** —— 那一刻前台是存档对话框, 抓到的是对话框本身。
- **只能画在 0x622396 的整屏面上**; 子窗口的像素会被下一次 blit 盖掉。
- 面板固定 **800x600**, 改对话框模板没用 (见 4.0), 想要"更大"只能自己重写界面。
- 只读渲染面 + 写本地文件 ⇒ 联机安全 (存档本来就是单机行为)。
- 缓存刷新按墙钟节流, 不能每帧降采样。

## 1. 存档文件是什么

`.SAV` 是 **OLE 复合文档** (`D0CF11E0`), 根存储下全是扁平流, 没有子存储:

| 流 | 说明 |
|---|---|
| `CONTENTS` | 世界数据, 占体积绝大部分 |
| `Version` / `Internal Version` | Ares 的 mod 标识 + 存档 magic |
| `Scenario Description` / `Player House` / `Player Name` / `Player Name2` | 列表显示的信息 |
| `Start Time` / `Last Save Time` / `Play Time` / `Campaign` / `Scenario Number` / `GameType` / `Executable Name` | 元信息 |
| `\x05SummaryInformation` | 标准 OLE 属性集 |

与 YRpp `LoadOptionsClass.h` 的 `SavegameInformation` 逐字段对得上。
内嵌流也可行 (往副本里追加流, `CONTENTS` 长度不变), 本功能选了旁挂文件。

## 2. 写档流程与钩点

入口 `0x67CEF0(ECX=ANSI 日志串, EDX=同上)`, 后面:

```
MultiByteToWideChar(0, 0, ECX, -1, [esp+0x2c], 0x40)   把路径转成宽字符
StgCreateDocfile(W 缓冲, STGM 0x1012)                   直接写最终文件, 无临时文件
  → 填 SavegameInformation → Write(IStorage*)
  → CreateStream("CONTENTS") → 0x67D300 写世界
  → Commit → Release 流/存储
  → 尾部 0x67D2F1 (BL=1 成功)
```

| 钩子 | 长度 | 原指令 | 用途 |
|---|---|---|---|
| `0x67CF42` = `SaveShot_SaveBegin` | 6 | `FF 15 C8 15 7E 00` | 取 EDX 的完整路径 |
| `0x67D2F1` = `SaveShot_SaveEnd` | 5 | `5F 5E 8A C3 5D` | BL=1 时写 BMP |

**路径别在 0x67CEF0 取**: 那里的 ECX 是 ANSI 串。`0x67CF42` 的 EDX 才是转换后的缓冲,
正常是宽字符; 但 API 名是 `StgCreateDocfile` (非 W), 所以代码按"第 2 字节是否为 0"
两种都认。`0x67D2F1` 在三条 `Release` 之后 ⇒ 文件已关闭, 可以安全读写。

## 3. 取图 (滚动缓存)

`SaveShot_Tick` 挂在消息帧钩里, 紧跟 `Shot_CapturePending`:

- 门控: `Enable` / `0xA8ED5C` 已开局 / `FrameCap_ActiveDlg()` 为空 / 存读档对话框不在 /
  距上次 ≥1000ms。
- 源: `SB_RawView()` 的视口原图 —— 本来就没有侧栏/底栏/消息/tooltip。
- 盒式降采样到 `Width` 宽 (高度按视口比例), 每轴最多取 4 点后按通道平均。
- 写盘直接用这份缓存 (对话框开着时它不再刷新, 天然是一帧"存档前"的画面)。

## 4. 存/读档界面

真 Win32 对话框, 模板在 `gamemd.exe` 资源里:

| 模式 | 模板 id | 列表 | 主按钮 | 标题 |
|---|---|---|---|---|
| Load (0x558A30) | 183 | `1317` | `1039` (GUI:Load) | `1036` |
| Save (0x558B90) | 692 | `1319` | `1735` (GUI:Save) | `1036` |
| Delete (0x558CB0) | 693 | `1320` | — | — |

模板统一 `533x369` DLU, 按引擎的单位 (6,13) 换算 = **800x600 px, 居中**。
实测: 列表在屏幕 `(679,367)`, 面板原点 `(560,240)`。

### 4.0 窗口层级

`0x622650` = `CreateDialogIndirectParamA` + `ShowWindow`。**对话框窗口是整屏的**
(`GetClientRect` = 1920x1080), 客户区坐标 = 屏幕坐标; 只有 800x600 那块面板会被
引擎 blit 上屏。

- `0x622396` 里 `[esp+0x10]` 拿到的是主窗口不是对话框。认对话框只能靠"有没有我们的
  列表控件": 枚举 `#32770` → `GetDlgItem(h, 1317/1319)`。没对话框时这个钩点仍每帧进,
  枚举要节流 (200ms)。
- **改模板 cx/cy 不生效**: 引擎按自己的尺寸摆控件、也按自己的尺寸 blit 面板。
- 面板内可用空间: 列表原宽 380, 右边到面板右缘还有 280px, 下面还有 170px。

### 4.1 排版 (SS_Layout)

全部按实测算, 不写死坐标:

```
panel  = MapDialogRect(hDlg, {0,0,533,369})   // 800x600
panelX = (clientW - panelW) / 2, panelY = (clientH - panelH) / 2
listX  = panelX + 12
sbW    = 列表右侧那个独立滚动条子窗口的宽度 (id=0, 通常 20px, 找不到算 0)
colW   = PreviewWidth (默认 200, 夹 120~420, 且给列表至少留 380)
listW  = 面板右缘 - pad - sbW - colW - listX
         → 不缩只长; 挤不下就 colW=0 (只加宽列表, 不画截图框)
```

- **滚动条是独立子窗口** (id=0, 紧贴列表右缘、同高同顶)。`MoveWindow` 列表不会带着
  它走, 不挪就会压到截图列上。
- **高度拉到面板底**。列表下方若压着可见小控件 (存档名输入框, 高 <60), 把它推到面板
  底部、列表停在它上面 8px。不可见的同名控件不算障碍。
- 左缘对齐、贴在列表下沿的子窗口 (那个输入框) 跟着平移 + 加宽, 但右缘不越过
  `band.left - pad`, 否则主按钮会压在它上面。
- 标题 `1036` 跟列表同左缘同宽。主按钮从模板位置 (425,122) 挪到底部那条带, 与输入框
  垂直居中: `[存档名输入框......][储存]`。
- 引擎偶尔会把控件摆回去, `SS_LayoutDrift` 检查列表矩形/面板尺寸, 不对就重排
  (每个对话框最多 3 次, 防互抢)。

### 4.2 日期列为什么是截断的

引擎画行时把列位置写死: 日期列约 `+147px`、宽只有 ~55px (放不下 `2026-10-30`,
画成 `2026...`)。加宽列表只会在右边多出空白 ⇒ 只能整块接管绘制 (4.3)。

### 4.3 行重绘: 控件不画, 我们在 present 前画

```
引擎把面板画进临时面 → 0x622396 (present 前最后一跳, 我们在这画) → 上屏
                    → 之后 Windows 才异步派发子窗口 WM_PAINT (控件的 GDI 像素)
```

控件自画会晚于我们 (两套文字, 滚动时死图不动); 让控件赶在 blit 前画又会被整块盖掉
(文字只闪一瞬)。所以**控件一个像素都不画**:

```c
SS_ListProc:  WM_PAINT      -> BeginPaint/EndPaint (只为让刷新区失效) + SS_RequestPanel
              WM_ERASEBKGND -> 1
              WM_NCDESTROY  -> 还原原 proc
              其它          -> CallWindowProc (点击/滚轮/键盘/滚动条一概不变)
SS_DrawRows(surf, list) : 0x622396 里画整块列表客户区
```

**字体跟随 `[VecText]`**: `VecText_ResolvedPx()` / `VecText_FontFace()` /
`VecText_Bold()`, 与标题、按钮同源 (msyh + FontPx)。

- 槽位用主字号槽 **2**: 与 VecText 同参, 不会互拆重建。
- 画法同 VecText: `RenderLine` 出覆盖率 → `BlitCoverage` 混进 16 位面。
  不用 `DrawTextW`: 那是另一套度量, 会和标题不同源。
- **行距按墨迹**, 不能用字体 cell (`g_G->adv`, msyh 的含 ~6px leading, 排出来空
  8~10px): `SS_MeasureInk` 渲染一次 `国Gg` 扫 DIB 得 `inkH/inkTop` (同字号只量一次),
  `LB_SETITEMHEIGHT = inkH + SS_ROW_GAP(3)`, 绘制
  `y = 行顶 + (rh-inkH)/2 - inkTop`。行高每个控件只设一次 (`s_RhList`), 每帧设会让
  控件反复重排。
- 行区域从 `y0 + 2 + SS_ROW_PAD(3)` 起算, 否则首行墨迹压在上边框上。
- 字体拿不到也要照画底色/边框: 控件已不画, 直接 return 会露出面板原像素。

```
FileEntry*  = LB_GETITEMDATA(i)                     // 引擎存的就是它
档名        = FileEntry + 0x000  (wchar_t[0x80])
文件名      = FileEntry + 0x100  (char[0x20], 相对游戏根或只有名字)
时间        = FileEntry + 0x1AC  (FILETIME → Local → System → "YYYY-MM-DD HH:MM:SS")
valid/wrong = +0x1B4 / +0x1B5   (假/版本不符的行画灰)
```

- 左 = 档名 (按剩余宽度截断), 右 = 完整时间右对齐; 色 (239,235,239) / 时间
  (214,210,218) / 假档 (128,126,134), 选中底 (123,32,123)。
- **外框**: 面板美术里那圈 2px 灰边 (123,121,123, 与输入框同色) 随列表变高后对不上
  原图, 由 `SS_DrawRows` 自己画。
- **刷新**: 控件的 `WM_PAINT` 比 `LB_GETCURSEL/LB_GETTOPINDEX` 与面板上次画的
  (`s_DrawnCur/s_DrawnTop`), 不同就 `InvalidateRect(对话框)` → 重画面板 → 0x622396
  → 按新滚动位置重画 + 换截图。30ms 节流。

### 4.4 两个截图框

| 位置 | 内容 |
|---|---|
| 上 (`s_ImgA`) | **当前画面** —— 缓存 `s_Pix` 现缩放, 不读文件 |
| 下 (`s_ImgB`) | 列表**选中那一档**已存的 `Thumbs\*.bmp`; 换选择才重读 |

- 双线性缩放到框内, 等比居中, 各带分配上限 (换尺寸才重分配)。
- 色调按引擎位宽重新打包 (`g_GBits==6` 走 565, 否则 555)。
- 框内有深底 + 1px 边; 没图时画 `无截图`。
- **框高 = 图高 + 2** (上下各留 1px 边框): 图片是等比 fit, 框比图高就上下留黑边。
  排版先按视口比例 (`s_PixW/s_PixH`, 没有就问 `SB_RawView`) 算
  `imgH = (colW-2)*vh/vw`; 两框 + 两标题塞不进列表高度时才等比缩。
- 标题 (`当前画面`/`存档截图`) 与 `无截图` 都走 `SS_PutTextLine`, 同一 `[VecText]`
  字号 (`s_CapH = px + 6`)。

## 5. 载入 / 删除: 三个页面是一套代码

模板 183/692/693 各只有一个按钮 (1039/1735/1736), 界面是同一个屏幕类建的:

```
0x558DD0  屏幕状态机 (this+0x04 = 页面: 1 读档 / 2 存档 / 3 删除,
                      this+0x18 = 动作: -1 空闲, 1 本页按钮, 0x40F 载入, 2 返回)
  ├ 建对话框: 0x622650(ecx=模板id, edx=DlgProc)
  │   183 -> 0x558a30   692 -> 0x558b90   693 -> 0x558cb0
  └ 每帧看 this+0x18: 非 -1 就 GETCURSEL/GETITEMDATA 再按页面执行
      页面1 -> 0x5594AE  读档 (跳过 +0x1B5 版本不符, 用 +0x100 文件名,
                                call vtable[1] = 0x559D60)
      页面2 -> 0x5591A6  存档
      页面3 -> 0x559095  删除
```

`vtable[1] = 0x559D60` (屏幕对象 vtable 在 `0x7ED2E4`, 它**不用 this**) 才是真读档:

```
0x559D60(name):
  esi = [0x887640]->vtable[0x28]()   // 当前屏幕栈深度
  edi = 0x623230(模板 0x41C)          // 建"载入中"对话框
  [0x887640]->vtable[0x0C]()          // pop 一层
  0x622800(edi); ScenarioStarted=0;  0xA8E378=0; 0x69BB40();
  bl = 0x67E440(name)                 // LoadGame, 重建地图 surface
  while (深度 < esi) vtable[0x10]()
  while (深度 > esi) vtable[0x0C]()
  0x622720(edi)                       // 销毁载入框
```

它**不销毁**存读档对话框: 那一步在 0x5594AE 返回后做。所以读档全程旧对话框还活着,
这期间的任何重绘都会踩到已释放的 UI 资源 (见 5.2)。

三个 DlgProc 都通过 `GetWindowLong(dlg, DWLP_USER)` 拿 `ctx`, 只往 `ctx+0x18` 写动作
码 —— 和状态机读的是同一字段, 所以 ctx 就是那个屏幕对象。

**空闲动作是 -1 不是 0**: 状态机建完对话框写 -1 (0x558F9F), 主循环拿 -1 当"继续跑"。
动作分派 (0x559030) **只按页面**决定干什么, 动作值只过"是不是本页按钮"那道门
(1 / 0x40F / 0x6C7 / 0x6C8) ⇒ 点载入必须**同时**写 `页面=1` + `动作=0x40F`,
只写动作会在存档页上执行一次**存档**, 覆盖用户档。所以写之前要核对
`ctx+4 == 2 && ctx+0x18 == -1`, 对不上就当没点。

### 5.1 两个按钮: 引擎原生美术

自建按钮进不了引擎的自绘表, 只能像素复刻渐变 —— 一眼是假的。正确做法照抄战役结算页
的"退出游戏"按钮 (`VecText.cpp: VecScoreDlgEntry`), 关键是**时机**:

```c
0x558B90 = 存档页 DlgProc (stdcall, ret 0x10), 前 5 字节 53 8B 5C 24 10 (无 rel32)
  -> 换成 SS_SaveDlgProc (跳板回原过程)
  WM_INITDIALOG:
    1) CreateWindowExW(0, L"Button", L"GUI:Load", WS_CHILD|WS_VISIBLE|BS_OWNERDRAW, ...)
       **必须在调原过程之前** —— 引擎的 WM_INITDIALOG 会遍历子控件, 给自绘按钮挂
       0x610CA0 子类并注册进 0xAC1B00 表; 只有进了那张表才用原版美术画。事后建的
       按钮永远进不去。
       文本必须是 CSF 键不是字面量: 引擎把窗口文本当键查 StringTable, 查不到就显示
       MISSING:<ANSI 字节>。用 `GUI:Load` / `GUI:Delete` (同族 `GUI:Save` = 储存)。
       初始坐标给 -2000,-2000, 位置等 SS_Layout 摆。
    2) 调原 DlgProc
    3) 从"储存"(1735) 的 ownerdraw 元素复制 +0xB0 (按钮底图 band) 与字体给新按钮。
  点击就是普通 WM_COMMAND(BN_CLICKED), id 0x540 载入 / 0x541 删除。
```

- **不能换 `GWLP_WNDPROC`** (会把对话框管理器拆掉); patch DlgProc 函数头是另一回事,
  因为里面原样调回原过程。
- `SS_Layout` 里两个"挪小控件"的循环必须 `continue` 掉 `s_HWndLoad/s_HWndDel`,
  否则我们自己的按钮会被当成存档名输入框挪走。
- 0xAC1B00 是 HWND → ownerdraw 元素表, 表项 `{ HWND, elem, ..., next@+0x204 }`。

### 5.2 自绘按钮的崩溃与守卫

`0x6071E0` (给某个 HWND 画自绘按钮) 一进门就假定 UI 主题资源 `[0xB0FC14..0x2C]`
非空 (`0x607369` 读 `[0xB0FC20]` 直接解引用)。`LoadGame` 会把这组资源释放并置 0,
而旧对话框还可见, 之后任意一次 `WM_PAINT` 都会在 `0x607372` 空指针崩溃。

**别靠隐藏窗口躲**: 外层收尾依赖状态机正常销毁那个对话框, 藏起来会让读档完成后停在
设置页、鼠标消失。界面保持原样, 崩溃交给守卫:

- 0x6071E0 前 6 字节 `81 EC 8C 01 00 00` (无 rel32) 换成 `SS_BtnDrawGuard`;
- `s_Loading` 期间整函数跳过 (读档这一程不需要任何按钮); 平时只在主题指针真的为空时
  拦 (那本来就是必崩前兆)。

### 5.3 载入完成后按"真载入"收尾

ESC 菜单命令分派 `0x4F1330` 把两条路分得很开:

```
0x51E 载入 (0x4F1348): ShowWindow(菜单, SW_HIDE) → 0x5587F0 (页面=1) →
      **看返回值** al!=0 → [ebp]=0x51e 后直接 ret (不显示菜单/不 UpdateWindow)
0x51F 存档 (0x4F13BD): ShowWindow(菜单, SW_HIDE) → 0x558810 (页面=2) →
      **不看返回值** → 0x4F14B3 析构 → 0x4F14BA 0x4F1720 →
      落 0x4F14BF: ShowWindow(菜单, SW_SHOW) + UpdateWindow(菜单)
```

从存档页发起读档, 外层永远走**存档**分支 ⇒ 世界换成新档、菜单又被显示出来, 表现为
"停在设置页, 鼠标消失, 要盲点才回游戏"。

修法: 在 `0x4F14BF` (5 字节 `6A 05 56 FF D7`, 无 rel) 挂桩, `s_TailLoad` 为真时照
0x4F1389 做: `[ebp]=0x51e` + `xor eax,eax` + pop edi/esi/ebp/ebx +
`add esp,0x614` + `ret 0x10`, 跳过 ShowWindow/UpdateWindow; 否则原样
`push 5; push esi; call edi` 再跳回 `0x4F14C4`。

`ebp` = `GetWindowLongA(hDlg, DWLP_USER=8)` (`0x4F12B1`), 即屏幕对象 —— 真载入也写
它第一个 DWORD。标志在 `WM_NCDESTROY` 里校验: `ctx+0x18` 仍是 `0x40F` 才留
(0x5594AE 结尾就拿它当返回值), 否则当取消/失败清掉。

**触发前 `SS_Detach` + 立 `s_Loading`**: 读档会重建整个世界 (surface / FileEntry /
控件全作废), 之后再碰旧控件、往面板画旧列表都是野指针。

### 5.4 删除

照 0x559095 自己干 (`DeleteFileA` + `LB_DELETESTRING`), 人留在存档页; 走引擎删除页
会被弹到别的页面。不可逆, 第一下只"上膛" (4 秒超时), 第二下才真删。

### 5.5 按钮动态文字

按钮文字**只在初始化时**从窗口文本走一遍 CSF (`0x6102EA` → `0x734E60` →
`0x623560` 存进对象字段, 自己 malloc 的宽串副本)。**绘制 0x6071E0 既不查 CSF 也不读
窗口文本**, 直接读那份副本 ⇒ `SetWindowTextW` 永远改不动字。

所以:

- 打开对话框时用"储存"按钮反查 (`SS_ProbeTextOff`): 扫元素 `+0x04..+0x200` 的每个
  DWORD, 找指向 `L"储存"` 的指针 → `s_TxtOff` (实测 0x40)。探不到就不改字。
- 换字 `SS_SetBtnText`: 必须用**引擎自己的 malloc `0x7C8E17`** 分一块新的再改字段,
  因为按钮销毁时引擎会 `free` 这个字段 —— 指到 DLL 里的静态宽串就是崩溃。旧块直接
  泄漏 (几十字节, 换零崩溃风险)。
- 上膛时换成 `L"确认删除"`, 4 秒落回 `L"删除"`, 只在状态变化时设。

CSF 里现成的空串键: `GUI:Blank` / `TXT_NONE` —— 想要"有美术没文字"时用。

## 6. 已知取舍

- 老存档没有 bmp ⇒ 下框显示"无截图"; 重新存一次就好。
- 行绘制是硬替换: 控件不再画任何像素, 引擎以后在行里加图标/换主题我们都不会画。
- 删除存档时 `Thumbs` 里的 bmp 会一并删; 但被外部删掉的档留下孤儿 bmp, 不做清理。
- 列表项若不再存 `FileEntry*` 到 item data, 预览会整块消失 (安全失败, 不崩)。
- ESC 菜单 GUI 页没有这个开关, 只有 ini。
