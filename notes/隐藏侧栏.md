# 隐藏原版建造侧栏 (FullMap)

目标: 关掉原版建造/生产侧栏 (页签 + cameo + 电力条), 地图铺满整个窗口宽度,
小地图 + 顶部两个按钮留在原来那一角 (苏联=右上, 盟军=左上) 且**可点击**。

代码: `src/GUI/FullMap.h` / `src/GUI/FullMap.cpp`, ini 节 `[FullMap]`。
构建: `MOExperienceDev` 下 `cmd /c build-full.bat` (产物自动部署到 `G:\motest`)。

## 二、为什么不能"只关掉面板"

`TabClass::Draw` (`0x6D0A20`) 每帧往**同一块**侧栏面依次画:
背景 PCX → **小地图** (`RadarClass`) → `SidebarClass::Draw` (页签/维修按钮 +
cameo + 电力条) → `BlitSidebar` (`0x6A70E0`) 整条 blit 上屏。

`MouseClass/TabClass/SidebarClass/PowerClass/RadarClass/DisplayClass/MapClass`
是**同一个单例** `0x87F7E8`。所以"跳过面板那步"会连小地图一起丢, 必须连
整条 blit 一起接管。

上屏顺序 (实测 `0x7776E0`): `UpdatePrimarySurface(Composite)` → `BlitSidebar`,
**侧栏在地图之后**, 接管 blit 不与地图抢。另一条路 (`[0xA8ED5C] != 1`) 走
Hidden 面, 不 blit 侧栏。

字节补丁 (见 §4) 在 `FM_Install` 里装。

## 四、字节补丁: 让视口和渲染面都变全宽

### 4.1 视口矩形 `0x72AD20` (纯函数, 只有 mov/xor/sub)

`0x72AD20` 输出 `{ X: (非NOD且非末日)?168:0, Y:0, W:客户宽-168, H:客户高-32 }`。
两个 `CreateAll` 调用点 (`0x560F9C` / `0x67E776`) 用它建面, `Set_View_Dimensions`
(`0x4A8960`) 用它做入参 ⇒ 改这一个函数, 面和视口一起变全宽。

| 地址 | 原指令 | 改成 |
|---|---|---|
| `0x72AD69` | `sub edx,0xA8` 的 imm32 (`A8 00 00`) | `00 00 00` |
| `0x72AD60` | `B9 A8 00 00 00` (`mov ecx,0xA8`) | 5x `90` |

### 4.2 ★ `CreateAll` 有第三个调用点, 不走 `0x72AD20`

`GScreenClass::CreateAll` (`0x533FD0`) 全仓只有三个 `call`:

| 调用点 | arg1.Width 来源 |
|---|---|
| `0x56100E` | `0x72AD20` 的输出 → 跟着补丁变全宽 |
| `0x67E7EA` | 同上 (形状一样) |
| **`0x6BDE14`** | **自己算, 完全不碰 `0x72AD20`** ← **新开一局走这条** |

```
0x6BDDAC: mov edx,[0x7F5BF8]      ; edx = 168
0x6BDDC4: mov eax,[0x886FB8]      ; eax = WindowBounds.Width
0x6BDDC8: sub eax,edx             ; W = Width-168   ★★ Composite 宽度来源
0x6BDDD7: mov [ebp-0x7A4],eax     ; CreateAll 的 arg1.Width
```

`CreateAll` 内部: `[ebp+8]/[ebp+0xC]`(=WindowBounds.W/H) 建 Hidden
(`[0x88730C]`); `edi`(=arg1) 的 `+8/+C` 建 **Composite** (`[0x88731C]`)。

⇒ 不改这里 Composite 恒为 `Width-168 = 1752`, 视口被安全阀夹到 1752,
右边 168px 无人绘制 = **黑底**。而**读档不重跑这条**, 所以读档看着正常。

**修法**: `0x6BDDC8` 的 `2B C2` → `90 90` (nop nop)。
`edx` 在这条之后已无用途 (侧栏矩形在 `0x6BDDB2` 就写好了), 所以不影响侧栏面。

### 4.3 ★★ 五处"侧栏横向偏移"取数改指 `SidebarBounds.X`

全二进制有 5 处把 `ViewBounds.Width` (`[0x886FA8]`) 当横向偏移用, 全部把
imm32 改成 `0x886F90`:

| 地址 | 指令 | 用途 |
|---|---|---|
| `0x478BD7` | `mov eax,[..]` imm@+1 | 鼠标钳制 / 侧栏路由 |
| `0x65386B` | `mov edx,[..]` imm@+2 | 顶部按钮光标形状区命中 |
| `0x654332` | `mov ecx,[..]` imm@+2 | **三个 radar gadget 的摆放 X** |
| `0x653A3F` | `mov ebx,[..]` imm@+2 | `RadarClass::Action` 鼠标换算 |
| `0x6D06C7` | `mov edi,[..]` imm@+2 | 侧栏顶部一簇光标判定 |

`0x653D92` (`ViewW/9`) **刻意不改** —— 原版 1752/9=194 已远大于地图宽, 等价。

`0x654320` 是三个 gadget 摆放位置的**唯一**计算点, 只在
`DisplayClass::InitGUI` (`0x6ABD30` → `0x6403A0` → `0x6ABD39`) 跑一次:
```
0x65432D: mov al,[0xA8EB7C]                  ; isNODSidebar
0x654332: mov ecx,[0x886FA8]  ★★ 偏移 = isNOD ? ViewBounds.Width : 0
0x65434F: SetPosition(0xB04978, [0xB04A00]+esi, [0xB04A04])   ; 按钮 A
0x654379: SetPosition(0xB04910, [0xB048C8]+esi, [0xB048CC])   ; 按钮 B
0x6543A3: SetPosition(0xB04A10, RadarClass+0x11F0 + esi, …)    ; 雷达 gadget
```
**只在开局算一次**, 所以运行时改 gadget 矩形撑不过下一次 InitGUI —— 改 imm32
才是唯一正确的修法。

### 4.4 ★★ `SidebarBounds.X` 的真实语义 = 视口矩形右边界

```
0x6A519B: call 0x72AD90                    ; 得到矩形 (与 0x72AD20 同形, 只是基址不同)
0x6A51AB: lea ebx,[edx+eax]                ; ebx = rect.W + rect.X
0x6A51C0: mov [0x886F90], ebx              ; SidebarBounds.X = 视口矩形右边界
```

`0x72AD90` 是 `0x72AD20` 的**孪生函数** (只差基址 `[0xA8EB84]/[0xA8EB88]`
vs `[0x886FB4]/[0x886FBC]`)。保持**不补丁**时 NOD 侧算出 `0 + (1920-168) = 1752`,
正好是侧栏列起点 —— **这个值本来是对的**, 是我们的 `FM_Poll` 早退让它没机会被纠正。
**不要去补 `0x72AD90`** (补了 W 变 1920, 右边界更错)。

`FM_Poll` / InitGUI 钩每帧纠正:
```
苏联 (isNOD=1): SidebarBounds.X = 视口右边界 - 168
盟军 (isNOD=0): SidebarBounds.X = 视口左边界 (=0)
```

## 五、点击链路 (全部已反汇编核实)

### 5.1 `GadgetClass` 虚表真实布局 (vtable `0x7F02BC`)

```
+0x04 GetNext  +0x08 GetPrev  +0x24 Remove
+0x28 Input(0x4E1640)  +0x2C DrawAll  +0x34 ExtractGadget  +0x38 MarkListToRedraw
+0x3C Disable  +0x40 Enable  +0x44 GetID  +0x48 MarkRedraw  +0x4C PeerToPeer
+0x50 SetFocus +0x54 KillFocus +0x58 IsFocused +0x5C IsListToRedraw +0x60 IsToRedraw
+0x64 SetPosition +0x68 SetDimension +0x6C Draw +0x70 OnMouseEnter +0x74 OnMouseLeave
+0x78 StickyProcess
+0x7C ★ Action(Flags,pKey,Modifier)   +0x80 Clicked(pKey,Flags,X,Y,Mod)
```
`GadgetClass::Clicked` (`0x4E13F0`) 尾段就是 `call [edx+0x7C]` (`0x4E1440`),
所以 `Action` 只能由 `Clicked` 触发。`Input` 是"根 gadget"的分发器:
`ExtractGadgetAt` → 命中者 `Clicked`。

### 5.2 `ExtractGadgetAt` (`0x4E15A0`) 的胜负规则

```
if (this->Disabled(+0x1E)) skip;
X=+0x0C Y=+0x10 W=+0x14 H=+0x18 直接当屏幕坐标比;
if (W*H(本次) > W*H(当前最佳)) skip;      ← ★ 面积小的才赢, 不是"最靠前"
沿 GetPrev 走到 NULL
```

**实测整条链只有一个节点** (`0x8A06F8` 视图容器 gadget, `GetPrev` 是 NULL)。
所以三个 radar gadget / 页签 / cameo **都不在这条链上**, `ExtractGadgetAt` 永远
返回视图容器。顶部按钮的原生响应走 `0x6D0680` 的 widget 分派 (ID 0xF2/0xF3),
不靠 gadget 命中。

### 5.3 三个 radar gadget

| 对象 | 地址 | 虚表 | 备注 |
|---|---|---|---|
| 雷达 gadget 本体 | `0xB04A10` | `0x7F02BC` | `Action` = `+0x7C` = `0x6539D0`, 构造 `0x652870` |
| 顶部按钮 A | `0xB04978` | ShapeButton | 构造 `0x69DCF0`, ID `[+0x24]=0xF2` |
| 顶部按钮 B | `0xB04910` | ShapeButton | ID `[+0x24]=0xF3` |

按钮 A/B 的宽高实测是 `0x0` —— 引擎从来没给它们 `SetDimension`, 所以它们
本来也不可能被 `ExtractGadgetAt` 命中。

### 5.4 `RadarClass::Action` (`0x6539D0`) 是**死代码**

它里面确实有"点雷达跳视口" (`0x653AB7 GetCoordsOnRadar` → `0x6D6070` 视口滚动),
但两处让它永远走不到:
1. `[0x880C94]` / `[0x880C98]`: 全二进制 (gamemd + Ares.dll) **只有读、没有写**,
   `.data` 初值 0 → 入口的 `cmp eax,1 / jne` 恒 bail。
2. 雷达 gadget `0xB04A10` 构造时宽高都是 0, `SetDimension` 无调用点。

⇒ **原版 RA2 的这条小地图点击链也是死的**。玩家看到的小地图跳转另有一条路
(`0x692F30` 里 `if (MouseCursorIsMini) → 0x4AC380`)。所以必须 MOE 侧自己接。

### 5.5 点击是**并行**的两条路, 没有"路由"

`DisplayClass::ProcessClick` (`0x6922E0`):
```
0x6922E3: call 0x692F30        ; 地图侧 (MouseCursorIsMini 分支 + 0x692300 ProcessClickCoords)
0x6922F4: call 0x6D0680        ; 侧栏 widget 分派, 末尾无条件 fall-through 到 0x6A7780
```
所以"点一下同时对主地图生效"是**天生**的, 不存在可以改的路由点。我们只在
`ProcessClickCoords` 里吞。

### 5.6 点击门的实现要点

落点 `0x692406` (Syringe 钩 6 字节), 返回 `0x6925FC` = 原函数"未处理"出口
(`pop edi/esi/ebp / xor al,al / pop ebx / add esp,0x18 / ret 0x18`), 跳回 `0x69240C`。

* **门里直接读 `GetAsyncKeyState(VK_LBUTTON)`** + "本次按下已处理"标记 (松开时清)。
  ★ 不要用 `FM_Poll` 采的"按下沿": `0x4F42F0` 一帧能被调好几次, 点击事件与 prepare
  的先后不可控, 边沿可能在 press 事件**之后**才被采到, 门永远错过按下那一帧。
* 命中范围是**整块保留区** (资金条 + 小地图 + 两个按钮), 这一块是我们画的 UI,
  点它不该动地图。命中就返回"吞没"。
* 只有**小地图本体**才做视口跳转; 点按钮/资金条只吞不跳。
* 视口滚动用 `RadarClass::ScrollTo` (`0x653F70`) —— 三条指令的包装:
  ```
  0x653F70: mov eax,[esp+4] / mov ecx,[0x887324] / push eax / call 0x6D6070 / ret 4
  ```
  `this` 完全不用, 可以安全 `fn(NULL, &coord)`。`0x6D6070`
  = `TacticalClass::SetTacticalPosition`: 取 coord 的格减半个视口, 越界夹回,
  写视口原点与平滑目标, 置 Redrawing。**纯本地摄像机, 联机安全。**

### 5.7 地图格范围 = 只读扫描 `TacticalClass`

`Fm_ScanTacticalMapRect`: 在 `TacticalClass + 0x0E0..0x200` 逐 4 字节找矩形,
两条判据筛: (1) 宽高像地图尺寸 (16..512 格, X/Y 在 -64..512);
(2) 可见区格坐标 `[0x880C84..90]` 必须落在里面 —— 两种语义都试
(`{minX,minY,maxX,maxY}` 与 `{X,Y,W,H}`)。命中即锁定。

★ **不要钩 `MapClass::CreateEmptyMap` (0x653F50)** —— 试了两次都在"我们的代码
跑完、跳板返回之后"崩, 逐条核对过落点/跳板/栈收支都对, 定位不到就弃用了。
为一个矩形去钩引擎内部函数, 收益/风险比太差。优先只读路径。

## 六、两个曾经踩过的坑 (保留, 都很贵)

### 6.1 ★ "不减" 不能写成"归零" (v0.2.170崩)

`0x6BDDC8` 的 `2B C2` (`sub eax,edx`) 被我改成 `2B C0` (`sub eax,eax`) ——
**错, 新游戏必崩**。语义完全相反: 那不是"Width-0", 那是 **eax = 0**。

后果链:
```
eax=0 → CreateAll 里 `mov eax,[esi+8]; test eax,eax; jle` 全跳过
      → [0x88731C] 与 [0x8872FC] 两个面都没建, 保持 NULL
      → 引擎 0x6D40FF `mov edx,[0x8872FC]` 拿到 0
      → 0x6D410D `mov edx,[edx]` 空指针读 → 0xC0000005
```
**"让某条 `sub` 不生效"唯一正确的写法是 nop。**
字节补丁只认**逐位语义**, 不认"看起来是等价变换"; 写完必须反汇编核对落地字节。

### 6.2 ★ `PatchAt` 的落点必须是"整条指令长度之和 == n"的窗口

`PatchAt` 强制 `n >= 5`。踩过的坑: 看到函数入口首 4 字节就以为能抢 5B ——
结果把下一条 4 字节指令劈两半, 跳板回到指令中间, 开机第一次就崩。

**不能假设"指令首字节 = 指令长度"** (`A1 disp32` 是 1 字节 opcode;
`8B 44 24 10` 本身是完整的 4 字节指令)。必须反汇编核对。

配套: `BytesSame` 的 `n` 必须等于数组长度, 否则钩子静默不装, 日志只有一行
`bytes mismatch`。

### 6.3 崩溃捕获: 用向量异常处理器, 别用 `SetUnhandledExceptionFilter`

`MOExperience.cpp` 的 `Moe_CrashFilter` 用 `AddVectoredExceptionHandler`。
`SetUnhandledExceptionFilter` 会被后加载的模块 (YRPP / Ares / 游戏自己)
随手覆盖掉 —— 实测装上它之后崩溃仍然没有 `CRASH:` 行。向量处理器在**所有**
异常上最先被调用, 且不可被覆盖。

只对致命异常动手 (读/写违规、非法指令、除零、栈溢出), 其余放行; 命中后照旧
`EXCEPTION_CONTINUE_SEARCH`, 不改控制流, 只是把现场 (故障地址 / 读写位 /
寄存器 / 故障点前后 8 字节 / 所在模块) 打进日志。

## 七、已知副作用 / 限制

- 原版建造栏彻底不可用 (下单位走超武侧栏 `[SWSidebar]` 或热键)。
- MOE 底部电量画在侧栏面上, 侧栏不整条呈现后它也不显示, 属预期。
- `GadgetClass::Disabled` 是合法置位不是摘链, 引擎后续再 `Enable` 是正常行为,
  下一轮 `FM_Poll` 重新置位。
- **联机安全**: 只写 `ViewBounds` / `view_bound` / `SidebarBounds` / 渲染面 /
  gadget 标志 / 本地摄像机, 全是本地渲染与输入状态, 每个客户端按自己的窗口
  尺寸算, 不碰任何模拟内存, 不发事件。

## 八、开关

```ini
[FullMap]
Enable=1                  ; 总开关
WidenView=1               ; 1=视口撑满宽
WidenSurface=1            ; 打 §4 的字节补丁; 0=只隐藏面板, 右侧留 168px
KeepRadar=1               ; 1=保留小地图
TrimViewGadget=1          ; 收窄视口 gadget 的命中区
DisableSidebarButtons=1   ; 摘页签/cameo
RadarClick=1              ; 小地图点击跳视口 + 吞穿透
InitGuiFix=1              ; InitGUI 入口纠正 SidebarBounds.X
ExtraH=5                ; 保留块比 SidebarBounds.Y 再多露几像素
```

安全阀: 视口宽度超过 Composite 实际宽度时**夹窄**视口并同步
`TacticalClass::view_bound` (`push &ViewBounds / call 0x6D5F60`, ecx=Tactical),
照抄引擎 `Set_View_Dimensions` 的做法。夹而不是 skip —— 视口比面宽时引擎照旧
往面外画, 那就是花屏的直接原因。
