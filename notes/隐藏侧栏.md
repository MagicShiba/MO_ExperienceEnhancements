# 隐藏原版建造侧栏 (FullMap)

目标: 关掉《心灵终结》原版右侧/左侧的建造·生产侧栏 (页签 + cameo + 电力条),
地图铺满整个窗口宽度, 小地图仍留在原来那一角 (苏联=右上, 盟军=左上)。

代码: `src/GUI/FullMap.h` / `src/GUI/FullMap.cpp`, ini 节 `[FullMap]`。

---

## 为什么不能"只关掉面板"

`TabClass::Draw` (`0x6D0A20`) 每帧往**同一块**离屏面
`DSurface::Sidebar` (`0x887300`) 里依次画:

| 步骤 | 地址 | 内容 |
|---|---|---|
| 1 | `0x6D0B68` | 侧栏背景 PCX |
| 2 | `0x4A2370` → `0x6D0E60` | **小地图** (RadarClass) |
| 3 | `0x6A6C30` | `SidebarClass::Draw`: 页签/滚动/维修按钮 + `StripClass::Draw` cameo + `PowerClass::DrawIt` |
| 4 | `0x6A70E0` | `BlitSidebar`: 整条 blit 到 `DSurface::Primary` (`0x887308`) |

而 `MouseClass/TabClass/SidebarClass/PowerClass/RadarClass/DisplayClass/MapClass`
是**同一个单例对象** `0x87F7E8` (vtable `0x7E1964`, `0x40D1B2` 安装)。
所以"跳过第 3 步"会连第 2 步的小地图一起丢掉, 必须连第 4 步一起接管。

## 实现要点

1. **撑视口** (`FM_Poll`, 每循环走 prepare 钩 `0x4F42F0`)
   `ViewBounds.Width = 客户宽 - 小地图宽 - 小地图面内X`, `ViewBounds.X = 0`。
   写完必须调 `0x6D5F60(&ViewBounds)` (`ECX = TacticalClass`), 否则
   `TacticalClass::view_bound` (`0xB0CE28`) 还是旧宽度 —— 摄像机钳制和
   `DisplayClass::ClientToCoords` (`0x6D2280`) 都读它, 右侧地图会点不动。
   这正是引擎 `DisplayClass::Set_View_Dimensions` (`0x4A8960`) 做的事, 照抄。

2. **接管上屏** (`FM_BlitSb`, 挂在 `BlitSidebar` `0x6A70E0`)
   原版 blit 的目标 `X = 客户区屏幕原点X + (isNOD ? ViewBounds.Width : 0)`,
   `Y = 客户区屏幕原点Y + 源矩形Y`, 即侧栏面内坐标与屏上 1:1 平移。
   撑宽之后:
   `屏上小地图X = 原点X + ViewBounds.Width + 面内X = 原点X + 客户宽 - 小地图宽`
   正好贴边。于是只 blit `DSurface::Sidebar` 的小地图那一小块
   (`CopyFromPart`, DSurface 虚表槽 `0x08`, 参数形如原版: `(&dst, src, &srcRect, 0, 1)`),
   原版那条整条 blit 完全不跑。返回 1 时 `MOExperience_BlitSbEntry` 按
   `pop 返回地址 / push 回去 / ret 4` 收尾, 并补齐原版尾声的三个脏标记。

3. **摘 gadget** (`Fm_DisarmSidebarGadgets`)
   撑宽后原来的侧栏按钮屏幕坐标会压在地图上抢点击。`GadgetClass` 的
   `Disabled` 在 `+0x1E` (`GadgetClass::Disable` = `0x4E1460` 写的同一个字节),
   命中与输入都会跳过。逐帧置位, 因为引擎切页/改视口会把按钮重新 `Enable`。
   候选来源: cameo 数组 `0xB07E80` (240 × `0x38`)、页签数组 `0xB07C48`
   (4 × `0x60`), 再按 dword 扫 `0xB07C40..0xB07E7C` 与 `0xB0B300..0xB0B51C`
   两段 (覆盖 `0x6ABD30 InitGUI` / `0x6A6C30 Draw` 里出现的全部静态 gadget
   指针), 非 gadget 由"指针范围 + 虚表范围 + 矩形合法 + 必须落在侧栏列内"
   四道校验挡掉。

## 已知副作用 / 限制

- 原版建造栏彻底不可用 (下单位走超武侧栏 `[SWSidebar]` 或热键)。
- MOE 的底部电量 (`PowerDisplay_DrawSb`) 画在侧栏面上, 侧栏面不整条呈现后
  它也不会显示, 属于预期。
- `GadgetClass::Disabled` 是在引擎 gadget 列表里"合法置位", 不是摘链, 所以
  引擎自己后续再 `Enable` 是正常行为, 下一轮 `FM_Poll` 会重新置位。
- 联机安全: 只写 `ViewBounds` / `view_bound` / `SidebarBounds` / 渲染面 /
  gadget 标志, 全是本地渲染与输入状态, 每个客户端按自己的窗口尺寸算, 不碰
  任何模拟内存, 不发事件。
- 调试开关全在 `[FullMap]`: `Enable` / `WidenView` / `KeepRadar` / `DisableSidebarButtons` (可分项开, 崩了就能二分到是哪一步)。
  任一前置校验不过 (客户宽读不到、小地图矩形还没初始化) 就静默不生效,
  原版 blit 照跑, 日志里打一行 `fullmap: ...` 便于对拍。
## 最终做法 (可用)

### 1. 视口变全宽: 改 ``0x72AD20``, 不碰建面
``0x72AD20`` 是纯函数, 输出 ``out = { X: (非NOD且非末日)?168:0, Y:0,
W:客户宽-168, H:客户高-32 }``。而 **``DSurface::Composite`` 的建面矩形与
``DisplayClass::Set_View_Dimensions`` 的入参都是它的输出** (``0x560F9C`` /
``0x67E776`` 两处 call), 所以改这一个函数, 面和视口自动一起全宽, 不用钩子、
不用跳板、不用新分配, ``view_bound`` 也由引擎自己同步。

两处等长字节补丁 (``FM_Install``):

| 地址 | 原字节 | 改成 |
|---|---|---|
| ``0x72AD69`` | ``sub edx,0xA8`` 的 imm32 = ``A8 00 00`` | ``00 00 00`` |
| ``0x72AD60`` | ``B9 A8 00 00 00`` (``mov ecx,0xA8``) | 5x ``90`` |

★ **死路: 钩 ``CreateAll`` (0x533FD0) 改建面矩形** —— 试了两次都崩
(``0xC0000005`` / ``EIP=0``)。崩点符合 ``CreateAll`` 里那几处未判空的
``mov edx,[eax]; call [edx+0x18]`` (``0x534117/185/323/39C``): 对象为 NULL 时
``mov edx,[0]`` -> ``call [0x18]`` -> 恰好跳到 0。**直连 DirectDraw 建面不要碰。**

### 2. 隐藏面板 + 保留小地图: 接管 ``BlitSidebar``
面板和小地图画在同一块离屏面 ``DSurface::Sidebar`` (0x887300), 必须连
``0x6A70E0`` 那次 blit 一起接管。做法: **裸钩一个字不动**, 只在 C 里把
``g_BlitSbTramp`` 从"引擎跳板"换成本 DLL 里一个只含 ``ret $4`` 的小函数
(``FM_BlitSb`` 返回该指针), 原版整条 blit 于是被跳过。

小地图矩形 = ``RadarClass+0x120C`` = ``0x8809F4`` (每帧由
``SidebarClass::Draw`` 0x6A6C34 刷新)。dst 用**右对齐**:
``客户宽 - 侧栏列宽 + 面内X``; 侧栏列没撑开时这个式子退化成引擎原版公式,
一像素不差。

> 坑: 最早用的是 ``0xB04A00/04/08/0C``, 实测 ``11,20,72x18`` —— 那是侧栏顶部
> 另一个小控件(用户看到的"简报按钮"), 不是小地图。

### 3. ★ 不要强制面板面重画
为了治"内容随鼠标漂"去置 ``[this+0x53A6]/[0x53A7]``, 结果 ``SidebarClass::Draw``
每帧走全量重画分支 (``0x6A6CFD`` 起的 ``CC_Draw_Shape`` 把侧栏面整块重铺),
**把先前 ``TabClass::Draw`` 画进去的小地图擦掉**; 小地图要等 ``RadarClass``
自己判定视口变了才重画 -> 每帧擦一次、隔几帧补一次 = **闪烁**。
面板面里小地图那块由 ``RadarClass`` 维护, 本来就是持久的。
"内容随鼠标漂"的真正原因是 blit 用了错矩形, 换对之后症状自然消失。

### 4. 上屏顺序 (实测)
``0x7776E0`` 这对呈现是 ``UpdatePrimarySurface(Composite)`` ->
``BlitSidebar(this, 1)``, **侧栏在地图之后**, 所以接管 blit 不会跟地图抢。
另一条路 (``0xA8ED5C != 1``) 走 ``UpdatePrimarySurface([0x88730C])`` = Hidden 面,
不 blit 侧栏。

## 踩坑记录

- **第一版崩 (裸钩)**。为"跳过原版 blit"改了 ``MOExperience_BlitSbEntry``:
  多压参数、``test`` 分支、接管时 ``ret $4``。结果 ``Enable=0`` 也崩, 日志停在
  ``mpwr:`` 之后 (prepare 钩跑完、第一次消息渲染之前)。
  **汇编层多一行少一行都可能踩到引擎对寄存器/栈形的隐含假设, 不值得赌。**
- **gadget 扫描 vtable 白名单写成 ``0x400000..0x560000``** —— 那段是 ``.text``,
  真扫到就会往代码段写、立刻崩。现在不扫指针了, 只按地址算两个内联数组
  (cameo ``0xB07E80``x0x38 / 页签 ``0xB07C48``x0x60), 用矩形是否落在侧栏列里判断。

## 开关

```ini
[FullMap]
Enable=1                  ; 总开关 (接管上屏: 面板消失, 小地图留下)
WidenView=1               ; 视口/面撑满宽 (WidenSurface=0 时只用于摘按钮)
WidenSurface=1            ; 打 0x72AD20 那两处字节补丁; 0=只隐藏面板, 右侧留 168px
KeepRadar=1               ; 1=呈小地图; 0=侧栏面整条都不呈现
DisableSidebarButtons=1   ; 摘页签/cameos, 点击落到地图
```

安全阀: 视口宽度超过 Composite 实际宽度时自动停用并打
``fullmap: view wider than surface``, 退回"只隐藏面板", 不崩。
### 5. ★ 锁定小地图矩形 (闪烁的真正原因)
日志实测 (加 ``fm-geom:`` 转储后一次抓到):

```
radar=11,20,145x137
radar=11,20,145x134
radar=11,20,145x126
radar=11,20,145x103      ← 高度在抖, X/Y/宽一直稳
```

``RadarClass+0x120C`` (0x8809F4) 的 **Height 实测在 103~137 之间跳**
(X=11 / Y=20 / W=145 恒定)。侧栏面里那张雷达图本身是固定尺寸的, 但
``[0xB07DC8/D0/D4/D8]`` 那四个 statics 会被别处写成忽大忽小的高度。逐帧照抄
就等于让 blit 矩形一闪一闪 -> **闪烁**。

处理: ``Fm_RadarRect`` 里锁一份, **只增不减** (头几帧从小长到真实尺寸后就稳住),
侧栏面自身尺寸变了 (改分辨率) 才重新锁。

### 6. 诊断转储
``fm-geom:`` 会打 侧栏面尺寸 / Primary 尺寸 / 小地图矩形 / SidebarBounds /
ViewBounds / WindowBounds / 客户区屏幕原点 / 实际 blit 目标 / 两个脏旗。
上面那个抖动就是它抓到的 —— 这类"逐帧照抄的矩形"一定要打出来看, 别靠推理。

## 点击链路完整实证 (2026-10-01, 反汇编逐条核对)

### GadgetClass vtable 实测布局 (基准 vtable 在 0x7E4F58 起)
```
+0x30 GetNext   +0x34 GetPrev   +0x38..+0x50 (子类覆写)
+0x54 Input(0x4E1640)  +0x58 DrawAll  +0x5C DeleteList  +0x60 ExtractGadget
+0x64 MarkListToRedraw +0x68 Disable   +0x6C Enable
+0x7C SetFocus  +0x80 KillFocus  +0x84 IsFocused
```
⚠ 扫 `call [reg+0x54]` 必须区分 `FF 50..57 54`(disp8) 与 `FF 92 54 01 00 00`(disp32 假匹配)。
我第一次把 modrm 0x90..0x97 当成 disp8, 结果 19 个"命中点"全是别的类的 +0x154。

### GadgetClass 命中测试 = ExtractGadgetAt (0x4E15A0, 非虚, 唯一调用点 0x4E16D4)
```
if (this->[0x1E]) skip;                       // Disabled
X=+0x0C Y=+0x10 W=+0x14 H=+0x18
if (mouseX < X) skip;  if (mouseX >= X+W) skip;
if (mouseY < Y) skip;  if (mouseY >= Y+H) skip;
→ 命中就一路记下, 然后沿 GetPrev(+0x04) 继续走到 NULL
```
**鼠标坐标直接和 gadget 的 X/Y 比, 不加任何偏移** —— 即 gadget 存的就是屏幕/客户坐标。

### [0xA8EF54] 是 ID 不是指针 (第二次确认)
```
004F43F0  IsCurrentWidget(g): return (g->vt[0x18]() == [0xA8EF54]);
004F4410  RemoveButton(g):  [0xA8EF54] ? g->vt[0x10]([0xA8EF54]) : ([0xA8EF54]=g)
004F4450  AddButton(g):     [0xA8EF54] = g->vt[0x24]()      // GetID()
```
所以 `[0xA8EF54]` = `GScreenClass::CurrentWidget` 的 **ID**, 当指针用必炸。

### 侧栏 gadget 不走 GadgetClass::Input
整个 SidebarClass 区 (0x6A4xxx..0x6ADxxx) 里**没有一处** `call [reg+0x54]` 打在 gadget 上
(唯一那个 0x6A9AF8 是 `DSurface*` 的 vtable, 因为 `mov ecx,[0x887300]`)。
侧栏有自己的一套点击处理。`GadgetClass::Input` 的唯一直接调用者是 0x4E14E9(DeleteList 里)。

### ★ 侧栏点击唯一入口 = SidebarClass::ProcessClick (0x6A7780)
全二进制唯一调用点 **0x6D09AA**(在 TabClass 区域那个函数里)。
```
006A778B  mov ecx, [0x886F90]     ; SidebarBounds.X
006A7791  mov eax, [edx]          ; rect.X (点击点, 客户坐标)
006A7793  sub eax, ecx            ; → 侧栏局部 X
...
006A77DB  mov al, [esi+0x53A5]    ; = [0x884B8D] 侧栏可见标志
006A77E3  je  0x6A7AC4            ; 为 0 → 跳过页签/cameo 命中
006A77CD  call 0x6A8B30           ; 页签/cameo 命中 (4 轮, 步长 0xF94)
...
006A7A8A  loop 0xB07C48..0xB07DC8 step 0x60  call 0x69E010   ; 4 个页签按钮状态机
006A7AFE  call 0x63FEA0           ; → 侧栏滚动 + 小地图判定
```
`esi` = 单例 0x87F7E8, 所以 `[esi+0x53A5]`=`[0x884B8D]`, `+0x53A6`=`[0x884B8E]`, `+0x53A7`=`[0x884B8F]`
—— 后两个就是我之前误当作"小地图重绘脏旗"去置位的东西, 其实是页签/cameo 重画标志。

### 0x63FEA0 = 侧栏横向滚动条处理 (不是小地图)
操作 `[esi+0x1510/0x1514/0x1518/0x151C]` 滚动位置 + `[esi+0x152C/0x1530/0x1534]` 范围,
写 `[esi+0x1520/0x1524/0x1528]` 视口位置。入口先读 `[0x884B8D]`, 为 0 直接跳 0x640385。
末尾 `0x640385` 才 `call 0x653850`(ret 8, 传 rect + 一个 DWORD)。

### ★ 0x653850 = 顶上一簇小控件的命中判定 (小地图不在这里!)
```
0x4A9700 -> 0x4F4BB0 : 只动 this(单例)+4 / +8 的计数, 与哨兵无关, 忽略
edi = isNOD ? [0x886FA8→我们已改成 0x886F90] : 0      // 横向偏移, 需 1752
; 第一段: [0xB04A00/04/08/0C] = {11,20,72,18}
;   命中 → push 0; push 0; mov ecx,0x87F7E8; call 0x5BDC80
; 第二段: [0xB048C8/CC/D0/D4]
;   命中 → 同样 call 0x5BDC80
; 之后: if (rect->X == 0x80F2) [0xA8EDA0] = 8 或 9
;       if (rect->X == 0x80F3) [0xA8EDA0] = 1
```
所以**顶上一簇那两个按钮挂在这两段矩形比较上**, 命中动作是 `0x5BDC80(0,0)`。
`0x80F2/0x80F3` 是模式哨兵, 不是坐标 —— 比较对象是 `rect->X` 原值(没被 0x4F4BB0 改过)。

### 第一轮诊断结果 (2026-10-01 12:39 版)
**路由是通的**: `sb-click` 与 `radar-hit` 成对出现, 说明点击进了 `SidebarClass::ProcessClick`
并落到 `0x653850`。但我打出来的 `click=` 是垃圾 (0/272/347/2064/2139/2387, 超出窗口宽 1920),
而 `mouse=1786,98` 才对。

**根因: 我把 arg0 当成点击点了, 实际是 arg1。**
```
006A7780  sub esp, 0x14
006A7783  mov edx, [esp + 0x1C]   ← 这一条在 push ebx/esi **之前** → 是 [S+8] = arg1
006A7791  mov eax, [edx]          ← [arg1]
006A7793  sub eax, ecx            ← 减 SidebarBounds.X
```
所以:
* **arg1 = 点击点** (RectangleStruct*, 客户坐标) → `0x6A8B30` 页签/cameo 命中 + `0x653850` 两段按钮判定
* **arg0 = 另一码事** (实测值 0/272/347/2064/2139/2387, 看着像地图格坐标; `0x653850` 尾部
  拿 `[arg0]` 去比 `0x80F2`/`0x80F3` 两个哨兵)
裸钩里 arg1 位于 pushal(+0x20)+pushfl(+0x24) 之后的 `[esp+0x2C]` (第一版错用了 0x28)。

### b1/b2 不是按钮, 是光标形状区 (死路)
`0x653850` 两段命中后调的 `0x5BDC80` 是 `MouseClass::SetCursor`:
```
005BDC8C  lea ecx, [eax*8]
005BDC93  sub ecx, eax
005BDC95  lea esi, [ecx*4 + 0x82D028]   ← MouseCursor::Cursors[86] (YRpp MouseClass.h)
```
所以 `[0xB04A00..0C]`=11,20,72x18 与 `[0xB048C8..D4]`=83,20,72x18 只是小地图上两片不同光标形状。
真正的按钮是注册进 GScreenClass 的 gadget (`0x6A7E91` 一带把 `[0xB04A10]`/`[0xB07DF8]`/
`[0xB0B3A0]`/`[0xB0B328]`/`[0xB0B408]` 逐个 `AddButton`)。

### 第二轮诊断: 钩 GadgetClass::Input (0x4E1640)
侧栏自有处理不走 Input, 但真正注册进去的 gadget 走它。首6B = `83 EC 0C 53 55 56`, 跳回 0x4E1646。
把每个收到输入的 gadget 的 `+0x0C/+0x10/+0x14/+0x18` 与 `+0x1E`(Disabled) 打出来,
只打横向跨过侧栏分界线 (`gx+gw > colX && gx < colX+200`) 的, 避免每帧刷屏。
裸钩传 `this`: `push %%ecx` (pushal 不改 ecx)。

所以 **arg0 = 命中 widget 的 egui ID 指针**, 由调用方 `0x6D09AA` 算好传进来;
arg1 = 点击点 (`0x6A7793` 减 `SidebarBounds.X`)。
(这也解释了上一轮我把 arg0 的 [0] 打成 0/272/347/2387 —— 那是别的路径的 idp, 不是 ID 值本身;

### 输入链路里只有一个 gadget (关键!)
`GadgetClass::Input(0x4E1640)` 每帧只被调一次, `this` = 一个横跨视口的容器式 gadget:
```
fullmap: gadget #N of N rect=0,0,1920x1048 dis=0 vt=0x7E608C colX=1752
```
* 原版它应是 `0,0,1752x1048` (= ViewBounds) —— 撑宽视口后它把侧栏列整个盖进命中区。
* vtable `0x7E608C`: `Input` 在 **+0x40** (基准 GadgetClass 是 +0x54, 这个类虚表更短),
  自有覆写 `+0x08=0x5519B0 / +0x18=0x4AEBB0 / +0x94=0x4AAC10 / +0xA0=0x4F4240 /
  +0xA8=0x4F42B0 / +0xB0=0x4AEBF0 / +0xB4=0x4A8850 / +0xB8=0x4A88C0 / +0xBC=0x4A8930 / +0xC0=0x4F4320`,
  `Remove/Disable/Enable/SetFocus/Clicked` 全用基类 → 纯绘制容器, 跨整视图。
* `ExtractGadgetAt(0x4E15A0)` 沿 **GetPrev(+0x04)** 走, **每个命中都覆盖结果**,
  所以最终返回的是"沿 GetPrev 方向最靠前那个命中的 gadget"。
* **推论**: 只要把它横向收到 `colX`(1752), 侧栏列的点击就不再被它吃掉,
  能落到链上真正位于侧栏的那个 gadget。指针现在是对的 (来自 Input 的 `this`),
  不再像 `[0xA8EF54]` 那样是野写。

### 第三轮诊断: 打出 egui ID
`MOExperience_SbClickEntry` 改成压两个参数 (先 arg1 再 arg0, 因为第一次 push 使 esp-4),
C 侧 `SbClickEntry(void* idp, void* pt)` → `FM_NoteSidebarClick(idp, pt)`,
日志加 `id=` 字段(十六进制)。由它判定引擎认为命中了哪个 widget。

### 第三轮诊断结果 (12:53 版) —— egui ID 出来了

`id=1` / `0x801` 不是有效 egui ID (egui 从 0x80xx 起, `0x6A78A1` 比的是 0x8065/0x8066/0x80CB,
`0x6A7904: cmp eax,0x80CB; jl 0x6A7B18` 会全落到 0x6A7B18 那支)。

**结论: 侧栏列的点击根本没有命中任何 widget。** 根因就是那个横跨视口的 gadget ——

### 修复: FM_TrimViewGadget (新开关 [FullMap] TrimViewGadget, 默认 1)
* 指针: `GadgetClass::Input` 的 `this` (`FM_NoteGadgetInput` 存进 `s_ViewGadget`)。
  **这是真 gadget 指针**, 与之前把 `[0xA8EF54]` (ID) 当指针的野写完全不同。
* 做法: 每循环若 `gx + gw > colX` 且 `gx < colX`, 就把 `Width` 收到 `colX - gx`, 并置
  `+0x20` = NeedsRedraw。引擎多半每帧从 ViewBounds 重设, 所以要每循环都做。
* 安全性: 只改命中区矩形 (输入/视图层), 不碰任何模拟状态, 联机安全。
* 判读: 日志会打一行 `fullmap: view gadget trimmed w=1920->1752`(只打第一次宽度变化)。

### ⚠ 工具坑: PatchAt 入口钩至少要 5 字节
`VecText.cpp:2114` 的 `PatchAt(unsigned at, void* target, int n)` 第一行就是
`if (n < 5) return 0;` —— 入口钩的 `n` 必须 >= 5, 否则**静默失败**, 只在日志里留一行
`xxx hook OFF`, 很容易误判成"钩装了但没触发"。
第五轮 `radarin hook OFF` 就是这么白丢的 (我按"抄 4B 是干净边界"给了 n=4,
其实 0x6539D0 处 `83 EC 44 | 8A 54 24` 是 6B 完整两条指令, n=6 跳回 0x6539D6)。
教训: **入口钩一律先 `python` 确认字节数再给 n, 且给完必须核对日志里那行是 ON。**

### 双保险: arena 矩形也打进 sb-click 行
入口探针不可靠, 所以把 `RadarClass::Input` 判命中用的矩形 `[0x880C84..90]`
一并塞进**必定触发**的 `fullmap: sb-click` 行 (`arena=x,y,WxH`)。
这样只要 sb-click 在跑, 就一定能拿到判定矩形, 不依赖任何探针。

引擎的点击路由压根不覆盖那块区域 → 点击被当成地图点击 (框单位/打靶)。

### 点击链路全部实证汇总 (可作为定论)
1. `MouseClass::ProcessClick` (0x478BD1) NOD 分支: `mouseX > ViewBounds.X + SidebarBounds.X(1752)`
   → 走侧栏分支 (imm32 补丁 0x478BD8 生效)。**路由是通的。**
2. `SidebarClass::ProcessClick` (0x6A7780, 唯一调用点 0x6D09AA) 收到**正确点击点**
   (arg1 = arg1 是点击点; arg0 = 命中 widget 的 egui ID 指针)。
   ⚠ 栈偏移坑: `0x6A7783` 的 `[esp+0x1C]` 在 `push ebx/esi` **之前** → 是 **arg1** 不是 arg0。

## 踩过的坑 (留着别再踩)
* **`PatchAt` 入口钩要求 `n >= 5`**, 不满足则**静默失败**, 只在日志留一行 `hook OFF`。
  极易误判成"钩装了但没触发"。给完 `n` 必须核对日志那行是 ON。
* **源码改动一律用 Edit 工具**, 不要用 PowerShell 字符串替换 —— `@'...'@` 单引号
  here-string 里 `` `n `` 不展开, 会静默不匹配; `Remove()`/`-replace` 还会咬掉大括号
  和相邻注释 (本轮又咬掉一次 `ADDR_SIDEBAR_DIRTY` 的定义)。
* 改完必须核对 `G:\motest\MOExperience.dll` 的时间戳 —— 手动 `g++` 编译过某个 .cpp 后,
  `build-fast.bat` 会认为 obj 是新的而跳过链接, dll 没更新。
* 扫 `call [reg+disp8]` 要区分 `FF 50..57`(disp8) 与 `FF 92 54 01 00 00`(disp32 假匹配)。
  我第一次把 modrm 0x90..0x97 当 disp8, 19 个"命中点"全是别的类的 +0x154。
* 裸钩内联汇编: MinGW i386 默认 **AT&T** 语法 (`call *%0`, `0x28(%%esp)`, `%` 要转义)。
  按 Intel 写会直接汇编失败。
* **不要凭类型直觉解引用全局地址。** 我曾把 `[0xA8EF54]` 当 `GadgetClass*` 用, 写出
  `0x9045752+0x14` 的野地址 —— 它其实是 gadget 的 **ID (DWORD)**
  (`0x4F4450 AddButton` 里写的是 `g->vt[0x24]()` = `GetID()`)。
* **不要把只读诊断的"指针"从 ID 之类的整数推出来。** 拿指针的唯一可靠途径是
  从虚函数实参 (`this`) 拿。
