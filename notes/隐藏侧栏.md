## 1. 三态与几何

三态只改"我们接管多少" + 视口宽度 (1752 <-> 1920 动态切)。`s_Mode` 每循环由
`Fm_PollToggle` 按 `GetAsyncKeyState(ToggleVk)` 采边沿循环 (自门控引擎帧号
`0xA8ED84`, 只在游戏窗口有焦点时响应)。

### 1.1 态取值器 (三态是绝对语义, 没有细化开关)

| 取值器 | 态0 full | 态1 radar | 态2 bare |
|---|---|---|---|
| `Fm_ModeKeep` 呈不呈现侧栏面 | 1 (整条) | 1 (顶部块) | 0 |
| `Fm_SidebarGone` 侧栏列算不存在 | 0 | 0 | 1 |
| `Fm_ModeDisarm` 摘页签/cameo | 0 (恢复可用) | 1 | 1 |
| `Fm_ModeGate` 小地图点击门 | 0 | 1 | 0 |
| `Fm_ModeTrim` 视口 gadget 收窄 | 0 | 1 | 0 |

### 1.2 几何表 (1920x1080 客户区)

| | 态0 full | 态1 radar | 态2 bare |
|---|---|---|---|
| `ViewBounds.X` | `isNOD\|\|末日 ? 0 : 168` | 0 | 0 |
| `ViewBounds.Width` | `clientW-168` = **1752** | **1920** | **1920** |
| `ViewBounds.Height` | `clientH-32` | `clientH-32` | `clientH-32` |
| `0x72AD20` 字节窗口 | 原版 | 全宽 | 全宽 |
| Composite 渲染面 | **恒全宽** | 全宽 | 全宽 |
| `SidebarBounds.X` (苏联) | 1752 | 1752 | 1920 (恒不成立的路由阈值) |
| `SidebarBounds.X` (盟军) | 0 | 0 | -176 = `-(168+8)` |
| 侧栏面呈现 | 我们 blit 整条 | blit 顶部块 `{0,0,168,SidebarBounds.Y+ExtraH}` | 整块抹黑, 不上屏 |
| 视口 gadget 命中区 | 整宽 (原版本就 1752) | `ViewBounds` 减去侧栏列 | 整宽 |
| 小地图点击门 | 关 (交引擎 widget 分派) | 开 | 关 |

⚠️ `SidebarBounds.X` 的双重语义: 既当"侧栏列在屏幕上的起点" (摆放/摘除 gadget),
又当"鼠标这次算地图还是算侧栏"的路由阈值。态2 用恒不成立的阈值, 但摘 gadget 必须用
`Fm_ColumnX(0)` 拿真实列起点 (苏联 1752 / 盟军 0), 否则整列 244 个 gadget 全漏筛。
⚠️ **`Fm_ModeGate` 在缩放档跨模式接手** (见 地图缩放.md §11.12 ④⑤): 态0 缩放档也返回
1, 因为缩小档下小地图那块在引擎眼里已经"不在视口里", `ProcessClickCoords` 会先把它
当视口外拒掉; 1x 的态0 逐位沿用原版 (返回 0)。门吞没的范围是**侧栏顶部那一块**
(`Fm_KeepTopRect` = `{0,0,列宽,SidebarBounds.Y}`), **不是** `Fm_KeepRect` ——
态0 那个是整条侧栏面, 会把页签/cameo 一起吞掉 (那两样点了是要下单的)。
⚠️ **点击判定一律用 `Fm_ColumnX(0)` 现算列起点, 不读 `SidebarBounds.X`**: 那个全局
引擎自己会按当前 `ViewBounds` 重算 (`0x6A51C0`), 缩小档下 ViewBounds=R ⇒ 瞬时值是
`R.Width` 而不是列起点。呈现位置 (FM_BlitSb / FM_DrawRadarTo) 早就这么做了 (§3.5),
点击判定现在也统一。
⚠️ **小地图点击的"跳过去"本模块不再自己算**: 门只吞穿透, 视口跳转由原生
`RadarClass::Action` 做 (§2.4)。原因见 地图缩放.md §11.12 ④⑤。

### 1.3 态0 为什么必须回到"原版视口宽度"

只 blit 整条侧栏但视口仍是 1920 时: 页签/cameo/小地图**一个都点不动**。凡是拿视口跟
侧栏列做比较的地方 (鼠标路由 `0x478BD7`、`SidebarClass` 自身命中、cameo 排布
`0x654332`) 全错 168。所以态0 反过来做: 视口宽度改回 1752, 我们不接管任何东西。

三条腿 (详见 §3.1-3.2): (1) 字节窗口按模式翻 (2) `Fm_ApplyViewWidth` 每循环纠正
`ViewBounds` 并同步 `view_bound` (3) 建面永远全宽。

⚠️ `0xB04A00/04/08/0C` 是侧栏顶部另一个 **72x18** 小控件 (用户看到的"简报按钮"),
**不是**小地图。用错它 = "内容随鼠标漂"。正确来源只有 `0x8809F4`。
⚠️ 小地图矩形高度每帧在 `103..137` 之间跳 (X/Y/宽稳定 `11,20,145`)。逐帧照抄就是
闪烁 —— `Fm_RadarRect` 把它锁住且**只增不减**, 侧栏面尺寸变了才重锁。

`TabClass::Draw` (`0x6D0A20`) 每帧往同一块侧栏面依次画: 背景 → 小地图
(`RadarClass`) → `SidebarClass::Draw` (`0x6A6C30`) → `BlitSidebar` (`0x6A70E0`)
整条 blit 上屏。所以"跳过面板那步"会连小地图一起丢, 必须接管整条 blit。
`BlitSidebar` 全二进制只有 `0x6A70AE` / `0x777723` 两个调用点, 且面板最终是被
**画进 Composite** 的 ⇒ `FM_DrawRadarTo` 把小地图也画进 Composite, 闪烁在构造上消失。

### 2.2 视口矩形纯函数 + 三个字节窗口

`0x72AD20` 是纯函数 (只有 mov/xor/sub), 输出
`{ X:(非NOD且非末日)?168:0, Y:0, W:clientW-168, H:clientH-32 }`。
**全仓 32 个调用点**: `CreateAll` 两处 / `Set_View_Dimensions` (`0x4A8960`) /
`0x63xxxx` 格-视图求交 / `0x77830C` 缩放中心。

| 落点 | 原字节 | 全宽字节 | 作用 |
|---|---|---|---|
| `0x72AD69` (`sub edx,0xA8` 的 imm32) | `A8 00 00` | `00 00 00` | W 不再扣 168 |
| `0x72AD60` (`mov ecx,0xA8`) | `B9 A8 00 00 00` | `90 x5` | 盟军侧 168 偏移去掉 |
| `0x6BDDC8` (`sub eax,edx`) | `2B C2` | `90 90` | 新开一局的 Composite 宽度 |

`GScreenClass::CreateAll` (`0x533FD0`) 只有三个调用点, 前两个用 `0x72AD20` 的输出建面,
第三个 (`0x6BDE14`) 自己算:
`0x6BDDAC mov edx,[0x7F5BF8]` / `0x6BDDC4 mov eax,[0x886FB8]` /
`0x6BDDC8 sub eax,edx` / `0x6BDDD7 mov [ebp-0x7A4],eax`。
`CreateAll` 内 `[ebp+8/+0xC]` 建 Hidden, `edi`(arg1) 建 **Composite**。
⇒ 不 nop 这里 Composite 恒 1752, 视口被安全阀夹到 1752, 右边 168px 无人绘制 = 黑底;
**读档不重跑这条**, 所以读档看着正常。

建面永远全宽: `CreateAll` 两个调用点 `0x560F9C` / `0x67E776` 的 `call 0x72AD20`
(`E8+rel32`, 5 字节) 改指向 `Fm_ViewRectStub` (`__fastcall`, ECX=出参, 返回出参指针,
永远返回 `{0,0,clientW,clientH-32}`)。改写前后寄存器收支不变。`Fm_PatchCallTo` 自带
保险: 先核对原字节是 `E8` 且 rel32 指向 `0x72AD20`, 不吻合不改。

`0x72AD90` 是 `0x72AD20` 的**孪生函数** (只差基址 `[0xA8EB84]/[0xA8EB88]` vs
`[0x886FB4]/[0x886FBC]`), 而 `0x6A519B call 0x72AD90` → `0x6A51AB lea ebx,[edx+eax]`
→ `0x6A51C0 mov [0x886F90],ebx` ⇒ **引擎自己把 `SidebarBounds.X` 算成视口右边界**
(原版 NOD = 1752, 本来就是对的)。**不要补 `0x72AD90`**。

### 2.3 五处"侧栏横向偏移"取数改指 `SidebarBounds.X`

全二进制有 5 处把 `ViewBounds.Width` (`[0x886FA8]`) 当横向偏移, imm32 全部改成
`0x886F90` (逐条核对原字节 `A8 6F 88 00`, 全一致才一起改):

| 地址 | 指令 | 用途 |
|---|---|---|
| `0x478BD7` | `mov eax,[..]` imm@+1 | 鼠标钳制 / 侧栏路由 |
| `0x65386B` | `mov edx,[..]` imm@+2 | 顶部按钮光标形状区命中 |
| `0x654332` | `mov ecx,[..]` imm@+2 | **三个 radar gadget 的摆放 X** |
| `0x653A3F` | `mov ebx,[..]` imm@+2 | `RadarClass::Action` 鼠标换算 |
| `0x6D06C7` | `mov edi,[..]` imm@+2 | 侧栏顶部一簇光标判定 |

`0x654320` 是三 gadget 位置的**唯一**计算点, 只在 `DisplayClass::InitGUI`
(`0x6ABD30` → `0x6403A0` → `0x6ABD39`) 跑一次 ⇒ 运行时改 gadget 矩形撑不过下一次
InitGUI, 改 imm32 是唯一正确修法。`0x65432D mov al,[0xA8EB7C]` 决定取 0 还是偏移。

`0x653D92` (`ViewW/9`) **刻意不改** (原版 1752/9=194 远大于任何地图宽, 等价)。

### 2.4 gadget 链与点击

`GadgetClass` 字段: `X=+0x0C Y=+0x10 W=+0x14 H=+0x18 NeedsRedraw=+0x1C
Redraw=+0x20 Disabled=+0x1E`; vtable `+0x04 GetNext +0x08 GetPrev +0x28 Input
+0x34 ExtractGadget +0x64 SetPosition +0x68 SetDimension +0x7C Action +0x80 Clicked`。

- `ExtractGadgetAt` (`0x4E15A0`): skip `Disabled`; X/Y/W/H 直接当屏幕坐标比;
  **`W*H` 面积小者胜** (不是"最靠前"); 沿 `GetPrev` 走到 NULL。
  实测整条链只有一个节点 (`0x8A06F8` 视图容器 gadget, 矩形恒等于 `ViewBounds`,
  实测 `{0,0,1920x1048}`), 所以三个 radar gadget / 页签 / cameo **都不在这条链上**,
  `ExtractGadgetAt` 永远返回视图容器。顶部按钮的原生响应走 `0x6D0680` 的 widget
  分派 (ID `0xF2`=`0xB04978` / `0xF3`=`0xB04910`), 不靠 gadget 命中。
- 三个 radar gadget: 本体 `0xB04A10` (虚表 `0x7F02BC`, `Action`=`+0x7C`=`0x6539D0`,
  构造 `0x652870`), 两个顶部按钮宽高实测为 `0` (引擎从未 `SetDimension`)。
- `RadarClass::Action` (`0x6539D0`) **是活的**: 入口 `cmp [0x880C98],1 / [0x880C94],1`,
  这两个全局运行时就是 1 (旧笔记说"只有读没有写 ⇒ 恒 bail"是错的, 已删)。
  它内部 `0x656750` → `{格*256+0x80}` → 视口跳格, 用的就是 §2.3 那五处补丁改过的
  侧栏横向偏移 ⇒ **小地图点击的跳转就交给它, 本模块只吞穿透**。
- 点击是**并行**的两条路: `DisplayClass::ProcessClick` (`0x6922E0`) 先 `call 0x692F30`
  (地图侧) 再 `call 0x6D0680` (侧栏 widget, 无条件 fall-through)。
  "点一下同时对主地图生效"是**天生**的, 不存在可改的路由点, 只能在
  `ProcessClickCoords` 里吞。
- 视口 gadget 收窄: `GadgetClass::Input` (`0x4E1640`) 拿真实 gadget 指针 (this),
  原函数紧接着调 `ExtractGadgetAt`, 所以钩子跑在**命中判定之前**。判它 = 矩形恒等于
  `ViewBounds` 且横向跨过侧栏列; 只写 gamemd 自己映像 (`0x400000..0x8A0000`) 里的对象。
  `FM_Poll` 里也每循环做一遍 (幂等)。

## 3. 不变量 (必须持续为真)

### 3.1 渲染面永远全宽

`0x72AD20` 的返回值**同时**喂"建面"和"视口", 所以态0 恢复原字节会把渲染面一起缩成
1752 ⇒ 切回全宽态就夹窄。两个办法都用上: 两个 `CreateAll` 调用点改指
`Fm_ViewRectStub`; 新开局那个走 `0x6BDDC8` 的 nop。

⚠️ 让 `0x6BDDC8` 那条 `sub` 不生效, **唯一正确的写法是 nop (`90 90`)**。
写成 `sub eax,eax` (`2B C0`) 是"结果恒为 0"而不是"不减 168" ⇒ `CreateAll` 里两处
`test W; jle` 被跳过 ⇒ `[0x88731C]/[0x8872FC]` 保持 NULL ⇒ `0x6D410D` 空指针,
**新游戏必崩**。

### 3.2 `ViewBounds` 与那 32 个调用点必须同源

只改 `ViewBounds` 不够: 那些地方会继续拿到全宽矩形, 与 1752 的 `ViewBounds` 对不上。
所以态0 必须把两个字节窗口恢复原版, 拿到**逐字段等同原版**的矩形, 引擎所有几何判定
自动正确。`Fm_ApplyViewWidth` 因为 (1) 保证稳态一致, 平时是幂等空操作 —— 但引擎自己
不会重算 `ViewBounds`, 且新开局那条路不走 `0x72AD20`, 所以这一步必须每循环做。

同步 = `push &ViewBounds / call 0x6D5F60` (ecx = `TacticalClass`,
`SetTacticalViewBounds`), 照抄 `Set_View_Dimensions` 的第二步。

### 3.3 侧栏列起点必须跟着**实际视口宽度**走 (不看模式)

`Fm_ViewWide()` 拿 `ViewBounds.Width` 与客户宽比 (切换当帧两者会短暂不一致)。
非 bare 公式据此决定减不减那 168: 全宽视口时减 (1920-168=1752), 原版视口时不减。
曾一直按"全宽视口"公式写死 ⇒ 态0 算成 **1584** ⇒ `InitGUI` 用它摆三 gadget 且不再重算,
引擎的 gadget 命中 1584 / 我们的 blit 与点击判定 1752, 两套坐标打架谁也点不到;
从态2 切回来还会留着 1920 的路由阈值 ⇒ 整条侧栏 blit 到屏外。**态0 也要每循环调
`Fm_SyncColumn`**, 不能跳。

### 3.4 `InitGUI` 入口钩必须按"侧栏真的存在"的几何纠正

那一堆**一次性**写入 (cameo/页签滚动偏移 = `-SidebarBounds.X`: `0x6ABE37`
`[0xB0B3E4]` / `0x6ABE67` `[0xB07E3C]` / `0x6ABE9E` `[esi-0x1C]` /
`0x6ABEDF` / `0x6ABF0F`, 以及 `0x654320` 摆三 gadget) 只发生一次, `FM_Poll` 每循环
纠正来不及。所以 `FM_SyncSidebarColumn()` 永远 `Fm_SyncColumn(0)`: 三态算出来都是 1752。

### 3.5 呈现位置从视口算, 不读 `SidebarBounds.X`

`FM_BlitSb` / `FM_DrawRadarTo` 的 dst 基准用 `Fm_ColumnX(0)`。`SidebarBounds.X` 在态2
被推成 1920 / -176 的路由阈值, 拿它当呈现位置会把整条侧栏画到屏外或地图中间。

### 3.6 安全阀: 视口宽 > Composite 实际宽 ⇒ 夹窄 (不是 skip)

视口比面宽时引擎照旧往面外画, 那就是"新开一局花屏"的直接原因。同一原因要求**任何一笔
blit 前**先按目标面实际尺寸夹一刀 (`Fm_FitRectToSurf`, 源与目标同步裁保持 1:1):
保留区 dst.X=1752+11=1763 往 1752 宽的面上 blit 会越过行尾 116px 踩坏后面的行。

### 3.7 换宽度要钉住左边界

引擎存的是视口**中心**格 (`+0xD64`, 目标 `+0xD74`), 而 `0x6D8B30` 用
`中心 - ViewBounds.Width/2` 算出左上角供 `CoordsToScreen` 换算 ⇒ 宽度一变左边界就跟着
跑半个差值 (1920<->1752 = 84px), 且撑宽可能被 `0x6D8640` 钳位推回、缩窄又不回来 =
单向漂移。改宽度时把中心按 `±ΔW/2` 挪 (`0xD64`+`0xD74` 一起), 只挪中心、让引擎照旧
钳位。

⚠️ 别去读 YRpp 头里 `TacticalPos` 那个字段来"量"位移 —— 它的偏移与 `VisibleCells`
元素数对不上 (0xB0 vs 0xB30), 不可信; 用 `0x6D8B30` 里已核实的算术直接算增量。

### 3.8 切模式的动作清单

`Fm_PollToggle`: 置三个侧栏重画脏标记 + 清 `s_RadarLockOk` + 清 `s_LbPress` + 清
`s_GadgetsArmed`; 进态0 额外 `s_ForceRedraw=8` (帧号门控), 逼 `SidebarClass::Draw` 走
全量重画 (`0x6A6CFD`), 因为态1/2 期间侧栏面被抹黑过。
`Fm_Poll` 恢复 gadget 只做**一次** (`s_GadgetsArmed`), 之后每帧不再碰那 244 个对象。
`GadgetClass::Disabled` 是合法置位不是摘链。

⚠️ **不能每帧压**面板重画: 全量重画分支会把 `TabClass::Draw` 刚画进去的小地图擦掉 ⇒
每帧擦一次、隔几帧补一次 = 闪烁。

### 3.9 侧栏的一次性布局必须按 **A** 在几何一变时重跑

`InitGUI` (0x6ABD30) 里那批写入只发生一次且按当时的 `ViewBounds` 算 ⇒ 视口几何
一变就得拿 A 重跑。唯一会重跑它的路是 `Set_View_Dimensions`, 而那条路在缩小档
被禁掉了 (地图缩放.md §11.2) ⇒ 缩小档换挡 / 只改高度 / 帧门挡住的那几次, 侧栏
布局一次都没重算。另 `CreateAll` (读档/改分辨率) 换掉侧栏面之后新面是空的, 也要补。
修法见 地图缩放.md §26 (`Fm_InitGuiForA` + `Fm_NoteSurfaceRebuild`)。
另外 ZBuffer/ABuffer 与视口必须同源 (隐藏侧栏.md §4.8), 而 `ScaleBar` 原来只在
"自己重建过"时才纠正 —— 读档后引擎自己按全宽建的那两块永远纠正不回来。

### 3.10 联机安全

只写 `ViewBounds` / `view_bound` / `SidebarBounds` / 渲染面 / gadget 标志 / 本地摄像机,
全是本地渲染与输入状态, 每客户端按自己窗口尺寸算, 不碰任何模拟内存, 不发事件。

## 4. 根因档案

### 4.1 右下角各层的锚点 = 视口右边界 (`FM_MapRightEdge` = `ViewBounds.X + Width`)

态0 → 1752 (贴侧栏左边), 态1/2 → 1920 (贴屏幕右缘)。两种形态各自贴边, 这就是
"适应侧栏显示/隐藏"。`SWS_Draw` 的 `xStart` 与两个按钮几何、`SWPanel_Draw` 的
`rightEdge`/`px` 全部改锚 `g_MapRight` (消息帧钩里回填, 返回 0 = 本模块没接管)。

⚠️ 试过改成 `Fm_ColumnX(0)` (三态**恒为** 1752) 想让位置跨模式不动 ⇒ 隐藏侧栏后列表
缩在 1752、右边空一大截。**跨模式一致 ≠ 对齐**。
⚠️ `SwsSig` 里**必须带上 `g_MapRight`**: 缓存图只按签名重建, 而画布尺寸两种状态都是
1920, 不加锚点就永远不重建 ⇒ 侧栏切换后旧坐标的图标一直留在地图上。
⚠️ `SWPanel` 的 `anchor = g_MapRight ? g_MapRight : surfW` 兜底要改掉 (那正是"整块
列表跳到屏幕最右缘"的表现): 退回 0 + 打 `swpanel: anchor lost`。

### 4.2 残影的根因: 地图**增量**重绘, 换视口宽度不标脏

"切换后地图上留一层旧侧栏"的唯一根因。证据链:

1. 地图增量画进 `Hidden` 面 —— 只有被标脏的格子才重画, 引擎不会每帧刷整个视口。
   旁证: `CellClass::MarkForRedraw()` (`0x486E70`) 只在"这个格子的像素变了"时用;
   `TacticalClass::RegisterDirtyArea` (`0x6D2790`) 存在的意义就是补这个洞。
2. `CellFlags` / `AltCellFlags` 里**都没有** dirty/redraw 位 ⇒ 脏信息只走
   `Drawing::DirtyAreas` 队列 (`0xB0CE78`)。
3. **换视口宽度的所有路径都只改矩形、一个格子都不标脏** —— 全是纯几何。
4. `GScreenClass::DoBlit` (`0x4F4780`) 的 `rect` 参数是**可选**的, 每次只搬
   `Hidden`→`Primary` 的一部分, 没搬到的像素留到下一帧。

⇒ 态0(1752)→态1/2(1920): 右边新露出的 168px 从没进过脏队列, `Hidden` 里留的还是
上一模式的侧栏面板/小地图 = 残影。它**跟着地图一起动** (都在 `Hidden` 里), 所以看着
像"贴在地图上", 不是钉在屏幕坐标。反向同理。

**修法**: `Fm_ApplyViewWidth` 里比较 `w != oldW`, 真的变了就置 `s_DirtyFrames=3`,
随后几帧把整个视口推进脏区:

```c
#define ADDR_REG_DIRTY_AREA 0x006D2790u   /* TacticalClass::RegisterDirtyArea */
typedef void (__fastcall *FnRegDirtyArea)(void*, RectangleStruct, int);
/* r = {0,0,vb->Width,vb->Height}; fn(tac, r, 1); */
```

客户区相对坐标, **不碰 `TacticalPos`**。必须排在 `Fm_ApplyViewWidth` 之后。纯渲染脏区。

⚠️ 走过的两条**错路**: (a) 往 `Primary` 抹黑 —— 依据"呈现是脏矩形局部 blit"未经验证,
且同一块每帧被写了**三次** (`FM_DrawRadarTo`→Composite 呈现前、抹黑→Primary 呈现后、
侧栏面 blit→Primary 呈现后), 多出来那次直接造成侧栏闪烁; (b) 呈现路径上追加"擦干净"
—— 呈现路径上每块区域只能有**一个**写入者。

### 4.3 隐藏原版超武列表: `inband` 的 x 上界只能用画布宽

`VecText.cpp` `VecSimpleEntry` 里命中 `caller==0x4A6345` 之后那道 `inband` 是
"隐藏原版列表"的**唯一开关**:

```c
inband = (sx >= 1300 && sx <= g_SWCompW && sy >= 32 && sy <= g_SWCompH);
if (inband) { 收表; return ecxIn; }      /* 跳过绘制 */
return g_OrigSimple(...);                 /* 放行, 原版原样画出来 */
```

侧栏隐藏后引擎把整批行挪到 `sx ≈ 1890`。**任何按"侧栏可见时"几何算出来的 x 上界都会
把它们整批踢出 `inband`** —— 写死 `1752` 会漏, 收紧到 `g_MapRight` (也是 1752) 同样
会漏。上界只能用画布宽 `g_SWCompW`; 下界 `1300` 保留 (挡世界悬浮提示 `c=0x73AC616A`)。

**漏了之后的症状很有辨识度**: 不是整块原版列表冒出来, 而是"左边只剩矢量计时器 +
右边原版名和黑底"。因为名和计时器走两条不同的路:
- 计时器: `Simple_` + **Print 层兜底** (`VecSWCapture`, 只判冒号、**没有 x 上界**)
  → 两条路都漏不上, 藏住了也进了表。
- 名: **只能在 `Simple_` 收** (Print 层的名与世界悬浮提示不可区分: 同经 `0x4A5FF2`、
  同落右侧带、同 CJK 首字, 收会把建筑名提示吞掉) → 一漏就既没藏也没进表。

⇒ 看到这个组合, 基本可直接断定 `Simple_` 的 `inband` 漏了。**底色条不走 Print 层**,
跟着一起漏 ⇒ "只剩黑底"。旁证: 战役框的捕获 `VecMenuMatch` 只按
`caller + w + h + flags`, 完全没有位置检查 ⇒ 战役框不受影响、超武列表受影响。

**配套修**: 1) `Simple_` 里**文本为空**的那次调用 = 该行**底色条**, 原来 `if (text && ...)`
直接跳过 ⇒ 底色永远藏不掉。改成 inband 命中且文本为空时**只拦不收**。2) `VecSWCapture`
的 `x > 1752` 上界**删掉**。3) `SW_FRESH_MS`(150) 是**收集**保鲜期; 面板**取用**的
过期上限另用 `SW_STALE_MS`(1000) —— 混用时切模式那几帧收不到行 → 一块不画 → 顺势放行
原版。宁可短暂沿用上次内容, 也不能让面板凭空消失。4) 见 §4.1 的 anchor 兜底。

⚠️ 教训: **凡是"拦截/替换"用的位置判据, 绝不能写死某个模式的坐标**。写死的判据在
几何一变时会把"拦截"翻成"放行", 于是**原始内容反而漏出来** —— 症状出现在被替换内容
的位置上, 根因却在判据里, 极易误判成"锚点算错了"。

### 4.3b 派生锚点跟着 `SidebarBounds.X` 走, 所以那个全局必须稳定

侧栏图标拷进侧栏条用的落点, 是 `SidebarClass::ComputeLayout` (0x6A5130, 调用点
0x6A5326) 从 `SidebarBounds.X` 推出的一组**派生锚点**:

| 全局 | 值 |
| --- | --- |
| `[0xB0B4F4]` | `X + 0x16` = cameo 列起点 (实测 1752+22=1774) |
| `[0xB0B4DC]` / `[0xB0B4E8]` | `X + 0x14` / `X + 0x1A` (或 `X+0x21`, 随 `[0xA8B230+0x34B8]`) |
| `[0xB0B508]` | `X + 0x27` |
| `[0xB0B4F8/500/504/50C/510/514]` | 行列尺寸一组 |

**所以只纠正 `SidebarBounds.X` 不够**: 引擎紧接着跑 ComputeLayout, 它读到的
`ViewBounds` 是 R, 于是 `[0xB0B4F4] = R.Width + 22`, 拷贝落点变成
`R.Width + 22 - colX` —— 缩小档下是**负数**, cameo 全被拷到侧栏条外面。0.769 档
`R.Width = 1348`, `1348 + 22 - 1752 = -382`, 就是日志里那条
`blit: ... rect=4294966914,228,...` 的 x。

⚠️ **但修法不能是"每帧补调 0x6A5130 重推锚点"**: `flag!=0` 分支会照 `ViewBounds`(= R)
重算 `SidebarBounds.X`, 于是和 `Fm_SyncColumn` 每帧互相覆盖。而 `SidebarBounds.X`
同时是 `FM_Install` 那五处 imm32 补丁读的值 (含 `0x653A3F` = `RadarClass::Action`) ——
它一抖, 小地图原生点击链就断。正确做法是**只把列起点钉在 1x 的值上并保持稳定**,
锚点交给 `Fm_InitGuiForA()` 在 ViewBounds=A 下重跑一次 `InitGUI` 一次性写对。

**教训: 纠正一个"派生自某个全局"的值之前, 先查清还有谁在读那个全局。** 这里的
`SidebarBounds.X` 不只是"侧栏位置", 它还是五处补丁的**跳转表项**。

### 4.4 收集表归并键必须是 `(y, kind)`, 不是 `(y, |dx|<=6)`

引擎这批行的位置随侧栏模式**整体平移** (名 1722 / 计时器 1749 → 隐藏后 ~1890/~1917)。
按 x 邻近归并时, 平移后的行一律判成新行 ⇒ 表里同时留旧模式与新模式的行 ⇒ 很快撑爆
`SWCAP_MAX`(32) ⇒ 把后来的行整批丢掉 ⇒ **面板条目变少 (实测 11 条只剩 5 条, 且丢的是
先画的那几条)**。

按 `(y, kind)` 归并, 平移只是就地更新 `x` (那里本来就有 `r->x = x` 跟随漂移), 表大小恒定
= 行数×2; x 抖动 (±3) 由 x 跟随天然吸收。表满时改成**踢掉最陈旧的一行**而不是直接丢弃
—— 否则前面的陈旧行把最后几行永久占死。`VecSWCapture` 里那个"找重"必须用同一个键。

### 4.5 电力数字闪烁: 画字排在"条带上屏"之后, 晚一帧

**症状**: 电力条旁的数字时有时无。**不是透明度问题** —— `PwrBlitCache` 的 alpha=100
本来就是覆盖写, `PwrBoltPx` 更是 a=255 直写。**根因 = 顺序**。`BlitSbEntryDraw`:

```c
/* 错 */                 /* 对 (现状) */
FM_BlitSb();              PowerDisplay_DrawSb();
PowerDisplay_DrawSb();    FM_BlitSb();
```

`FM_BlitSb()` 就是把侧栏面 blit 上屏的那一步。字画在它之后 ⇒ 晚一帧。而 prepare 钩里画
的那份会被引擎 `SidebarClass::Draw` 的重画擦掉, "提前画"救不了 ⇒ **只有上屏之前画的那份
算数**。引擎每次重画面板的那一帧字就不在; 侧栏重画由引擎的重画标记驱动 (悬停/点击/数值
变化), 触发很随机, 看着就像闪烁。

同一条链上消息帧那一处顺序是对的: `FM_DrawRadarTo`(layer5) 先清条带再画,
`PowerDisplay_DrawSb`(layer6) 在它之后重画 —— 只有 `BlitSidebar` 入口这一处反了。

⚠️ 教训: **凡是"画在别人拥有的面上、靠呈现带上屏"的层, 绘制必须在呈现之前**。同一份
代码在消息帧里顺序对、在呈现钩里顺序错, 症状只表现为间歇性闪烁, 极易误判成透明度/累积/
重画门控问题。(顺手加的"擦脚印"黑填充还会引入黑边, 纯负作用。)
⚠️ 另: 超武侧栏**不要**为了"躲开右下角倒计时列表"偷偷减可见行数。行数由
`[SWSidebar] MaxRows` / `TopMargin` 调, 整块也能用显隐按钮收起。

### 4.6 视口字节窗口"永远装不上": 状态探测把初始态当成外部改动

**症状**: 隐藏侧栏 (态1/2) 时地图破碎 + 残影; 日志出现
`fullmap: viewrect bytes mismatch (to vanilla)`。

`Fm_ViewPatchSet` 原来"**假定自己装过**": 拿"**相反态**"的字节当预期。初始态是
`Mode=0`, 此刻磁盘上本来就是原版态, 代码却在找全宽态 ⇒ 必然 mismatch ⇒
`s_ViewPatched = -2` ⇒ **之后 `0x72AD20` 永远不会被打开**。态1/2 下另外三十来个调用点
(`0x63xxxx` 格/视图求交、`0x77830C` 缩放中心等) 仍返回 1752 宽的矩形去配 1920 的
`ViewBounds` ⇒ 花屏。

**修法**: `Fm_ViewPatchDetect()` 先从当前字节判态 (原版/全宽/都不是), 只有"两种已知态
都不像"才判外部改动停手。

### 4.7 建面矩形高度: 读档与新开局必须逐字段相同

`CreateAll` 用同一个 viewRect 建 Composite (`0x88731C`) 与地图面 (`0x8872FC`), 紧接着
`Set_View_Dimensions` 拿它去重建裁剪器。

* **新开局** (0x6BDE14): `{0,0,clientW,clientH}` —— 高度**不减**那 32 → 1920x1080
* **读档** (0x560F9C / 0x67E776): 原来给的是原版 `H-32` → 1920x**1048**

条带 168x1080 往 1048 高的面上只盖得住 1048 行, 再往下那 32 行既没被条带写也不会被
地图画 (视口高 1048) ⇒ **永远留着旧像素的残影带**, 跟着画面一起动。这是"同样的侧栏,
新开局正常、读档出残影"的唯一结构性差别。

**修法**: `Fm_ViewRectStub` 高度改成不减 (`clientH`); `ViewBounds.Height` 由
`Fm_ApplyViewWidth` 下一句就纠正回 `clientH-32`。配套 `Fm_CoverColumnTail` 把目标列
"没被 blit 覆盖到"的尾部抹黑兜底。

⚠️ **`Fm_CoverColumnTail` 只在态0 用** (`if (!Fm_ModeFull()) return;`)。态1/2 视口
整宽, 侧栏列归**地图**所有 —— 抹黑就是把地图擦成一条黑带, 而且地图是增量画的, 擦完
不会自己回来。症状: "小地图模式下侧栏列下面一片黑"。判断依据只能是"**这一列归谁**"
(= 视口覆不覆盖它), 不能按"条带有没有盖全"。

### 4.8 可见区裁剪器必须与视口同源 (读档才出现的"未探索的区域")

`DisplayClass::Set_View_Dimensions` (0x4A8960) 除了写 `ViewBounds` + 调
`SetTacticalViewBounds`, 还做三件**只调 0x6D5F60 做不到**的事:

| | 内容 |
|---|---|
| (a) | 用 `ViewBounds` **重建两个可见区缓冲** (2026-10 更正: 它们不是 ClipperClass, 而是 `ZBufferClass` 构 0x7BC970 与 `ABufferClass` 构 0x410CE0, 每像素 2 字节, Render 每帧还要 memset 清零; 见 notes/地图缩放.md §1/§4) `[0x887644]`/`[0x87E8A4]` —— 结构相同: `+0..+0x0F` 是那个矩形, `+0x20 = W*H*2`, `+0x28/+0x2C = W/H`, `+0x24 = 0x8000`, 带 `Clip(x,y,flags)` |
| (b) | 重建 `WWMouseClass` 的视口 (vtable `+0x0C`; 0x4A89C2 **不判空**就解引用) |
| (c) | 末尾 `call DisplayClass::InitGUI` (0x6ABD30) 重排侧栏 |

旧代码只写 `ViewBounds` + 0x6D5F60 ⇒ (a)(b) 停在**建面时**的宽度; 而建面恒全宽 ⇒
引擎内部长期是"视口 1752 / 裁剪器 1920"。**读档必现**: `CreateAll` 之后紧跟一次
`Set_View_Dimensions`(我们给的 1920 矩形), 之后没人再重建 (新开局走另一处调用点拿到真
1752, 所以正常)。鼠标落在侧栏列上时被按 1920 的范围当成"还在地图里"去查格, 那一格在
地图之外 ⇒ 侧栏标题栏报"未探索的区域"。

**修法**: `Fm_ApplyViewWidth` 里宽度真变时额外走一次 `Set_View_Dimensions`。安全阀:
只在宽度真变时调 / 引擎帧号门控一帧一次 (prepare 一帧上百次) / `WWMouseClass` 必须在 /
`s_InSetViewDims` 防它末尾 `InitGUI` 重入。

### 4.9 脏区要标**整窗**, 不是标视口

视口宽度一变, 视口外那条 (侧栏列所在) 从来没被引擎当视口的一部分标过脏, 留的还是上
一模式的像素 —— 只标视口治不好那条带。`Fm_DirtyRedraw` 改成 `{0,0,WindowW,WindowH}`
(客户区相对, 不碰 `TacticalPos`), 触发条件从"宽度变了"放宽成"几何 (x/w/h) 变了"。

### 4.10 DllMain 里必须先确认宿主映像在

`FM_Install` 由 `DllMain` 调, 而 Syringe/CnCNet 链路上它可能在 gamemd 映像还没落到
0x400000 时就被装进某个进程 ⇒ 读 0x72AD69 时 `0xC0000005`。实测第一次启动就是这个
(`vtext` / `chatedit` 的字节核对同样第一次失败)。

**修法**: `Fm_HostImageOk()` 要求 0x400000 已提交且是 PE 头, 且该模块文件名是
gamemd.exe / ra2md.exe; 不在就一个字节都不写 (原版几何, 侧栏照旧) —— 半装远比不装糟。
⚠️ 别只查 `GetModuleHandleA("gamemd.exe")`: 换个壳启动就查不到, 功能会静默失效。

### 4.11 缩放档侧栏列光标闪烁: 条带 blit 的横坐标与光标烙印的横坐标不同源

**症状**：非 1x 时侧栏那一列光标忽隐忽现（频率不固定，鼠标动不动都闪）；1x 不闪；F11 藏掉侧栏后那块不闪。

**根因 = 呈现路径里两个横坐标基准被换掉了一个。** 原版 `BlitSidebar` (0x6A70E0) 在同一处用**同一个**字段 `[0x886FA8]`(= `ViewBounds.Width` = 缩放档的 R) 做两件事：

| | 落点 |
|---|---|
| 烙光标精灵进条带 | `0x6A71B7` `mouse->vtable[0x3C](Sidebar面, 1)`；其 isNOD 分支 `0x7B910E` 读该字段取负 ⇒ 精灵落在 `光标屏幕X − ViewBounds.Width` |
| 条带上屏 | `0x6A71D0` `dst.X = 客户原点X + (isNOD ? ViewBounds.Width : 0)` |

`FM_BlitSb` 把 blit 目标换成了 `Fm_ColumnX(0)`，而它读 `s_ViewA`（**A**，刻意不跟缩放走）。1x 时 A==R 两者相等；缩放档差 `A.Width − R.Width` ⇒ 精灵落到错位置、真实光标处被普通侧栏内容盖掉、列上多一道鬼影；R 每次换挡/滚动重新居中 ⇒ 偏差在 0..差值间跳 ⇒ 频率不固定。态2 不 blit 条带 ⇒ 不闪。

**修法**（`Fm_CursorStampStrip`）：调 `vtable[0x3C]` 期间把 `ViewBounds.Width` 借给 `colX`，调完立刻还原。整条 flag=1 分支只读这一个字段（flag=0 分支读 `SidebarBounds.Y` 与面高，无关），中间无引擎代码。盟军侧栏（isNOD=0）引擎本来就用 0、`colX` 也是 0，不动。同时把这次烙印从"算 dst 之前"挪到"算完 `colX`、条带 blit 之前"（原版本来也在 blit 之前，相对顺序未变）。

**不变量**：接管呈现路径时，**引擎在这条路径内部用来推导坐标的全局（此处 `ViewBounds`），呈现目标与精灵定位必须继续读同一个**。只改呈现目标而留着配套的定位调用 = 让引擎按两套坐标画同一个东西。

## 6. 不要试 (死路清单)

| 试过 | 结果 |
|---|---|
| 钩 `GScreenClass::CreateAll` (`0x533FD0`) 改建面矩形 | 崩 (`0xC0000005` / `EIP=0`)。改调用点字节就行, 不用钩 |
| 钩 `MapClass::CreateEmptyMap` (`0x653F50`) 拿地图矩形 | 崩 (跳板返回之后)。现已不需要地图矩形: 跳转交给原生 `RadarClass::Action` (§2.4) |
| 补 `0x72AD90` (想统一视口矩形函数) | W 变 1920, `SidebarBounds.X` 更错 |
| `0x6BDDC8` 写成 `sub eax,eax` 而非 nop | **新游戏必崩** (§3.1) |
| 视口字节窗口"假定自己装过" (拿相反态当唯一预期) | §4.6。初始态必然 mismatch ⇒ 永久停手 ⇒ 态1/2 花屏 |
| 只写 `ViewBounds` + `SetTacticalViewBounds` 就当视口同步完了 | §4.8。裁剪器 `[0x887644]/[0x87E8A4]` 与 WWMouse 视口不会跟着走 |
| 字节补丁按"看起来等价"写, 不反汇编核对落地字节 | 字节补丁只认逐位语义 |
| 五处横向偏移补丁"必须全部匹配才一起打" | ★ 已改成逐处安装。原先一处对不上就一处都不打, 会连坐掉 `0x653A3F`, 原生链整条死掉 (§2.3) |
| 每帧补调 `SidebarClass::ComputeLayout` "重推"侧栏派生锚点 | `flag!=0` 分支会照 `ViewBounds`(=R) 重算 `SidebarBounds.X`, 与 `Fm_SyncColumn` 每帧互相覆盖; 而那正是五处补丁读的值 ⇒ 小地图点不动 (§4.3b) |
| `PatchAt` 落点只按"函数入口首 4 字节"猜 | 强制 `n >= 5`, 会把下一条 4 字节指令劈两半。**不能假设"指令首字节 = 指令长度"** (`A1 disp32` 是 1 字节 opcode) |
| `BytesSame` 的 `n` 小于数组长度 | 钩子静默不装, 日志只有一行 `bytes mismatch` |
| `SetUnhandledExceptionFilter` 做崩溃捕获 | 会被后加载的模块 (YRPP / Ares) 随手覆盖。改用 `AddVectoredExceptionHandler` (`MOE.cpp` 的 `Moe_CrashFilter`), 命中后照旧 `EXCEPTION_CONTINUE_SEARCH`, 只打现场 |
| 每帧强制面板面重画治"内容随鼠标漂" | 擦掉刚画好的小地图 ⇒ 闪烁。那个症状的真正原因是 blit 用了错矩形 (`0xB04A00` 那个 72x18 小控件) |
| 往 `Primary` 抹黑 / 呈现路径上追加擦干净 | §4.2 两条错路 |
| 写 `MapClass::Redraws` | Phobos/Ares 都不写它, 语义没文档 |
| `FM_Poll` 里采"按下沿"写进点击门的 `s_LbPress` | `0x4F42F0` 一帧能被调好几次, 边沿可能在 press 事件**之后**才被采到 ⇒ 门永远错过那一帧。门里直接读 `GetAsyncKeyState` + 松开时清标记 |
| 侧栏面呈现位置改读 `SidebarBounds.X` | §3.5 |
| 摘 gadget 按 `sb->X` 筛 | 态2 它已被推成路由阈值 ⇒ 整列 244 个全漏筛 |
| 用 `FM_MapRightEdge` 之外的锚点 (画布宽) 贴右下角层 | §4.1 |
| 拦截判据里写死某模式坐标 | §4.3 末 |
| 按"条带有没有盖全"决定要不要擦一列 | §4.7 末。**按"这一列归谁"(视口覆不覆盖它)** 判 —— 态1/2 侧栏列是地图的, 擦了就是黑带 |
