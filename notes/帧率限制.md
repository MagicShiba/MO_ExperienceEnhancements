# ESC 菜单/设置页限帧 (FrameCap)

代码: `src/perf/FrameCap.cpp` / `FrameCap.h`。配置只有 `[FrameCap] Enable=1`（ESC 菜单 GUI 页「杂项」里也有开关），帧率固定 60，不显示 fps。

**只在 ESC 菜单（含各级设置子页）打开时限速**，菜单关掉立刻完全放行 —— 对局与联机零影响。本 MO 通过启动器直接进对局，没有大厅/主菜单，所以判定不看 `ScenarioStarted`。

## 为什么需要

引擎 MainLoop (`0x55D360`) 和 Main_Game 循环 (`0x48CE8A`) 都没有帧率节流，唯一的等待是窗口失焦分支 (`0x55D387`) 的 `Sleep`。聚焦时帧率完全交给 DirectDraw 阻塞：窗口化 + 无后台缓冲时渲染退化成 Blt，cnc-ddraw 的 `dds_Blt` 只 `ReleaseSemaphore` 唤醒独立渲染线程，游戏线程不被阻塞（它的 `maxfps` 也只限那条渲染线程）。ESC 菜单打开后游戏逻辑暂停、每帧极轻，主循环能跑到上千 Hz，单核打满。

不用 ddraw.ini：启动器每次启动都用 `Resources` 里的模板覆盖 `ddraw.ini`，且 ddraw 在 MOE 注入前就读完了 ini。

## 挂点（一个模式只有一个节拍器）

| 位置 | 角色 |
|---|---|
| `PV_MainGate` (`0x55D360`) | 主循环**还在推进帧号**时，只有这里节拍 |
| `PeekMessageA` IAT (`0x7E1484`) | **只有"队列空"的那次**参与节拍；帧号冻结（模态循环）时只有这里节拍 |

- 模式判定 `FC_Mode()`：菜单开着 + 帧号还在动 → LOOP（门节拍）；菜单开着 + 帧号 120ms 没动 → MODAL；没注册对话框的子页面靠帧号冻结 300ms 判 MODAL；载入屏相位 `0xA9FAB0` 在 1~3 时一律不限；`GameMode` 3/4（联机）一律不限。
- **不再在 Render 尾 (`0x4F4589`) 限帧**：那里现在只画 Ares 计数器。三个挂点各推一次 deadline 会让一轮迭代推后 2 个周期（实测掉到 37fps）。
- LOOP 模式下还会读"帧周期估计"（只在我们没等的帧采样，EWMA）：>= 15ms 就认为引擎自己的帧定时器 `0x55E160` 已经在压，本帧不再等 —— 否则 GameSpeed 档位非 MAX 时会被叠加成 30fps。
- **未到帧时刻必须等（让出 CPU），不能只 `return`** —— 模态循环是 `while (!PeekMessage(...))` 空转（实测 175 万次/秒），只 return 等于放任它全速跑，帧率数字看着是 60 但 CPU 一点不降。
- 只限主线程（`GetCurrentThreadId() == s_MainTid`）。

## 反例：这些做法一定出问题

`GetTickCount() + s_Next += 17 + Sleep(wait-1)` 这种写法有四个毛病（`tools/fcmodel.c` 可复现）：

| 毛病 | 实测 |
|---|---|
| `GetTickCount` 分辨率 16ms，`Sleep` 向上取整 | `Sleep(16)` 平均 **29ms**（15~37）、`Sleep(15)` 18.4ms、`Sleep(1)` 13.7ms —— 17ms 的节拍根本凑不出来 |
| 每次放行只 `+17`，落后也不重排；三挂点各推一次 | 一轮迭代 3 个挂点 + 6ms 帧体 → **37fps** |
| 连"已经取到消息"的那次也压 | 消息吞吐钉在 ~60 条/秒，输入一流就堆：500Hz 投递 3 秒 → 积压 728 条、最大延迟 **1.5s** |
| `Sleep` 不可被打断 | 点一下要等满一个周期（最坏 30ms） |

单挂点配置下平均能到 ~100 帧，但帧间隔是"一半 0ms、一半 30ms"的抖动（实测 3 秒内 177 帧 <5ms、58 帧 20~35ms）—— 视觉上就是顿挫，不是 60 帧的均匀。

现在的做法：**QPC 绝对时刻 + `MsgWaitForMultipleObjects(QS_ALLINPUT)`**（有输入立刻返回，点击不再等满一个周期）+ **只在队列空时压** + **限速期间把系统定时器提到 1ms**（只开不关，见下）。实测静止 60.3 帧/秒（间隔 5~20ms 占满），500Hz 投递下积压 5 条、最大延迟 3ms。

定时器精度只开不关的原因：GameSpeed 的 >60 档也要 1ms，反复 `timeBeginPeriod/timeEndPeriod` 会让切档后第一个窗口掉回 15.6ms 粒度。**副作用**：精度提到 1ms 后 `Sleep(1)` 不再是 15.6ms，所以 `PV_MiniLoop`（暂停overlay）的 `Sleep(1)` 换成了 `MsgWait(15)`，别再改回去。

## 坑：cnc-ddraw 会抢走这个 IAT

cnc-ddraw 第一次建 DirectDraw 时（`dd.c` 的 `hook_init`）把游戏模块里的 `user32!PeekMessageA` 槽直接改成它的 `fake_PeekMessageA`，我们的钩子会被整个绕过。所以每次 `FC_Cap` 比一次槽位（只是指针比较），不是我们就挂回去，链条变成 `fc → cnc-ddraw fake → 真函数`，两边功能都保留。

**重挂只碰两种槽**：还没被动过的 `user32!PeekMessageA` 本体（init 时自己 `GetProcAddress` 记下来），和 cnc-ddraw 的 fake（`IsCncDdraw()`，判据是 7.x 独有的导出 `DDGetProcAddress`/`DDIsWindowed`/`DDEnableZoom`）。别家 ddraw 包装器可能把"当时槽位的值"（= 我们的函数）当 `real` 缓存，挂上去会 `fc → 它 → fc …` 递归爆栈。

**不能用的挂点（会崩，别再试）**：

| 地址 | 结论 |
|---|---|
| `0x623120` | 20+ 处 `jmp` 直接跳进来的共享代码块（`0x4F115D jmp 0x623120` 就在 ESC 菜单路径上）。装钩会破坏执行流，打开 ESC 设置页必崩 `0xC0000005` |
| `0x48D080` | 常规序言，能跑但只覆盖菜单 tick，设置页仍限不住 |

## 判定：对话框可见 **或** 帧号冻结

子页面（游戏控制 / 载入游戏 / 储存游戏 / 删除游戏 / 放弃任务）不走注册对话框那条路，打开时首页还会被隐藏。所以两条取或：

1. 注册的 ESC 对话框可见（`FrameCap_SetActiveDlg`，由 `Esc_OnShow` 告知，首页路径）；
2. 引擎帧号 `0xA8ED84` 超过 300ms 不推进 —— 进了模态循环，主循环必然停摆（子页面唯一可靠信号）。

- 读盘时帧号同样不推进，用进度屏相位 `0xA9FAB0`（1/2/3 = 载入中）排除，免得限速读盘。
- 判定结果缓存 20ms：空转时每秒会被调用上百万次，不缓存仅判断本身就够费。
- 子页销毁时 `SetActiveDlg` 回退到首页（首页可能还开着），否则菜单被误判为关闭。
