# 箱子类型

箱子内容 = **一个字节** `CellClass + 0x11E`（YRpp 的 `OverlayData`）。0~18 = 确定类型，
**≥19（运行时放的一律 0xFF）= 未定，拾取那一瞬间才按权重 roll**。所以随机刷出来的箱子在
拾取前没有"类型"可读；能显示确定类型的只有地图预置的箱子和触发动作 108 放的箱子。

所有地址来自 gamemd.exe 反汇编。

## 1. 谁读它

`CellClass::CollectCrate(FootClass*)` = `0x481A00`：

```
0x481A1C  overlayIdx = cell->OverlayTypeIndex        (+0x44)
0x481A31  if (!OverlayTypes[overlayIdx]->Crate) return   (+0x2AA = Crate 标记)
0x481AC8  idx = cell->OverlayData                    (+0x11E)
0x481ACE  if (idx >= 0x13)  → 按权重 roll（消耗共享 RNG）
0x481B2B  if (GameMode == 0 && cell->OverlayData == 0) → 按箱子图像类覆盖
0x481D52  if (cell->LandType == 2 /*Water*/ && !allowed[idx]) → idx = 0
0x481DB8  if (idx == 6) idx = 0                       /* Squad 实际算资金 */
0x481DDC  switch (idx) 跳 0x4833C4 表（0~17）
```

四张全局表（不是 RulesClass 成员，随存档序列化，`0x67F940` 起）：

| 地址 | 类型 | 含义 |
|---|---|---|
| `0x81DA8C` | int[19] | 权重（exe 初值 = 原版权重，被 `[Powerups]` 覆盖） |
| `0x81DAD8` | int[19] | 拾取动画索引，-1 = 无（exe 初值全 -1） |
| `0x89EC28` | double[19] | 参数（钱数 / 倍率 / 伤害） |
| `0x89ECC0` | byte[19] | **允许出现在水上**，水上格且为 0 时强制成 0 = 资金 |
| `0x7E523C` | char*[19] | 名称→索引的权威表（`[Powerups]` 解析器 `0x673EA2` 按此顺序循环） |

roll 在 `0x481AF0`：`Random::RandomRanged(1, 总权重)` 后累加比对（`0x65C7E0`，
RNG 在 `0xA8B230 + 0x218`）。**这一步消耗全局共享 RNG。**

- 标准权重合计 **66**，Bounty Hunt 也正好 66。

- MO 的 `INI/Map Code/*.ini` 里 `Explosion ;4/5`、`Napalm ;X` 这些注释不准，以本表为准；
  BH 的 `Invulnerability=3` / `IonStorm=3` 按分派表是空气箱子。

## 3. 运行时放箱子 = 一定未定

`CellClass::PlaceOverlay`（`0x5FD060` 起）：普通 overlay 把 `+0x11E` 清 0，是箱子时
`0x5FD105 mov byte [ebp+0x11E], 0xFF`。`MapClass::PlaceRandomCrate`（`0x56BD40`）
→ 256 槽箱子表（`MapClass+0x158`，每槽 0x10：+0 生成帧 / +8 寿命 / +0xC 格坐标）
→ 放 overlay → 0xFF。只有地图文件的 `OverlayDataPack` 能带预设值。

`0x481DB8` 的 `cmp ebx,6 / jne / xor ebx,ebx` 让类型 6 在分派前变成 0，地图作者写 6
拿不到"随机金额"。

## 4. 字节 0 的图像类覆盖（只在 GameMode == 0 且字节 == 0 时）

`0x481B58`~`0x481B94` 顺序判 `Rules.CrateImg`(+0xFC) → `WoodCrateImg`(+0xF8) →
`WaterCrateImg`(+0x100)，**后者覆盖前者**，命中则取 `Rules.SilverCrate`(+0x1464) /
`WoodCrate`(+0x1468) / `WaterCrate`(+0x146C)。MO 的 `CrateImg=CRATE` 与
`WoodCrateImg=CRATE` 是同一个 overlay（只有两个 `Crate=yes` 的 OverlayType：
CRATE / WCRATE），所以最终取 **`WoodCrate=Money`** —— MO 里字节 0 永远是金钱箱。
字节 1~18 不过这道映射。

## 5. 箱子从哪来（全库扫描结论）

工具 `AutoLoadDev/tools/mapcrate.py`（base64 → LCW 解块 → 512×512 的 OverlayPack /
OverlayDataPack）解了 `MapsMO` 下 778 张图：

- **overlay 预设格子全库只有 5 个**（coop_ahypo ×2、jungleboogie ×3），字节全是 0。
- 真正的来源是**触发动作 108 Create Goodie Crate**：61 张图、549 次。内容分布：

| 内容 | 类型 | 次数 |
|---|---|---|
| 金钱(随机) | 6 | 260 |
| 医疗 | 2 | 88 |
| 升级 | 14 | 63 |
| 防御力强化 | 9 | 40 |
| 大量金钱(固定值) | 0 | 37 |
| 火力强化 | 11 | 29 |
| 速度强化 | 10 | 25 |
| 一次核弹 | 12 | 4 |
| 重置黑幕 / 显示全图 / 空 | 7 / 8 / 15 | 各 1 |

  未被使用：1 随机单位、3 隐形、4 爆炸、5 大型爆炸、13 空、16 毒气、17 一片矿。

- 编辑器侧 `FAData_TriggerAndScript.ini`：`108=Create Goodie Crate at...,0,31,...`，第 2 参数
  = `Crate type`（枚举 = `[Chinese-CrateTypes]` 0~17）。引擎侧一致：动作分派
  `0x6DD8E7 jmp [edx*4+0x6DFDEC]`，**索引 = 动作号-1**；动作 108 处理在 `0x6DF69B`，
  `[esi+0x44]` 当路点、`[esi+0x90]` 当内容，调 `MapClass::PlacePowerupCrate`（`0x56BEC0`），
  其中 `0x56BFF9 mov [eax+0x11E], dl` 把内容写进格子；内容 == 0x14 时**不写**（留 0xFF = 随机）。
- 预设字节为什么留得住：读图 `0x5FD3F6` 跑两遍 —— 第一遍按 OverlayPack 建 OverlayClass
  （`0x5FD105` 先写 0xFF），第二遍（`0x5FD5FB`~`0x5FD640`）读 OverlayDataPack，
  `0x5FD640 mov [eax+0x11E], dl` 逐格无条件覆盖。

### 稀有箱子（核弹 / 黑幕 / 全图 / 空）

只有 4 张图用了，共 7 条动作 108，路点全是 0（落在玩家起始点附近）：

| 内容 | 地图 | 事件 | 挂着什么 | 能否出现 |
|---|---|---|---|---|
| 12 核弹 | i_elusivebridges | 7 被任意所属方摧毁 | Movie Theater / Smithsonian Castle | 是（另有一条标签孤儿） |
| 12 核弹 | f_skymountain `_Small objects_1` | 48 被任意方式摧毁 | 标签孤儿 | 否（触发器禁用） |
| 7 重置黑幕 | f_skymountain `_Small objects_2` | 48 | Alcatraz Lighthouse | 否（触发器禁用） |
| 8 显示全图 | coop_apanzer | 13 流逝时间 2 分钟 | 未挂载 | 是 |
| 15 空 | coop_asarin | 13 流逝时间 0 | 未挂载 | 是（发了等于白发） |

- `[Triggers]` 第 4 字段 1 = 开局禁用；f_skymountain 全图没有任何 53/54/22 动作 → 永不触发。
- 时间类事件（13）不需要把标签挂到对象上也会跑（22 张挑战图的 `[Start] Crates` 同样只在
  `[Tags]` 里，实测照出 8 个箱子）。"标签孤儿"只对对象事件（7/48）致命。
- 事件 7 = 被任意**所属方**摧毁（友伤/附带伤害不算），48 = 被任意方式摧毁。
- 13 Invulnerability 与 1/3/4/5/16/17 全库无人使用。

## 7. 图标实现（src/gui/CrateIcon.cpp）

数据链只有两跳，和 `CollectCrate` 读的是同一份：`CellClass+0x44` → `OverlayTypes`
（Items `0xA83D84` / Count `0xA83D90`）→ `OverlayTypeClass+0x2AA Crate`；再取
`CellClass+0x11E` 的类型字节。

**不要用 `OverlayClass::Array` 反推箱子位置**：构造 `0x5FC380` 里 `0x5FC4A5 test eax,eax /
jne 跳过` —— 只有 `0x47C550(cell)` 回 0 时才 `0x5F4EC0` 设 Location，否则停在 (0,0,0)。
按对象坐标 `>>8` 会把所有箱子塌到 (0,0)。所以只扫视图区覆盖的格子：
`GV_ViewCellRect()`（四角反投影 + 2 格余量）→ 逐格 `OU_CellPtr`。视野约 40×30 格，
200ms 重建一次；超过 20000 格（拉远到整图）直接跳过。

判定：类型字节 ≥ 19 不显示；16/17/18 没有图标；6 复用金钱图标（引擎把 6 改写成 0）。
图标贴图 `icon_crate_type.pcx`，216×50，9 列 2 行，单格 24×25，键色 `0xF81F`。

投影点 `OU_ProjWorld` 不是木箱的视觉中心，图标要左移 2px、上移 4px 才居中对齐 →
`CI_OFF_X=-2` / `CI_OFF_Y=-4`，改观感只动这两个。

### 画在哪一层

画在 **Composite**（`MsgDrawBody` 里、天气之后、`MOE_DrawUILayers` 之前），`GtLock`/`GtUnlock`
成对取像素，每帧重画（Composite 每帧被引擎重铺）。

**不要往引擎的地图缓冲 `[0x87E8A4]` 里写**：它是环形缓冲（滚图只改 `+0x10` 偏移），而取址
函数 `0x4114B0` 内部 `Lock(x,y)` 之后**立刻 `Unlock()`**，只在调用方已持锁时返回的指针才有效。
在自己钩子里调它拿到的是失效指针：写不进屏幕，还会写坏堆（崩在 `exe+0x9810C`
`mov dx,[ecx+edx*2]`）。

### 黑幕下怎么画

游戏根目录有没有 `shroud.shp` 就是判据（原版黑幕打包在 mix 里，只有换成半透明黑幕的玩法
才在根目录放这个文件；`PvpNotice.cpp` 也用它判"开了透明迷雾"）。`Ci_Init` 里只算一次：

| 有 shroud.shp | 该格在黑幕下 | 画法 |
|---|---|---|
| 有 | 是 | 照画，RGB565 每通道右移一位（≈ 50% 亮度） |
| 有 | 否 | 照画，原色 |
| 无 | 是 | 不画（不透明黑幕整块盖死，还会泄露位置） |
| 无 | 否 | 照画，原色 |

黑幕判定读 `CellClass+0x12C` 的 bit3（`CELL_SHROUD_REVEALED`）：未置 = 还在黑幕下。
`CellClass::Unshroud 0x4876F6 or al,0x18` 置 bit3|bit4、`MapClass::Reshroud
0x577B48 and ecx,0xFFFFFFE7` 清 bit3|bit4。迷雾（已探索、视线外）是 `+0x140` bit1，本功能不看。
**不要调 `CellClass::IsShrouded 0x487950` / `MapClass::IsLocationShrouded 0x586360`**：
内含 `idiv [0xABDE88]`（LevelHeight，镜像初值 0），载入期调用会除零。

### 开关

`[CrateIcon] Enable`，ESC 设置页「杂项」组第一行（`GUI_ITEM_CRATE` → `s_Toggle` 表 →
`CrateIcon_On` / `CrateIcon_SetOn`），改动即时生效并落盘；`SetOn` 作废视野键与列表。
