# 箱子类型调查与显示方案

（调查结论，2026-10；所有地址均来自 gamemd.exe 反汇编实证）

## 0. 结论速览

1. 箱子内容 = **一个字节**：`CellClass + 0x11E`（YRpp 里叫 `OverlayData`，注释就是
   "The crate type on this cell"）。取值 0~18 = 固定类型，**≥19（运行时放的都是 0xFF）=
   没定，拾取那一瞬间才按权重 roll**。
2. 所以**联机/单机随机刷出来的箱子，在拾取前根本没有"类型"这个东西**，读不到。
   想显示确定内容，必须先让它有类型 = 改变随机流程（见 §5 方案 B）。
3. 能只读显示的只有两类：地图里预置的箱子（OverlayData 来自地图 OverlayDataPack），
   以及被我们自己定了型的箱子。剩下的只能显示"概率表"。
4. 类型共 19 种，但真正有代码处理的 16 种；`Invulnerability(13)` / `IonStorm(15)` /
   `Pod(18)` 引擎里只有动画没有效果。

## 1. 类型存在哪 / 谁读它

`CellClass::CollectCrate(FootClass*)` = `0x481A00`（YRpp 同名）。顺序：

```
0x481A1C  overlayIdx = cell->OverlayTypeIndex        (+0x44)
0x481A31  if (!OverlayTypes[overlayIdx]->Crate) return false   (+0x2AA = Crate 标记)
0x481AC8  idx = cell->OverlayData                    (+0x11E)
0x481ACE  if (idx >= 0x13)  → 按权重 roll（消耗共享 RNG）
0x481B2B  if (GameMode == 0 && cell->OverlayData == 0) → 按箱子图像类覆盖
0x481D52  if (cell->LandType == 2 /*Water*/ && !enabled[idx]) → idx = 0
0x481DB8  if (idx == 6) idx = 0                       /* Squad 实际算资金 */
0x481DDC  switch (idx) 跳 0x4833C4 表（0~17）
```

- 权重表 `0x81DA8C[19]`(int)，动画表 `0x81DAD8[19]`(AnimType 索引, -1=无)，
  参数表 `0x89EC28[19]`(double，钱数 / 倍率 / 伤害)，开关表 `0x89ECC0[19]`(byte，
  **含义是"允许出现在水上"**，水上格且为 0 时强制成 0=资金)。
  这四张表是全局变量（不是 RulesClass 成员），随存档一起序列化（`0x67F940` 起）。
- 名称→索引的权威表：`0x7E523C[19]`（`[Powerups]` 解析器 `0x673EA2` 按这个顺序循环）。
- 权重 roll：`0x481AF0` `Random::RandomRanged(1, 总权重)` 后累加比对
  （`0x65C7E0`，RNG 在 `0xA8B230 + 0x218`）。**这一步消耗全局共享 RNG。**

- 标准权重合计 **66**；Bounty Hunt 也正好 66。
- 效果分派跳转表：`0x4833C4[18]`，`idx > 0x11` 一律走 `0x4832F5`（只播动画）。
- 拾取反馈动画 = `[Powerups]` 第 2 字段（`ARMOR`/`MONEY`/`FIREPOWR`/`SPEED`/`VETERAN`/

  以本表为准；BH 里 `Invulnerability=3` / `IonStorm=3` 按引擎分派表是**空气箱子**
  （建议实测确认，见 §7）。

## 3. 运行时放箱子 = 一定"未定"

`CellClass::PlaceOverlay`（`0x5FD060` 起）：

```
0x5FD0B2  cell->OverlayTypeIndex = idx
0x5FD0CC  cell->OverlayData = 0            (普通 overlay)
...
0x5FD105  mov byte [ebp+0x11E], 0xFF       (OverlayTypes[idx]->Crate != 0 时)
```

即：**只要是箱子，运行时放下去一律 0xFF**。`MapClass::PlaceRandomCrate`（`0x56BD40`）
→ 256 槽箱子表（`MapClass+0x158`，每槽 0x10 字节：+0 生成帧、+8 寿命、+0xC 格坐标）
→ 放 overlay → 0xFF。只有地图文件里的 `OverlayDataPack` 能带预设值。

## 4. 战役里的图像类覆盖（只在 GameMode==0 且字节==0 时）

```
if (overlayType == Rules.CrateImg      /*+0xFC*/) idx = Rules.SilverCrate /*+0x1464*/
else if (overlayType == Rules.WoodCrateImg /*+0xF8*/) idx = Rules.WoodCrate /*+0x1468*/
else if (overlayType == Rules.WaterCrateImg /*+0x100*/) idx = Rules.WaterCrate /*+0x146C*/
```

MO 的 `WoodCrateImg=CRATE` 与 `CrateImg=CRATE` 是**同一个 overlay**，
比较顺序里 `CrateImg` 在前 ⇒ 战役地图上普通的 CRATE 走 **SilverCrate=HealBase（维修）**，
`WoodCrate=Money` 实际到不了。显示端要照抄这段逻辑，否则战役里会显示错。

## 5. 显示方案

### 方案 A（只读，零风险，建议先做）

- 触发：鼠标所在格（`OU_MouseCell`）是箱子 → 在格上方画一行标签。
- 内容分两种：
  - 字节 < 19（地图预置 / 我们定过型）：显示确定类型（含 §4 图像类补正、§1 水上补正）。
  - 字节 ≥ 19：显示 `?` + 全表概率（`0x81DA8C` 权重 + `0x89ECC0` 水上开关，实时算，
    地图换了 `[Powerups]` 也自动跟着变）。
- 成本：一格一次读内存 + 一行矢量文本，可忽略。
- 缺点：随机箱子看不到确定内容（物理上不可能，见 §0）。

### 方案 B（让箱子先有类型，才谈得上"显示箱子类型"）

在 `0x5FD105`（7 字节 `C6 85 1E 01 00 00 FF`）挂钩，把 0xFF 换成我们自己按权重选的
索引，返回 `0x5FD112`。写进 `CellClass+0x11E` 之后：

- 引擎自己就当"固定类型"用，拾取处不需要再挂钩；
- 存档/读档自动带上（OverlayData 属于 CellClass，随地图存）；
- 不需要自建表、不需要额外同步事件。

选型两种：

- **B1 用共享 RNG**（和引擎同表同算法）：所有客户端结果一致，但会改变全局随机数流
  （AI/动画/其它系统全部跟着错位）——对"体验优化"类 mod 影响面过大。
- **B2 自算 hash**（`hash(格坐标, 生成帧)` 再按权重取档）：**完全不碰共享 RNG**，
  各端独立算出同一个结果，对原版随机性零影响。推荐。

联机：按项目铁律，先只对 `GameMode 0/5`（战役、单机遭遇战）启用；`3/4`（LAN/Internet）
不挂钩。若将来要放开，前提是确认"箱子生成在每一端都执行同一路径"，且各端 DLL 一致。

### 方案 C（纯提示，不做 B）

悬停只显示概率表。适合"不想动任何玩法"的场合。

### 绘制落点

- 取格 → 屏：`CoordsToClient`(0x5B1A00 一类) + `SB_ViewToScreen`，Z 用
  `OU_CellFloorZ` / `CellClass::GetFloorHeight`；写法照抄 `gui/GridView.cpp:GV_ProjCorner`。
- 文本走 `VecText`（同 `preview/*`、`gui/GridView`）；图标可选：`[Powerups]` 第 2 字段
  的 AnimType 图像（要先确认这些 SHP 是单帧图标，见 §7）。
- 常显 vs 悬停：常显要遍历视口内所有格子（`OverlayTypeIndex != -1` 且
  `OverlayTypes[i]->Crate`），`CrateMaximum` 最大 255，屏上几十个时矢量文本会吃不消，
  建议常显只画图标、文字只在悬停时画。

## 8. 预设箱子实测（地图全库扫描，2026-10-28）

工具：`AutoLoadDev/tools/mapcrate.py`（base64 → LCW 解块 → 512×512 OverlayPack/OverlayDataPack）。
`MapsMO` 下 778 张 `.map` 全部解码成功（每张 262144 + 262144 字节），结果：

| 地图 | 格坐标 | 覆盖物 | 数据字节 | 内容 |
|---|---|---|---|---|
| Cooperative/coop_ahypo.map | (92,176) | 179 CRATE | 0 | 金钱 |
| Cooperative/coop_ahypo.map | (99,176) | 179 CRATE | 0 | 金钱 |
| Standard/jungleboogie.map | (87,53) | 242 WCRATE | 0 | 金钱 |
| Standard/jungleboogie.map | (81,102) | 242 WCRATE | 0 | 金钱 |
| Standard/jungleboogie.map | (123,115) | 242 WCRATE | 0 | 金钱 |

即全库只有 **5 个预设箱子格子（不是 5 种类型）**，全部字节 0；其余 776 张图一个都没有。
`[CrateRules]` 的 `CrateMaximum=255 / CrateRegen=3` 说明 MO 的箱子几乎全靠运行时随机刷。

### 预设字节为什么会留在格子里

读图函数（`0x5FD3F6` 起）跑两遍：
1. 第一遍按 OverlayPack 建 OverlayClass，`PlaceOverlay` 在 `0x5FD105` 先写 `0xFF`（桥 0x18/0x19/0xED/0xEE 除外，保留旧值）。
2. 第二遍（`0x5FD5FB`~`0x5FD640`）再读 OverlayDataPack，`0x5FD640 mov [eax+0x11E], dl` **逐格无条件**覆盖。

所以预设箱子的类型字节是地图说了算，`CollectCrate` 直接拿它当类型（`0x481ACE cmp bl,0x13`）。

### 两个只影响"字节 0 / 字节 6"的坑

- **字节 6 恒等于 0**：`0x481DB8` 有 `cmp ebx,6 / jne / xor ebx,ebx`，类型 6 在分派前就被改成 0。
  想让地图作者写 6 得到"随机金额"是无效的。
- **GM 0 且字节 0 时还要过图像映射**（`0x481B58`~`0x481B94`，顺序 CrateImg → WoodCrateImg → WaterCrateImg，后者覆盖前者）：
  MO 的 `CrateImg=CRATE → SilverCrate=HealBase`、`WoodCrateImg=CRATE → WoodCrate=Money` 同时命中 CRATE，
  最终取 **WoodCrate=Money**；`WCRATE → WaterCrate=Money`。
  也就是说 MO 里字节 0 永远是金钱箱，不会变成旧结论里的 HealBase。字节 1~18 不过这道映射，直接生效。

### 不在"预设格子"里的另一类

61 张图的触发器动作 108（CreateCrate，`549` 次）会在开局往 waypoint 放箱子，参数第 1 位全是 0。
那是运行时创建，落格后同样写 `+0x11E`，但不算预设；战役图在 mix 里，未统计。
