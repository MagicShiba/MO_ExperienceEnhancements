## 1. 架构与挂点

**不建 Gadget** (虚表/GameCreate 配重太大), **纯覆盖层 + 轮询**; 只读 + 渲染面绘制, 唯一写引擎数据的是防御页去重 (本地 UI 数据)。

| 环节 | 挂点 | 说明 |
|---|---|---|
| Poll | `0x4F42F0` `MOExperience_PrepareEntry` → `SWS_Poll` | **不是每帧一次**, 见 §9 |
| Draw | `0x5D4A94` `MessageDrawHook` → `SWS_Draw` | 合成面 (Composite) |
| 点击吞没 | `.inj: 0x692419 = SWS_ClickGate, 7` | `ProcessClickCoords` 内, 同 Phobos `SkipOnNewButtons` |
| 滚轮 | `0x777998` `MOExperience_WheelHook` → `SWS_WheelIn` | dir 与战役框反向, §5 |
| 去重按钮 | 显隐箭头**左边** | §6 |

吞没门: 前 7B = `movsx ecx,[esi]` + `movsx edx,[esi+2]` (无 rel); 落栏内跳 `0x6925FC`, 否则跑原版。

```
SWS_Poll   帧门(ADDR_FRAME) → 开关/按键边沿 → 按钮命中 → 栏区命中 → 15帧节流 SwsScan → SwsDedupSync
SwsScan    五元组稳定门控 → 逐项全校验 → 写 s_Items[] (原序) + s_OrderN=-1
SWS_Draw   SwsSig/交互态/age → SwsRebuild(画进缓存) | SwsRebuildCollapsed → 一次锁面 → SwsCacheBlit(alpha)
SWS_ClickGate  s_HoldSkip 或 SwsMouseOnIcon → 0x6925FC
```

`SwsScan` 门控: 先纯安全读, 超武 Items/Count + House Items/Count + `CurrentPlayer` 五元组任一变化 → 只缓存本轮返回; 稳定后才做入局检查 (本家须在 House 数组内) + 逐项全校验。**扫整表的新模块照抄**: 启动期半初始化垃圾会 fault (`IsPlausiblePtr` 只判下界, 会放行 `0x404E0000`)。

显示门 = `Owner==本家 && IsPresent==1` && ID 可打印 && `swIdx∈[0,2048)` && 标志位 0/1 && `!hide && SW_ShowCameo && ManualFire`。**fail-closed 是硬要求**: 任一不过就跳过, 零命中就不画。

### 1.1 数据源: Super 对象

**清单 = `SuperClass::Array` 里 `Owner==本家 && IsPresent==1` 的对象**, 就这一份。

- **不从 rules ini 读**。`CCINIClass::INI_Rules` (0x887048) 在扫描期只有**基础规则**; 战役/地图可在**地图内嵌 ini** 里新增或改写 `[XxxSpecial]` 节, 磁盘上那份 rulesmo.ini 里根本没有那些节 (实测 `SP_CryospearSpecial` / `WarheadSpecial1` 出现 **0 次**)。⇒ 需要的那几个 Ares 键一律走 §1.3 的 ExtData。
- **不把防御支援页当数据源**。它不是"玩家拥有哪些超武": `SW_ShowCameo=no` 的那批压根不会出现在防御页上 (Ares `Ext/SWType/Hooks.Update.cpp:178` `HouseClass_UpdateSuperWeaponsUnavailable`); 而且防御页那份是**被我们单方面删条目**的镜像, 拿它当源等于自己改自己。

### 1.2 三条旗标读**对象字段** (战役内嵌 ini 才算)

`ManualControl` / `UseChargeDrain` / `Action` 读对象字段 —— 引擎建对象时用的是合并后的 ini, 战役/地图改写天然生效。ini 那份只用来对账, 不一致打 `sws: flags OFFSET? manual <ID>`。

⚠ **对账键名必须是 `ManualControl`, 不是 `SW.ManualFire`** (后者是 **Ares** 的键, 写进 `SWTypeExt::ExtData`, 与这个对象字段毫无关系)。⚠ **绝不能用 `SW_ManualFire` 覆盖 `manual`**: `ManualControl` (gamemd) 与 `SW.ManualFire` (Ares) 是两个不同的键, 前者在对象上、后者只在 ExtData 里;
对象字段本身已是合并后的值, ExtData 对 `manual`/`drain` 没有增量, 覆盖只会把过滤弄乱。ExtData 的 `SW_ManualFire` 只用来**额外收紧**。

三个偏移逐个对回 gamemd (`0x6CE62E` 起的 CTOR + `0x6CEE60` 的 `add ecx,0x24` + `DrawCameo` 的 `mov edx,[eax+0xB8]` + 侧栏点击处理 `0x6AAF08 cmp dword [ecx+0xBC],edi` 四处互证): `0xBC=Action` / `0xE5=UseChargeDrain` / `0xF5=ManualControl`。**推导出来的偏移必须配自证日志**。

### 1.3 Ares `SWTypeExt::ExtData` —— 超武行为的**权威来源**

不自己复刻 ini 解析, 直接读 Ares 已经算好的结果。ExtData 在 `SWTypeExt::ExtMap` (`ContainerMap<SuperWeaponTypeClass, ExtData>`) 里。

| 需求 | 字段 | 偏移 | 证据 |
|---|---|---|---|
| 过滤 (`ShowCameo=no` 不进侧栏) | `SW_ShowCameo` | **+0x1E5** (bool, 1 字节) | `0x1003347D` + `0x1003962C` |
| 一键生效 | `SW_UseAITargeting` | **+0x20E** | `0x100335C7` |
| 图标文件名 | `SidebarPCX` | **+0x4B0** (定长串, 已小写) | `0x10033B60` |
| 额外收紧 manual | `SW_ManualFire` | +0x1E2 | `0x10033451` |
| 火风暴维持系数 | `SW_ChargeToDrainRatio` | **+0x220** (double) + 标志 **+0x228** | `0x10032690` |
| 发射花费 (资金门/提示) | `Money.Amount` | **+0x1A0** (int, <0 = 花费) | `0x100334E0` |
| 自证校验 | `AttachedToObject` | **+0x00** | Ares `Extension<T,TExt>` 0 号成员 |
| ExtData 大小 | — | 0x500 | `push 0x500` @ `0x10034701` |

**字段偏移的求法固定** (`LoadFromINIFile` 里的模式, 只认紧邻的那一对, 别用 FIFO 配对):
```
push <键名>;  push edi;  lea eax,[esp+18h];  push eax;
lea ecx,[esi+OFF];  call Valueable<T>::Read        ; esi = ExtData 基址
```

**键 = `SuperWeaponTypeClass*` 本身** (类型指针), 不是 `&type->ID`: 源码 `ExtMap.Find(pSuper->Type)` (`Hooks.Update.cpp:188`) + `_Container.hpp:226` `using key_type = base_type*`; 二进制 `0x10039624` = `push [eax+0x28]`, 同函数紧接 `mov edi,[eax+0x98]` (=
`Type->ArrayIndex`) 反证 +0x28 确实是 Type 指针。`find` 的散列只对**指针自己的 4 个字节**做 (`movzx eax,bl` / `shr eax,8` / `xor 0x811C9DC5` / `imul 0x1000193`), 全程不解引用。⚠ 别被 `StripClass_Draw_SuperWeapon_PCX` 的 `push [eax+0x24]` 带偏 —— 那里 eax 是**另一个**对象; 而
`Type+0x24` 是**内联 ID 字符数组** (gamemd `0x6CEA5D lea esi,[ebp+0x24]` 传给 `ReadString`), 按 `void**` 解引用会读到字符串内容并崩。

**最硬的交叉验证** —— 引擎自己的 AddCameo 判门 (`0x1003961D`, 对应 `Hooks.Update.cpp:186-193`):
```
mov ecx, <ExtMap>;  push [eax+0x28];  call find
cmp byte ptr [eax+0x1E5], 0          ; ● SW_ShowCameo
jne -> AddCameo(0x1F, index)
```
⇒ `+0x1E5` 就是引擎自己决定"进不进防御页"的那个 1 字节 bool, 读它 = 与引擎逐位一致。

**定位一律从 Ares 自己的指令里读地址** (ImageBase 0x10000000, ASLR 后会变):
- `ExtMap` = AresBase + 0xC1C54 —— 从导出钩子体开头的 `mov ecx, <imm32>` 取。
- `find()` = 同一段里 `E8 <rel32>` 的落点 = AresBase + 0x57C70。
- **必须核对 `find` 的栈清理**: 实测 `ret 4` (`0x10057CE3` = `C2 04 00`) = 恰好 1 个栈参、自己清栈。我们是按指针跨模块调它, 签名猜错 = 栈被清错 = **崩溃而不是返回 NULL**。定位器里要抠落点附近的字节核对, 对不上就整条路线停用。
- 取到后校验 `AttachedToObject == type`: `find` 是哈希查桶, 碰撞会返回别人的 ExtData, 不校验会把别的超武的 ShowCameo/PCX 套到这个类型上 (症状是图标/过滤随机错且难复现)。

每个类型都有 ExtData (`SuperWeaponTypeClass_CTOR @0x6CE6F6` 里 `FindOrAllocate`); ctor 把 `+0x4B0` 清 0、`+0x4D0` 置空, 新建未配置的超武**安全地得到"无图标"** ⇒ 取不到只有"定位失败"一个原因。

### 1.4 图标兜底: 让引擎自己重画一次防御页 (`SwsNudgePaint`)

抓取钩 (`0x6A9958`) 只在**引擎正在画防御页 cameo** 时才有数据, 而钩子要 `frame >= 60` 才装得上、防御页默认不是激活页签、地图内嵌 ini 新增的超武压根不在 rulesmo.ini 里 ⇒ "格子空着"。玩家点一次"过滤/显示"按钮能救回来, 就是因为按钮那条路调了 `AddCameo` + `RepaintSidebar`; **只调 `RepaintSidebar` 抓不到** —— 差别就在 `AddCameo`: 它把
super 挂到防御页的 cameo 槽上, 而抓取钩只在**槽被画**时才有像素。

`SwsNudgePaint` 复用 `SwsDedupRestore` 那条路径, 只要还有条目没抓到图标就每轮扫描催一次, 催满 8 次停手, 条目集一变配额重给。**必须排在 `SwsDedupSync` 之前** —— 去重会把"还没图标"的条目留在防御页上等图标, 催画要赶在它被搬走之前。纯 UI 重绘请求, 不碰模拟。

### 1.5 图标: 在 Ares 填好 `CameoPCX` 之后把它读出来

gamemd 原码 (离线反汇编确认):
```
6A9950  73 0C              jae 0x6A995E              ; 越界分支
6A9952  8B 90 B8 00 00 00  mov edx,[eax+0xB8]        ; ← Ares 的钩点 (EAX = SWType)
6A9958  89 54 24 48        mov [esp+0x48],edx        ; ← ★ 我们钩这里 (5 字节)
6A995C  EB 08              jmp 0x6A9966
6A995E  C7 44 24 48 000000  mov [esp+0x48],0
6A9966  A1 4C 3D A8 00     mov eax,[0xA83D4C]
```
Ares 的钩替换掉 0x6A9952 那 6 字节, **把 `CameoPCX` 填好之后**才落到 0x6A9958: 此刻 `CameoPCX` 已填好 (还没被 blit 掉再清零), 且 **EAX 已被 Syringe trampoline 还原成 `SuperWeaponTypeClass*`**。

**壳 (27 字节)**, 替换 0x6A9958 那 5 字节:
```
60                pushad
A3 <slot>         mov [slot],eax          ; pSW = EAX (Syringe 已还原)
E8 <rel>          call Sws_CaptureCameo  ; 拷走 60x48
61                popad
8B 90 B8 00 00 00 mov edx,[eax+0xB8]      ; ★ 补回被我们盖掉的那条指令
89 54 24 48       mov [esp+0x48],edx      ;   (Ares 的钩跳过了它, 所以要补)
E9 <rel>          jmp 0x006A9966
```

**`CameoPCX` 的地址定位**: 扫两个**导出符号** (`GetProcAddress` 直接拿) 的函数体, 取第一个命中 Ares `.data` 的绝对地址写/读:

| 符号 | opcode | 含义 | 离线实测命中 |
|---|---|---|---|
| `StripClass_Draw_SuperWeapon_PCX` | `A3 imm32` | `mov [m],eax` | **+0x17** |
| 同上 (备用形态) | `89 0D/15/1D/25 imm32` | `mov [m],ecx/edx/ebx/esp` | — |
| `StripClass_Draw_DrawPCX` | `83 3D imm32 00` | `cmp dword [m],0` | **+0x03** ★ |
| 同上 | `C7 05 imm32 00000000` | `mov dword [m],0` | **+0x7D** |

⚠ **两个符号都必须扫到**且扫出的地址必须**同一个** —— 那是"这地址真的是 CameoPCX"的唯一证据 (只扫 `A3`/`C7 05` 漏掉 `DrawPCX`, 它**读**用的是 `83 3D` ⇒ 钩子不装 ⇒ 图标永远空)。扫描窗口须 ≥ 0x80。

⚠ **不要用 `IsPlausiblePtr` 判 Ares 里的地址**: 它只放行 `[0x10000, 0x7FF00000)`, 而 Ares.dll 的 PE ImageBase 就是 **0x10000000** —— 没有 ASLR 时整个模块都在上界之外。一律按 `SwsAresImage()` 的**映像范围**判。

⚠ **能"在别人做完之后观察", 就不要"替别人做"** —— 不要去猜 Ares 钩子体的寄存器约定: Ares 体内 `GET(pSW,EAX)` 编译成 `mov eax,[esp+4]`, 那个"寄存器快照"是 **Syringe trampoline 压在栈上的**, 裸 jmp 过去只会读到游戏栈垃圾。

其它装钩约束 (**本项目所有装钩的地方通用**):
- ⚠ 写 gamemd 的 `.text` **必须** `VirtualProtect(PAGE_EXECUTE_READWRITE)` + `FlushInstructionCache` (`AirWay.cpp:71` / `ChatEdit.cpp:1110` / `FullMap.cpp:421` / `VecText.cpp:2142`)。只**读** Ares / 只写**堆**的那两处不 protect 也没事 —— **别因为"那两处没炸"就以为可以省**。
- ⚠ `mov [slot],eax` 不能省: 抓取函数是**另一个函数**, 没有寄存器快照可读。漏了它 ⇒ 抓到的 type = 0。
- ⚠ `pushad`/`popad` 必须成对: 中间是真实 call, 会破坏 ebx/esi/edi/ebp, 而编译器只当 ecx/edx/memory 被破坏 (§11 坑 7 同一个原因)。
- ⚠ 必须**拷像素**, 不能留 `BSurface*`: 引擎切页签/重载美术会释放重建。

图标优先级: **抓到的那张 > ExtData 的 `SidebarPCX`**。前者就是引擎此刻画的那张。

⚠ **抓到 ≠ 显示**: `Sws_CaptureCameo` 把 60x48 拷进 `s_Cap[]`, 但 `SwsTypeEntry` 每轮扫描会把 `tc->capPix` 清成 NULL —— **必须**在 `SwsScan` 里 `if (!tc->capPix) tc->capPix = SwsCaptured(type);` 交给侧栏。

**搬出要等图标到位**: 图标还没着落的条目**先留在防御页上** (`SwsSidebarHasIcon`)。搬走之后引擎不再画它 ⇒ 抓取钩永远抓不到 ⇒ 两边都没图标。重复几秒 ≫ 永久空格子。

**离线先验证再进游戏**: `Ares.dll` 就在 `G:\motest`, 导出表 + `.data` 范围 + 钩子体机器码 + gamemd 原码都能脚本读出来 —— 打算盖掉的 5 字节原本是什么、两个钩子认出的地址是否同一个, 全都可以离线定死。

### 1.6 `s_ItemN == 0` 是"侧栏整个消失"的唯一开关

```
s_ItemN == 0  ─┬─→ SwsRebuild goto nogeo      → 侧栏整块不画 (连两个按钮都没了)
               └─→ SwsDedupSync 的 s_ItemN<=0 闸门 → 防御页去重停手, cameo 原样留着
```
**现场指纹: "屏上没有侧栏" + "原版防御支援页一堆超武一个没被搬走"** ⇒ 不用猜, 就是 `SwsScan` 交了 0 条。

⚠️ **`fail-closed` 遇到"字段读出垃圾"就等于整条功能静默失效** —— 症状和代码逻辑完全对不上。所以 `SwsScan` 的各 `return` 和 `SwsRebuild` 的 3 条 `goto nogeo` 全有**旁路日志** (同一原因只记一次, 原因变了再记), 见 §10。

⚠ **`fail-closed` 的"上界"必须由容器自己给出, 不能拍脑袋**。统一走 `SwsVecItems()`: `Items` 可信 ∧ `1 ≤ Capacity ≤ 65536` ∧ `0 ≤ Count ≤ Capacity` —— 最后一条是**硬门** (`Add` 先 `Reserve` 再写 `Items[Count++]`, 恒成立, 反过来就一定是野值)。上游实例门原本每条 cameo 走一遍全表 ⇒ 单次去重复查十几万次循环; 现在走
`SwsBuildLiveSet()` 一趟建位图 + `SwsLiveHas()` O(1) 查。

**绝不能只在"首次填充"分支写 `s_Items[n]`** (下标随建筑增减重排 → 张冠李戴): 名字/图标/阵营/优先级/`instant` 属**类型**, 存 `SwsTypeCache` (按 type 指针缓存, `prio<0`=未填充), 每轮拷进 `s_Items[n]`。

## 2. 地址与结构偏移 (本机 Ares 3.0)

跑的是 **Ares 3.0**, 不是 YRpp 基线 gamemd。**本机 Super/SWType/BuildType 字段比 YRpp 头文件大 0x0C / 4 字节, 头文件地址不能抄。**

### 2.1 数据全局

| 地址 | 含义 |
|---|---|
| `0xA83CB8` | `SuperClass::Array` (含虚表) |
| `0xA8E330` | `SuperWeaponTypeClass::Array` |
| `0xA80228` | `HouseClass::Array` |
| `0xA83D4C` | `HouseClass* CurrentPlayer` |
| `0xA8ED84` | 当前逻辑帧号 `ADDR_FRAME` |
| `0xA8B230` + `0x34B8` | `Scenario.PlayerSideIndex` (0~3, 读不到回 0) |
| `0x87F7E8` | **侧栏对象本身** (见下方警告) |
| `0x8809A0` | `CurrentSWTypeIndex` = `0x87F7E8+0x11B8` |
| `0x887048` | `CCINIClass::INI_Rules` |
| `0xAC4848` | `PCX::Instance` (`this` 就是该地址, 不能解引用; 无虚表) |

> **`0x87F7E8` 是对象本身, 不是"指针的存放地址"** (`MouseClass`/`SidebarClass`/`DisplayClass` 是同一静态对象): 按 `*(void**)0x87F7E8` 读会拿到虚表指针 → `Tabs` 偏移全错 → 当 `this` 调引擎函数当场崩。**每个定址都要一条独立证据, 别靠命名猜。**

容器 (`DynamicVectorClass`, 带虚表): `+0 vtable / +4 Items / +8 Capacity / +0x0C IsInit+IsAlloc / +0x10 Count / +0x14 CapInc`, `sizeof=0x18`。

| 实例级倒计时总长 (可为 -1) | `+0x24` | — |

| `SWType::ID` / `UIName` / `ArrayIndex` / `RechargeTime` | `+0x24`/`+0x60`/`+0x98`/`+0xB0` | `0x18`/`0x54`/`0x8C`/`0xA4` |

### 2.3 `BSurface` (PCX surface) `sizeof=0x20`

`+0 vptr / +0x04 Width / +0x08 Height / +0x0C LockLevel / +0x10 BytesPerPixel(=2) / +0x14 Buffer(WORD*, 行距=Width*2) / +0x18 Size(=W*H*2) / +0x1C Allocated`。别把 `0x88/0x8C/0x94/0x98` 当字段偏移 —— 那是**虚表大小**; 写错 → 校验提前 return → 图标静默失效。占位面尺寸离谱
(1x1/0), `SwsCPcx` 的 `pw/ph ∈ [1,256]` 与 `Size == pw*ph*2` 挡它。

## 4. 绘制管线: 离屏缓存 + 15 逻辑帧节流

合成面每渲染帧都被重画 → **重建** `SwsRebuild` (布局+排序+像素全画进自有缓存, **不持锁面**) + 每渲染帧一次 **合成** `SwsCacheBlit` (带 alpha 拷贝, 内层只有乘加移位)。缓存 = **16 位色 `s_CchC` + 8 位覆盖率 `s_CchA`**; 只存色就把半透明烙死。`SwsCacheAlloc` 只清覆盖率面, 上限 `SWS_CACHE_MAXPX = 2M` 超过不画。

`SWS_Draw` 每帧只算三样决定是否重建:
1. `SwsSig(w,h,pitch)` = 画布尺寸 + `g_MapRight` + 显隐 + 去重开关 + 滚动偏移 + 条目集合 (`swIdx/side/prio/ready/susp/instant/drainState/pcxFile`)。锚点必须进签名 (F11 切视口时地图右缘在 1752/1920 跳而画布尺寸不变 → "切换后残留一块图标"); 刻意**不含 `remain`** (有在充能的就永不作废)。★ `drainState` 必须进签名: 火风暴类激活/停用只改这一个字段, 不加的话状态切换不触发重绘。
2. 交互态 `hover/btnHov/curSel` 与上次值比 → 移上去/点中/松开上膛/滚轮/点箭头/点去重按钮都**当帧重画**。
3. 兜底 `age >= 15` 逻辑帧, 帧号回拨 (新开局/读档) 强制重建。

顺序固定, 乱序会被盖掉: 底框(一次黑底 op=30) → 图标+状态文字 → 每列边框 → 条目高亮框 → 滚动条 → 显隐箭头 + 去重按钮 → 悬停名提示框。
- 边框在图标**之后** (否则被 60x48 图标盖住); 高亮框在**每列边框之后**且独立一遍 (画 `it->x-1 .. x+ICON_W`, `ColGap=0` 时压住左右邻列外边框; 塞进图标循环会缺一截、像错位)。
- 提示框**不逐像素跟随鼠标** (锚鼠标 x 时移 1px 就要重画整块), 默认锚图标水平中心、画在图标下方, 居中盒会探出块缘时盒右缘贴块右缘 (`xStart+totW`); 悬停那个图标**不透明** (`opaque=1`), 不压"未满格"暗罩。
- 提示框 = 半透明黑底 + 1px 边框 `A5D3FF`, 框 (`sw+6` × `行数*adv+2`, 黑底白字不画阴影), 贴边夹取**按框算**; 名字含 `\n` 按行叠放 (行高 `adv`, 短行左对齐, 最多 4 行, 超了整个不画); `A5D3FF` 也是箭头/高亮主题色 (`SWS_ACCENT_R/G/B`)。

**提示框必须在分配缓存之前量出来** (`SwsTipPrepare`→`SwsTipRect`, 它可能探出侧栏块), 否则被缓存边界裁掉; 高亮框描边在 `it->x-1` / 下边正好 `yStart+blockH` → 缓存矩形**左/下各再让 1px**。字形走自有覆盖率缓存 `s_Tip` (1024×128×1B), 每帧 `RenderLine` 不行 (每次先 `ClearDib` 一遍)。**GDI 槽** (`GdiText.cpp`):
提示框用槽 6 (`[VecText]` 字号), 充能百分比用槽 5 (`[SWSidebar] FontPx`); **两者不能共用一槽**。画字前必须**显式 `GdiEnsure`**, 直接拿 `g_G` 会借到上一模块的槽。

### 图标顶部文字 (最多两行)

| 状态 | 行1 | 行2 |
|---|---|---|
| 暂停 (`CanHold`) | `Hold` | — |
| 火风暴类运作中 | 百分比 (**倒着走**) | `Run` |
| 充能中 | 百分比 (**正着走**) | — |
| 就绪 | 无 (图标本身即"可用") | — |

⚠ **满格判据必须看"计时器有没有在跑" (`remain > 0`), 不能只看 `IsReady`** —— 火风暴类的 `IsReady` 不可信: Ares 激活它走 `ClickFire` → `Launch()`, **不清 `IsReady`** (它本来就是从 Ready 点过来的), 停用/耗尽后也没人补清 (实测日志 `sws: drain BlasticadeSpecial state=2 ready=1 tot=3600 left=410`:
`ready=1` 而 `left` 在减)。只按 `!ready` 判的话这些超武永远不会压暗、也永远不显示上升百分比。⚠ 压暗判据必须与百分比门控**完全一致** (`remain > 0 || !ready`), 两类超武用同一个"满格"判据。

**资金门 (`Money.Amount`, 只读)**: 超武可带发射花费 (Ares `Money.Amount`, 负 = 花费; 提示 `-Money.Amount`)。两条行为与引擎/Ares 逐一对齐:
- 压暗: `IsReady && !CanTransactMoney(Money.Amount)` (Ares `StripClass_Draw_SuperDarken` `0x6A99B7`)。我们并入未满格压暗判据 (`remain>0 || !ready || !SwsAfford`)。
- 选中门: 资金不足时点击**不选中/不发射** (同 Ares `SidebarClass_ProcessCameoClick` `0x6AAEDF` 的 `CanTransactMoney` 拦门 + EVA/提示)。即时类 (`instant`) 也拦。
`SwsAfford()` = `money + Money.Amount >= 0` (同 `HouseClass::CanTransactMoney`; `Money` = `HouseClass+0x30C`, 实证 gamemd `0x705DF3` = `mov eax,[ecx+0x30C]; ret`)。读不到资金/脏值时放行 (fail-open, 引擎发射那步还会再拦)。

百分比方向与分母:
- 充能: `100 - remain*100/total` (正着走)。
- 火风暴类运作中: `remain*100/drainTotal` (倒着走), `drainTotal = total × ChargeToDrainRatio`。**不能用引擎 `GetCameoChargeStage` 的 ChargeDrain 分支当分母** —— 它返回 `remaining / GetRechargeTime()` (满充能时间), 所以引擎那个"充能条"在激活瞬间停在 `ratio` 处 (爆裂屏障 50%、心灵之火 25%)。但**侧栏百分比不是那个充能条**: 原版侧栏拿**维持时长**当分母, 所以是 100% 起跳往下走。`drainTotal` 必须显式乘 ratio, 因为 `Timer::Start(duration)` **只写 `StartTime`/`TimeLeft`, 不存总量**, `Super+0x24` 恒为 -1。

`Run` 用英文而不是"运作中": 顶栏只有 60px 宽, FontPx=16 下 4 个汉字必然溢出/糊成一团 (`Hold` 只有 4 个拉丁字母, 一直正常)。引擎给这几类的 `Text.Active` 走 CSF 标签 (`NAME:BLASTRUNNING`), 我们没有 CSF 读取能力。

## 5. 几何 / 布局 / 滚动

### 5.0 列序与停靠边

`side` 固定 0=盟军 1=苏联 2=厄普西隆 3=焚风, 但**列的绘制顺序**由 `[SWSidebar] Side` 决定, 规则是**盟军永远靠屏幕外缘、焚风永远靠地图内侧**:

| 面板 | 屏幕外缘 | 列序 (从左到右) |
|---|---|---|
| `Side=right` (默认) | 右 | 焚风 → 厄普西隆 → 苏联 → **盟军** |
| `Side=left` | 左 | **盟军** → 苏联 → 厄普西隆 → 焚风 |

原版侧栏恒在右, 所以放左时锚**屏幕左缘 x=0** (正常视口左缘即屏幕左缘; FullMap 态1/2 推开视口留给左面板的正是那条空档, 不用改 FullMap)。无阵营归属的超武 (`SwsSideOf` 查不到) **不单独开一列**, 落到玩家阵营那一列 (`s_Items[n].side = side >= 0 ? side : pside`)。

**单一阵营时自动拆两列** (`s_SplitSide`): 非空列数 == 1 且条目 >= 2 时, 两个物理列共用该阵营的边框色, 条目按**行奇偶**分列, 每列 `ceil(n/2)` 条 —— 纵向利用率翻倍。只有 1 条时不拆 (第二列会是空框)。

**填充模式** (`FillMode=1` / 箭头右键切换): 排序**不看阵营** (只按 ini 优先级 → 原版顺序), 列分配不看阵营, 目的: 占领敌建筑/战役自定义超武导致阵营列一变多时**减少翻页**。列数按容量定: `cols = ceil(n / MaxRows)` 并夹到 `2~4` (n<=MaxRows 且 n>=2 时也至少 2 列, 与单阵营拆分观感一致), 条目按**行优先** `k % cols` 分列 (各列高度尽量均衡, 与用户约定的"平衡分配"一致); `n > 4×MaxRows` 才用满 4 列并走滚动条。**边框统一用中性灰** (`kFillCol`, 一列内混阵营, 阵营色无意义; 条目选中高亮仍按各自阵营色)。右键显隐箭头切模式; 模式进 `SwsSig` 且排序缓存按 `s_OrderFill` 作废重排。

⚠ **命中判定必须用 `s_ColMinX`/`s_ColMaxX`**: 列序可能是反的, 循环末列反而是最左一列, 拿它当右边界会把整块判成"不在栏内"。

⚠ 面板在左时滚动条落在块的**左边** (`barX = xStart - 5`), 而 `firstX = xStart` 是缓存矩形左缘 —— 不把 `barX` 并进 `firstX` 的话整根条子会被缓存裁掉。同理 `right` 只能取 `max(列右缘, barX + barW)`。

### 5.0b 原版侧栏的排序规则 (默认优先级)

引擎那边**不是按添加顺序排**, 而是**排序插入**: `SidebarClass::AddCameo` → `StripClass_AddCameo`, 比较器 = `BuildType::operator<` → `SortsBefore` (gamemd `0x6A8420`, YRpp `SidebarClass.h` 里 `JMP_STD(0x6A8420)`)。

逐条反汇编那个比较器, 对两个超武条目 (`ItemType==0x1F`, 恒命中这一支):
```
006A84AB  mov eax,[ecx+edi*4]     ; Type[leftIndex]
006A84B1  mov edx,[eax+0xB0]      ; left .RechargeTime
006A84B7  mov esi,[ecx+0xB0]      ; right.RechargeTime
006A84C1  → return 1             ; left < right ⇒ 左在前
006A84CD  → return 0             ; left > right
006A84DB  mov eax,[eax+0x60]      ; 相等 ⇒ 比 UIName
006A84E1  jmp 0x6A86F3            ; strcmp(left,right) 后 `setle`
```
⇒ **原版顺序 = `RechargeTime` 升序, 相等按 `UIName` 字典序升序** (冷却快的排前面)。入口那道 `isSpecial` 门判 `ItemType ∈ {0x1F, 0x20, 0x39}`, 超武之间两边都是 0x1F 所以不涉及建筑/单位分支。

我们的排序键 = **`阵营` → `ini 自定义优先级` → `原版顺序`**。自定义优先级默认 1000 (= 没写), 填正数 (<1000) 就自然排到前面, 不需要额外分组; `swIdx`(ArrayIndex) 只作为最后的稳定 tiebreak。

### 5.1 常规几何

- 图标盒固定 **60×48** (Phobos cameo 尺寸), **不要**做成配置项: PCX 是固定尺寸源, 缩放后目标矩形只按屏幕边界裁剪 → 非默认尺寸溢出格子错位。
- 锚点 = **地图区右缘** `g_MapRight` (态0=1752 / 态1,2=1920), `=0` 才退回画布宽; 锚画布右缘会把整块塞到原版侧栏底下。
- `TopMargin` 比例时 `yStart = h*比例 - blockH/2` (视觉居中), 像素时直接当 Y; 纵向要给块顶上方的两个按钮留 `SWS_BTN_H+2`。收起态**不减半个块高**。排序: 阵营 → ini 优先级 → `ArrayIndex`, 只在 `s_OrderN != s_ItemN` 时真排一次。
- **`s_Items`(原序=SuperClass 数组序) 与 `s_Order`(排序后) 是两套下标**: 遍历排序结果一律写 `s_Items[s_Order[i]]`, `SwsHitItem` 返回**排序后**下标。
- **面板级滚动**: 单个 `s_Scroll` 所有列一起滚 (`ColGap=0` 后列间无空隙, 逐列的 4px 滚动条会盖在下一列图标上)。上限 = `最长列条目数 - 可见行数` (**不是** `colCount-1`); 滑块 `scroll/maxSk` **正比**, 第 0 项在**上**面。出界条目 `x = -1`, 既不绘制也**不参与命中** —— 必须 `if (x < 0) continue;`, 否则 `mx >= -1 && mx < 59` 对屏幕左侧整条竖带恒真。
- **按钮** 20×18: 显隐在块右缘，过滤 (隐藏重复) 在它左边 3px，两边都在块**上方**。
  - 贴图取 `icons/btn_small_arrow.pcx` / `icons/btn_small_filter.pcx` (各 80×18,
    四格从左到右 = 盟军/苏联/厄普西隆/焚风)，按 `SidebarSkin_Side()` 取当前 UI
    皮肤那一格; 切皮肤时指纹失效立即换图。箭头按 `dir` 与 `Side` 水平镜像，
    过滤关闭态压暗。
  - 只能挂上方: `SWS_Draw` 拿的是合成面 (宽 = 屏幕宽 − 原版侧栏宽 1752)，
    挂右边会算到面外被丢掉。
  - 收起态沿用 `s_BtnXKeep/s_BtnYKeep`，不要改成"贴屏幕右缘" (折叠/展开时箭头
    会跳)。**隐藏态也必须画箭头**, 否则玩家找不到展开处。

### 吞没/命中判定

- 必须按"**真的画了东西的地方**", 不能用整块容器矩形: 某列条目少时下半截是空的, 没图标却把整片点击吞掉 ("侧栏盖住的地图那块点不动"); 现在门只看 `SwsMouseOnIcon()`, 空地还给引擎。
- **UI 元素画在判定框之外 = 永远点不到**: 两个按钮都在栏区判定框之上 → 命中判定必须排在栏区判定**之前**。**右键取消也必须限在栏区内**, 否则玩家在地图上右键取消单位会把超武选中状态也清掉。
- 判定用 `s_BoundsKnown` (缓存里有可合成的一帧): 点击那帧 Poll 先跑 + 点击必 `s_ForceScan` 触发重扫, 用扫描中的状态会撞上清零窗口。`s_HoldSkip` 在物理左键按住期间一直吞引擎地图点击, 松开即清。

### 按键边沿

**多个分支必须共用同一份状态变量**: 可见分支点箭头后直接 `return`, 绕过末尾的 `s_PrevLB = lb` → 下一帧进隐藏分支拿到的还是旧值而按键确实按着 = 伪造出一个**新按下沿**, 刚收起的侧栏立刻弹回来。修法: 每条 `return` 前自己写回按键态。判据: 任何"提前 return 的路径"都会跳过末尾的状态更新。

## 6. 隐藏防御支援页里的重复超武 (DedupDefensePage)

侧栏有的超武, 引擎自带的**防御支援页** (页签 1) 里不再出现一遍; 侧栏上没有的 (ini 隐藏 / `SW.ShowCameo=no` / `SW.ManualFire=no`) 照旧。开关在显隐箭头左边。

**⚠ 这个功能只能"少删", 绝不能"多删"** (超武丢失类 bug 的唯一来源): 判据必须是"侧栏此刻真的在画这个超武"的**真子集**, 因为搬出是**单向**的 —— "侧栏不画
+ 防御页被删" = 两头都没了且不自愈。四道门 (任一不过就保留 cameo):

| 门 | 判据 | 挡的是什么 |
|---|---|---|
| 类型门 | `SwsSidebarShows()` = `!hide && SW_ShowCameo && ManualFire` | ini 隐藏 / `SW.ShowCameo=no` / `SW.ManualFire=no` |
| 实例门 | `SwsLiveHas()` = 本家有 `IsPresent==1` 的 Super | cameo 已进防御页但 Super 还没变 `IsPresent` 的时间差 (Ares `HouseClass_UpdateSuperWeaponsUnavailable` / ICBM / `Grant1ShotSW`) |
| 快照门 | `SwsSidebarShowing()` = 最近一次 `SwsScan` 的 `s_Items` 里真的有 | `SwsScan` 早退 (数组换了 / 本家未入 House 数组 / 半初始化垃圾) 时 `s_ItemN==0` |
| 图标门 | `SwsSidebarHasIcon()` = `capPix \|\| pcxFile` | 图标还没着落 (§1.5), 搬走后永远抓不到 |

`SW_ShowCameo` **必须**在类型门里, 而且是**双向**的: 少了它侧栏会冒出游戏里根本没有的超武; 多了它 `SwsDedupRestore` 会把引擎本来不给的 cameo **主动加进防御页**, 那是改游戏行为。实例门也是**两个方向对称性**的要求: `SwsDedupRestore()` 一直有实例门而 `SwsDedupRemove()` 必须也有 → 差出来的就是丢失窗口。

⚠ **紧凑搬移的位移量必须现算** (`tail = cnt - 1 - i`, 再前移): 倒着删, 下标才不因搬移失效。

引擎机制: cameo 入口 `SidebarClass::AddCameo` `0x6A6300`, 调用点 `HouseClass_UpdateSuperWeaponsUnavailable`、`ICBM` 补给箱 `0x482D4C`、脚本 `Grant1ShotSW`/`GrantPermanentSW`; 引擎唯一的移除路径 `StripClass::RecheckCameo` `0x6AA600` **只删
`IsPresent==0` 的** —— 我们的都还在。入口拦截做不到 (超武 cameo 不走那条路), 所以用 15 帧复查。

### `RulesExt::TabCameos[4]`

Ares 3.0 换掉了 cameo 容器 (`ares(Antares)/src/Ext/Rules/Hooks.CameoList.cpp`): `DynamicVectorClass<BuildType> RulesExt::TabCameos[4];` (Ares.dll 的 .data)。增删/绘制/点击/排序/`RecheckCameos` 全走它; `StripClass::Cameos[75]` 内联数组是**死内存** (只有
`Index`/`TopRowIndex`/`CameoCount` 还在用)。Ares 没导出"删某个 cameo"的接口, 只能直接改这个数组。

### 定位办法 (`SwsAresFindTabCameos`) —— 从 Ares 自己的代码里读地址

Ares 导出的 `SidebarClass_AddCameo_SkipSizeCheck` (钩 `0x6A63B7`) 开头几十字节:
```
8B 04 CD <disp32>     mov  eax, [ecx*8 + TabCameos[0].Items]
6B 0C CD <disp32> 34  imul ecx, [ecx*8 + TabCameos[0].Count], 0x34
```
两个 `disp32` 都是编译期写死的绝对地址 → `TabCameos = (Items的disp32) - 4`, 再用第二条互证 `(Count的disp32) - 0x10 == TabCameos`。不扫 `.data`、不误命中别的容器, ASLR 后依然对; 容器头地址终身不变 (Ares 只在 `ClearCameos` 清内容, 从不搬容器), 只有 `Items` 随扩容变 → **每次用之前现读 `Items`**。

⚠ 判据只放验证过语义的东西: 不拿 `StripClass::CameoCount` 当定位依据或复核闸门 (它与 `TabCameos[i].Count` 不同步, 当闸门等于堵死)。`SwsTabCameoOk` 只校验容器自身。定位后逐个校验四个容器 (`SwsDVecOk`: vtable 相同且落在 Ares 映像内、`CapacityIncrement ==
100`、`Capacity >= Count >= 0`、`Items` 可读), 任一不过即 fail-closed。**只在确实在跑一局时才找** (`CurrentPlayer` 有效 + 帧号走过 60; 主菜单里容器还没建好), 试一次就够, 失败整条功能关掉并记一行。"可能整条路都不走"的代码必须有一条**无论如何都会打的旁路日志**。

### 两个方向依赖不对称 (关键)

- **搬出 (隐藏)**: 必须直接改 `TabCameos[1]`, 再调 `SwsDefenseRepair()` 收尾。
- **搬回 (显示)**: **完全不碰容器**, 对每个 `IsPresent && 侧栏有` 的超武调引擎自己的 `AddCameo(0x1F, idx)`; 它自带查重, 对已在页里的重复调用是**无害空操作**。搬回也查容器判重的话, 校验一不过就**静默失败** —— 同理 `SwsDefenseRepair()` **只在搬出之后才调**。

`SwsDefenseRepair` 顺序: 同步 `StripClass::CameoCount = TabCameos[1].Count` (**必须**, 页签布局按它算; 读出来 <0 就跳过, 不写坏别人内存) → 非空则 `UpdateScrollButtons`; 空则 `GadgetClass::Disable(页签按钮)` + 跳第一个非空页签 `SetTab` → 滚动位置**只夹取不重置** → 两个 redraw 标志
→ `RepaintSidebar(1)`。

**`SwsSidebarShows()` 是纯谓词 (只有类型门), 里面不能判 `s_Enable` / `s_DedupHide`**: 它被搬出和搬回共用, 而"切回显示"时 `s_DedupHide` 恰为 0 → 恢复循环把所有超武 `continue` 掉。其余门也别塞进去。

`SwsDedupSync` 每 15 帧 (0.25s) 在 `s_DedupHide` 时置 `s_DedupDirty`, 让 `SwsDedupRemove` **在已隐藏态也再跑一遍移除** (幂等)。目标态 `want = s_DedupHide` —— **收起 (F4) 不参与**: 已经搬走的保持搬走, 折叠期间防御页也不恢复, 由"隐藏重复"按钮切回。收起时 `s_Items` 为空, `Remove` 的真子集门天然一条都搬不动 (只能少删); 展开后第一次扫描重新置脏补搬。同理 `want && s_ItemN <= 0` 时**这一轮什么都不做**: 扫描早退那 0.25s 里删 = 整页清空 (收起态另有早退分支直接记态返回)。

> ⚠ **判据里塞进一个没验证过后果的前提 = 给自己埋丢失**。收起期间防御页里**已经被搬走过**了, "收起=恢复原样"反而会让用户点的隐藏失效; 恢复只走"隐藏重复"按钮 (want=0 → `SwsDedupRestore`)。

## 7. 图标链路 (PCX 优先, SHP 兜底)

MO 的超武图标**多数是 PCX**: 96 个超武节用 `SidebarPCX=xxx.pcx`, PCX 打包在 `expandmo*.mix`/`thememo.mix`, 磁盘上没有。但**也可能只有 SHP** (`SidebarImage=xxx.shp`, 常见于地图内嵌 ini 新增的超武节 / 未写 `SidebarPCX=` 的), 这类以前完全不显示 (抓取钩只认 Ares 的 `CameoPCX`, SHP 路径下它是 NULL)。

```
1. PCX 优先: 引擎抓像素 (Ares CameoPCX, 见 §抓取钩) —— 战役改写/地图内嵌声明的一律对
2. SHP: 无 SidebarPCX 时, 扫描 (SwsScan) 直接调 SwsRenderShpCap -> SwsRenderShp
   用引擎 CC_Draw_Shape @0x4AED70 把 type->SidebarImage (+0xB8) 渲进自有
   BSurface (调色板 FileSystem::CAMEO_PAL @0x87F6B0, frame 0, flags 0x400,
   brightness 0x3e8 —— 复刻引擎那次调用), 画完拷 60x48 像素
3. 两条都空 = 空条目 (边框/百分比照旧), 记一行 `sws: nopcx <ID>`
```

- **SHP 原理**: `CC_Draw_Shape` 只用目标的 `GetRect` (虚表 +0x78), 不锁面, 直接写 `+0x14 Buffer`。所以在栈上拼一个 0x20 的假 BSurface (`+0 vptr=0x7E2070 / +4 W / +8 H / +0xC LockLevel / +0x10 bpp=2 / +0x14 Buffer / +0x18 Size / +0x1C own`) 就能当绘制目标。先铺色键紫 (0xF81F) 再画, SHP 透明像素落成色键被绘制层跳过。
- **SHP 在扫描时直渲, 不走抓取钩**。原因: 抓取钩 `0x6A9958` 只在引擎画防御页超武 cameo 时触发 —— PCX 类即便没钩到也能靠 `SidebarPCX=` 读文件名现取, SHP 类没这条退路, 靠钩子就得**切一次防御栏**才出图。所以扫描时直接渲 (结果只存 `tc->capPix`, **不登记进抓取钩的 `s_Cap[]`**, 以免挡住地图内嵌声明 PCX 的引擎抓取)。抓取钩现在只负责 PCX。全程只读 UI 绘制链对象 + 引擎现成调色板, 不碰模拟, 联机安全。
- 引擎 `BSurface*` **绝不能跨帧缓存**: 切页签/重载美术会释放重建 → 平时脏图、切页签崩溃; 现在**只缓存文件名**, surface 每帧现取。
- 文件名按 Ares 的做法**小写化**后存 (`AresPCXFile::operator=` 里就是 `_strlwr_s`), MIX 里 PCX 一律小写。
- 无 PCX 的超武 = 空条目 (边框/百分比照旧), 记一行 `sws: nopcx <ID>`。悬停名字优先 `SWType::UIName`, 空则退回 ID。

## 8. 即时类超武与 SpecialPlace 事件

### `instant` 判据 (每类型算一次)

判据直接抄 Phobos 的 `SWButtonClass::LaunchSuper` (`src/Ext/Sidebar/SWSidebar/SWButtonClass.cpp:203`) —— MO 原版侧栏就是它, "与原版一致"的基准是它:
```cpp
if (pType->Action == Action::None || pSWExt->SW_UseAITargeting)
    OutList.Add(EventClass(..., SpecialPlace, swIndex, CellStruct::Empty));
else
    CurrentSWTypeIndex = swIndex;      // + EVA_SelectTarget
```

两个条件缺一不可:
- **`Action == 0` 读对象字段**: 引擎/Ares 建对象时已把合并后的 Action 写好, gamemd 自带的侧栏点击处理 (`0x6AAF08 cmp dword [ecx+0xBC],edi`) 判的也是它 —— 引擎那条路**不看** UseAITargeting。
- **`SW_UseAITargeting` 读 ExtData**: `WarheadSpecial1` 在 rulesmo.ini 里是 `Type=GenericWarhead` + `Action=Custom` ⇒ Ares 在 `0x1003332A` 把它改写成 `Actions::SuperWeaponAllowed` (0x7F) ⇒ **光看 `Action==0` 判不出来**。它"点一下就生效"靠的是 emigdal.map 内嵌 ini 里那行 `SW.UseAITargeting=yes` —— **这条键只在地图内嵌 ini 里有**, 只能从 ExtData 拿。

⚠ **`Action=Custom` 不是 `Action::None`**: MO 基础规则里几乎所有超武都写了 `Action=Custom`, 只在 ini 里找 `Action=None` 是找不到的。

引擎侧两条出口 (gamemd `SidebarClass_ProcessClickCoords` 内):
```
6AAEF7..6AAF08  pSuper = HouseClass::Player->Supers[esi];
                cmp dword [pSuper->Type + 0xBC], edi(0)
6AAF0E  jne 0x6AAF46            ; Action != 0 -> 0x6AAF92 mov [0x8809A0],esi = CurrentSWTypeIndex
6AAF10..6AAF3C  EventClass(house, 0x12 SpecialPlace, Type->ArrayIndex, CellStruct{0,0})
```
所以"要不要点第二次地图"完全由 `Type->Action` 决定, 与鼠标位置无关。

### 释放方式 (联机铁律)

走 `EventClass::OutList` 塞标准 `SpecialPlace`, 引擎在 DoList 执行, 联机由 Mega/Connect 同步。**不写 `CurrentSWTypeIndex`** (本地 UI 态, 引擎当帧不会释放 → "点了没反应"; 且直接改模拟状态会破坏联机同步)。

- ctor `0x4C6B60` (`thiscall`, this=111 字节缓冲, houseIdx/Type/id/CellStruct)
- OutList: Count `0xA802C8` / Next `0xA802D0` / Buf `0xA802D4` / Par `0xA83A54`
- 事件 111B, 容量 `0x80`, `Next` 用 `(next+1)&0x7F`; 读回 `Next` 要**夹一次**
- 拷完调一次 `call [0x7E1530]` 无参回调, 返回 EAX 存 `Par[next]`; `houseIndex = [house+0x30]`, `CurrentPlayer = *(0xA83D4C)`; `EventType::SpecialPlace = 0x12`
- **ctor 之前必须清零 111 字节**: `EventClass` 是 pack(1) 且 `operator==` 是 `memcmp(...,111)`, 留栈垃圾会给联机同步埋雷
- **`Location` 传 `CellStruct::Empty` (0,0)** —— 与引擎点**原版侧栏**发出的那条逐字节一致 (已用抓包核对)。布局 `[0] Type / [1] IsExecuted / [2] HouseIndex / [3..6] Frame / [7..] DataBuffer`, 其中 `SPECIAL_PLACE { int ID@7; CellStruct Location@11; }`
- 无参回调必须用**普通函数指针调用**, 不能内联汇编 (§11 坑 7); 满了 (`count >= 0x80`) 返回 0 → 记 `sws: instant queued fail`, 仍吞掉这一击

### 上膛 (`Action != None`): **必须整段照抄引擎, `UnselectAll` 是前提**

`SwsArmSW(swIdx)` 抄 gamemd `0x6AAF46..0x6AAF9D` (`SidebarClass_ProcessClick` 的 `Action != None` 分支), 与 Phobos `SWButtonClass::LaunchSuper` 一一对应:

```
6AAF4C  [0x88098C]=0     CurrentBuilding = NULL
6AAF52  [0x880990]=0     CurrentBuildingType = NULL
6AAF58  [0x880994]=-1    CurrentBuildingOwnerArrayIndex = -1
6AAF62  call 0x4A8BF0    DisplayClass::SetActiveFoundation(NULL)
6AAF6D  call 0x4AC8C0    MapClass::SetRepairMode(0)
6AAF78  call 0x4AC660    MapClass::SetSellMode(0)
6AAF7D  [0x88099A]=0     PowerToggleMode
6AAF84  [0x88099B]=0     PlanningMode
6AAF8B  [0x88099C]=0     PlaceBeaconMode
6AAF92  [0x8809A0]=esi   CurrentSWTypeIndex = swIdx
6AAF98  call 0x48DC90    MapClass::UnselectAll   ← ★ 少这条就"选了单位放不出去"
```
(偏移与 YRpp `DisplayClass.h` 逐项对上: +0x11A4/+0x11A8/+0x11AC/+0x11B2/+0x11B3/+0x11B4/+0x11B8。)

**为什么 `UnselectAll` 不是收尾而是前提** —— `DisplayClass::DecideAction` (`0x692610`) 开头先判**当前单位选中表** `0xA8ECC8`:
```
00692613  mov eax,[0xA8ECC8]   ; 单位选中表
0069261B  test eax,eax
00692626  je 0x692673           ; 空 → 走正常判定
00692640 / 00692666  call vfunc ; 非空 → **带返回值直接早退**
```
选中着单位就**永远走不到** `0x692B06` —— 而那里才是"已上膛的超武按当前格/目标算出该做什么 Action"的唯一入口:
```
00692B06  mov eax,[0x8809A0]   ; CurrentSWTypeIndex
00692B18  mov ecx,[SWType::Array+eax*4]
00692B1D  call [eax+0x6C]      ; 该类型按 (cell, pObject) 给出 Action, 覆盖默认的 0x2E
00692B24  mov [esp+0x10],eax
```
再由 `0x6CEEB0` 反查 `Type->Action == action` 才建 SpecialPlace 事件。少了 `UnselectAll`: 上膛成功但点地图 = 引擎拿默认 `0x2E`, 不在放置分派白名单里 → 点了没反应。原版侧栏上膛时顺手清了选中, 所以表现为"选载具可直接套铁幕"。

⚠ 只写 `CurrentSWTypeIndex` 无选中时正常, 一选中单位就必坏。

### 火风暴类 (爆裂屏障 / 心灵之火 / 黄金之风): **支持, 不特殊化**

`Action` 就是 0, `actionNone=1` 自动让 `instant=1` 走 SpecialPlace 立即分支 (点击激活, 不用再点地图)。

状态机由引擎自己跑: `SpecialPlace` 事件 → `HouseClass::Fire_SW` (`0x4FAE50`) → `HouseClass::SWFire` (起于 `0x4FAC46`, Ares 在 `0x4FAE72` 挂 `HouseClass_SWFire_PreDependent`) → `SuperClass::ClickFire` (`0x6CB920`, **全代码唯一调用点 `0x4FAE97` 就在 `SWFire` 里**) →
Ares `Hooks.cpp:521-562` 的 `Draining↔Ready` 互切 + `RechargeTimer.Start` + `Launch`/`Deactivate`。⇒ 侧栏**不需要写任何引擎状态**, 只要别抢在引擎前面自己发射。`drain` 只决定 instant, 不参与过滤。

其它事实:
- 维持时长 = `(rechargeTime - left) × SW_ChargeToDrainRatio`, 能量耗尽自动回充。
- `ChargeDrainState` = `Super+0x7C`, 三态 `0=Charging / 1=Ready / 2=Draining`。偏移实证: Ares `0x1003517F mov [esi+0x7C],1` / `0x10035217 mov [esi+0x7C],2`; gamemd `SuperClass::NameReadiness @0x6CC2B8` 按 `[ecx+0x7C]` 分支出 Charging/Ready/Draining。
- **停用会重设计时器**: 停用时 Ares 算 `duration = rechargeTime - left/ratio` 再 `RechargeTimer.Start(duration)`, 而 `ChargeDrainState` 置 `Ready(1)` —— 所以会出现"状态是 Ready 但计时器仍在跑"的情形, 上升百分比仍要显示 (这正是 §4 用 `remain > 0` 而不是 `drainState` 判满格的原因)。
- 手册说"可以手动关闭"只在 `SW.Unstoppable=no` 时成立, MO 给的是 `yes`, 所以启动后停不掉。

## 9. 帧率: `0x4F42F0` 不是"每帧一次"

`SWS_Poll` 与同函数里其它 9 个 `*_Poll` 挂在 `0x4F42F0` (`MOExperience_PrepareEntry`)。**"每循环"不等于"每帧"**: gamemd 里 `call 0x4F42F0` 有 **113 个静态调用点**, 散在 AI / 对象 / 渲染 / 消息代码里, 多处位于**逐对象循环内**; 两个独立锚点交叉验证 → **每渲染帧 142 次** (区间 47~225)。

142 倍扇出 = 每帧 142× `GetAsyncKeyState` + 284 次 `QueryPerformanceCounter`。已做: ①**帧门** —— `SWS_Poll` 开头读 `ADDR_FRAME`, 与上次相同就直接返回; ②日志汇总周期 60 → 600 帧; ③布局/排序/像素全移进"重建"路径 (§4)。**还能砍的**: 其余 9 个 `*_Poll`
同样在扇出里且被 `PowerDrawBoth` 无条件调用 = 最大剩余开销。

⚠ **写钩子注释前必须数一遍 `call <addr>` 的静态引用和它所在的循环层级** —— 真帧入口应该只有 1 个调用点。

## 11. 已确认的坑 (改代码前先看)

1. `0x87F7E8` 是对象本身, 不能解引用 (§2.1)。
2. **透明度函数约定相反**: `SwsCFillA` **内部已乘** `s_Alpha`, 调用方只给原始不透明度; `SwsCCov`/`SwsCFillR` **不乘**, 调用方才预乘 (给 `SwsCFillA` 传 `70*s_Alpha/100` 是乘两次)。只有悬停名提示框与悬停图标不吃 `Alpha`。
3. **缓存 blit 里有两套坐标系**: 目标列漏 `s_CchX` → 整块贴到画面最左边; 夹取写成"只有出画时才修正" → 内层多跑 `s_CchX` 次 → **整块侧栏被平铺糊满全屏**。正确: 目标列区间 `[0,surfW)` 平移成缓存内下标再与 `[0,s_CchW)` 取交, **两头都夹**。其它原语 (`SwsCFill`/`SwsCPcx`/`SwsCCov`) 都是先减原点→夹→一律缓存下标, 无此问题。
4. **单像素混合算术测试抓不到循环边界错**, **逐点测试也看不见"包含关系"** (提示框自身矩形对但缓存矩形没包住 → 截断; blit 像素对但循环边界没夹 → 平铺糊屏)。合成/拷贝必须另做**结构性**测试: 预填哨兵的合成面跑真循环, 逐像素断言"该写的写对 / a=0 的没动 / 矩形外一格没动"。
5. **探针扫内存必须跳过虚表指针**: offset 0 是代码地址, 被当结构读会顺着"文件名指针"二次解引用 → 必崩。**缓存槽位必须同时记 id**, 否则查找永远失配、槽位涨满后一律返 NULL。
6. **判新行/新字串的缓冲要清满**: 充能百分比那 8 字节 `wchar_t st[8]` 只清前 4 个, 第 5 个是栈垃圾 → `RenderLine` 把 "100%" 后的垃圾也画出来。
7. **内联汇编 clobber 列表必须完整**: 只声明 `ecx/edx/cc/memory` 而真实 `call` 还破坏 `ebx/esi/edi/ebp` → 崩在 `EAX=ESI=<代码地址>`。**用普通函数指针调用, 让编译器自己生成 `call`。**
8. **`AppendCStr` 的返回值必须接住**: 丢掉它下一段会写回同一位置, 把 ID 整段覆盖掉, 看起来就像"ID 是空的"。

**别试**
- 在 `AddCameo` 入口 (`0x6A6316`) 钩拦截门 —— 该点根本不会被调用; 用 15 帧复查。
- 扫 `.data` 找 `RulesExt::TabCameos` —— 从 Ares 导出函数里的绝对地址读。
- 拿 `CameoCount` 当 `TabCameos` 定位/复核闸门; `s_BoundValid` 当吞没门 (用 `s_BoundsKnown`); 给 `SwsSidebarShows` 加模式判定; 拿 `SwsScan` 下标 `n` 当条目身份; 用 `Unsorted::ScenarioInit 0xA8E7AC` 判在跑一局; 整块栏区矩形判吞没命中; 硬编码 `DSurface::Composite 0x88731C`; 每帧路径上读 ini; 图标盒 60×48 做成配置项。
- 自己复刻 ini 合并语义 (挂 `SuperWeaponTypeClass::LoadFromINI` 快照): 追不上 Ares 的合并顺序, 且 `CCINIClass::INI_Rules` 在扫描期只有基础规则那份 —— **走 ExtData** (§1.3)。
- "延一帧写 `CurrentSWTypeIndex`" 或按下就写 —— 引擎放置判据 (`0x692B06`) 是 `CurrentSWTypeIndex != -1` **且当帧按键按着** → 就地释放, 延一帧躲不掉; 必须**等左键松开边沿**才写 (`s_SelDown`/`s_ArmIdx`/`s_PendSel`)。
- 上膛时**只写 `CurrentSWTypeIndex`** —— `DecideAction` 开头判选中表, 选中着单位会早退到不了超武那支 (见 §8"上膛")。
- 引回 `PCX::BlitToSurface 0x6BA580` 当兜底 —— 只能 blit 进已锁的合成面, 而重建期刻意不持锁面; 且它 100% 不透明、不认 `Alpha`。校验不过现在就是**不画这个图标** + 记一行。
- 给火风暴类强制 `instant = 0` —— 那会要求点地图, 与原版 (点击激活) 不符。

## 12. 通用方法论

- **别拿"缺失"当证据**: 以为抄了 Phobos `LaunchSuper` 就够、Firestorm 没 `Action=None` 就要选格 —— 正确做法是抓包 / 读被调用方源码。
- **拿上一版 `.o` 当回归基准**: 同参数 `-O2` 输出稳定, `nm --defined-only` 逐函数比代码大小 + `strings` diff 字面量, 少一条日志往往就是删错分支。
- **一个改动引出两个症状时, 先找它们共享的数据路径**。
- **离线先验证再进游戏**: PE 导出表 / `.data` 范围 / 钩子体机器码 / 原 exe 反汇编都能脚本读出来 (见 §1.5)。
- **测试** (`test/`, `run-tests.bat`, 纯逻辑不加载 gamemd): `sws_blit_test` 哨兵合成面跑真 blit 循环; `sws_geom_test` 网格扫分辨率×MaxRows×Gap×ColGap×RightMargin×名字宽度×滚动位置; `sws_hover_test` 造"原序 ≠ 排序后"断言命中经 `s_Order` 解析回同一条目; `sws_blend_test` 混合算术数值例。geom 不变量跟**夹取后**的值比; **每套都做反向验证** (bug 版改回去确认它会红)。
