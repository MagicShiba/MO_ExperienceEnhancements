# 超武侧栏 (SWSBar)

## Phobos 原理 (最小参照, 未入库全文)

- 位置: `references/Phobos/src/Ext/Sidebar/SWSidebar/` (`SWSidebarClass`,
  `SWColumnClass`, `SWButtonClass`, `ToggleSWButtonClass`)。
- 本质: 一组 `GadgetClass` 按钮列, 经 `GScreenClass::AddButton` 注册,
  由引擎输入/绘制管线统一驱动。
- 数据: `HouseClass::CurrentPlayer->Supers[superIdx]` (`SuperClass`:
  `IsPresent/IsReady/IsSuspended/RechargeTimer`, `SuperWeaponType`:
  `RechargeTime/Action/SidebarImage`)。
- 过滤: `SuperWeaponSidebar.Allow` (缺省取
  `RulesExt::SuperWeaponSidebar_AllowByDefault`) /
  `RequiredHouses` / `Significance >= RequiredSignificance` /
  `SW_ShowCameo`。
- 排序: `SuperWeaponSidebar.PriorityHouses` (本家优先) +
  `BuildType::SortsBefore(Special, ...)` (rules 顺序)。
- 布局: 左侧停靠, 列高 pyramid 递减 (`Pyramid`), 垂直居中;
  配置在 `[Sidebar]` (`SuperWeaponSidebar.Max/MaxColumns/Interval/
  LeftOffset/CameoHeight`)。
- 绘制: 图标 `SidebarPCX` (Ares, MO 全套 `*icon.pcx`) 或 SHP
  `SidebarImage`; 未就绪盖 `DARKEN_SHP`; 进度盖 `GCLOCK2_SHP`
  (`AnimStage`); 就绪/快捷键字走 `NameReadiness()`。
- 交互: 左键 `LaunchSuper` (需打靶→置 `Display::CurrentSWTypeIndex`
  进 targeting; `Action==None`/AI 靶→直发 `SpecialPlace` 事件);
  右键取消 (`CurrentSWTypeIndex=-1`); 开关掣翻
  `ScenarioExt::SWSidebar_Enable`。
- 点击吞没: `DisplayClass::ProcessClickCoords` 内 `0x692419`
  (7B: `movsx ecx,[esi]` + `movsx edx,[esi+2]`, 无 rel),
  落自家按钮区跳 `0x6925FC`。

## 本移植取舍 (见 `src/SWSBar.cpp`)

- 不建 Gadget (虚表/GameCreate 配重太大): 纯覆盖层, 渲染挂
  `MOExperience_MessageDrawHook` (Composite 面), 输入靠轮询 +
  `0x692419` 吞没门 (同点同去向, 首 7B 实测无 rel, 见构建记录)。
- 只要图标不要 UI 资源: 不加载 Phobos 那套 On/Off/Top/Center/
  Bottom PCX; 图标盒 60x48 自画 (底 + 阵营色边框 + 名/状态字 +
  进度条)。MO 图标本体是 Ares `SidebarPCX`, 读 Ares 扩展内存
  成本过高, 故图标暂用文字盒占位 (后续可经 `0x4AED70`
  `CC_Draw_Shape` 补 SHP/PCX, 接口已留)。
- 超武/支援技能同注册类型 (`SuperWeaponTypes`), 不区分;
  显示门 = `Owner==本家 && IsPresent` (Phobos 摘牌逻辑同义)。
- 4 列右置 (盟/苏/厄/焚风), 空列隐藏; 归属内建表 96 个
  (由 `rulesmo.ini` 离线推导: 授予建筑 `SuperWeapon*=` +
  `Owner`/`Prerequisite` 链, 脚本见构建记录), 查不到落玩家
  阵营列 (`Scenario.PlayerSideIndex`, 读不到回 0)。
- 单节 `[SWSidebar]`: 全局键 + 超武 ID 键共处一节。
  值语义: 负数=隐藏, 0=默认 (优先级 1000), 正数=优先级
  (越小越靠前, 同值按 ArrayIndex)。缺键=默认显示。
- `ToggleKey` (默认 F4) 显隐, 隐藏即不占空间 (不画+门放行)。
- 点击: 左键图标只写 `Display+0x11B8` (`CurrentSWTypeIndex`,
  UI 态, 非模拟, 联机安全); 右键栏内写 -1。
  `Action==None` 的直发类本版也只进打靶 (limitation)。
- 偏移全 fail-closed: 数组/指针/ID 可打印/`swIdx` 范围/
  标志位 0/1 任一不满足即跳过该项; 扫描零命中即不画。

## 配置 (`dist/MOExperience.ini` → 游戏内同名文件已同步追加)

`[SWSidebar]`: Enable/Opacity/ToggleKey/ClickFire/IconW/IconH/
Gap/ColGap/RightMargin/CenterY/TopMargin/FontPx/Bold/FontFace +
`<SWID>=<int>` (例: `NukeSpecial=10`, `SpyPlaneSpecial=-1`)。

## 验证 (进游戏后看 `MOExperience.log`)

1. `sws: en=1 op=60 click=1 iniN=N` (初始化回显)。
2. 开一局并造出超武建筑 → `sws: scan ok n=M e0=K`
   (M=本家现存超武数, e0=首个 ArrayIndex)。
   - 若无此行: 偏移/门控假设失效, 按 fail-closed 无显示,
     把日志贴回来定位 (重点: `sws: scan ok` 缺席 + 是否崩)。
3. 右侧应出现阵营色列 (盟军蓝/苏联红/厄普西隆紫/焚风橙边框),
   名 + `Ready`/倒计时/`Hold` + 底部进度条。
4. F4 显隐; 左键图标进打靶 (光标变超武), 右键栏内取消;
   栏外点击行为与原版一致 (吞没门只拦栏内)。
5. `[SWSidebar]` 加 `NukeSpecial=-1` 重启 → 该项消失;
   加 `NukeSpecial=1` → 本列置顶。

  `sw_faction.py` (初版投票) / `sw_faction2.py`

## 启动崩溃根因与修复 (0.2.154a 首版)

- 现象: Syringe 挂钩成功 (1477 hooks), DLL 初始化走完
  (`MOExperience 0.2.154a start`), 约 4 秒后进程 fault。
- 定位: 首个异常 EIP 落在 `SWS_Poll+0x1AC`, 指令
  `mov eax,[edx+0x1C]` (`type = *(sup+0x1C)`), EDX=0x404E0000。
  调用链 (栈回溯): `PrepareEntry → PowerDrawBoth → SWS_Poll`。
  启动期超武数组半初始化 (Items 非空但条目是垃圾),
  `IsPlausiblePtr` 只判下界, 垃圾指针通过后解引用 fault。
  Syringe 吞掉首异常继续执行, 游戏随后在字体光栅循环
  (0x497AE3/0x497AFC, `mov dx,[eax]` 取字形) 连环 fault。
- 修复: 组合门控 (见 `SwsScan`): 先纯安全读
  (超武 Items/Count + House Items/Count + 本家五元组),
  任一与上一轮不同则只缓存、本轮返回 (内容零解引用);
  五元组稳定后再做入局检查 (本家须在 House 数组内) 与逐项全校验。
- 教训: 凡是扫整表 (数组内容) 的新模块, 一律先稳定门控再碰内容;
  固定地址字可随便读, 指针内容不行。

## 图标与 ShowCameo 过滤 (0.2.154a 后)

- 不要名称: 名行删除, 状态字 (Ready/倒计时/Hold) 叠在图标底部,
  进度条压底边, 未就绪整块罩 45% 黑 (免 DARKEN_SHP)。
- 图标走引擎 SHP 管线: `CC_Draw_Shape(Composite, CAMEO_PAL,
  SidebarImage, 0, pos, 全面, bf_400, 0,0,Ground, 1000, 0,
  NULL,0,0,0)` (Phobos SWButton::Draw 同参)。
  SidebarImage 偏移同样 +12 (0xB8), 进表前做 SHP 自检
  (非引用 + 宽 16~128 + 高 16~128 + 帧 1~16), 不过即回退画盒。
  调色板 CAMEO_PAL (0x87F6B0), 空则退 SIDEBAR_PAL (0x87F6CC)。
- ShowCameo=false 过滤不读 Ares 扩展内存: 蹭引擎自己的文本列表
  (`g_SWCap` 名行, 400ms 保鲜), 对上名才显示。引擎侧已做全部过滤,
  交集即所求 (IsPresent 且引擎在画)。
- 诊断: `sws: got N shp M` (N=过滤后, M=有 SHP 的);
  M=0 则 SHP 路不通, 下一步走 PCX (SidebarPCX 文件名需另找源)。

## 2026-09-29 图标链路定案 (PCX, 走引擎现成设施)

结论: MO 的超武图标**不是 SHP**。`rulesmo.ini` 里 96 个超武节用
`SidebarPCX=xxx.pcx`, `SidebarImage` 出现 1 次、`Cameo` 0 次; PCX 打包在
`expandmo*.mix` / `thememo.mix` 里, 磁盘上没有。所以 `SidebarImage` 指向
引擎的 `XXICON.SHP` 占位引用, 画出来必然是**同一个紫球** (11 个条目
指针完全相同)。

最终链路 (全部引擎现成设施, 与 Phobos `SWButtonClass::Draw` / Ares
`Misc/Cameos.cpp` 同款):

1. 读键: `*(CCINIClass**)0x887048` (游戏已加载好的 rules 对象, 走 MIX)
   -> `INIClass::ReadString` @ `0x528A10` 读 `<超武ID>` 节 `SidebarPCX=`
2. 载图: `PCX::Instance` = `0xAC4848` (**`this` 就是该地址本身, 不能解引用**;
   `DEFINE_REFERENCE(PCX, ...)` 类型是 `PCX` 不是 `PCX*`)
   -> `GetSurface` @ `0x6BA140`, 未命中则 `ForceLoadFile` @ `0x6B9D00`
3. 贴图: `PCX::BlitToSurface` @ `0x6BA580`, 矩形 `{x,y,60,48}`,
   目标面**用 SWS_Draw 收到的 surf**, 色键 `COLOR_PURPLE=0xF81F`
4. 无 PCX 时才回退 SHP: 跟随 `SHPReference::Data`(+0x0C) / `GetData()`
   @ `0x69E580`, 再 `CC_Draw_Shape` @ `0x4AED70` (`__fastcall`, ECX=surf,
   EDX=palette, 其余 14 个压栈)

### 三个决定性坑 (都曾表现为"图标不对"或崩溃)

- `PCX::GetSurface` 在文件**未加载时不返回 NULL**, 而是直接给一张占位
  surface。必须**无条件先 `LoadFile`**, 否则 11 个图标 blit 的全是同一张
  占位图 (症状: 全是紫球, 但日志显示 "pcx ok")。
- 引擎的 `BSurface*` **绝不能跨帧缓存**。引擎切页签/重载美术时会释放并
  重建 PCX surface; 缓存的指针变野指针 -> 平时画成脏图, 切页签时崩溃。
  现在只缓存**文件名**, surface 每帧现取。
- 硬编码 `DSurface::Composite` = `0x88731C` 在本机 Ares 构建里**不是**
  surface 对象 (该处虚表为 NULL), `BlitToSurface` 内部一调虚函数就跳 0
  (转储: `EIP=0, ECX=0x88731C`, 返回地址 `0x6BA597`)。用 SWS_Draw 的
  `surf` 参数。

## 本机 (Ares 3.0) 地址可信度表 —— YRpp 地址不能直接信

游戏实际跑的是 **Ares 3.0** (`syringe.log`: "Applying Ares 3.0",
`Ares.dll` 20.333.289), 不是 YRpp 基线 gamemd。以 `Ares.dll` 的
`.syhks00` (1448 条 hook) 为准:

| 地址 | 含义 | 本机可信? |
|---|---|---|
| `0x528A10` | `INIClass::ReadString` | **被 Ares inline hook** (`INIClass_GetString`, sz=5)。drop-in 替换, 语义一致, 可调 |
| `0x88731C` | `DSurface::Composite` | **不可信** (虚表 NULL) |
| `0x6B9D00/0x6BA140/0x6BA580` | PCX 加载/取面/贴图 | 可信 (Ares 自己也在调) |
| `0xAC4848` | `PCX::Instance` (this) | 可信 |
| `0x4A38D0` | `LoadWholeFileEx` | 可信, 但读 rulesmo.ini 实测拿不到文本 |
| `0x4AED70` | `CC_Draw_Shape` | 可信, 但必须 `__fastcall` |
| `0x69E580` | `SHPStruct::GetData` | 可信 |
| `0x887048 / 0x87F6B0 / 0xA8E330 / 0x473C50` 等数据全局 | | 可信 |

Ares 3.0 自己读 `SidebarPCX=` 并在 `0x6A9952 / 0x6A9A43` 画 PCX cameo ——
原版侧栏里那些正常图标就是 Ares 加载的这一批 PCX。

## 其它已确认的坑

- 探针扫内存时**必须跳过虚表指针**: offset 0 是 0x004xxxxx 的代码地址,
  被当成 SHP 结构读会顺着"文件名指针"二次解引用 -> 必崩。同理不要顺着
  野指针打字符串。
- `SwsPcxFileOf` 建槽位时**必须 `SwsCopyId` 记 id**, 否则查找永远失配、
  槽位涨满后一律返回 NULL (曾导致 PCX 分支静默失效, 全体回落紫球)。
- 删代码时判断注释起点要用 `lstrip().startswith("/*")` —— 注释是缩进的,
  否则脚本会一路走错位置, "删掉了"其实没删 (那个图标探针因此赖了很多轮)。
- **构建校验必须看退出码 + DLL 时间戳**, 不能只 grep "error C": gcc 的
  `error:`(无 C) 不匹配, 曾连续多轮报告"构建成功"而 DLL 根本没更新。

## 诊断日志 (保留, 排查同类问题很好用)

- `sws: raw/tri/win/show/stat/got/scan ok` —— 扫描链路健康 (五元组变化才打)

- 清理前存在过 `drw/dsw/dim/precx/rd/pl/nmcmp/aridx/sample` 等一次性探针,
  图标定案后已全部删除。

## 未解决: 点击后"原地释放"

现象: 点图标选中后立即在原地释放, 期望是像原版侧栏那样"选中 -> 再点
地图才打靶"。已知:
- RA2 放置判定用的是"左键**按住**", 所以延后一帧写 CurrentSW 无效。
- Phobos 靠真 Gadget 吃掉按下顺带清掉鼠标按键态; 我们不是 Gadget。
- 试过"松开时才上膛"(等左键 release 边沿), 日志显示 `armed(hold)`
  (60 帧兜底触发) + 引擎在我们上膛同帧就 `learn CLR`, 说明引擎在我们
  写之前已经自己完成了选中+放置。
- 试过在 `0x692419` (`DisplayClass::ProcessClickCoords`, Phobos 同点)
  吞点击: 曾因 `s_EatPress` 只置位不清而**吞掉全游戏点击**, 已修成只活
  一帧。
- `WWMouseClass` (0x887640) 前 0x80 字节在按键时**没有任何变化**, 左键
  状态不在那里, 想清按键态的思路暂时走不通。
- 另注: `swIdx` 曾用 `+0x98` 读出 135 (= 类型总数, 不是本类型的
  ArrayIndex), 写进去会让引擎 `Supers[]` 越界并当场清掉选中; 现改为在
  类型数组里按 ID 反查真实下标 (`SwsArrayIndexOf`)。
