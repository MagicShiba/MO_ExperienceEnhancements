# 玩家颜色切换（本地）

## 1. 目标与约束

- 仅修改本地 `HouseClass::CurrentPlayer` 的颜色/色板，用于截图/预览基地配色。
- 不写 INI，不持久化；重开游戏恢复原颜色。
- 只改显示相关状态，不进入模拟逻辑；联机时 ESC 自定义页本来就被
  `OU_IsMP()` 跳过，彩虹 tick 也会在联机时自动停止并还原。
- 彩虹色每 3 帧推进一次色相，新增 1 个 Syringe 钩子
  `0x55DDA0+5 -> PlayerColor_TickHook`；其余切换仍由 ESC 菜单直接调用。

## 2. 代码位置

- 颜色逻辑：`src/GUI/PlayerColor.cpp` / `PlayerColor.h`。
- 界面：`src/GUI/EscMenu.cpp`，只负责布局、绘制、命中测试和点击分发。
- 构建脚本需包含 `src\GUI\PlayerColor.cpp` 并链接 `obj\PlayerColor.o`：
  - `build-full.bat`
  - `build-fast.bat`（NEEDFULL 列表和链接行）

对外接口：

```c
int PlayerColor_Count(void);
int PlayerColor_Current(void);
int PlayerColor_Set(int slot);
unsigned short PlayerColor_Swatch(int slot);
void PlayerColor_Tick(void);
```

`slot` 是动态颜色列表的下标，不是引擎 `ColorScheme` 索引。

## 3. 为什么使用 53 阶色板

`[Colors]` 加载时，游戏对每个颜色名调用两次
`ColorScheme::FindByName`：一次 `ShadeCount=1`，一次 `ShadeCount=53`。
因此 `ColorScheme::Array` 中同名颜色通常成对出现：

- `ShadeCount=1`：UI/消息用的平面色板。
- `ShadeCount=53`：玩家房屋/单位重映射用的多阶色板。

原实现按名字找 `ShadeCount=1` 再写入 `HouseClass::ColorSchemeIndex`，
单位会整体变亮。现在统一使用 `ShadeCount=53`：

- 列表只收集 `ShadeCount == 53` 的 scheme。
- 当前颜色、切换目标、色块取色都基于同一套 53 阶 scheme。

`ColorScheme` 关键偏移：

| 字段 | 偏移 |
| --- | --- |
| `ID` | `+0x304` |
| `BaseColor` | `+0x308` |
| `LightConvert` | `+0x30C` |
| `ShadeCount` | `+0x310` |
| `MainShadeIndex` | `+0x330` |

`LightConvertClass`：

| 字段 | 偏移 |
| --- | --- |
| bytes-per-pixel | `+0x4` |
| palette | `+0x174` |

色块取 `LightConvert` 的 16 位调色板第 `MainShadeIndex` 项；
没有 `LightConvert` 时退回 `BaseColor` 转 RGB565。

## 4. 动态颜色列表

- `ColorScheme::Array`：对象 `0xB054D0`，`Items` `0xB054D4`，
  `Count` `0xB054E0`。
- 遍历 `Items`，只保留 `ShadeCount == 53`，按 `ID` 去重，普通颜色最多
  `PLAYER_COLOR_MAX-1=95` 项；最后再追加 1 个彩虹项，总数最多 96。
- 列表顺序即 `rulesmo.ini [Colors]` 的顺序。因此不仅包含 13 个
  玩家色，也包含 `LightGrey`、消息色和 `[Colors]` 里的其它颜色；
  以后新增 `[Colors]` 项会自动出现，不再受 13 色硬编码限制。
- `uimd.ini` 里的玩家颜色槽位在 MIX 内，运行期不能直接用
  `GetPrivateProfileString` 读取，所以没有按 `uimd.ini` 的 13/14
  槽位过滤；直接枚举全部 53 阶 `[Colors]` 更稳，也满足“支持更多颜色”。

## 5. 切换与刷新

- 当前房屋：`HouseClass::CurrentPlayer` `0xA83D4C`。
- 颜色索引：`HouseClass::ColorSchemeIndex` `+0x16054`。
- 设置流程：
  1. `ColorSchemeIndex = 目标 scheme 索引`；
  2. 调用 `0x50B840` 刷新 `HouseClass::Color`（`+0x56F9`）；
  3. 调用 `0x50BA00` 刷新 `LaserColor`（`+0x56FC..FE`）。
- `PlayerColor_Current()` 把当前 `ColorSchemeIndex` 与动态列表比较，
  返回高亮下标；不在列表中时返回 `-1`。
- 只改 `CurrentPlayer`，不改其它房屋。
- 调色板变化后必须让战术视图强制重绘：调用
  `TacticalClass::RegisterDirtyArea`（`0x6D2790`），矩形取
  `DSurface::ViewBounds`（`0x886FA0`）的宽高并向外扩 64 像素。
  否则有动画的对象每帧重绘会立刻变色，静态建筑/单位仍显示旧缓存，
  看起来像“刷新不及时/色相跳变”。
- `RegisterDirtyArea` 是只读渲染面操作，不改变模拟状态，联机安全。

## 6. 彩虹色（列表最后一项）

- `PlayerColor_Count()` 返回“普通颜色数 + 1”；最后一项就是彩虹，
  `PlayerColor_Set(普通颜色数)` 进入彩虹模式。
- 色相用整数 `0..1535`（6 段 × 256），每 3 帧前进 6（`FRAME_SKIP=3` ×
  `STEP=6`），约 12.8 秒走完一圈；ESC 里的彩虹色块固定绘制成 6 条彩虹色带，
  不依赖自动刷新，所以不选中时也能一眼识别。
- 1536 不是 2 的幂，**不能**用 `& 1535` 回绕；那会清掉 bit 9，
  导致第 3 段（512..767）被跳过并产生跳变。必须用 `% 1536`。
- `PlayerColor_Tick` 在 `s_Rainbow == 0` 时直接返回，不推进色相、
  不刷新房屋、不标脏视图：普通颜色模式没有彩虹的帧开销。
- 色相不是每帧应用：每 3 帧才写一次 `Colors[16..31]` 并调用
  `UpdateColors` / 回拷非所属色 / 刷新房屋颜色，频率降到原来的 1/3。
- 每次应用只标脏战术视图的 1/5（`PC_RAINBOW_DIRTY_PARTS=5`），
  按竖条轮转，每条左右各扩 64 像素与相邻条重叠；5 次覆盖全视图。
  色相每步只差 6/1536，条带间的色差很小；进入/退出彩虹仍整视图刷新。
- 进入彩虹时预计算 `s_RainbowValues[16]`（每个基色的最大通道），
  更新时不再重复求 max；`s_RainbowData` 在进入时缓存，避免每帧再取
  `FullColorData` 指针。
- tick 里只比较当前房屋指针，不每帧扫描房屋数组；房屋存活检查只放在
  进入和退出彩虹时。
- 进入彩虹模式时：
  1. 保存当前 scheme 的 `LightConvert` 的 `FullColorData`
     （`ShadeCount * 256 * BytesPerPixel` 字节）、`Color1/Color2/Tinted`，
     以及 `UsedPalette1`（`+0x188`，即 scheme 的 `Colors` 调色板）
     的 16 个所属色基色 `Colors[16..31]`，还有 `BaseColor`（`+0x308`）；
  2. 每次应用只把当前色相的 16 档明暗写入 `Colors[16..31]`，同时把
     `BaseColor` 的 **H 字节**改为当前色相、保留原 S/V（`BaseColor` 是
     `[Colors]` 的 HSV 原样三元组，不是 RGB），然后调用
     `UpdateColors(1000,1000,1000,0)` 重建 `FullColorData`；
  3. 再把每个 shade 的 `0..15`、`32..255` 条目从保存副本拷回，
     只保留 `16..31` 的彩虹结果，彻底避免非所属色被改动；
  4. 调用 `0x50B840` / `0x50BA00` 刷新 `HouseClass::Color` 和激光色，
     侧边栏/雷达等也会跟着流动。
- 不能直接把彩虹 RGB 传给 `UpdateColors`：`IndexesToIgnore` 掩码
  `0x83E1AC` 让绝大多数调色板索引都走颜色因子分支，直接传色相会把
  整个单位/建筑染色；只改 `Colors[16..31]` 并保持 `Color1=1000`
  才能只覆盖所属色。
- `ColorScheme::BaseColor`（HSV：`H,S,V`，`+0x308`）也随色相变化：普通颜色
  切换时文本会跟随玩家色，彩虹模式只改 H 字节、保留原 S/V，消息/提示等文本
  才会和单位色一样只变色相。**不能写 RGB**：引擎 `0x517440` 按 HSV 解释，
  写 RGB 会变成饱和度/亮度乱跳。
- 离开彩虹、切回普通色、联机、当前房屋变化时，恢复保存的
  `Colors[16..31]`、`BaseColor`、`FullColorData` 和颜色字段，再刷新房屋颜色。
- 每帧推进由 `0x55DDA0`（MainLoop，5 字节）上的
  `PlayerColor_TickHook` 完成；`.inj` 与 `SyringeHooks.cpp` 保持同步
  （CnCNet-Spawner 在 `0x55DDA5` 有相邻钩子，不重叠）。
- 注意：彩虹修改的是当前 scheme 共享的 `LightConvert`。如果同一局里
  还有别的房屋使用同一 scheme，它们也会一起彩虹；退出彩虹后恢复。
  若以后需要严格隔离，可改为克隆独立 scheme/LightConvert。

## 7. ESC 界面接入

- 标签：中文 `玩家颜色`，英文 `Player color`，不再带“13色/仅本地”。
- 色块尺寸 `ESC_COLOR_SW=14`，间距 `ESC_COLOR_GAP=4`，
  标签区 `ESC_COLOR_LABEL_W=128`（避免英文最后一个 `r` 被截断）。
- 按右侧面板可用宽度自动计算每行色块数，超出后换行；
  颜色行高度由 `Esc_ColorRows()` 动态增加，后续“皮肤”行自动下移。
- 点击只在命中具体色块时生效；点行文字或空白不切换。
- 颜色行仍是“杂项”分组下的一项，不新增独立页面。
- 布局绘制和点击命中共用同一套行高累加顺序，避免每行重算上方全部行。
