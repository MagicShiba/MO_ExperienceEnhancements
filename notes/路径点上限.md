# 路径点上限 (同路线分支 16 / 执行侧 MegaMissionList 256)

文本倒查（`gamemd.exe` 打包串表，全对上）：
- `MSG:NodeMaximum` @ `0x836B8C`（"已达到此路线…"）← `0x6384E1` 拒收与状态 2 提示。
- `MSG:PlannerMaximum` @ `0x836C6C`（"已超过部队…"）← `0x639130` 拒收。

- 加点函数 `0x638120` 起：token 为空则新建（`0x635F20`，0x9C）；`+0x14` 为同 token
  分支数（共用该路线的单位数），不是路径点数；每分支节点数未见封顶检查。
- `0x6384DC: cmp $0x10,%eax; jne 0x638477`（正常建分支），相等落 `0x6384E1`
  拒收（播 `MSG:NodeMaximum` 音、返 0）。即单路线最多 16 个单位，
  超限部分另成路线（报 hetero），分队解决不了。
- `WaypointCap`：5 字节 `83 F8 10 75 96` 换 `jmp` 到壳，
  壳内 `cmp 生效上限; jb 0x638477; jmp 0x6384E1`。eax 全程不动，两目标头都自建标志。
  单机按配置（0=INF），联机原版 16；生效上限与装/卸钩都按实时模式每轮判定，
  不缓存（加载期联机状态未就绪，缓存会带偏整局）。
- 将满提示：`0x6383B4: cmpl $0xF,0x14(%ebp)`（==15 存状态 2，UI 播上限音），
  一并搬到 上限-1（`E9+90` 6 字节补丁，壳内比对；eax 在此处已死，两目标头都先写 eax）。
  单机 INF 即永不提示；联机原版。
- 下令前检查 `0x639130`：仅规划模式跑；`ebp=本家分支数+新单位数`，>128 整单拒收
  并播 `MSG:PlannerMaximum` 音（`0x6391A7: cmp $0x80,%ebp / jle`，中间隔 pop ebp/pop ebx，
  壳内照原样先 pop 再跳；通过=`0x639203`，拒收=`0x6391B1`）。
  单机恒过（`WP_ORDER_SP`=INF，溢出由派发侧直写兜底，不分帧）；联机原版 128。
- 与 `[General] MaxWaypointPathLength`（rulesmo=25，规划模式编号路径）
  不是同一个上限，别混。

## 执行侧 MegaMissionList 256

- 执行侧每帧只从 `DoList` 搬 256 条进 `MegaMissionList`
  （`0x64C739: cmp [0xA83ED0],0x100 / jge`），满即在 `DoList` 原槽置
  `IsExecuted` 位（`0x64CAA8`）丢弃。
- `MegaMissionList` = `QueueClass<Event,256>` @ `0xA83ED0`
 （Count+0，Head+4，Tail+8，Array[256] +12 每项 111B，Timings[256] @ `0xA8ADDC`），
  原地无扩容空间，故 Array/Timings 整体搬家到堆上 4096 份，头不动：
  初始化基址+个数（`0x4E7F00/05`）、入队上限（`0x64C739` 0x100→0x1000）、
  入队数组/Timings 基址（`0x64C774/8C`）、Tail 环绕掩码（`0x64C79F`）、
  出队数组基址（`0x64CC03`）、Head 前进掩码（`0x64CC21`，漏了它头尾脱节，
  头回绕 256 而尾走到 4095，出队重读已执行槽 = 选A动B）、Head/下标环绕掩码 10 处、
  出队侧散读基址 20 处
  （`[idx*111+旧基址]` 全是出队字段读，掩码放开后会读越界，必须同搬），共 38 处，
  全是 imm32/disp32 同长改写，原代码流不动，无跳板（见 `MegaListCap.cpp`），
   只在单机装（联机完全绕过）。
  与 `WaypointCap` 上限 4096 对齐。
- 联机安全：联机每帧待执行 MegaMission ≤ `OutList` 128 < 256，
  所有联机可达状态下标/计数 <256，新旧基址掩码映射逐位一致；
  直写 `DoList` 本来就只在单机发生。行为与原版一致，不影响同步。

## 单机同步直行（不分帧不分队）、联机分帧

- 跨帧补发会把一队拆成多路线（后帧单位找不到当帧路线，第二个路径点起报
  hetero），所以规划令永不分帧：`OT_DecideKind` 见 `PlanningModeActive=1`
  直接放行（单机联机一致，联机走原版 16/128 拒收）；单机普通令同样永不排队
  （同步走原 ClickedMission），`OT_SubmitRaw` 单机直接回 0（调用方 `OU_Enqueue` 直发）。
  联机普通令才走 OT 队列（`OrderThrottle=2` 时跨帧补发，含 MoveFeedback/PlanningMode 还原）。
- 单机单位令永不碰 `OutList`（`Mega @0x646EF5` / 槽 `0x6FFE55` / 正统入队
  `0x6521C9` 三钩只在单机装，联机原版，全直写，`OU_Enqueue` 单机同样直写），按原版转运手续
  （`+1&=~1`、`+2=下单家`、`+3=cur+1`、111B 拷、现造 `Timings→PAR`、
  DoList 账本进一步）直接进 `DoList`。单队列单波次不分队，上限即 `DoList`
  的 16384（`OutList` 定长 128 碰都不碰）。联机一律走原版
  （分组/包序敏感，直写全禁）。
- 其它 30+ 处同句式 `cmpl $0x80` 都是单发事件（PLACE/PRODUCE 等），无单位 burst，
  不钩。单机 `OutList` 基本只剩单发事件，转运保持原版时序即可。
- `OU_Enqueue`（中键等自家下单，含模糊）：单机一律直写；联机走 OutList，满回 0。
- 配置 `[Features] WaypointCap`：0=单机不限（默认），N=单机上限（最大 4096）；
  联机原版 16/128；单机/联机按实时 `OU_IsMP()` 判定，不缓存。
- 跨帧会裂路线：手势结束 token 即定稿，迟到单位自成第二条路线。
  单机规划溢出只能直写进管线，不排队不丢弃。
