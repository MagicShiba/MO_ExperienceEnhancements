# 光照预设 (in-game lighting presets)

调查记录: 2026-10-26。目标是让游戏内可切换"早上/下午/黄昏/晚上"这类光照预设。
参考来源: 地图编辑器脚本 `FA2SP_HDM_Edition_1.5.0_MentalOmega/Scripts/创造*光照.fscript`。

## 1. 预设脚本的语义

FA2 脚本用 `SetIniKey(section, key, value)` 写的是**地图文件 (.map = INI 文本) 的 [Lighting] 段**。
四个预设的差异只在 `Ambient` 与 `Red/Green/Blue`; `Level/IonLevel` 一律 0.028:

| 预设 | Level | Ambient | Red | Green | Blue |
|---|---|---|---|---|---|
| 早上 | 0.028 | 0.75 | 1.09 | 0.80 | 0.49 |
| 下午 | 0.028 | 1.00 | 1.08 | 0.94 | 0.68 |
| 黄昏 | 0.028 | 0.35 | 0.51 | 0.46 | 1.41 |
| 晚上 | 0.028 | 0.75 | 0.71 | 0.81 | 1.19 |
| YR苏4关 | 0.008 | 0.75 | 0.80 | 0.80 | 0.90 |

Ion 段四个预设完全一样: IonLevel 0.028, IonAmbient 0.65, IonRed 0.695, IonGreen 0.445, IonBlue 0.775。

## 2. 引擎把 [Lighting] 读到哪里 (gamemd.exe, 实证)

读入函数在 `0x68A7xx` (ScenarioClass 载入地图 ini 的一段)。它把值写进 **ScenarioClass**
(`ScenarioClass::Instance = 0xA8B230`)。字段偏移 (与 YRpp `ScenarioClass.h` 的
`LightingStruct`/`TintStruct` 完全对上, 且反汇编逐条核实):

| 偏移 | 字段 | ini 键 | 存储换算 |
|---|---|---|---|
| +0x3528 | AmbientOriginal | `Ambient` | `(int)(v*100 + 0.01)` |
| +0x352C | AmbientCurrent | `Ambient` | 同上 (三个一起写) |
| +0x3530 | AmbientTarget  | `Ambient` | 同上 |
| +0x3534 | NormalLighting.Tint.R | `Red`   | `(int)(v*100 + 0.01)` |
| +0x3538 | NormalLighting.Tint.G | `Green` | 同上 |
| +0x353C | NormalLighting.Tint.B | `Blue`  | 同上 |
| +0x3540 | NormalLighting.Ground | `Ground` | `(int)(v*1000 + 0.01)` |
| +0x3544 | NormalLighting.Level  | `Level`  | 同上 |
| +0x3548.. | Ion* (Ambient/R/G/B/Ground/Level) | `Ion*` | 同上 |
| +0x3560.. | Nuke* | — | |
| +0x3578.. | Dominator* | — | |

换算用的常量: `0x7E2AC0` = 100.0, `0x7E4658` = 1000.0, `0x7E3808` = 0.01 (加 0.01 是为了
让 0.75 这种值截断后不落到 74)。

**单位**: 字段 = 真实值 ×100 (Ambient 与 tint); Ground/Level = 真实值 ×1000。
逐格光照计算 (`0x484680`) 用 `AmbientCurrent * 1.25` 作为底光, 再加格子的 Intensity,
再按 `Level * 格子高度 - Ground` 修正。

## 3. 运行期改光照的引擎入口 (都在 gamemd.exe)

| 地址 | 函数 | 作用 |
|---|---|---|
| `0x4AE4C0` | `UpdateCellLighting()` | 用当前 scenario 光照重算**所有格子**的光照值 |
| `0x53AD00` | `RecalcLighting(R, G, B, tint)` | 更新光源对象 + 调 `UpdateCellLighting` + 强制重画 |
| `0x53AC80` | `UpdateHashPalLighting(R,G,B,tint)` | 只更新调色板重映射 (被内联进 `RecalcLighting`) |
| `0x53C280` | `UpdateLighting()` | 事件驱动: 核爆/离子风暴/支配者状态切换光照 |
| `0x555AC0` | `ScenarioLighting(r,g,b)` | 把 tint 三个分量**夹到 0..1000** |
| `0x4F42F0` | `MapClass::Prepare(flag)` | 标脏战术视图并重画地图面 (`ecx = 0x87F7E8` = MapClass) |

`RecalcLighting` 是 `__stdcall`: `ecx=R, edx=G, 栈: B, tint`。
**tint 分量单位 = 字段值 ×10 (= 真实值 ×1000)**, 引擎内部再夹到 1000 → 即真实值上限 1.0。
所以地图编辑器里 `Red=1.09`、`Blue=1.41` 这种 >1 的值, **在游戏里会被夹成 1.0**,
预设效果和编辑器不完全一致 (偏色仍在, 但过冲没了)。

## 4. 引擎自己的"运行期改光照"范例 (照抄它最稳)

游戏内地图动作 (TRIG 动作, YRpp `TActionClass.h`):
- `SetAmbientRed`   @ `0x6E2E60` → `RecalcLighting(newR*10, oldG*10, oldB*10, 0)`, 然后写 `+0x3534`
- `SetAmbientGreen` @ `0x6E2EB0` → 同理写 `+0x3538`
- `SetAmbientBlue`  @ `0x6E2F00` → 同理写 `+0x353C`
- `SetAmbientLevel` @ `0x6E2F50` → 写 `+0x3528` (AmbientOriginal), 再把 `+0x3530` (Target) 同步过去

注意这些动作是**先 Recalc 再写字段**, 写完的字段要等下一次光照刷新才生效。
自己实现时应该**先写字段再刷新**, 才能立刻生效。

Ares 也是同一套 (`SWTypeExt::ChangeLighting`): `scen->AmbientTarget = ambient; scen->RecalcLighting(r,g,b,1);`
—— 但它只写 Target, 而 `UpdateLighting()` 的普通分支每次都会把 Target 重置回
`AmbientOriginal` (`0x53C38E`), 所以**必须同时写 `+0x3528`**, 否则会被引擎改回去。

环境光渐变: 引擎每帧比较 `AmbientTarget` vs `AmbientCurrent`, 按
`Rules.AmbientChangeRate` (`0x8871E0+0x1668`) / `AmbientChangeStep` (`+0x1670`) 过渡。
要"立刻切"就把 `+0x3528/0x352C/0x3530` 三个一起写成同一个值 (Current==Target 即不过渡)。

## 5. 结论: 实现路径

写 6 个字段 (Ambient×3 + R/G/B) + 可选 Ground/Level, 然后
`RecalcLighting(R*10, G*10, B*10, 0)` (内部已含 `UpdateCellLighting` + `Prepare(1)` 重画)。
一次调用即可, 不用自己逐格算。

需要自己做的:
- **保存/恢复原值**: 切换前快照 `+0x3528..+0x3544`, "恢复默认"时写回。
- **换图重置**: 场景重开 (`ScenarioStarted` 由 0 变 1) 时, 原值要重新快照, 预设要重新套用。
- 联机: 光照是纯客户端渲染量 (格子光照 + 调色板), 不进模拟, 不广播 → 联机安全。
  但按 MOE 规矩, 这仍属于"渲染面"改动, 不写任何模拟状态。

## 6. UI 落点 (MOE 现状) — 已实现

ESC 菜单 GUI 页是表驱动 (`src/gui/EscMenu.cpp`):
`s_GuiLayout[]` (行表) + `s_Toggle[]` / `s_Choice[]` / `s_TChoice[]` / `s_TextNum[]` (控件表)。
"光照预设"分段行 + "光照参数"行是这样加的:
1. `GUI_ITEM_*` 枚举加 6 项 (预设行 + 参数行 + 四个格子), `kLabelKey[]` 加键名,
   `s_GuiLayout[]` 加 `{EG_GROUP, GUI_GROUP_LIGHT}` / `{EG_CHOICE, GUI_ITEM_LIGHT_PRESET}`
   / `{EG_LIGHTPARM, GUI_ITEM_LIGHT_PARM}`。
2. `s_Choice[]` 加一项 (名字表 + get/apply 回调 `EscChoiceLightGet/Apply`)。
3. 文案进 `MOExperienceResources\<locale>.ini` 的 `EscMenu` 段 (中英各一份)。
4. 预设数值**内置在 DLL 里** (`src/gui/LightingPreset.cpp` 的 `s_PresetTable`), 不进 ini。

注意 `EscMenu.cpp` 的规矩: **加行优先往表里插, 不要往 apply 的 switch 里加分支**。
`GUI_ITEM_COUNT` / `ESC_GUI_DISPLAY` 是编译期常量, 改了要同步。

## 7. 已实现 (src/gui/LightingPreset.{h,cpp})

- 参数四个: 环境光 / 红 / 绿 / 蓝, 单位 = 字段单位 (ini 值 ×100), 上限 150。
- 预设号: 0=原图, 1=标准 (四项都 100), 2=早上, 3=下午, 4=黄昏, 5=晚上,
  -1=自定义 (手动调过)。分段控件多一格 "自定义" 只是状态显示, 不可点。
- 写入: 三个 Ambient (`+0x3528/2C/30`) 一起写 + R/G/B (`+0x3534/38/3C`), 再
  `RecalcLighting(R*10, G*10, B*10, 0)`。先写后刷, 立刻生效。
- **原图值惰性快照**: 第一次改动之前才快照引擎当前值 (`Light_EnsureOrig`),
  这样不依赖"引擎读 ini"与"进局"的先后顺序。
- **纯临时**: 不写 ini、不广播。ESC 菜单"取消"回滚到打开菜单时的值
  (`Lighting_SaveState/RestoreState`, 跟其它设置项同一套快照机制)。

### 读档 / 换局后恢复 (Lighting_Poll)

判据是**"引擎接管了光照字段"**: 引擎重建场景时会用地图 ini (或存档里的值)
重写那几处, 与我们最后写的不同。这个判据不依赖时序。

恢复成什么:
- 引擎给的值 == 我们最后写的那组 → 场景重开了但没改光照 (存档里存的是我们
  改过的) → 回到地图原值 (`s_Orig`);
- 否则 → 引擎给的就是这份存档/这张地图该有的值 → 以它为准 (换图时它就是新
  地图的值, 顺手刷新快照)。

**恢复 = 写全部六个字段 + `RecalcLighting`**, 格子光照与调色板一起回来;
只改字段不重算的话画面还是旧的 (这就是"恢复不彻底"的成因)。

场景重开本身用**逻辑帧号倒退**认 (引擎复用 Scenario 对象, 指针不变, 只能靠
帧号; 实测读档后日志里就有 `pv: frame rewound`)。倒退后等 3 帧再动手, 避开
场景还没摆好的时候。

**只有用户改过光照时**才按"场景重开"恢复 (`s_UserSet` 标记): 帧号倒退不只发生
在读档 (换图/进任务简报也会), 无条件恢复会把用户的预设刷回原图。
"引擎接管字段"那条路 (字段值 != 我们最后写的) 不受这个限制 —— 引擎改了光照
就以引擎为准, 写回并重算。

### 设置页可滚

设置页加了 3 行 (26 行), 1024x768 放不下 → 把原来只给文本页的滚动机制泛化成
两页共用 (`EscPage.scroll` 指针 + `Esc_Page*` 系列函数), 设置页也能滚轮滚动。

### 分组

"光照"组改名 **"光照与显示"**, 并把原本在"杂项"里的 **玩家色** 与
**阵营 UI (皮肤)** 挪进来; "杂项"只剩 **设置页帧率上限** 一项。

### 已知副作用

改 tint 会连带改**玩家色** —— 引擎的 `UpdateHashPalLighting` (`0x53AC80`) 遍历所有
LightClass 重算调色板, 玩家色的 LightConvert 也在其中。这是引擎固有行为 (地图 ini 的
`[Lighting]` 也一样), 不是本功能额外加的改动。

## 8. 实测结论

- 写字段 + `RecalcLighting` 后画面**立刻**变 (关掉菜单就能看到)。
- 点"黄昏"预设, 参数行同步显示 35 / 51 / 46 / 141, 与预设表一致。
- tint 被夹到 1.0: `Blue=1.41` 在游戏里变成 1.0, 偏色仍在但过冲没了。
- `Level`/`Ground` 本实现不碰 (预设脚本里四个预设的 Level 相同, 没必要暴露)。
