# 光照预设 (in-game lighting presets)

游戏内可切换"早上/下午/黄昏/晚上"等预设, 并可直接调六项光照参数。
预设数值来自 FA2 脚本 `创造*光照.fscript` (写的就是地图 ini 的 [Lighting] 段)。

## 1. 预设脚本的语义

四个预设只差 `Ambient` 与 `Red/Green/Blue`; `Level` 一律 0.028:

| 预设 | Level | Ambient | Red | Green | Blue |
|---|---|---|---|---|---|
| 早上 | 0.028 | 0.75 | 1.09 | 0.80 | 0.49 |
| 下午 | 0.028 | 1.00 | 1.08 | 0.94 | 0.68 |
| 黄昏 | 0.028 | 0.35 | 0.51 | 0.46 | 1.41 |
| 晚上 | 0.028 | 0.75 | 0.71 | 0.81 | 1.19 |
| YR苏4关 | 0.008 | 0.75 | 0.80 | 0.80 | 0.90 |

Ion 段四个预设完全一样: IonLevel 0.028, IonAmbient 0.65, IonRed 0.695, IonGreen 0.445, IonBlue 0.775。

## 2. 引擎把 [Lighting] 读到哪里 (gamemd.exe, 实证)

读入在 `0x68A7xx`, 写进 **ScenarioClass** (`Instance = 0xA8B230`)。偏移与 YRpp
`LightingStruct` 一致, 且反汇编逐条核实:

| 偏移 | 字段 | ini 键 | 存储换算 |
|---|---|---|---|
| +0x3528 | AmbientOriginal | `Ambient` | `(int)(v*100 + 0.01)` |
| +0x352C | AmbientCurrent | `Ambient` | 同上 (三个一起写) |
| +0x3530 | AmbientTarget  | `Ambient` | 同上 |
| +0x3534 | NormalLighting.Tint.R | `Red`   | `(int)(v*100 + 0.01)` |
| +0x3538 | NormalLighting.Tint.G | `Green` | 同上 |
| +0x353C | NormalLighting.Tint.B | `Blue`  | 同上 |
| +0x3540 | NormalLighting.Ground | `Ground` | `(int)(v*1000 + 0.01)` |
| +0x3544 | NormalLighting.Level  | `Level`  | 同上 |
| +0x3548.. | Ion* (Ambient/R/G/B/Ground/Level) | `Ion*` | 同上 |
| +0x3560.. | Nuke* | — | |
| +0x3578.. | Dominator* | — | |

常量: `0x7E2AC0`=100.0, `0x7E4658`=1000.0, `0x7E3808`=0.01 (加 0.01 是为了让
0.75 这种值截断后不落到 74)。

**单位**: Ambient 与 tint 字段 = 真实值 ×100, Ground/Level = ×1000。
`CellClass::CalculateLightSourceLighting (0x484180)` 用 `AmbientCurrent` 作底光,
叠格子自身 Intensity, 再按 `Level * 格子高度 - Ground` 修正。

### 2.1 Ground / Level (按地形高度分层的亮度修正)

不是"又一组 tint", 而是**沿 Z 层线性变化的亮度偏移**, 只在该格建 `LightConvert`
时 (`0x48445F..0x4845A0`) 算一次:

```
地面:  v  += Level * cell.Level        - Ground
桥面:  v2 += Level * (cell.Level + 4)  - Ground      // +4 = 桥的 4 层
```

- `cell.Level` = `CellClass+0x11B` (signed byte); 桥那条第二路输出是同一格的桥面颜色。
- 结果 clamp 0..2000 再走归一化 (见 3.1), 所以是**颜色维度**的修正, 不是 intensity。
- 语义: `Level > 0` 每高一层更亮 (0.032 = 每层 +3.2%); `Ground` 是 0 平面的偏移,
  注意是**减** —— `Ground=0.05` 是整片压暗 5%。
- 生效范围: 地形/覆盖物/单位都经格子 convert 绘制, 都会跟着变; UI 不受影响。
  改这两项必须重建 convert (只写字段不重建 = 画面不动)。
- 并不罕见: MapsMO 778 张带 `[Lighting]` 的图里 `Level != 0` 有 291 张、`Ground != 0`
  91 张, 常见值 `Level=0.008/0.012/0.032`、`Ground=0.05`。
- 特殊光照生效时换组: Ion `+0x3558/5C`、Nuke `+0x3570/74`、Dominator `+0x358C/90`
  (Dominator 分支第一段取的是 Nuke 的 `+0x3574`, 疑似引擎笔误, 只在 Dominator 生效
  且 Level != 0 时有差别)。

## 3. 运行期改光照的引擎入口

| 地址 | 函数 | 作用 |
|---|---|---|
| `0x4AE4C0` | `UpdateCellLighting()` | 用当前 scenario 光照重算**所有格子**的光照值 |
| `0x53AD00` | `RecalcLighting(R, G, B, tint)` | 更新光源对象 + 调 `UpdateCellLighting` + 强制重画 |
| `0x53C280` | `UpdateLighting()` | 事件驱动: 核爆/离子风暴/支配者状态切换光照 |
| `0x555AC0` | `ScenarioLighting(r,g,b)` | 把 tint 三个分量**夹到 0..1000** 并量化 |
| `0x4F42F0` | `MapClass::Prepare(flag)` | 标脏战术视图并重画地图面 |

`RecalcLighting` 是 `__stdcall`: `ecx=R, edx=G, 栈: B, tint`。
**tint 分量单位 = 字段值 ×10 (= 真实值 ×1000)**。

### 3.1 初始色 = 按最大分量归一化

`CalculateLightSourceLighting` 把 tint 算成 `tint*10`, 再过 `0x5558E0`:

```
M = max(r*10, g*10, b*10)
Color1 = round( (r*10, g*10, b*10) * 1000 / M )      /* 最大分量恰好 = 1000 */
intensity = M / 1000                                  /* 16.16, 存在 convert 里 */
```

再经 `ScenarioLighting`: 夹 0..1000, 并按 `[0xA8EB78]` 量化到 32 的倍数
(`& 0xFFFFFFE0`), 最后落到 `LightConvertClass::InitLightConvert (0x544E70)` 的
Color1 (`+0x198/19c/1a0`)。三分量全 1000 时直接复用默认件 (`0x87F69C[0]`)。

实测与公式逐位吻合:

| 地图 tint 字段 | 原始 tint×10 | 初始 Color1 (归一化 + 量化) |
|---|---|---|
| 51, 46, 141 | 510, 460, 1410 | 352, 320, 992 |
| 71, 81, 119 | 710, 810, 1190 | 576, 672, 992 |
| 100, 100, 100 | 1000, 1000, 1000 | 默认件 1000,1000,1000 |

**环境光不进 Color1**: 同一 tint 下把 amb 从 10 改到 135, `rebuilt=0`、Color1 不变 ——
环境光走"每格标量 → 调色板档位", 颜色只由 tint 决定。所以正确关系是**按最大分量
整体归一化**, 不要逐分量夹 (夹到 100 会让 (992,576,384) 变成 (1000,900,600), 偏灰)。

### 3.2 触发器改光照 vs 地图 ini (两条路必然不同)

地图触发动作 `SetTintRed/Green/Blue` (`0x6E2E60 / 0x6E2EB0 / 0x6E2F00`) 干的是:

```
RecalcLighting(new*10, oldG*10, oldB*10, 0)   /* 然后才写 +0x3534/38/3c */
```

`UpdateColors` 写进 Color1 的是**原始 tint×10**, 既不归一化也不量化, 上限 2000:

| tint 字段 | 初始 Color1 (ini) | 触发/Recalc 写入 | 亮度比 |
|---|---|---|---|
| 150, 90, 60 | 992, 576, 384 | 1500, 900, 600 | 1.51 / 1.56 / 1.56 |
| 51, 46, 141 | 352, 320, 992 | 510, 460, 1410 | 1.45 / 1.44 / 1.42 |
| 80, 80, 80 (max<1.0) | 1000, 1000, 1000 | 800, 800, 800 | 0.80 (反而偏暗) |

三条系统性差异:

1. **归一化**: ini 那条把颜色按最大分量拉到 1.0、亮度交给 intensity; 触发器保留原始
   绝对值 → `max(tint) > 1.0` 偏亮 (上限 2.0), `< 1.0` 偏暗 (默认件被绕过)。
2. **强度/档位**: 触发器只改颜色, 不动 convert 的 intensity 与每格标量。
3. **作用域**: 触发器改整个池 —— LightConvert 池 (`[0x87F69C]` / `[0x87F6A8]`) +
   每份 ColorScheme 的 convert (`0xB054D4` 数组 / `0xB054E0` 个数, 元素 `+0x30C`,
   `+0x310 > 1` 才算在用) + `0x626690` 容器, 一次全改; 且**破坏性**, 之后传 `-1`
   重算也回不到原色。建格只碰目标格那一件, 且只做"比较后换件"。
   `RecalcLighting` 收尾: `UpdateCellLighting(0x87F7E8)` + `MapClass::Prepare(1)`。

**两条路 (菜单"调色方式")**:

```
逐格: 写字段 → LightConv_ResetBase() → LightConv_RebuildCells() → RecalcLighting(-1,-1,-1,0)
统一: 写字段 → LightConv_TriggerTint()  (= RecalcLighting(R*10,G*10,B*10,0), 原样触发器)
```

逐格第一步负责每格颜色 (与载入同源, 逐像素一致), 第二步只重算调色板渐变 + 触发重画,
不改颜色。统一那条就是触发器本身, 整池 + 玩家色一起改, 所以地形/单位/玩家色一起偏亮
(实测一张图 19502 格只有 4 种颜色, 池里 12 件 convert, 另有 43 件在用的 ColorScheme ——
只改格子会是另一幅画面)。

**统一模式的可逆性 (不需要记录原值)**: 需要复原的只有两类"底件", 建出来都是常量
1000,1000,1000, 直接写常量即可:

1. **池 [0] 默认件**。`InitLightConvert` 开头 `0x544E94`: 目标色三分量都等于 1000 时
   **直接返回 `[0x87F69C][0]`, 不比较它的 Color1**。触发器连 index 0 一起改, 不修的话
   之后所有"该用默认件"的格子都拿到被染色的件, 逐格重建也救不回来。
2. **每份在用 ColorScheme 的 convert** (`+0x30C`)。光照不烘进它的 Color1 (scheme 的
   明暗走 FullColorData), 不修就是整局玩家色偏色。

池里其余件的 Color1 就是它自己的身份 (按色去重), 逐格都归一到 1000, 用不到被染过的
那批, 不用管。`0x626690` 容器拿不到清单, 不复原 (引擎自己也不会还)。用一个
`s_Tinted` 记"这轮动过整池没有"。

**体积**: 每件 `LightConvertClass` = 0x1B4 = 436 字节 (调色板指针 `+0x190`, 缺省指向
静态表 `0x829C20`), 池 Items 4 字节/槽。实测一张图 12~26 件 ≈ 5~11 KB; 池只追加
(`0x544FBD` 只 `count++` 写槽, 没有删除路径)。

### 3.3 地图的 [Lighting] 与存档里的 [Lighting]

**存档带 [Lighting], 但不是地图文件的副本 —— 是存盘那一刻把运行时字段整段重写进去
的一份快照。** 存档是 OLE 复合文档, 实体在 `CONTENTS` 流, 按
`[u32 压缩长度][u32 原始长度][LZO1X]` 分块, 所以二进制里 `grep "[Lighting]"` 找不到。

**存盘** (`0x68B5C0`): 先 `0x5257C0(ini,"Lighting")` 清空整段, 再逐键 `0x5285B0`
(= `WriteDouble`, `"%f"` 六位小数) 写 19 个键:

| 键 | Scenario 字段 | 写盘 | 读档 |
|---|---|---|---|
| Ambient | `+0x3528` (Original) | ×0.01 | ×100, +0.5 取整, 写回 `+0x3528/2C/30` |
| Red / Green / Blue | `+0x3534 / 38 / 3C` | ×0.01 | ×100 |
| Ground / Level | `+0x3540 / 44` | ×0.001 | ×1000 |
| Ion* / IonGround / IonLevel | `+0x3548..50/54, +0x3558/5C` | ×0.01 / ×0.001 | ×100 / ×1000 |
| Dominator* / ChangeRate | `+0x357C..88, +0x358C/90, +0x3594` | ×0.01 / ×0.001 | ×100 / ×1000 |

**读档** `0x68A817`: `GetDouble("Lighting", key, 字段×0.01)` → ×100 + 0.5 → 取整 →
写字段; `Ambient` 一项写进 `+0x3528/2C/30` **三个**。

与地图的差异:

1. **来源**: 地图是作者写的文本 (载入读一次); 存档是存盘瞬间的字段值。触发器
   `SetAmbientLevel (0x6E2F50)`、`SetTintRed (0x6E2E60)` 与本项目的 `Light_WriteAll`
   写的是同一批字段 → **运行期改的光照会跟着存档走**, 读档继承"存盘那一刻"的值。
2. **精度**: 字段是整数, 步进 0.01 (Ground/Level 0.001)。`Ambient=0.675` 载入 round
   成 68, 存档里是 `0.680000`; 再读回还是 68, 不累积漂移, 但与 .map 原文差 ≤0.005。
3. **键集固定**: 清段后只写这 19 个键, 地图里的注释/拼写变体/引擎不认识的键全部消失。
4. **Ambient 只剩一个值**: 不保存 Original/Current/Target 三份, 读档三兄弟写同一值
   → 存盘时正在做环境光渐变的, 读档会直接跳到目标值。
5. **存档不保存"地图原值"**: 改过光照再存盘, 原值只剩 `.map` 里那份; 菜单的 `s_Orig`
   只是本局快照。

## 4. 引擎自己的运行期改光照范例

- `SetAmbientRed/Green/Blue` @ `0x6E2E60 / 2EB0 / 2F00`: 先 `RecalcLighting` 再写
  `+0x3534/38/3C` —— 写完要等下一次光照刷新才生效, 自己实现应**先写字段再刷新**。
- `SetAmbientLevel` @ `0x6E2F50`: 写 `+0x3528`, 再把 `+0x3530` 同步过去。
- Ares (`SWTypeExt::ChangeLighting`) 只写 `AmbientTarget`, 而 `UpdateLighting` 的普通
  分支每次都把 Target 复位回 Original (`0x53C38E`), 所以**必须同时写 `+0x3528`**。
- 渐变: 每帧比较 Target vs Current, 按 `Rules.AmbientChangeRate` (`0x8871E0+0x1668`)
  / `AmbientChangeStep` (`+0x1670`) 过渡。要立刻切就把 `+0x3528/2C/30` 写成同一值。

## 5. 实现

`src/gui/LightingPreset.{h,cpp}` (菜单侧) + `src/misc/LightConvFix.{h,cpp}` (重建/改色)。

- 参数六个, 分两行: **环境 / 等级 / 地面** 与 **红 / 绿 / 蓝**。单位是引擎字段单位
  (环境与 R/G/B = ini ×100, 等级/地面 = ini ×1000), 上限 999。
- 预设号: 0=原图, 1=标准 (四项都 100), 2=早上, 3=下午, 4=黄昏, 5=晚上, -1=自定义。
  分段控件多一格"自定义"只是状态显示, 不可点。预设只覆盖环境光 + 三色。
- 写入: Ambient 三兄弟 + tint R/G/B + Level/Ground, 再按调色方式刷新 (`Light_Refresh`)。
- **原图值惰性快照**: 第一次改动前才快照引擎当前值 (`Light_EnsureOrig`), 不依赖"引擎读
  ini"与"进局"的先后。
- **纯临时**: 不写 ini、不广播。ESC 菜单"取消"回滚到打开时的值 (调色方式一起回滚)。

### 调色方式 (本局有效, 不落盘)

| | 逐格 (默认) | 统一 |
|---|---|---|
| 做法 | `LightConv_RebuildCells()` → 每格 `InitLightConvert(null)` 重算, 再 `RecalcLighting(-1,-1,-1,0)` 只重算渐变 + 重画 | `LightConv_TriggerTint(R*10,G*10,B*10)` = 原样调 `RecalcLighting(具体 R/G/B, 0)` |
| 结果 | 与地图 ini 初始光照逐像素一致 | 与引擎触发器一致: 整片同一个颜色, 不归一化 → 通常亮 1.5 倍 |
| 等级/地面 | 生效 (建 convert 时算) | 不生效 (全片一个颜色) |
| 副作用 | 无 | 改色破坏性; 切回逐格时 `LightConv_ResetBase` 按常量复原两类底件, `0x626690` 那部分不复原 |

### 读档 / 换局后恢复 (Lighting_Poll)

触发: 两个场景就绪钩子 —— 引擎把"对局中"(`0xA8ED5C`) 置 1 的两条指令, 新开局
`0x683E75` / 读档 `0x67E6C4` (两条路径互不经过, 都要挂)。钩子只置 pending, 刷新留给
`Lighting_Poll`。

等什么: 过了载入闸、`LightConv_WorldReady()` 为真才动手, 但**最多等 240 帧** —— 任何
闸门卡住都会让 Poll 从此不干活, 到点硬刷一次 (多刷只是白干一次, 不刷是永久错)。

用哪组值: 判据是"引擎接管了字段"(当前值 != 我们最后写的):
- 引擎值 == 地图自带值 (`s_Orig`) 且我们改过 → 盖回我们那组 (读档/重开不是地图动作);
- 其它 (包括读到第三组值) → 以引擎为准, 旧快照作废。

**恢复 = 写全部六项 + 按当前调色方式刷新**, 只写字段不重算画面还是旧的。

整个自动链路受 `[LightingRefresh] Enable` 管 (`LightFix_Enabled`); 两个钩子关闭时连
pending 都不置 (被偷字节是纯 mov, 返回 0 重放安全), 手动改光照不受影响。

### UI 落点 (EscMenu.cpp 表驱动)

`s_GuiLayout[]` + `s_Choice[]` + `GUI_ITEM_*` 枚举 + `kLabelKey[]`, 文案在
`MOExperienceResources\<locale>.ini`。加行优先往表里插, 不要往 apply 的 switch 里加
分支; `GUI_ITEM_COUNT` / `ESC_GUI_DISPLAY` 是编译期常量, 改了要同步 (现在 33 行)。

参数行"一行三格": `s_LightItem[]` 参数号 → item, `Esc_LightRowFirst()` 行 item
(`LIGHT_PARM` / `LIGHT_TINT`) → 该行第一个参数号。画、点、滚轮、编辑框定位四处都用
这两个函数, 不要各自算 `item - 基准`。

组名 "环境显示" 内含: 光照预设 / 调色方式 / 环境·等级·地面 / 红·绿·蓝 / 天气几项。

## 6. 实测结论

- 写字段 + 刷新后画面**立刻**变 (关掉菜单即可看到)。
- 选"黄昏"预设, 参数行同步显示 35 / 51 / 46 / 141, 与预设表一致。
- 地图自带 `Blue=1.41` 时参数行显示 141; 逐格画面上限仍是 1.0 (建格时夹 1000),
  想真按 1.41 上色只能选"统一"。
- `Level=0.032` 显示 32, 越高越亮 3.2%/层。
- 逐格把参数设回原值后画面与进图时一致; 统一明显偏亮 (~1.5 倍), 与触发器效果一致。
