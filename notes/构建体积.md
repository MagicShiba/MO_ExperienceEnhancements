# 产物体积

`dist\MOExperience.dll` 现为 **706,560 字节**（0.2.646 起）。构成：

| 节 | 大小 | 说明 |
|---|---|---|
| `.text` | 563,712 | 代码，61 个 `.cpp` |
| `.rsrc` | 49,664 | 11 个 PCX 图标（RCDATA/lcid 1033），全部在用 |
| `.rdata` | 41,472 | 常量、跳表、字符串 |
| `.reloc` | 32,256 | 重定位表，不可去 |
| `.data` | 9,728 | 已初始化数据 |
| `.idata` | 5,120 | 5 个 DLL 的导入 |
| `.edata` | 2,048 | 66 个导出（见下） |
| `.eh_fram` | 512 | 只剩 libgcc `_divdi3.o` 那一份 |

## 一、省下来的两块

- **链接加 `-s`**（−187 KB）：COFF 符号表 6.4k 项 + libgcc 带进来的 `.debug_*`。
  代价是 DLL 里再也查不到符号，崩溃反查只靠 `obj\MOExperience.map`（`-Wl,-Map=` 与
  `-s` 不冲突，照旧生成）。
- **编译加 `-fno-unwind-tables -fno-asynchronous-unwind-tables`**（−64 KB）：
  32 位 mingw 默认给每个函数发 `.eh_frame`，而本 DLL `-fno-exceptions`、不用
  `_Unwind_*`，这些表没人读。**改这个标志必须清 `obj\` 全量重编**，增量构建看不出变化。

## 二、试过但否掉的

- `-ffunction-sections` + `-Wl,--gc-sections`：只省约 4 KB（代码本来就都可达），
  而且 `.syhks00` 会被当成无用节回收 —— 钩子表整块消失，DLL 静默失效。别再试。
- 再加 `-fdata-sections`：5 MB 的静态缓冲（VecText 字形缓存等）从 `.bss` 挪进
  `.data`，文件直接 +5 MB。
- 去掉 `__declspec(dllexport)`（省约 4 KB）：`.syhks00` 每条只存**处理函数名**，
  Syringe 用 `GetProcAddress` 按名解析 —— 66 个导出里 61 个是钩子处理函数，删了就全挂。
- 去掉 `.reloc`：`LoadLibraryEx` 实测把它加载到 `0x67F80000`，不是首选基址
  `0x6f200000`，没有重定位表直接加载失败。
- `-luuid`：一个 `uuid.o` 里装了几千个 GUID 常量，只为两个符号就全拖进来
  （+412 KB 符号表）。要 GUID 就自己写字面量，链接只留 `-lole32`。

## 三、验证方法

改链接/编译标志后：`rm -rf obj && build-fast.bat`（Git Bash 下 `build-fast.bat /clean`
的 `/clean` 会被 MSYS 当路径改写，别用），然后按节比对
（`pefile` 或 `objdump -h`）并抽查 `.syhks00` 条目数与导出名是否仍一一对应。
`LoadLibraryEx(path, NULL, DONT_RESOLVE_DLL_REFERENCES)` 可以在不跑 `DllMain`、
不解析导入的前提下确认 PE 能被映射。
