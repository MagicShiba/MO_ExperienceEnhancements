# 无 AI 对局自动声明（PvpNotice）

没有游戏内 AI 时，用自己的名字在聊天里发一句"本机用了拓展、非纯净版本"，每 30 秒
一条。走引擎自己的联机聊天报文，对方不用装本拓展也能看到。

代码 `src/misc/PvpNotice.cpp`。文本硬编码在 .cpp 里，只按系统语言选中/英文。

若游戏根目录（exe 所在目录）存在 `shroud.shp` —— 也就是换了透明迷雾的替换件 ——
正文里会多一句“也启用了透明迷雾。”，否则不提。判定只在 `PvpNotice_EnsureInit`
里做一次（`g_IniPath` 去掉文件名 + `GetFileAttributesA`），结果打日志：
`pvponotice: 30s, single=N, shroud=0/1`。

## 一、何时发

| 场景 | GameMode | 行为 |
| --- | --- | --- |
| 局域网 | `3` | 恒每 30 秒发，无开关 |
| 互联网 | `4` | 恒每 30 秒发，无开关 |
| 单人遭遇战 | `5` | 按 `[PvpNotice] Single`：`0`=不发（默认）/ `1`=也发（自测）/ `2`=只发一次 |
| 战役 / 菜单 | `0` 等 | 不发 |

除上面还得等 **`Unsorted::ScenarioStarted`（`0xA8ED5C`）为 1**，也就是真正开局之后：

- 大厅（GameMode 已经是 3/4）和载入屏都算"没开局"，一条都不发 —— 那里发出去的消息
  会跟着开局重置消息列表一起消失（表现就是"第一条没了，后面正常"）。
- 开局后再静默 `PN_WARMUP`=3 秒才发首条，之后每 30 秒一条。

两种都还要求房表里除中立房外**没有非人类房**（即没有 AI），判定地址：

| 用途 | 地址 / 偏移 |
| --- | --- |
| GameMode | `SessionClass::Instance` `0xA8B238` **+0** |
| 是否已开局 | `Unsorted::ScenarioStarted` `0xA8ED5C`（byte） |
| 房表 items / count | `0xA8022C` / `0xA80238` |
| 是否人类 | `[房+0x1EC]` `IsHumanPlayer` |
| 房类型 | `[房+0x34]` → `HouseType*` |
| 中立/旁支 | `[HT+0x1A6]` `MultiplayPassive == 1` |

`Single=2` 的"已发过"标记在离开对局（GameMode 不在 3/4/5）时清零。
不看真人数量，1 个真人也发。

## 二、聊天广播的位置

聊天**不走** `EventType::Message`：事件跳转表 `0x1A` 落到空出口 `0x4C8109`。

真实链路在 MainLoop 按键处理函数 `0x55E420` 内部，且**不是可调用函数**：

```
0x55E746  GameMode 分流 (3/4)
0x55E77B  信标检查 → 0x55E7B3 → GameMode!=4 ? 0x55EDBF : WOL /page
0x55EDBF  ★ 广播块
```

| 地址 | 做的事 |
| --- | --- |
| `0x55EDBF` | `cmp edi,3 / je / cmp edi,ebp(=4)`，是 3 或 4 才把报文类型置 `0x0C` |
| `0x55EDC8` | `mov dword [0xA8D638], 0x0C` → 类型 = 聊天 |
| `0x55EDD2` | 从 `NodeName[0]`（`0xA8DA78`）取本机名，转 ASCII 抄到 `0xA8D63C` |
| `0x55EE19` | `[esp+0x10]`：`3` → 正文取 `GetEditBuffer()`；`4` → 取 `0xA8BDCC` |
| `0x55EE0F` | `0x5DAC00(0xA8D610)` 算 CRC → `[0xA8D74C]` |
| `0x55EFAF` | 遍历 `ConnectionManager`（`0xA8E9C0`）的连接，跳过自己 |
| `0x55F015` | `0x5410F0(conn, &0xA8D638, 0x1C7, 1, …)` 发包，`0x541820` 冲刷 |
| `0x55F0A8` | 本地回声 `AddMessage(名字, 正文, 玩家色, …)` |
| `0x55F110` | `jmp 0x55F1B1` → `0x4F42F0(2)` → 尾声 |

报文结构（收发同一块全局，必然自洽）：

```
0xA8D638 +0x00 dword  类型 (0x0C=聊天)
         +0x04 char[] 发送者名字 (ASCII)
         +0x30 wchar[]正文
         +0x110 dword 玩家序号
         +0x114 dword CRC
```

## 三、为什么不能照抄 ChatEdit 的提交

ChatEdit 的"提交"= 写 `EditBuffer` + 调原生 `MessageListClass::Input`（`0x5D4510`），
这条路的回车分支（`0x5D4808`）只做三件事：补一个尾空格、`IsEdit=0`、**返回 3**，
**它不发包**。真正的广播在调用者 `0x55E420` 的帧里按 `Input` 的返回值分流：

```
0x55E615  call Input(this, &slot, key)
0x55E624  cmp edi,1 …            ; 返回值
0x55E739  cmp edi,3 → 0x55E746   ; 3 = 已提交, 走广播分流
```

所以"模拟玩家按回车"必须先把 `IsEdit` 置 1（聊天框会闪一帧，还会打乱 ChatEdit 的
编辑状态），代价比直接复用广播块大。PvpNotice 因此只借 ChatEdit 的"写 `EditBuffer`
协议"，发包仍跳广播块。

## 四、复用方式

`0x55EDBF` 只依赖 `[esp+0x10]`（`0x14`/`0x18` 先写后读），用 `edi/ebp/ebx/esi`，
尾声固定 `pop edi / pop esi / pop ebp / pop ebx / add esp,0x890 / ret`（`0x55F1C8`）。

所以 `PN_ChatSendCore` 复刻 `0x55E420` 的序幕（`sub esp,0x890` + 压 4 个寄存器），
写 `[esp+0x10]=3`、`edi=3`、`ebp=4`，再 `jmp 0x55EDBF`。它自己 pop 干净并 ret 回来，
全程走引擎原码，不拼包、不改报文格式。

**但跳块前必须把 `0xABCE18` 置 3**（详见"坑"第 1 条），否则模式为 0，投递掩码
`0xA8D667` 一直是 0，只有本地回声。投递分两条路：

| `0xA8DBA0` | 行为 |
| --- | --- |
| `0` | 逐房找同名连接，直接 `0x5410F0` 发 |
| 非 `0` | 逐房累 `0xA8D667` 掩码，末尾 `0x55F056` 汇总发一条（调试串 `"Sending chat, mask = %d"`） |

房表过滤条件是 `[HouseType+0x1A5]`（`Multiplay`）非 0，中立房不满足，正好跳过。

正文前置：写进 `MessageListClass::EditBuffer`（`0xA8BC60+0x28`），
`EditInitialPos(+0x2B4)=0`（`GetEditBuffer` `0x5D4400` = `this+0x28+InitialPos*2`，
只看 InitialPos，不读 `EditCurrentPos`）。发完把首字清 0。

## 五、坑

1. **`0xABCE18` 必须自己置 3（这是"对方收不到"的原因）**。它决定"发给谁"：
   `1` = 人类玩家（Enter 开框）、`2` = 同盟（Backspace）、`3` = 全部（`\`）。
   开框时赋值，收底 `0x55F1C2` 清 0。直接跳 `0x55EDBF` 绕过了开框，模式停在 0，
   于是广播块里

   ```
   0x55EF9A  mov eax,[0xABCE18]
   0x55EFA1  cmp eax,2 / 0x55EFA6 cmp eax,3 → 都不等就跳过这个房
   0x55F05F  mask=[0xA8D667] 为 0 → 0x55F0A8 只做本地回声
   ```

   结果就是"自己看得到、别人收不到"。发送前置 3、发完还原即可。
   `0xA8D667` 就是引擎调试串 `"Sending chat, mask = %d"` 里的那个掩码，
   为 0 说明一个目标都没投出去；日志里的 `mask=` 可直接用来验证。
2. **哨兵必须压寄存器真实值**。引擎块尾声会 `pop edi/esi/ebp/ebx` 把栈上那 4 个
   值弹回寄存器，而 naked 函数编译器不会替它保存 callee-saved。压固定常量等于
   静默改写调用者的寄存器。
3. **`0x55F1B1` 会再调一次 `0x4F42F0`**（本 DLL 的 prepare 钩），等于从 `_Poll`
   重入自己，需 `g_InPrepare` 闸（见 `MOExperience.cpp`）。有这道闸就不必再加
   PvpNotice 自己的重入标记。
4. **会覆盖玩家正在输入的编辑缓冲**。不判 `IsEdit`，该发就发；ChatEdit 每帧把
   自己的缓冲镜像回原生缓冲，所以框里正在打的字下一帧就回来了。
5. **正文别超长**：正文域约 112 wchar，代码取 108 留结尾 0。
6. 「有 AI 就不发」排除的是"非人类且非中立"的房；脚本房/野房仍算 AI。
7. 目标版本固定，地址硬编码，不做特征字节校验。
