# 音频资源池与循环音恢复

依据：当前 gamemd.exe 反汇编，参考 AutoLoadDev/references 下 YRpp 的 Audio.h、VocClass.h 及 Ares 音频实现。规模为当前 EXE 的正常初始化值，不代表所有引擎变体。

## 1. 当前实现

- SoundFx 用游戏的 PlayGlobal 播放本地音效，不修改模拟状态、模拟随机数或共享 VocClass.Priority。
- 雨/风循环自持 AudioController。Weather 周期调用 Sfx_LoopAlive：原生 GetEvent 验证归属，state=4 或句柄失效才重建；初始化、待播、延时、在播态均保留。
- 失效不额外等待，两次创建尝试至少间隔200ms；仅名字解析失败退避2000ms，避免反复扫描音效表。恢复仍遵循条目自身的 Delay。
- 主动关闭天气调用 End 并取消恢复。本实现不占世界位置节点，不安装通用引擎保活钩子，范围仅为本模块的自持循环通道。
- 声音可暂时被竞争压过，竞争减少后重试恢复；不保证资源持续不足时仍可闻。Priority 属于共享音效条目，不能用提高它的方式代替恢复。

## 2. 独立资源池

| 资源 | 规模 | 含义 |
|---|---|---|
| 世界位置声源节点 | 200 | 当前尚未归还的声源节点，不是整局累计播放次数，也不等于可闻声音数 |
| 逻辑音频事件 | 300 × 0x280 | 当前数0x87E28C，峰值0x87E290 |
| 播放 voice | 原生16个，扩容请求32个 | 实际播放通道，可按优先级抢占复用 |
| 采样缓存 | 原生1MiB，扩容预算8MiB，另有200个描述符 | 与世界声源节点独立 |

因此，不需要短时间播放200声才会挤掉循环；voice、缓存和条目 Limit 都可能产生竞争，不能仅凭静音判定是哪层耗尽。

### 世界位置节点

- 0x7510E5..0x7510EF 建立200×0x3C节点池，池地址0xB1D3A4。0x750E20 分配节点并调用 PlayAt，挂入0xB1D320；0xB1D3A8记录当前占用，0xB1D3AC记录峰值。
- 0x750EC0 周期维护：无有效事件且类型为空或不是无限循环时，0x750F14摘链、0x750F21归池、0x750F26占用减一。普通短声音结束后可自然回收。
- 无限循环判据0x406650：`Control & 1` 且 `Loop(+0x4C)==0`。暂时无事件时仍保留位置节点，0x750D90..0x750DB3在可闻且声音允许时重建事件。大量驻留无限循环可占满200节点。
- 0x750F40按坐标/掩码 End，控制器清空后由维护回收；0x750FA0则 Stop并直接摘链归池。
- 更新链：0x48D08C → 0x406F70，满足计时间隔后依次调用0x4041D0（事件）、0x750EC0（位置节点），并非每个逻辑帧无条件一次。

### 事件、voice 与缓存

- 事件池：0x403F3D..0x403F4C建立300×0x280池；0x405190分配失败会回收已recycled事件再重试，仍不足才返回0；0x40442B..0x404469也会日常归池。
- voice：0x406C25..0x406C31请求并校验16个，设备重建0x406E3A..0x406E49同样如此。设备+0xF4的100是容量上限，不是预建数。0x405B50 → 0x4035F0选空闲/低优先级voice，0x405B8C调用0x4025B0停止旧声音后复用。
- 0x87DE38七档×十桶是优先级/音量组织的VocClass候选链，不是70个voice槽。0x404E63返回节点减0xA4得到Voc，0x404623按类型停止事件以释放资源。
- 缓存：0x403F29..0x403F38传入块payload=0x2000（8192字节）、预算0x100000、描述符200。0x401A0B..0x401A17按`1MB/(8192+28)=127`建立块池，另建200×0x64采样描述符。
- 0x401C00查找/装入缓存；描述符或块不足时仅换出零引用旧项，0x401F80/0x401F90增减引用。0x402030仅返回`ecx+0x1C`，不是分配函数。

## 3. 事件生命周期与控制器

PlayGlobal（0x750920）只建立事件，不保存永久声源意图。`loop`规定事件存活时如何续播，不保证事件销毁后自动恢复；位置无限循环由节点维护恢复，其他对象路径取决于其调用方。

AudioController 为20字节`{Event, Stamp, EventType, AudioIndex, Unused}`，AudioIndex必须为0x87E294。SetEvent（0x4060F0）复制event+0x138的Stamp，并将控制器写入event+0x278。

Stamp在创建/复用0x4052AD..0x4052BD赋新值，正常续轮不变。GetEvent（0x406130）先检查音频启用，再核对Type/Stamp，失配则清Event；不能手动对齐Stamp接管已复用事件。End（0x405FD0）验证归属后请求淡出；设备关闭后不应自行解引用旧事件。

关键终止路径：

| 地址 | 条件 |
|---|---|
| 0x4059F0 | voice终止回调，含抢占；正常采样结束走0x405A00 |
| 0x4043CF | voice为空或已归其他事件 |
| 0x4057A3 | 类型无可用样本或voice初始化失败 |
| 0x40468F | 取样为空或0x4054A0提交失败 |
| 0x404312 / 0x404627 | 条目Limit驱逐 / 按类型释放资源 |

0x404700返回0还可能表示序列结束、有限循环用尽或主动End，不等于缓存满。通用保活须区分这些原因及主动停止，不能只改一个回调。终止回调内不可清event+0xB0：调用者返回后还会解引用；已复用的voice参数也不可再改。

## 4. 资源扩容

AudioCapacity.cpp 在初始化及设备重建时生效，需重启游戏。仅增加本地音频资源，不调用模拟逻辑、不改变音效优先级；扩容不能代替循环恢复，也不保证完全消除抢占。

开关为 `[Features] AudioCapacity=1`（默认开）。设为 0 时三个钩子仍跳过原指令，但改用原版参数请求16个voice、传1MiB缓存预算，并把实际创建数直接交回调用方，效果等同未扩容。开关在钩子里自行读 ini：音频设备初始化早于 UI 帧的 MOE_EnsureInit，不能依赖统一初始化。改 ini 后需重启游戏；联机不受影响（只改本地音频资源）。

- **voice请求16→32**：钩住0x406C2C和0x406E41的5字节call，调用原0x403530并传32。返回实际创建数；不少于16时向调用方返回16以通过原成功检查，实际池计数不改。少于16仍走原失败处理，不要求设备必须支持32。
- **缓存预算1→8MiB**：0x403F33的5字节`mov edx,0x100000`替换为传8MiB，保留8192字节payload和200个描述符。块数由127增为1020，池分配含节点开销约8MiB。
- voice的创建、更新、选择、停止和销毁均使用设备+0xF8动态链表；未发现固定16槽依赖。设备+0xF4原上限100不变。每个voice另有0x1C0本体和0xE0驱动状态，播放时的DirectSound缓冲也会增加内存/混音开销。
- 缓存通过0x4019E0按预算动态建立块池，无固定1MiB数组。300事件、200位置节点、200采样描述符与条目Limit不变，仍可能成为其他瓶颈。
- 内存分配并非全面防OOM；本次取保守32通道和8MiB，而不是顶满设备上限。静态兼容检查不等于实际设备或联机实测。

原指令：`406C2C: E8 FF C8 FF FF`、`406E41: E8 EA C6 FF FF`、`403F33: BA 00 00 10 00`。两份Ares参考音频源码未实现这些扩容；钩子兼容性另由hook-rel-audit检查当前DLL。

启动日志：`audio: capacity ON` / `audio: capacity OFF (ini)`记开关；`audio: voices=N`记录实际创建数；`audio: sample cache budget=8MiB`只在扩容时记录传入预算，不代表分配结果或已经播放成功。

## 5. 验证

MinGW音频生命周期隔离测试覆盖状态0..3保留、状态4失效、Stamp复用拒绝、创建失败重试、设备关闭、主动停止及优先级不变。扩容钩子隔离测试覆盖0/15/16/24/32个实际创建结果、初始化/重建返回地址、8MiB参数，以及开关关闭时回落16通道/1MiB缓存且不钳制返回值。构建部署及hook-rel-audit三源一致性/冲突检查通过，新增音频钩子未与当前Ares等DLL声明重叠。尚未启动游戏验证实际voice数、设备重建或听感，隔离测试不替代实测。

实际验证：使用原始优先级，制造声音竞争后减少声源，确认循环恢复；关闭天气后不应重响。_Amb_WindCold自带Delay，建立事件不代表立刻可闻。临时逐次启动/丢失日志不保留。
