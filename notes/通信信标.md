# 通信信标 (B 键放置) 单机启用

原版只在联机可用。单机被**四处** `GameMode==0 || GameMode==5` 早退挡住,
全部共享同一段字节 `a1 38 b2 a8 00 85 c0`（`mov eax,[0xA8B238]` + `test eax,eax`）：

| 地址 | 函数 | 早退落点 | 早退之后还剩什么 | 单机要补吗 |
|---|---|---|---|---|
| `0x5370A0` | `BeaconPlacementCommandClass::Execute` | `0x5370B3` (ret 4) | 全部（就是整个动作） | **要** |
| `0x430CD4` | `BeaconManagerClass::PlaceBeacon` 尾 | `0x430F20` | EVA + 两条操作提示 + 组包广播 | **要**（只要 UI 那半段） |
| `0x4314F1` | `EditBeaconMessage` | `0x4316EA` | 只剩发包 + 非本家 EVA | 不要 |
| `0x431331` | `DeleteBeacon` | `0x4313F8` | 只剩发包 | 不要 |

关键结论：**信标本体（建对象/写槽/绘制/雷达点/点选/文字读写）全都不查 GameMode**，
四处早退都挡在“动作入口”或“动作收尾”，所以单机补前两处即可完整可用。

上限（每玩家 3 个）**保持原样不动**：单机联机一致，也不碰协议，见末节。

## 一、键位 → 布署模式

```
BeaconPlacementCommandClass::Execute   0x5370A0   (vtable 0x7EBBDC)
  a1 38 b2 a8 00   mov  eax,[0xA8B238]      ; GameMode
  85 c0            test eax,eax
  74 0a            je   0x5370B3             ; Campaign(0) → ret 4, 什么都不做
  83 f8 05         cmp  eax,5
  74 05            je   0x5370B3             ; Skirmish(5) → 同上
0x5370AE: e8 7d a9 1f 00   call 0x731A30
0x5370B3: c2 04 00         ret  4
```

`0x731A30`（信标布署开关壳）：
```
mov eax,[0xA8B538]      ; Unsorted::MuteSWLaunches
test eax,eax
jne 0x731A45 (ret)      ; 非 0 直接不响应
push -1                 ; -1 = 切换
mov ecx,0x87F7E8        ; DisplayClass::Instance
call 0x4AC960           ; SetPlaceBeaconMode
ret
```

`0x4AC960 SetPlaceBeaconMode(int mode)`（`ret 4`，mode：-1 切换 / 0 关 / 1 开）：
- 与 `[0x87F7E8+0x11B4]` 比较，相同就什么都不做；
- `[0x87F7E8+0x11A8]`（CurrentBuilding）非 0 就拒（正在放建筑）；
- 打开时用 `[0xA83D4C]+0x30` 调 `CanPlaceBeacon 0x430F30`，**满 3 个就静默拒绝**
  （`0x4AC9B6 xor bl,bl`，无提示、无音效）；
- 成功：`[+0x11B4]=1`（`0x4AC9E3`）然后 `call 0x48DC90 UnselectAll()`。
  `UnselectAll` 是必需的：`DisplayClass::DecideAction 0x692610` 在有选中物体时
  会先走别的分支，选着单位按 B 会拿不到 `action=0x3C`。
- 关闭路径顺带清 `[+0x11B0/11B1/11B2/11B3]` 四个布署模式字节。

**`0x88099C` 就是 `[0x87F7E8+0x11B4]`**（0x87F7E8 + 0x11B4 = 0x88099C），
所以“单例基址+字段”与“全局绝对地址”两种写法指的是同一个字节。它的全部引用只有 5 处：
`0x4FB8A2` / `0x6AAF8B` / `0x6DEDD0` / `0x6E26A6` 写 0（关各类布署模式）、
`0x6929AF` 读（`mov al,[0x88099C]; test; je; mov [esp+0x10],0x3C`）。
邻座 `0x880999/99A/99B` = `+0x11B1/11B2/11B3`，是另外三种布署模式。

## 二、放置提交（不查 GameMode）

`0x4AC033`（`DisplayClass` 左键提交内）：
```
cmp eax,0x3C                 ; Action::PlaceBeacon
jne ...
mov eax,[0xA8B538]           ; MuteSWLaunches
test eax,eax
jne 0x4AC0A2                 ; 非 0 只关模式不放置
call 0x5657A0                ; 取格 (esi = CellStruct*)
; Coord = (cell.X*256+0x80, cell.Y*256+0x80, [cell+0x11B]*[0x8A0740])
push -1                      ; houseBeaconId = -1 (自动选空槽)
call 0x430BA0                ; PlaceBeacon(Coord, houseId=[0xA83D4C]+0x30, -1)
0x4AC0A2: SetPlaceBeaconMode(0)   ; 放完自动退出布署模式
```

`0x430BA0 PlaceBeacon`（`ret 0x14`，5 参数：Coord 3 个 dword + houseId + id）：
- `0x430BC6..0x430BD2` 扫本家 3 个槽；满了且 `id==-1` → `0x430F20` 早退；
- `0x114` 字节分配（`0x7C8E17`），拷 `0x89C430/434/438` 上次坐标模板，
  `and al,0xFC`（`0x430C16`），清 0x40 个 dword 的 `Text[128]`；
- 写槽 `0x430C72`；`HouseID`（`0x430CBE`）、`Bitfield |= 1`（`0x430CC4`）、
  `AllocatedCount++`（`0x430CD0`）—— **这三步在早退之前，单机照跑**；
- `0x430CD4` 早退（单机到此为止：信标已存在、已在画、能点选、文字能存）；
- `id != -1`（远程包）分支 `0x430E5D`：复用槽、释放旧信标、`AllocatedCount--`，
  然后 `jmp 0x430C76` **跳过**上面三步（远程包不改本地所有权/计数）。

## 三、收尾段（EVA / 提示 / 广播）

从 `0x430CEA` 开始（单机补的就是这里）：
```
0x430CEA  mov ecx,[0xA83D4C]
0x430CF0  cmp ebx,[ecx+0x30]        ; ebx = houseId, 是本家吗
0x430CF3  jne 0x430E87              ; 非本家 → 侦察提示分支
; ---- 本家 ----
0x430D18  格式串 0x818AC4 "TXT_BEACON_HELP1"  (+ 玩家名 [CurrentPlayer+0x16054])
0x430D2C  call 0x5D3BA0             ; MessageListClass::AddMessage
0x430D55  格式串 0x818AB0 "TXT_BEACON_HELP2"
0x430D69  call 0x5D3BA0
0x430D78  VoxClass::Play("EVA_BeaconPlaced")             ; 0x752700
0x430D94  VocClass::PlayGlobal(idx, 0x2000, 1.0f)       ; 0x750920
0x430D99  mov ecx,[0xA8DA78]        ; ★ 从这里开始组 IPX 包
0x430DA7  mov ecx,[ecx]             ; 玩家表首元素 → 名字转换 0x7350C0
0x430D9F  [esp+0x18] = 0x20         ; 包类型 0x20 = 放置
...
0x430E02  [esp+0x54] = bl           ; houseId
0x430E06  cmp eax,esi / jle 0x430F20  ; eax=[0xA8DA84] 玩家数; ≤1 直接退
0x430E0C..0x430E4E  逐玩家 0x5410F0 Send_Global_Message(buf, 0x3D, 1, addr, 0, 0)
0x430E50  pop edi/esi/ebp/ebx; add esp,0x1D0; ret 0x14
; ---- 非本家（只在本机收到别人放的包时走）----
0x430E87  Bitfield&1 → IsAlliedWith(0x4F9A10) → 0x4F9A50 → [house+0x1F5] 迷雾
0x430F03  0x65FA70(0xB, cell)       ; RadarEvent
0x430F16  VoxClass::Play("EVA_BeaconDetected")
```

单机补 `0x430CD4` 后若一路跑下去会进 `0x430D99` 那段组包：
`[0xA8DA78]` 是 `NodeNameType::Array`（`DynamicVectorClass` @ `0xA8DA74`）的 Items 指针，
`0x430DA7` 再解引用它的首元素。单人局玩家表可能为空 → Items 为 NULL → 崩。
所以单机在 `0x430D99` 再拦一刀，直接跳到共享收尾 `0x430E50`：
EVA 和提示照拿，组包与广播整段不跑（单机本来也没有对端）。

## 四、删除 / 改文字（单机无需补）

`DeleteBeacon 0x4311C0`（`ret 8`，houseId, houseBeaconId）：
- `(-1,-1)` 表示“删本地选中的那个”：`0x4311F4..0x431219` 扫 8×3 找 `Bitfield&2`；
- 显式槽路径 `0x431221`；释放 `0x4312EB`、清槽 `0x431322`、
  `AllocatedCount--` `0x43132E`，**都在早退之前**；
- 删除特效在 `0x4312B0..0x4312E6`（`0x880A04` + `0x430650`），也在早退之前；
- `0x431331` 早退之后只有发包（类型 `0x21`，长 `0x3D`）。

`EditBeaconMessage 0x431450`（`ret 0x10`，text, houseId, houseBeaconId, unknown）：
- `(-1,-1)` 同样走“本地选中的那个”；
- 清 128 wchar + `0x7CA422` 拷新文字在 `0x4314D6..0x4314EE`，**在早退之前**；
- `0x4314F1` 早退之后：本家且槽位对得上就发包（类型 `0x22`，长 `0x1C7`），
  非本家则 `EVA_BeaconDetected` + RadarEvent。

`DeleteAllBeacons 0x431410`（`ret 4`）：按 `house*3` 删一家 3 槽，无 GameMode 检查。

“删除信标”命令 `0x537F90`（vtable `0x7EBF9C`）= `call 0x731A10; ret 4`；
`0x731A10`：有选中对象就转给对象，否则 `DeleteBeacon(-1,-1)`。原版没有单独的
删除热键（KeyboardMD.ini 只有 `PlaceBeacon=66`），删除靠选中信标后按 Del：
`0x55E746` 之后的 `0x55E77B` 分支 → `0x431170` 找选中信标 → `0x431450` 传空文字
清讯息；真正的删除走 `0x537F90` 那条命令。

## 七、数据布局

`BeaconManagerClass` @ `0x89C3B0`（`sizeof 0x80`）：
```
BeaconClass* Beacons[8][3]   +0x00   (共 0x60 字节, 索引 = house*3 + id)
int          AllocatedCount  +0x60
Point2D      BeaconSize      +0x64
int          BeaconFrameCount +0x6C
Point2D      RadarBeaconSize +0x70
int          RadarBeaconFrameCount +0x78
int          RadarBeaconAnimPeriod +0x7C
```
全局旁挂：`BeaconArt` `0x89C474`、`RadarBeaconArt` `0x89C478`、
美术已载标记 `0x89C410`、上次坐标模板 `0x89C430/434/438`。

`BeaconClass`（`sizeof 0x114`）：
```
CoordStruct Coord   +0x00
byte        Bitfield +0x0C   1=已放置(可见)  2=本地选中
wchar_t     Text[128] +0x0E
int         HouseID  +0x110
```

生命周期：
- 构造 `0x430190`：清 `0x18` 个 dword（`0x60` 字节）并注册 `0x4301C0` 清理；
- `Reset 0x430980`（`0x5349A0` 调）：释放 8×3 并清 `+0x60` —— **换场景即清空**；
- 玩家离场/战败 `0x4FC1C6` → `DeleteAllBeacons`；
- 美术 `LoadArt 0x4309D0`（`__thiscall(self=0x89C3B0)`）：唯一调用点在 `0x687BB2`，
  属**联机开局流程**（`0x686B20` 一族），单机不走 ⇒ 单机美术与动画周期都停在
  静态构造留下的 0。单机要用信标必须自己补调一次，见第十节。
  资源本身在：`PBEACON.SHP` 66×?、20 帧，`RDRBEACN.SHP`，补调后
  `period=32 / w=66 / f=20`（实测日志）。

## 八、上限 3 为什么不动

- “上限”就是数组第二维：`CanPlaceBeacon 0x430F30` 扫本家 3 槽（`0x430F45 cmp,3`），
  **没有独立常量**。`AllocatedCount` 只被 3 处引用（构造/析构），不参与定址。
- 要改就得一次改全：`0x430900..0x431A00` 内 `cmp reg,3` / `cmp reg,8` 共 **18 处**
  （9 个函数），另有 7 处 `lea reg,[reg+reg*2]`（把 `house*3` 编进指令，不是 3 字节改不了）。
  数组长在固定全局 `0x89C3B0` 上，后面紧跟 `+0x60` 的计数与尺寸字段，**原地无法扩容**。
- 对同步的影响不在 CRC 而在协议：信标从不进 `EventClass` 的 OutList/DoList
  （`Execute_DoList 0x64CC68` 不碰 `0x89C3B0`），也不喂
  `CurrentFrameCRC 0xAC51FC` / `LatestFramesCRC[256] 0xB04474`；
  复制走独立 IPX 全局包（`IPXManagerClass 0xA8E9C0` 的 `Send_Global_Message 0x5410F0`）。
  包里 `houseBeaconId` 只有**一个字节**，接收端按 `house*3 + id` 定址：
  单侧改成 4 格后 `id=3` 会让原版客户端写进隔壁房子的 0 号槽，`house==7` 时
  直接踩 `0x89C410`（`AllocatedCount`）—— 静默串味或内存破坏。
  所以“提高上限”不是同步分帧问题，而是**协议越界**问题。
- 保持 3 个：单机联机完全一致，零协议改动，也就不用考虑 `AutoRemoveEarliestBeacon`
  那种“满了自动删最旧”的替代方案（那会额外产生一次删除广播）。

## 九、包格式（顺带订正）

`push 0x3D` 是**包长 61 字节**，不是包类型；类型是缓冲区首 dword：

| 动作 | 首 dword | 包长 | 发送点 |
|---|---|---|---|
| 放置 | `0x20` | `0x3D` | `0x430D9F` / `0x430E41` |
| 删除 | `0x21` | `0x3D` | `0x431367` / `0x4313E9` |
| 改文字 | `0x22` | `0x1C7` | `0x43153F` / `0x431632` |

接收端派发 `0x48D1E0`：`type` @ `[0xA8D638]`，`lea eax,[ecx-0xA]; cmp eax,0x25; ja default`
→ 字节表 `0x48DB44` → 13 项 dword 表 `0x48DB10`：
`0x20→idx6→0x48D798`（`PlaceBeacon([0xA8D667],[0xA8D66B],[0xA8D66F], id=[0xA8D674])`）、
`0x21→idx7→0x48D7D5`（`DeleteBeacon`）、`0x22→idx8→0x48D7F4`（`EditBeaconMessage`）。

## 十、实现（BeaconSP.cpp）

单机专用，与 `WaypointCap.cpp` 同形态：每轮 `OU_IsMP()` 实时判定，
联机不装钩（已装的恢复原版字节），联机字节与原版逐字节一致。

| 站点 | 长度 | 原字节 | 单机落点 | 作用 |
|---|---|---|---|---|
| `0x5370A0` | 5 | `a1 38 b2 a8 00` | `0x5370AE` | B 键布署开关 |
| `0x430CD4` | 5 | `a1 38 b2 a8 00` | `0x430CEA` | EVA + 两条操作提示 |
| `0x430D99` | 6 | `8b 0d 78 da a8 00` | `0x430E50` | 跳过组包/广播，直接收尾 |

三处都是“无 rel 的指令边界”，壳里只判开关再跳，不碰任何寄存器值。
不装钩时三处走原版字节，行为与未打补丁完全一致。

配置 `[Features] BeaconInSP`（缺失=1，改后重启）。

信标讯息的输入依赖 `[MsgText] ChatBoxSP=1`（默认开）：`0x55E477` 那道 session
检查是 `ChatBoxSP` 在管，关掉它单人连回车都进不了信标讯息分支。
放信标本身、EVA、两条操作提示不依赖它。

### 美术 / 动画周期闸门（崩溃修复）

`0x89C42C`（`BeaconManagerClass+0x7C`，`RadarBeaconAnimPeriod`）只由
`LoadArt 0x4309D0` 写成 `RDRBEACN.SHP 帧数 * 4`（`0x430A8F`）。单机不走
`0x687BB2`（联机开局流程），所以两个 SHP 指针与这个周期都停在 0。

三处 `idiv` 全在 `AllocatedCount != 0` 之后，原版单机永远走不到：

| 指令 | 地址 | 前置 |
|---|---|---|
| `idiv [ecx+0x7C]` | `0x431718` | `0x431700 DrawRadar`，`[ecx+0x60] != 0` |
| `idiv [ecx+0x7C]` | `0x4318B6` | `0x431800`，`[ecx+0x60] != 0` |
| `idiv [0x89C42C]` | `0x430659` | `0x430650` 单信标绘制 |

单机一旦能放信标就立刻踩到：`0xC0000094` 除零，`eip=0x4318B6`，
现场 `AllocatedCount=1`（信标已建好、已写槽，卡在收尾的雷达绘制）。

所以启用前先过闸门：两个指针都空时补调一次 `LoadArt`（只一次，它不释放旧
缓冲），然后要求 `PBEACON` 指针、`RDRBEACN` 指针、`+0x7C` 三者都非 0，
否则**拒绝启用**并记一行日志——空 SHP 指针进 `0x430250` 一样会崩。
补调后实测 `period=32 / w=66 / f=20`。

`+0x64/68/6C` = BeaconSize(X,Y) + 帧数，`+0x70/74/78/7C` = RadarBeaconSize(X,Y)
+ 帧数 + 周期，全部由 `LoadArt` 从 SHP 头部 `[+2]/[+4]/[+6]` 填。

### 装钩顺序

装钩前先过闸门；闸门不过或联机时把三处全部恢复原版字节。
`g_BsOn` 每轮按“三处是否真的全装上”重算，壳内只读这一个 int。
