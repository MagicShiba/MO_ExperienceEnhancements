# 侧栏滚动条 (SideScroll)

代码 `src/GUI/SideScroll.cpp`。相关: `隐藏侧栏.md`、`超武侧栏.md`。
ini `[SideScroll]`。构建 `build-fast.bat`, 测试 `test/sidescroll_geom_test.c`。

原版侧栏只有两个**整页**翻页按钮和滚轮 (滚轮是合成点击那两个按钮), 都是整行粗调,
没法停在第 3 行。本模块在 cameo 网格右侧空档加一条可拖的竖条, 一像素对一行。**只画
滑块**: 无底色/无描边/不半透明, 且鼠标停进侧栏时才出现。

---

## 1. 引擎事实 (gamemd 反汇编实证)

### 1.1 原版已有什么

| 东西 | 地址 | 行为 |
|---|---|---|
| 上翻 / 下翻按钮 | gadget `0xB0B328` / `0xB0B408` | 整页 |
| 滚轮 | `0x777998` → `0x533F50` | 在 gadget 链 (`0x87F65C`/`0x87F668`) 里合成点击这两个按钮 |

两个按钮 `SetPosition` 在 `InitGUI` 的 `0x6ABEBD`/`0x6ABEF2`, Y 都是
`[0xB0B50C] = [0xB0B4F8] + [0xB0B504] + 7` ⇒ **都在 cameo 区底部**并排。点击处理
(`ret 0x4`, 结束于 `0x6A8B05`) 直接 `[strip+0x48] ±= 可见行数`。

⇒ 页内滚动只有"整页"和"整行"两个粒度, 没有任何按比例定位的入口。

### 1.2 侧栏几何

| 全局 | 地址 | 值 |
|---|---|---|
| 侧栏对象 | **`0x87F7E8`** | **地址就是对象本身** (Mouse/Sidebar/Display 同一静态对象); 按 `*(void**)0x87F7E8` 读会拿到虚表指针 |
| `Tabs[0]` | `this+0x1544`, 步长 **`0xF94`** | 由 `0x6A6678` `imul ebx,0xF94` + `0x6A667B` 反推 |
| `ActiveTab` | `this+0x539C` | |
| `StripClass::TopRowIndex` | `Tabs[tab]+0x44` | **★ 本模块写的就是它 (行号)** |
| `StripClass::CameoCount` | `+0x54` | |
| 滚动动画态 | `+0x48` 目标行偏移(带符号) / `+0x4C` 像素偏移 / `+0x3E` 方向 / `+0x3F` 动画中 | `StripClass::Scroll` @ `0x6A8B30` |
| `SidebarBounds` | `0x886F90` `{X=列起点, Y=0x9E, W=列宽168, H}` | X 既是位置也是鼠标路由阈值 |
| cameo 区 | `[0xB0B4F8]` 上缘 Y, `[0xB0B504]` 高 = 行数×50, 行高 50 | |
| cameo 列 | `[0xB0B4F4]` = colX+0x16, 列距 `[0xB0B4FC]`=63, 盒 60×48 | |
| 可见 cameo 数 | `GetVisibleCameoCount` **`0x6AC430`** | **无参、不读 ecx、结尾 `ret` 不清栈** ⇒ `int __cdecl(void)` |

**⇒ 网格占 `colX+22 .. colX+145`, 列宽 168, 右侧约 21px 空档 = 滚动条的位置。**

侧栏面实测 `168x1080` (日志 `fullmap: surf ... strip=168x1080`), **x 原点 = 侧栏列起点,
y 原点 = 屏幕上沿** ⇒ 屏幕 x 要减 `colX`, y 直接用。

### 1.3 引擎自己的最大行号

`StripClass::Scroll` (`0x6A8BFF..0x6A8C09`) 往下滚的判据:

```
mov ebp,[ebx+0x44]   ; TopRowIndex
add ebp,eax          ; + 可见行数
imul ebp,edx         ; × 2 (每行两个 cameo)
cmp  ebp,ecx         ; vs CameoCount
jl   <继续>          ; 可见窗口还没触底
```

解出 **`maxTop = ceil(count/2) - 可见行数`**, 与 `SS_Geo` 的算法一致 (测试逐条比对)。

⚠ `GetVisibleCameoCount` 返回的是 **cameo 数 (行数×2)**, 不是行数。忘了 `/2` 会让
`maxTop` 少一半。

### 1.4 重画标志

引擎滚完自己置 **`[0x884B8F]` = `this+0x53A7`** (`0x6A8EA7`) + 侧栏脏标记
`[0xB0B518]` (`BlitSidebar` `0x6A7143` 查它)。我们照抄这一对。

`0x53A7` 的重画矩形**从 `[0xB0B4F8]` 起** (`0x6A6D47`/`0x6A6ED8`), 在小地图下方 ⇒
拖动时每帧压它**不会**擦掉小地图。不要顺手去压 `0x53A6`: 全二进制只有 `0x6A926B`
一处置它, 不是常规路径。

## 2. 两条算术约定

### 2.1 行↔像素的两个方向都四舍五入

```
绘制: thumbY = by + (span*cur + maxTop/2) / maxTop
拖动: nt     = ((th-by)*maxTop + span/2) / span
```

必须互为反函数。截断版在 1616000 组几何里有 **504582 组往返不一致** —— 症状是"滑块停在
某处但列表差一行"。四舍五入后在**轨道像素数 ≥ 行数**的可行区间内**往返精确**。

`maxTop > span` (行数比轨道像素还多) 时相邻行必然共用一个像素, **任何实现都不可能
精确**; 那一段靠两个可满足的性质兜底: 单调不减、单像素最多跨 2 行 (实测最坏 2 行)。
这不是缺陷, 是信息量不够。

### 2.2 `span = 轨道高 - 滑块高`

滑块高 = 可见比例, 无下限钳制 (`MinThumb` 已删: 侧栏行数不可能多到滑块缩没)。
`maxTop>0` 时恒有 `thumbH<camH` ⇒ `span>=1`; `span<=0` 只可能是野值, 直接 fail-closed。

## 3. 不变量

1. **只在侧栏整条可见时存在。** 判据 `FM_SidebarVisible()`。态1/2 下那一列的屏幕区域
   归**地图** —— 画了也不会上屏, 而落在那里的点击是**地图点击** (框选/打靶)。`SS_Poll`
   排在 `FM_Poll` 之后 (要读它刚刷新的状态)。
2. **只在鼠标停进侧栏列时绘制。** 判据 `SS_MouseOnSidebar`。
   ⚠ **绘制门与交互门是两件事**: 滑块不显示时照样吃点击。判据都在 `SS_Poll` 里, 不依赖
   `SS_Draw` 画过。
3. **只写 4 个本地 UI 状态字段** (`+0x44` 与三个动画态字段), 不碰模拟、不发事件 ⇒ 联机安全
   (与 `选中与下令上限.md` 那两道限制完全不同的层)。
4. **画在呈现之前。** 挂 `BlitSidebar` (`0x6A70E0`) —— 侧栏面靠这一下带上屏。
5. **开拖时锁定页签** (`s_DragStrip`), 拖动中切页签不会拖走另一个页签。
6. **整条都吃按下沿**: 点滑块上直接开拖 (保留抓取点, 不跳); 点轨道空白处 `SS_JumpTo`
   把滑块中心挪到指针处**并顺手开拖** ⇒ 一次点击完成"跳过去 + 继续微调"。
   那块区域不属于引擎任何 gadget, 吃下不抢原版点击。
   ⚠ 跳转与拖动必须用**同一个**像素↔行映射, 否则松手瞬间会跳一行。
7. 帧门 (`ADDR_FRAME`): `0x4F42F0` 一帧能被调 142 次。

## 4. 测试 (`test/sidescroll_geom_test.c`)

把 `SS_Geo`/`SS_DragTo`/`SS_JumpTo` 逐字抄进独立 .c, 扫 `camH × visRows × cnt × HitWidth`
(约 1616000 组) 断言: `maxTop` 与引擎一致; 不显示 ⇔ 引擎也不能滚; 不压 cameo; 换算后
在 `[0,168)` 内; 显示条右对齐在生效区内且不出 168 面; 每行滑块不出轨; 拖动/跳转都单调且两端精确、单像素最多跨 2 行;
跳完接着拖不二次跳; `drag(draw(r)) == r`。
**反向验证** (每条都确认它会红):

| 把代码改成 | 结果 |
|---|---|
| 四舍五入 → 截断 | `draw/drag not inverse` 483284 |
| `maxTop` 少一行 | `maxTop != engine` 132480 + `hidden but engine can scroll` 2304 |
| `HitWidth=24` (压到网格) | `overlaps cameo grid` 44928 |

## 5. ini `[SideScroll]`

| 键 | 默认 | 含义 |
|---|---|---|
| `Enable` | 1 | 总开关 |
| `HitWidth` | 14 | 生效宽度 6~20 (点击/拖动判定) |
| `ShowWidth` | 6 | 显示宽度 2~20 (滑块绘制, 右对齐在生效区内, 超过则钳到生效宽度) |
| `RightMargin` | 3 | 离侧栏右缘 0~12 |
| `ThumbColor` | `0xA5D3FF` | 滑块颜色, 写 `0xRRGGBB` |

就这五个。轨道底色/描边/半透明三层曾做过, 但侧栏背景本身有纹理, 叠底衬反而显脏, 而
"只在鼠标停进侧栏时才出现"已经把"常驻一条竖线"的问题解决了。

## 7. 不要试

| 做法 | 为什么不行 |
|---|---|
| 画在网格上面或左侧 | 压图标 / 压电力条。右侧空档是唯一不遮的位置 |
| 不用 `FM_SidebarVisible()` 就吃点击 | 态1/2 下那列是地图, 吞点击 = 框选/打靶失效 |
| 把"鼠标不在侧栏"也当成不吃点击 | 滑块不可见时仍要能点 (§3.2) |
| 只写 `+0x44`, 不清三个动画态字段 | 引擎拿旧的"还剩几行"继续滑 ⇒ **松手后又自己挪回去** |
| 拖动时调 `UpdateScrollButtons` (`0x6A6610`) | 它只判 `CameoCount > 可见数`, 不知道行号 |
| 两侧都用截断除法 | §2.1, 差一行 |
| 忘了 `GetVisibleCameoCount` 返回 cameo 数要 `/2` | §1.3 |
| 跨模块调 `GetVisibleCameoCount` 当 `__thiscall` | 它不读 ecx 且结尾 `ret` 不清栈 ⇒ `__cdecl` 无参。签名猜错 = **崩溃而不是返回错值** |
| 按 `*(void**)0x87F7E8` 取侧栏对象 | 拿到的是虚表指针 |
| 把滚动位置写进 rules/ini 或事件 | 那是模拟数据; 这里只需要"哪几行画在屏幕上" |
| 再加回轨道底色/描边/半透明三层 | 用户明确要求去掉 (§5) |
