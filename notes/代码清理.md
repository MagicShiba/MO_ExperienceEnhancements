# 代码清理准则

## 一、先证明没有死代码，再谈"冗余"

三种方式各自独立查，都是 0 才算干净：

| 查法 | 注意 |
|---|---|
| `g++ -Wall -Wextra -c -o /dev/null` 全量编译 | 必须 `-c`：`-fsyntax-only` **不报** `-Wunused-function` |
| `nm` 取全部已定义全局函数 × 源码交叉引用 | 只看函数粒度，抓不到"同一件事写多份" |
| `#if 0` / 注释掉的代码 / TEMP·FIXME | 应为 0 |

`unused parameter` 与 `missing-field-initializers` 是允许的噪音（回调签名、`= {0}`）。

## 二、真正的冗余是"同一件事被写多份"

已收拢的公共底座（新代码一律走它们，不要再抄一份）：

| 事项 | 落点 |
|---|---|
| 引擎地址 / 结构偏移 | **只许写在 `src/core/EngineAddr.h`**，禁止 .cpp 里本地 `#define` |
| 手绘几何（点/线/框/裁剪） | `OU_Put` / `OU_Line` / `OU_Box`（`OuClip` 可空） |
| 面锁定 | `OU_SurfLock` / `OU_SurfUnlock`（虚表 +0x5C/+0x60） |
| 事件清零 | `OU_EvClear` |
| MegaMission 下单 | `OU_MakeMega` / `OU_FireMega`（内部走 `OT_Fire`） |
| TARGET 编码 | `OU_ObjTgt`（失败回 **-1**）/ `OU_CellTgt`（恒回 id） |
| 类型判定 | `OU_InVec` / `OU_IsUnit` / `OU_IsTarget` |
| 格子高度 | `OU_CellFloorZ` / `OU_MouseCellZ` |
| 游戏根目录 | `GtGameDir()` |

**地址散落的真实代价**：`OFF_HOUSE_MONEY` 曾在 `RepairAll.cpp` 写成 `0x2F0`、别处 `0x30C`。
exe 实证 `0x705DF3`（Available_Money，`mov eax,[ecx+0x30C]; ret`）与 `0x4F9950`
（GiveMoney）都是 `0x30C`。而 RepairAll 拿它做 Owner 合法性校验
（`money >= 0 && money <= 10000000`），读错字段 → 校验恒失败 → "修复全部"静默什么都不做。

**故意没做的**：

- 8 个队列整体前移（`X_ShiftDown`）：宏展开成结构体赋值会让编译器生成 `memmove` 调用，
  而本工程无 CRT、memmove 是逐字节实现，`PatrolCircle` 那个 17408 容量队列在滴发路径上
  会明显变慢。逐字段搬。
- `Fetch_ID` 索引自检（8 处 `base/count` 范围判断）：各处上限不一致（多数 200000，
  DeployPreview 20000），统一会改掉某处判据，收益只有几行。

## 三、注释准则

注释只写**现在是什么 / 为什么必须这样**：

- **不写历史**：不写"原来是…""以前是固定 128x96 的静态数组""所以不再用 X 字段"。
  变更史归 `notes/`，而且只留结论，不留时间线。
- **不写版本号**：任何注释里都不出现 `0.2.xxx`。版本只在 `MOE_VERSION` 里。
- **不写测量过程**：可以留结论性数字（"约 200us/帧"）支撑"为什么这样写"，删掉
  "实测 206us，改成…以后 65us" 这种前后对比。
- **不重复样板**：构建方式（`build-fast.bat` / mingw32 / 无 CRT）由构建脚本承载，
  不在每个文件头重复；钩子铁律（含 rel 不许 return 0）在每个**有 rel 钩点**的文件里
  写一次就够。
- **长细则归 notes**：功能规格（分配规则、参数语义、限数表）写到对应 `notes/*.md`，
  文件头只留 3~5 条改代码时必须知道的约束 + 指向该文档。
- 不必强压到一两行；一节完整的话比断成五句半句更好读。
- 单行代码末尾的短注释保留（`/* 槽位 3 */` 这种），不要为了"统一风格"删掉。

## 四、清理时怎么验证

- **纯注释改动**：重编后 `dist/MOExperience.dll` 的 sha256 应与改动前**完全一致**
  （无 `-g`，注释不进产物）。不一致 = 误改了代码。
- 删代码的改动：`build-fast.bat` 通过 + `-Wall -Wextra` 无新增警告。
- 用 `git diff --numstat` 记净变化，别只凭感觉说"减少了"。

## 五、重复实现统一到底层

- 文件存在检查：任意路径用 `FileExists(path)`，游戏根目录下用
  `FileAtGameRoot(name)`（`g_GameDir` 无尾分隔符，内部补 `\\`）。
  别再各写一份 `GetFileAttributesA`——拼错分隔符会静默返回"不存在"。
- 取格子指针一律 `OU_CellPtr`（自带 0~511 边界与可读性检查），不要在调用处
  再写一遍 `cx < 0 || cy > 511`。
