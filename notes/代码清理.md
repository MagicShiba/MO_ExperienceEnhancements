## 做了什么 (净 44621 -> 44385 行)

### 1. 引擎地址宏: 50 个宏 / 139 处副本 -> 1 个头

`src/core/EngineAddr.h` 新建, 122 行 (含每个地址的出处注释)。33 个文件里的本地
`#define` 全部删除, 改为 `#include "EngineAddr.h"`。

最多的是 `ADDR_FRAME` (11 份), `ADDR_SCENARIO` (6 份), `OFF_INLIMBO` (5 份)。

**顺带抓到一个真 bug**: `OFF_HOUSE_MONEY` 在 `RepairAll.cpp` 写成 `0x2F0`,
别处是 `0x30C`。exe 实证:
- `0x705DF3`: `8B 81 0C 03 00 00 C3` = `mov eax,[ecx+0x30C]; ret` (Available_Money)
- `0x4F9950`: `mov edx,[ecx+0x30C]; add eax,edx; mov [ecx+0x30C],eax` (GiveMoney)

即 **0x30C 正确**。而 RepairAll 拿这个值做"Owner 合法性校验"
(`money >= 0 && money <= 10000000`), 读错字段 → 校验恒失败 → **修复全部静默地
什么都不做**。这就是"改一处要改 11 处"的直接代价。

### 2. 手绘几何: 10 份 Bresenham -> 1 份

`OrderUtil` 新增 `OU_Put` / `OU_Line` / `OU_Box` (可选 `OuClip` 裁剪区),
删掉 DeployPreview / FuzzyAttack / PatrolCircle / SmartArea / SmartOrder /
TreeChop / WeaponRange / GridView 各自的 Plot+Line+Mark 三件套, 各留 2 个薄包装。

`OU_ThinLine` 与它们合并: 原来本文件是"往下补 thick 行", 而 7 个模块是
"居中补 y-1..y+1", 统一成**居中** (thick=1 仍是单行, 只有 2 处内部调用位移 1px)。

### 3. Surface 锁定: 9 份"取虚表->判空->调 Lock" -> 1 份

`OU_SurfLock` / `OU_SurfUnlock`。虚表槽 `+0x5C` Lock / `+0x60` Unlock 是硬编码的
引擎内部布局, 原来 9 个文件各存一份 `VT_XX_LOCK` + 同样的 7 行。同时删掉 18 个
重复 typedef (`void* (__fastcall*)(void*,void*,int,int)`)。

保留了 `IsPlausiblePtr(fn)` 这道校验 (原来只有 SWSBar 有, 现在全都过一遍)。

### 4. 事件样板

- `OU_EvClear(ev)`: 18 处 `for (i = 0; i < EVT_SIZE; i++) ev[i] = 0;` 收成一行,
  连带删掉 13 个随之变成死声明的 `unsigned i;`。
- `OU_FirePlanCommit(houseIdx)`: PatrolCircle / RallyPath 各有一份逐字相同的
  6 行, 现在一份。

## 故意没做的

- **ChatEdit 的 `CE_VT_LOCK`**: 走的是另一个 helper (`GtVtable`), 形态不同,
  没动。
- **8 个 `X_ShiftDown` (队列整体前移)**: 能用一个宏压成 1 行, 但宏体写成
  `arr[k] = arr[k+1]` 会让编译器对结构体赋值生成 `memmove` 调用, 而本工程的
  memmove 是逐字节实现 —— `PatrolCircle` 那个 17408 容量的队列在滴发路径上会
  明显变慢。DeployPreview 里早就写着"无 CRT 禁 memmove: 逐字段搬", 照办。
- **Fetch_ID 索引自检 (8 处 `base/count` 范围判断)**: 能收成一个
  `OU_IdIdxSane()`, 但各处上限不一致 (多数 200000, DeployPreview 是 20000)。
  统一会改掉某处的判据, 收益只有 ~3 行/处, 不做; 20000 那处是否笔误待查。

### 1. 13 份 `*_Fire` 套餐 -> `OU_FireMega`

MegaMission 事件是 111 字节裸缓冲, `FN_MEGA`(0x4C6860) 是 12 参数 thiscall。
13 个模块各抄一遍"清缓冲 -> 逐个填槽位 -> 调函数 (失败回退 OU_Enqueue)",
每份 8 行, 且**槽位顺序各写一遍**。现在:

```c
void OU_MakeMega(char ev[EVT_SIZE], int houseIdx, int srcID, unsigned srcRtti,
                 int mission, int tgtID, unsigned tgtRtti,
                 int dstID, unsigned dstRtti,
                 int folID, unsigned folRtti, int plan);
int  OU_FireMega(...同上一套... , void* unit, int uid, int idxOk);
```

`OU_FireMega` 内部仍走 `OT_Fire` (联机 mode=2 才接管, 否则直写 DoList),
形状与鼠标真实点击同形 —— 这是联机同步的关键, 没动。

### 2. TARGET 8 字节编码 -> `OU_ObjTgt` / `OU_ObjId` / `OU_CellTgt`

`id@+0 / rtti@+4`, 由 `FN_TGT_OBJ`(0x6E6AB0) / `FN_TGT_CELL`(0x6E6B20) 填。
原来 8+ 处手写 `char tb[8]; tb[0..7]=0; *(int*)tb = id; tb[4] = rtti;`。

**失败判据**: `OU_ObjTgt` 解不出回 **-1**, 不是 0 —— id 本身可以是 0 (推平图
某类单位首个), 用 0 当失败会误杀。`OU_CellTgt` 恒回 id, 与原点相同也不判失败。

### 3. 类型数组判定 + `0xA8EB00` 副本 -> `OU_InVec` / `OU_IsUnit` / `ADDR_TYPARRAY`

4 个模块各写"取 DynamicVector, 遍历 Items[0..Count) 比对指针", 另 4 个各存
一份 `0xA8EB00` 地址。现在地址进 `EngineAddr.h`, 判定进 `OU_InVec`。
`OU_IsUnit` = Unit/Infantry/Aircraft, `OU_IsTarget` = 再加 Building。

### 4. 格高度样板 -> `OU_CellFloorZ` / `OU_MouseCellZ`

`TC_CellZ` / `DP_CellZ` / `SO_CellBuilding` / `TC_MouseCellZ` / `DP_MouseCellZ`
五份副本 (含 `idx=(Y<<9)+X` 与 `GetFloorHeight` 的 thiscall-传单指针细节) 收成
两个函数; `OU_MouseCellInner` 增加第 7 参 `int* zOut`。

### 5. 4 份"游戏根目录截取" -> `GtGameDir()`

`GetModuleFileNameA` + 往回找 `\` 的副本曾有 4 份。`BuildPaths()` 一次填好
`g_GameDir`, 惰性取用。`Shot_BuildTarget` 因此 -37/+10。

### 6. 用户点名的不可达判断

```c
- if (edge && s_Hov && ADDR_SCEN_STARTED) s_Req = 1;
+ if (edge && s_Hov) s_Req = 1;      /* Shot_Poll 只在 prepare / 侧栏呈现里跑 */
```

`Shot_Poll` 只被 `PowerDrawBoth` (prepare / 侧栏呈现) 调用, 大厅与载入屏没有
战术渲染 ⇒ 那时既无底栏按钮也无点击机会, 整个条件恒真。
