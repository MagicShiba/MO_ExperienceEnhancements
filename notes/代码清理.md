用户要求: "看看哪些代码是不必要的, 减少冗余代码, 减少总行数"。

## 结论先说: **没有死代码**

三种方式各自独立验证, 都是 0:

| 查法 | 结果 |
|---|---|
| `-Wall -Wextra` 全量编译 (需 `-c`, `-fsyntax-only` 不出 `-Wunused-function`) | 未用静态函数 0, 未用变量 1 (那个 `dx` 已删) |
| `nm` 取全部已定义全局函数 × 源码交叉引用 | 421 个全局函数, 从未被调用 **0** |
| `#if 0` / 注释掉的代码 / TEMP·FIXME 标记 | 0 / 0 / 0 |
| ini 里声明但没人读的配置键 | 0 (全是动态键名读取, 字面量扫描会误判) |

所以"不必要的代码"不在函数粒度, 而在**同一件事被写了多份**。

## 做了什么 (净 44621 -> 44385 行)

### 1. 引擎地址宏: 50 个宏 / 139 处副本 -> 1 个头

`src/EngineAddr.h` 新建, 122 行 (含每个地址的出处注释)。33 个文件里的本地
`#define` 全部删除, 改为 `#include "EngineAddr.h"`。

最多的是 `ADDR_FRAME` (11 份), `ADDR_SCENARIO` (6 份), `OFF_INLIMBO` (5 份)。

**顺带抓到一个真 bug**: `OFF_HOUSE_MONEY` 在 `RepairAll.cpp` 写成 `0x2F0`,
别处是 `0x30C`。exe 实证:
- `0x705DF3`: `8B 81 0C 03 00 00 C3` = `mov eax,[ecx+0x30C]; ret` (Available_Money)
- `0x4F9950`: `mov edx,[ecx+0x30C]; add eax,edx; mov [ecx+0x30C],eax` (GiveMoney)

即 **0x30C 正确**。而 RepairAll 拿这个值做"Owner 合法性校验"
(`money >= 0 && money <= 10000000`), 读错字段 → 校验恒失败 → **修复全部静默地
什么都不做**。这就是"改一处要改 11 处"的直接代价。

### 2. 手绘几何: 10 份 Bresenham -> 1 份

`OrderUtil` 新增 `OU_Put` / `OU_Line` / `OU_Box` (可选 `OuClip` 裁剪区),
删掉 DeployPreview / FuzzyAttack / PatrolCircle / SmartArea / SmartOrder /
TreeChop / WeaponRange / GridView 各自的 Plot+Line+Mark 三件套, 各留 2 个薄包装。

`OU_ThinLine` 与它们合并: 原来本文件是"往下补 thick 行", 而 7 个模块是
"居中补 y-1..y+1", 统一成**居中** (thick=1 仍是单行, 只有 2 处内部调用位移 1px)。

### 3. Surface 锁定: 9 份"取虚表->判空->调 Lock" -> 1 份

`OU_SurfLock` / `OU_SurfUnlock`。虚表槽 `+0x5C` Lock / `+0x60` Unlock 是硬编码的
引擎内部布局, 原来 9 个文件各存一份 `VT_XX_LOCK` + 同样的 7 行。同时删掉 18 个
重复 typedef (`void* (__fastcall*)(void*,void*,int,int)`)。

保留了 `IsPlausiblePtr(fn)` 这道校验 (原来只有 SWSBar 有, 现在全都过一遍)。

### 4. 事件样板

- `OU_EvClear(ev)`: 18 处 `for (i = 0; i < EVT_SIZE; i++) ev[i] = 0;` 收成一行,
  连带删掉 13 个随之变成死声明的 `unsigned i;`。
- `OU_FirePlanCommit(houseIdx)`: PatrolCircle / RallyPath 各有一份逐字相同的
  6 行, 现在一份。

## 故意没做的

- **13 个 `X_FireXXX` 套餐 (8 行/个)**: 能收成一个函数, 但参数要 13~14 个,
  调用点反而更难读。单看行数能省 ~60 行, 不值得。倒是 `FN_MEGA` 的槽位顺序
  仍是各写一遍 —— 将来若真出错, 优先怀疑这里。
- **`char dstB[8]` + `*(int*)(dstB+0)` 取 id/rtti (15 处)**: 各上下文差异大
  (有的要 src+dst, 有的只要 id), 抽出来要 3~4 个变体, 收益抵不上风险。
- **ChatEdit 的 `CE_VT_LOCK`**: 走的是另一个 helper (`GtVtable`), 形态不同,
  没动。
