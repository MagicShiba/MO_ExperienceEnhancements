# 帧率 / 帧内耗时

结论先行：本 DLL 的全部开销约占整帧 **10%**（约 300us / 3077us，1920x1080、1x 缩放、
超武侧栏展开）。**把所有绘制全删也只有 ~360fps**，再往上就是引擎自己的账。
比性能只看 `fmed`（中位帧率），`f=` 会被载入/卡顿拉低。

## 一、`0x4F42F0` 不是每帧一次

它是"渲染前 prepare"，有上百个静态调用点（AI / 对象 / 渲染 / 消息），多处在逐对象
循环内。1920x1080 场景实测 **161 次/帧**，换图后 72 次/帧。`PowerDrawBoth` 挂在这里，
所以里面每个 `*_Poll` 都会跟着跑 N 遍/帧。

**任何新挂 `0x4F42F0` 的轮询都必须自己门控**，否则直接按 161 倍计。

`PowerDrawBoth` 的门控（`PrepDue()`）：**帧号变了 或 距上次 ≥16ms**。

- 前半句把同一帧内的重复调用压成一次（帧内输入状态本来就不变）。
- 后半句保证暂停/步进时（帧号 `0xA8ED84` 冻结，`PV_MiniLoop` 里 prepare 照跑）输入
  照样被采样，F5 恢复不失灵。

留成"每循环必跑"的只有 `FM_Poll`（撑满视口 + 摘侧栏 gadget，引擎每次切页都会把按钮
重挂回来）、`SS_Poll`（依赖 FM_Poll 结果）、`SB_Poll`、鼠标钩重试。
`PowerDisplay_DrawSb` / `PiP_DrawButton` 每帧画一次就够 —— 呈现前 `BlitSbEntryDraw`
还有一次兜底。

## 二、当前开销账（`Perf=1`，侧栏展开，fmed≈317 那行）

```
msg 247 = msgswp 93 (超武面板) + msgdraw 139 (dSWS 107 = swsL 85 + swsB 17; dRAD 29) + msgtail 10
prep 61 (72 次入口; fm 9 sb 7 ss 2, 其余是门与探针)
blitsb 15 (sbPIP 7 + sbPWR 3 + sbFM 3)
VecText: vsimple 24 (其中 12 放行给引擎) + vecgdim 15 + vprint 5 + vecblit 4
```

`Perf=1` 自带约 35us 探针开销，所以只看比例，别看绝对值。

- `msgswp`（超武倒计时面板）≈ 47k 像素一趟 over，1.4~2ns/px，已接近内存带宽。面板在
  地图区内，Composite 每帧被地图覆盖，无法跳过贴层。
- `blitsb` 里大头是引擎 `CopyFromPart`（侧栏面 → 主面），小地图上屏必需。
- `vecblit` 是放行给引擎逐字绘制的成本（顶栏数字/提示），算术已优化到查表仍无改善 →
  瓶颈是字形覆盖率与目标面内存访问，**不要再往混合算术方向优化**。
- 侧栏三种状态：展开 282fps（`dSWS` 457us）、收起 321fps（74us）、关闭 284fps
  （我们 0.1us，那 ~430us 是原版侧栏自己画回来的）。**关闭态我们确实零开销。**

## 三、有效的优化手段（都已落地）

1. **`RenderLine` 先查行缓存再 `CharsFit`** —— 原来命中缓存也要每帧白跑一次
   `GetTextExtentExPointW`。键用原始 len（限宽只影响画多宽）。这是全局收益，所有用
   `RenderLine` 的地方（超武面板/提示/标签）都跟着快。
2. **`GdiEnsure` 槽位不可撞车** —— 已用 0 战役提示、2 全局矢量、3 底电、5/6 超武侧栏、
   7 刻度条、8 顶栏资金、9 超武面板。撞车会每次重建 DIB/字体。
3. **合成层缓存（SWPanel / SWSBar）** —— 内容与几何不变时把"底+阴影+正文"预合成到
   32 位 alpha 层（`0xAARRGGBB`，A=0 透明），每帧只做一趟整矩形 over。层是否复用由
   内容指纹（文本+颜色+anchor+surfH+配置）决定。
4. **贴层分 tag** —— 建层时给像素分三类：`tag0` 全透明（整段跳过）、`tag1` 纯底板
   （纯黑+固定 alpha，混合逐通道可分离，用 32/64/32 项通道表直接算，与
   `Blend16(dst,0,0,0,a)` 逐位相同）、`tag2` 才走通用 `Blend16`。实测 95% 像素是
   `tag1`，全不透明 0 个（`Alpha=75` 把图标也压成半透明了）。
5. **贴层 SSE2（`SwsBlitRunSse2`）** —— 8 像素一批，与标量**逐位等价**：
   `|(dr-r)*ia| ≤ 31*255 = 7905`，16 位 `pmullw` 不溢出、积精确；`psraw 8` 就是 C 的
   算术右移，负数舍入同向；`a==0`/`a>=255` 用 `pcmpeqw` 掩码选回 `d`/`c`；位深/gm 走
   运行时向量移位（565/555 同一份代码）。420us → 88us。
   **改完必须跑内置 `SwsSse2Scan` 自检**（同帧同批真实像素两路比对），日志要 `bad=0`。
   `IsProcessorFeaturePresent(10)` 判 SSE2，老 CPU 退回标量。
6. **重建加墙钟门** —— 只有"15 个逻辑帧"一道门时：60fps 是 250ms 挺好，300fps 只有
   50ms → 每秒重建 20 次，为刷一个每秒才变一次的百分比。加 `SWS_REBUILD_MS 200`，
   两道门都过才重建（内容/悬停/选中变化仍当帧重建）。74 → 18us/帧。
   **教训：帧数门在高帧率下会失效，任何"每 N 帧"节流都要再叠一道墙钟门。**
7. **去掉雷达重复上屏** —— 同一块小地图每帧 blit 两次（`FM_DrawRadarTo` → Composite，
   `FM_BlitSb` → Primary），而 present 会把 Composite 整幅送上屏，Primary 那次每帧都
   被覆盖 = 白烧。去掉 `FM_BlitSb` 末尾的 `CopyFromPart`（脏标记/抹黑/光标烙印照做）。
   附带确认：本 MO 的侧栏本来就不是靠 `BlitSidebar` 上屏（钩子恒返回 `Fm_Ret4` 跳过
   原版整条 blit），它走 Composite present。**只写 Primary 的绘制每帧被覆盖。**
8. **`OU_KeyDown` 帧内缓存** —— `GetAsyncKeyState` 是系统调用（~1us），一帧里 10 个
   `*_Draw` 各查一次 Ctrl/中键就是十几 us。帧号相同且墙钟 <16ms 时复用上次结果。
9. **`Perf_Hit`（只计次）全部删掉**，只留 `PF_VHIT`/`PF_VMISS`（命中率）。钩子频率
   普查结论：全部 ≤14 次/帧，`pcol/napp/msgadd/chatsp/pipH` 一次都没出现 —— 没有高频
   钩子陷阱。

## 四、评估过但没做的（免得重走）

- **`msgswp` 换 64K 单表**：每次查表跨 L2，大概率不划算。它的 `Blend16` 是 8 位空间
  混合，与本 DLL 的 5 位空间 SSE2 内核不同式，要 SIMD 得重写并重新证明逐位等价。
- **`prep` 里 72 次入口**：三段 Poll 是故意每循环跑的（靠 1 帧门会闪一帧原版按钮），
  只剩 ~3us 真活，不值得冒画面风险。
- **`sbPIP` 7us**：跳过它依赖"条带面本帧不会被别人清"，没证据，省 5us 不值。
- **`BlitSb` / `DrawRadarTo` 合并**：改动会碰视觉残留。

## 五、看账的方式

`MOExperience.ini` 的 `[Log] Perf` 三种口径：
`0`=关 / `1`=全量分段账（自带 ~35us 探针开销，只看比例）/ `2`=只记 `ms= f= fmed=`
（几乎零开销，**比帧率只用这个**）。

```
perf: ms=1000 f=302 fmed=325 prepN=72 prep=61 fm=9 sb=7 ...
```

各项都是 **us/帧**（已除以帧数）。`Perf_Now()` 在关闭时直接返回 0，调用点全部短路。
`prepN` 就是 `s_PfCnt[PF_PREPARE]/frames`。

## 六、工具

- `tools/snap.py [out.png [x y w h]]` —— 无依赖抓屏存 PNG（ctypes + GDI + zlib）。
- `tools/gwin.py [关键字]` —— 列可见窗口的 win/client 矩形。配合：
  `python tools/gwin.py Omega` 再 `python tools/snap.py shot.png <cx> <cy> <w> <h>`。
- `tools/run_test.bat` —— 起游戏读档测一局。Syringe 的 exe 名**必须双引号**，否则弹
  "Syringe cannot be run just like that."。约 25s 进对局，`taskkill /F /IM gamemd.exe`，
  再 grep 日志的 `perf: ms= ... fmed=`。
