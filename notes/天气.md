# 天气覆盖层 (图像档 / 粒子档)

目标: 在单机/联机里给整屏加雨雪, 速度与引擎自身的动画一致, 且不在配置文件里留
"恒定天气"。

## 1. 两种画法 + 三个降水开关 + 云层 (云影/雾气)

* **画法**: `WEATHER_DRAW_IMAGE`(0) 用 art 里的 `RAIN`/`SNOW.SHP` 整屏帧;
  `WEATHER_DRAW_PARTICLE`(1) 自绘粒子。ESC 设置页「杂项 → 画法」一段两选。
* **开关**: 雨 / 雪 / 火雨 三个互不影响的开关 (雨 + 雪 = 雨夹雪, 没有单独的雨夹雪档),
  加一个独立开的**云层**。火雨只有粒子形态, 与画法无关; 云层与降水无关。
* **云层一档一个值**: `Weather_CloudMode` = 关(0) / 云影(1) / 雾气(2), 一种状态一个
  值, 没有"开关 + 画法"两份状态。压暗 = 云影, 混向雾色 = 雾气, 两套浓度场。
  ESC 那一行是**三段互斥**「云影 | 雾气 | 关闭」(`EG_CLOUD`), 段序是显示顺序, 与取值
  不同序, 对应关系在 `kCldSegMode`。
* **雾色跟环境光**: 与雨雪同一条公式 (`Wth_CldToneCalc`), 强度共用
  `WeatherLightMix`; 目标色夹在通道满值以内 (越界会把溢出位串进邻通道), 所以夜里
  雾是灰的、黄昏偏暖, 不会自己发白光。
* **落盘策略 (两类开关不一样)**:
  | 项 | 落盘? | 键 |
  |---|---|---|
  | 画法 | **是** (长期设置) | `[Environment] DrawMode=image/particle` |
  | 云层模式 | **是** (长期设置) | `[Environment] CloudMode=0/1/2` |
  | 雨 / 雪 / 火雨 | 否 (只在本次运行) | — (s_Toggle 里 `section=NULL`) |
  降水开关不落盘的原因: 上次开了雨, 下次启动就一直在下, 变成"恒定天气"。
  画法与云层模式是"我偏好这种显示方式", 属于长期设置, 由 ESC 菜单写回 ini, 模块装载时
  用 `Wth_LoadState()` 读回来。
* 表驱动: `s_Toggle` 六行 (云层那一行的 section 置 NULL, 只为设置项快照留 get/set;
  画面上不画胶囊); `s_Choice` 两行 —— 画法 (`EscChoiceWthMode`) 与**云层风格**
  (`EscChoiceWthStyle`, 落盘 `CloudStyle`)。云层三段不走 `s_Choice` (一段一个取值但
  段序与取值不同序), 点击处理里按 `kCldSegMode` 分派, 只有一个键、真变了才
  `Esc_QueueValue`。
  读字符串键一律走 `OU_ReadString` (它默认值 + 去注释 + 两端去空都在里面), 不要直接
  调 `GetPrivateProfileStringA`: 本 ini 的值后面常跟 `\t;说明`, 原样读回来是
  `"particle\t;…"`, 与 `"particle"` 永远不相等 —— 画法就永远退回默认值。
* **换局 / 读档的保留规则**: 按**地图**判, 不看场景指针 (每次开局都会换, 读同一张图
  也换)。进对局那一拍 (`Wth_SceneCheck`: `ScenarioStarted` 0→1 边沿, 或帧号倒退 ——
  读档时主循环停着, 边沿那一拍轮不到) 比 `ScenarioClass::Name`:
  - **同一张图** → 天气开关、雷电、雨声全部保留。但引擎读档时销毁了全部音频事件,
    所以循环音的标记清 0 让下一帧重起 (不重起就是"天气还在, 声音没了"), 雷电重新计时。
  - **换了地图** → 收声 + 降水/雷电开关复位, 与新一局"默认无天气"一致。
  `FileName` 读档后是存档名, 比不出图; 地图自己的名字用 `OU_ScenarioName`
  (读 `ScenarioClass::Name`, 空时退回 `UIName`; 与 `UnitPanel` 的键盘移动跨图恢复
  共用同一份实现)。

## 2. 图像档

### 2.1 资源

`AnimTypeClass::Array` (`0x8B4150` = `DynamicVectorClass<AnimTypeClass*>`, `+0x04` 数据指针,
`+0x10` 个数) 里按 ID 找 `RAIN` / `SNOW`, 再走 `ObjectTypeClass` 虚表槽 39 (`LoadImage`)
拿 `SHPStruct*`。实测 (日志):

| ID | SHP 尺寸 | SHP 帧数 | LoopStart/LoopEnd |
|---|---|---|---|
| RAIN | 768x576 | 31 | 0 / 19 |
| SNOW | 800x600 | 20 | 0 / 19 |

SHP 帧数比循环段多, 所以必须按类型里的 LoopStart/LoopEnd 截断 (LoopEnd 是开区间,
可见末帧 = LoopEnd-1)。

### 2.2 播放速度: 类型里的 +0x2B0 已经是"间隔", 不是 art 里的 Rate

`artmo.ini` 里 `[RAIN]`/`[SNOW]` 都写 `Rate=400`, 但活进程里 `+0x2B0` 读出来是 **2**
(`tools/animdump.c`)。也就是说引擎在读 ini 时就把 Rate 换算成了"每动画帧要过几个
逻辑帧" = `900/Rate` 截断 (ModEnc `Rate`: playback delay = 900/Rate ticks, tick 即逻辑帧)。

⇒ 直接用这个值当间隔, **不要**再拿 art 的原始 Rate 重算一遍 `900/Rate` (会冻住)。

逻辑帧计数用 `0xA8ED84` (每帧 +1, 暂停/进菜单时不动), 每次渲染取增量。

### 2.3 绘制: 直接 blit 到 Composite, 没有中间面

* 引擎 `CC_Draw_Shape` (`0x4AED70`) 自己跳过 SHP 的透明像素 (RLE skip 段),
  `Bounds` 参数就是**裁剪框** —— 平铺时每格把视图区当裁剪框传进去, 侧栏/底栏自动
  裁掉。每帧只有"视图区/格子数"次引擎 blit, 没有自有缓冲与逐像素循环。

**平铺格距要比图小 4 像素** (`WTH_IMG_OVERLAP`)。这张图不是可无缝平铺的贴图 ——
它最外一两列/行是空的或者被裁掉了笔画, 按整图尺寸铺, 沿格线就露出一条透明的缝
(画面中间那道十字形的"缝隙" 就是格线)。让相邻两格重叠几个像素把缝压住: 重叠区只占
4/768 ≈ 0.5%, 密度差看不出来。

## 3. 粒子档

### 3.1 一个粒子系统, 三份参数

雨 / 雪 / 火雨 **是同一套粒子**: 一个池子 (`g_Px[WTH_PX_MAX]`, 按 kind 顺序排)、
一套推进 (`Wth_PxStep`)、一个落笔循环 (`Wth_PxDraw`)。差别全在 `g_Kind[]` 的
`WthKind` 表里 (数量/速度/长度/颜色/头部画法/烟)。

* 加一种天气 = 加一行参数 + 一个 `WTH_HEAD_*`; 不再复制 spawn/step/draw 三份代码。
* 头部画法只有三种: `WTH_HEAD_LINE` (有宽度的线 = 雨丝) / `WTH_HEAD_FLAKE`
  (十字 + 下沿暗影 = 雪花) / `WTH_HEAD_GLOW` (加法光斑 + 烟柱 = 火球)。
  拖尾是共用的一段 (`Wth_PxTrail`): 颜色由 `colA → colB` 渐变, alpha 按 `fade` 衰减,
  `tailSmoke/plume` 非 0 时后段并进烟色再接烟柱。雨把 colB 设成等于 colA 就成了单色雨丝。
* 只推进 / 只画本帧 `mask` 里的 kind (图像档时雨雪交给 SHP, 粒子原地待命)。
* 位置/速度全是 **1/16 像素定点整数**, 速度单位是"每**逻辑帧**"—— 与图像档、引擎
  动画同一把尺子: 60 帧下 10~17px/帧的雨, 游戏降到 15 帧就跟着慢。
* 粒子活在**视图区局部坐标系**里, 相机位移每帧整批反向平移 (`Wth_CamStep`),
  看起来钉在世界里; 位移超过 ±64px 视为切镜头/读档, 不搬 (否则整屏雨瞬移)。
* 掉出下边界从上面回来用**取模**, 不重新布点 —— 密度天然守恒, 也不用每帧算几百个随机数。
* 雪花左右摇摆用三角形波 (`g_Tick` 相位), 不摆幅用每 kind 的 `sway` 控制。

### 3.2 参数全在 ini 的 [Environment] 段

`Weather.cpp` 的 `Wth_Defaults()` 是缺省值, `Wth_ReadCfg()` 用
`GetPrivateProfileIntA/StringA` 覆盖 (装载时读一次, 改 ini 要重启游戏)。
三种天气的键名只差前缀, 读取表用 `WTH_KCFG("Rain"/"Snow"/"Fire", kind)` 宏展开。

| 组 | 键 | 含义 |
|---|---|---|
| 开关 | `CloudMode` / `DrawMode` | 只有这两项落盘 (长期设置) |
| 通用 | `XxxDensity` | **密度**: 每 N 平方像素 1 个粒子。数量 = 视图面积/N, 无上下限夹取 —— 同一个密度在 800×600 与 1920×1080 下看起来一样疏密 (池子 4096, 全开不下时按比例一起变稀) |
| 通用 | `SpeedScale` | **粒子速度统一百分比倍率** (100=配置原速), 一次改三类粒子的快慢 |
| 通用 | `ImageSpeed` | 图像档播放速度百分比 (100=引擎原速), 只影响 SHP 动画 |
| 通用 | `WeatherLightMix` | 雨/雪/雾色受环境光照影响的百分比 (0=原色, 100=完全跟随)。光照模型与地形一致 (环境光+色调x等级), 火雨自发光不参与; 每帧算一次 |
| 速度 | `XxxSpeed` | **60 帧基准下的像素/秒**, 写成 `最小,最大`; 内部换算 `×4/15` 成 1/16px/逻辑帧 |
| 浓淡 | `XxxAlpha` | 0~255, 写成 `最小,最大` |
| 长度 | `XxxLen` | 拖尾像素长度, 写成 `最小,最大` (雪为 0 = 没拖尾) |
| 大小 | `XxxSize` | 雨丝宽 / 雪臂长 (1~4) / 火头半径, 写成 `最小,最大`, **每个粒子出生时各抽一个** —— 雨才有大有小 |
| 风 | `RainWind` / `SnowWind` | 风速 = 下落速度的百分比, 写成 `最小,最大` (支持负数, 负=向左), 每个粒子出生时各抽一个; 两值全 0 (SnowWind 默认) = 用 `Spread` 随机抖动; 拖尾方向由 `sx` 自动跟随 |
| 溅射 | `XxxSplash`(每注几颗, 可写 `最小,最大` 区间随机) / `XxxSplashRate`(每秒落点数, 0=按粒子数自动; 有效上限 ~1000, 单帧最多 16 次, 水花/水纹池 1024/256 也会在饱和后互相顶掉) | 落地溅开的水花/火星, 落点铺满整个画面; 只有粒子档才有 (图像档的 SHP 自带水花) |
| 水纹 | `RippleSize` | 落地水纹的最大半径, 写成 `最小,最大` (像素, 2~12), 每个落点各抽一个。雪没有水纹, 只有扬起的雪粉 |
| 颜色 | `RainColor` / `SnowColor` / `FireHeadColor`(头) / `FireMidColor`(拖尾根) / `FireEndColor`(尾端) / `SmokeLightColor` / `SmokeDarkColor` | `RRGGBB` / `#RRGGBB` / `R,G,B` 都认 |
| 火雨 | `FireSmoke` | 每隔多少逻辑帧冒一团烟 (`最小,最大`) |
| 火雨 | `FireTailSmoke` | 尾迹后段并入烟色的程度 (0=不并, 255=末端全变烟色) |
| 火雨 | `FirePlume` | 火舌之上的烟柱长度 (像素, 0=不画) |
| 烟 | `SmokeLife`、`SmokeAlpha`、`SmokeGrow` (都写成 `最小,最大`)、`SmokeRadius`(≤8) | 寿命/浓淡/每帧变大/最大半径 |
| 雪 | `SnowBigRate` | 大片雪花的百分比 (0~100), 0=全小片 (大片臂长再 +1) |
| 雷电 | `ThunderFrames` | 两道闪电的间隔 (`最小,最大`, 游戏帧) |
| 云层 | `CloudOpacity`(浓度 0~255, 压暗/混色共用)、`CloudFogFloor`(雾气底浓度 %)、`CloudScale`(云块尺度 px)、`CloudStyle`(风格名); 开关与画法见 §1 的 `CloudMode`, 雾色光照强度用 `WeatherLightMix` | 见 3.5 |

成对参数都写成 `最小,最大` 一行, 只写一个数就是上下限相同; 解析见 `Wth_CfgPair`。
`Wth_ReadCfg` 末尾按 kind 循环夹一遍 (density/size/len/splash/smoke…), 手改配置
写飞了也不会越界; `density` 是除数, 有下限。

### 3.3 显眼度

* 雨: 头部 4 像素做成 **1~2px 宽** (每颗雨点抽一个, 见 `RainSize`) + 亮蓝白 +
  alpha 150~220 —— 1px 半透线在亮地形上看不见。
* 雪: **必须比雨慢一个量级** (22~67px/s vs 600~1020px/s), 否则是"白色的雨";
  造型 4 种 (六角星 / 十字 / 绒球 / 斜叉), 造型与大小各自随机 —— 一屏混着飘才不像
  "一堆大小不同的十字"; 朝下那几笔压暗, 纯白在雪原/沙地上会糊掉。
* 火雨: 白热头 (3x3 加法光斑) + **上粗下细的火舌** + 火舌之上的**烟柱**。
  火舌/烟柱走普通混合 (亮地形上才看得出暗红), 只有头走加法 (有发光感)。
* 烟: 两套 —— ① 跟着火球走的**烟柱** (顺火舌延长线, 越远越宽越淡); ② 会飘会散的
  **烟团** (`WthSmoke` 环形缓冲, 192 上限)。
* **尾迹不断成节的两条硬约束**: 1) 行 x 按拖尾斜率跳 (`xoff -= sx`), 风大时中间
  空格 → 用 `Wth_HFill` 补水平空隙; 2) 烟柱每行 alpha 不能乘随机数 (相邻行一差就
  是断的), 用每 32 行一个三角波的慢周期平滑包络。
* 另外尾迹后段按 `FireTailSmoke` 并入烟色, 火舌末端与烟柱起点 alpha 直接接上
  (`a0/4`), 所以"白尾"是**渐变成烟**, 不是一个硬切换, 也没有突然截断的头。
* **火头最后画**: 它走加法混, 先画会被火舌的普通混合盖成橙色, 白热芯就没了。
* **烟色按背景亮度选**: 每团/每根烟先读一次头顶像素的绿通道, 亮底用暗烟
  (70,66,62)、暗底用亮烟 (178,176,172)。固定灰必然在某一半地形上看不见, 或在亮地形
  上显得像土。

### 3.4 落地溅射与烟的生灭

* **落点铺满整个画面** (只留 8px 边距), 不取地形高度, 更不拿视图底边当地面 ——
  底边是屏幕边界, 按底边溅会在最下沿堆出一条"水墙"。这是正交俯视, 屏幕上方同样是
  地面, 只在下半屏落会像"半空里炸开"; 也正因为铺满, 这些水花本身就充当了不挂在雨丝
  上的**纯溅射**, 不会出现"上密下疏"的错觉。
* 节拍由粒子数推出来 (`Wth_LandTick`: 每种 `粒子数/24` 次/秒), 雨越密落得越勤;
  ini 里给了 `XxxSplashRate` 就用定值 (0 = 自动)。
* **溅射跟粒子 mask 走**: 图像档的 RAIN/SNOW.SHP 自带落地水花, 再叠一层我们的粒子
  只会显重复, 所以图像档一个水花都不加。
* 落地最显眼的三笔:
  1. **扩散环** (`WthRip`) —— 扁平椭圆, 半径 2px 均匀长到 `RippleSize` 抽到的值 (默认
     5~9, 上限 `WTH_RIP_RMAX`=12; 上限比烟团的 `WTH_SM_RMAX` 大, 两者共用 `g_SmHalf` 表),
     环线画两个像素厚 (外圈实、内圈半透), 单像素线在贴图密集的地面上看不见; 中间留空。
     **雪不画环** —— 地上不会出现一圈水纹, 雪只有扬起的雪粉。
  2. **溅起的水柱** —— 每个落点第一颗颗粒几乎竖直往上冲 (雨 96~156, 单位 1/16 像素/帧),
     头几帧就是一条竖线。
  3. **横向水花** —— 其余颗粒斜着甩出去, 各走各的抛物线。
* **雪粉不是水**: 零重力, 一半零初速原地淡掉, 一半滑动 2~6 像素后停稳 (初速
  横 8~28 / 纵 4~16, 阻尼 60/256 十来帧衰到 0); 寿命 `SnowPowderLife` 可配, 首颗在
  区间上半段抽 (相当于落定的那片雪花本身)。全不动太呆, 全动又像往上飘。
* `WthDrop` 环形缓冲, 自带重力/阻尼/寿命 (雨火重力 7; 雪粉 0 重力 + 阻尼 60);
  绘制时从上一帧位置连到这一帧 (尾淡头亮的"短划"), 卡帧的大跳只留末端 8px。
* 烟 alpha 用抛物线 `a = a0*4*age*(life-age)/life²` (两头贴 0; 线性淡出在大半径时
  还剩一圈可见圆, 看着像"突然消失"); 起始半径 2~7, 长大靠 `grow`。

### 3.5 云层: 云影 (压暗) / 雾气 (混向雾色)

* **落笔只有一套** (`Wth_TonePx`, 标量与 SSE2 同一条公式):
  ```
  云影: c -> (c*m8 + dith) >> 8                      m8 = 256-alpha
  雾气: c -> (c*m8 + tgt*(256-m8) + dith) >> 8       tgt = g_CldTgt (雾色)
  ```
  `tgt` 取 0 就是云影。两者都是对整屏同一比例的**线性混合**, 均值不变 => 色比不漂
  (不会"盖一层灰", 深水也不发紫)。
* **雾色吃环境光** (`Wth_CldToneCalc`, 每帧在 `Wth_CloudFill` 里算一次):
  `m = Ambient + RGB[c] * Level / 1000`, `tgt = maxc * m / 100`, 再按
  `WeatherLightMix` 与通道满值插值 (0 = 纯白, 100 = 完全跟光照)。
  * `m` **夹在 0..100** (雨雪那边放到 200): 目标色超过通道满值后, 打包
    `(r<<rsh)|(g<<5)|b` 会把溢出位串进邻通道, 屏幕上就是彩色噪点。雾不发光, 夜里
    雾发灰是有意的; 嫌暗就把 `WeatherLightMix` 调向 0。
  * 三通道目标**各一份** (`s_CldTgt[3]` / `s_CldTgt256[3]`): 雾色带色偏时 R/B 不等,
    不能共用一个常量。它们进 `Wth_CldSse2Init` 的缓存键 (只比 rsh/gm 会让雾色停在
    上一帧)。
* **浓度场必须两套** —— 云和雾的区别不是浓淡, 是**有没有边**。云影那张场:
  ```
  base    = 低频 fBm       -> 云在哪、多厚
  detail  = 高频 fBm       -> 只在云内部起作用
  density = clamp((detail - (1 - base)) / base)
  ```
  云心 base≈1 时阈值≈0 => **实心**; 云边 base 小、阈值高, 只有 detail 的尖峰能过
  => 边被侵蚀成絮状。这个"有边"正是云的特征 (来源: Guerilla 的体积云, 只留二维),
  直接拿去混白就是一块块有轮廓的白团。

  雾气走 `Wth_CldFogFill`, 整段绕开阈值/侵蚀/覆盖率校准 (那些都是给有边的东西用的):
  只取低频 (oct<=2, amp<=34) + 掺 40% 高频 (`CLD_FOG_DET`) 做飘动纹理, 按场自身
  2%/98% 分位拉成 0..1, smoothstep 后再平方, 最后压进 `[CloudFogFloor, 255]`。
  * **下限不为 0** 是硬要求: 雾没有"从哪儿开始"的位置。底浓度**烘进图里**而不是
    采样端加 —— 后者等于整屏加一层白, 浓淡对比反被压平。
  * 平方那一步: 分位拉伸后中位数正好落在区间正中 (整屏一层 15% 的白, 像盖了块布);
    平方把中段推到 1/4 处, 既有通透处也有雾团。
  * 烘完多跑一遍模糊 (`blur + 1`): 雾里不该有纹理感。
  * 平铺周期与云影相同 (`CLD_TILE_MUL`): 雾团尺度靠风格的 `bPer` 调 (小 = 团大),
    采样端另加倍率只会压成一片没有起伏的白纱。
  * 换画法要重烘 (15ms 量级), 所以**烘焙键 = 风格号*2 + 口径**, alpha 场的缓存键也
    用它 —— 少了口径那一项, 菜单里点"雾气"要等镜头挪 4 像素才生效。
* **图像太碎是硬约束问题**: 轮廓由最细那层 + 域扭曲决定, 而最细一层只有 3 个纹素
  (= 像素噪声) 时会切出一圈碎屑。硬约束是**最细一层格子 >= 6 个纹素**:
  `per0 * 2^(oct-1) <= 42` (256 纹理)。超过就一定碎, 调覆盖率/浓度都救不回来。
* **为什么要二分校准覆盖率**: 上面的 remap 会把面积再缩一次 (云心要求 detail 也过阈值),
  直接拿 45% 当阈值时实际只剩 5%。烘焙后按 `Wth_CldFill` 的计数二分 12 次, 覆盖率对
  阈值单调, 收敛到 1/4096 级, 于是 `cover` 参数是准的。
* **开方**: remap 的中性值落在 0.5, 直接当 alpha 整屏偏淡; 开一次方把中段抬起来, 云心
  才"实"。用逐位整数开方 (`Wth_ISqrt`), 不引 libm。
* **模糊**: 烘焙后跑 `blur` 次 `[1,2,1]` 分离模糊 (环面), 抹掉纹素级锯齿。
* **无缝平铺**: 每层噪声的格点索引按自己的周期取模 (`x0 = ix % per`), 第 o 层周期取
  `per0 * 2^o` —— 每层都正好铺满整张图一遍, 整张图首尾天然衔接。
* **风格必须换置换表, 不能只换阈值**: 同一张 perm 表下, 整屏云块是**同一条噪声脊**
  的不同截断 —— 相邻团总是互为两端, 换个阈值只是改浓淡, "哪里长云"动不了, 于是
  所有风格看着都像同一张图的明暗版本。每种风格自带 `perm` 种子, 烘焙前
  `Wth_PermInit(st->perm)` 重打一张表, 云形之间没有共同骨架。
  `Wth_Perlin` 的 `seed` 参数只取低 8 位当**表内平移**, 用来错开各倍频层, 不换表。
* **y 压要烘进纹理, 不能在采样端压**: 这是 2:1 的等距视图, 地面是扁的, 云块也得扁。
  做法是在**烘焙时**把 y 方向的噪声格数乘 `100/squash%` (`Wth_PeryOf`, 于是
  `Wth_Perlin` 两轴各自取模, `perY > perX` 不影响无缝平铺)。纹理仍是 256², 采样和
  绘制都是 1:1 正方形, 两轴平铺周期一样长。
  * 为什么不能改到采样端: 那样纹理里还是圆团, 只能靠 `tileY = tile*squash%` 把 y 周期
    砍半 —— 屏幕上确实扁了, 但**一屏的重复次数翻倍**, 且纹理里 y 方向一点新内容都
    没有 (同一团云的拉伸)。烘进纹理等于把这块面积换成"更多、更扁的云"。
  * 顺带的观感维度: `squash` 各风格不同 —— 压得狠像贴地薄云带, 压得少像高空大团。
  * 代价是 y 的格数翻倍, 最细一层会变成 3~4 个纹素的噪声 (云边啃成锯末), 所以
    `CLD_YMAX = CLD_TEX/8` 兜底: 每层 `perY` 最多 32 格 (8 纹素)。
  * 域扭曲的 y 位移要按 `squash%` 缩小 (`wy = warp*sq/100`) —— 位移是"域"单位, y 的
    域压过之后同样的位移会落到两倍的格数上, 不缩云边在 y 方向就拧成波浪。
* **风格表** (`kCldStyle`, ESC 菜单里选, 落盘 `CloudStyle`):

  | 序号 | 名字 | perm | 低频 bPer,bOct,bAmp | 高频 dPer,dOct,dAmp | warp/clump | squash | 覆盖率/软边 | 效果 |
  |---|---|---|---|---|---|---|---|---|
  | 0 | cumulus | 01234567 | 6,3,50 | 14,3,52 | 90 / 0 | 50 | 46% / 30 | 团状积云, 全屏均匀 |
  | 1 | big | 2F8A31C5 | 3,3,55 | 9,3,45 | 85 / 22 | 54 | 32% / 26 | 大团稀疏, 团间大片晴空 |
  | 2 | small | 51D0B473 | 11,3,62 | 26,3,62 | 80 / 0 | 48 | 42% / 30 | 细碎, 高频压过低频, 边全是絮 |
  | 3 | sheet | 7C31F09B | 5,2,40 | 9,2,38 | 0 / 20 | 40 | 70% / 55 | 平滑层云, 无扭曲, 一大片纱 |
  | 4 | overcast | 9E5A2D03 | 6,3,42 | 10,3,28 | 60 / 35 | 58 | 88% / 58 | 阴天, 几乎整屏在影里 |
  | 5 | patchy | B4C7E119 | 4,3,52 | 16,3,55 | 100 / 55 | 47 | 42% / 18 | 疏密不均, 硬边, 一半晴朗 |
  | 6 | streak | C3E5D7A2 | 5,3,50 | 14,3,50 | 60 / 25 | 30 | 40% / 34 | 条状云带: 大团 + 压到 30% |
  | 7 | cirrus | D4F19B37 | 8,3,45 | 18,3,40 | 130 / 0 | 22 | 34% / 32 | 卷云: 强扭曲拉出丝缕, 压最扁 |

  * `bAmp/dAmp` 是**每层幅度衰减 (%)**, 50 = 经典 fBm。调小让低频独占 => 大团平滑;
    调大让高频顶上来 => 絮多、轮廓碎。这是"平滑 vs 细碎"的主旋钮, 比改层数稳。
  * `warp` 是域扭曲千分数, 0 = 边不起浪 (层云/薄云那种一整片的感觉)。
  * `clump` 叠一层 per=2 的单层噪声当**大区域疏密**: 这一片云多、那一片几乎空。
    覆盖总量由二分校准补回, 所以它只改分布形状, 不改总量。
  * `squash` 参与烘焙 (改它要重烘; 换风格本来就会重烘, 所以没有额外代价)。
  * 加一种风格 = 表里加一行 (`per0 * 2^(oct-1) <= 42`, 且 `per0*100/squash` 再乘
    `2^(oct-1)` 也不超过 `CLD_YMAX`) + Weather.h 的 `WEATHER_CLOUD_STYLE_N` +
    EscMenu 的 `kCldStyleKey` + 4 份语言文件的 `GuiWthStyleN`。
* **调参只有下面这几个** (覆盖率与软边由风格预设定, 手调阈值只会"没反应"或整屏压暗):

| 参数 | 作用 | 默认 |
|---|---|---|
| `CloudMode` | 0 = 关 / 1 = 云影 (压暗) / 2 = 雾气 (混向雾色) | 1 |
| `CloudOpacity` | 云层浓度 alpha (70 ≈ 云心压暗 27%), 两种画法共用 | 70 |
| `CloudFogFloor` | 雾气底浓度 % (0~100): 薄处也留这一层, 0 = 最薄处可全透明 | 20 |
| `CloudScale` | 云块尺度 (像素); 平铺周期 = 它 × `CLD_TILE_MUL`(6) | 400 |
| `CloudStyle` | 风格名或序号 | cumulus |

* 压暗是**乘法** (`(c*m8+dith)>>8`), 不会"盖一层灰"。但 16bpp 的 5/6/5 在暗色上
  只有几档, 固定 `+128` 取整会把色比撕开 (整条 alpha 只剩几种颜色, 云影切出硬边
  台阶, 深蓝发紫红)。所以取整用 **4x4 有序抖动 (Bayer) 的 8..248**: 变成邻域比例
  混合, 均值不变 => 色比不变, 台阶变成细噪点 (1 个 5 位 LSB ≈ 3% 亮度)。
  `kBayer` 相位三通道共用 (块起点恒为 8 的倍数, 块内相位恒为 `i&3`) —— 只在亮度上
  抖动, 分相位会变成彩色噪点。
* **两条路必须逐位一致**: 块循环/alpha 取址全在 `Wth_CloudFillRows` 里, 标量与 SSE2
  只差逐像素那一步 (`Wth_TonePx` / `WthCldSse2Row::Fill`), 用同一张 `kCldW`、同一条
  抖动公式, 由 `Wth_CloudFill` 按 CPU 分派。SSE2 那条在目标色为 0 (= 云影) 时跳过
  混合项, 省 6 条乘加。改完跑 `python tools/cldwhitecheck.py` (同一份源码里标量 vs
  SSE2, 云影/雾气 × 四种雾色 × 565/555, 共 2880 组) 与 `python tools/cldfilltest.py`
  (与 HEAD 比逐字节)。
* **云场按实际视图尺寸分配** (`Wth_CloudAlloc`, 堆上): 固定静态数组在大视图下越界,
  会把别的全局变量当 alpha 读, 画面下部出成片黑块。
* **块内插值必须 smoothstep**: 线性权重只有 C0 连续, 云边陡 (alpha 每 8 像素跳十几级)
  的地方会留一圈 Mach 带, 看着像一张 8x8 马赛克网。`kCldW[8]` 是 8 个像素中心
  (0.5/8 … 7.5/8) 过 smoothstep 再放大到 256 的权重表; 标量与 SSE2 用同一张表。
* 漂移固定 2/1 px/s (`CLD_DRIFT_X/Y`), 不开放参数: 云层是慢变量, 调它没有意义。
* 开销: 烘焙一次 (256², 几毫秒, 日志打 `weather: cloud style=... bake=Nms`); 场只在
  镜头/漂移走了 4 像素或换了风格/口径时重算; 逐像素走 SSE2。`Perf=1` 里看 `dCLD`。

### 3.6 调参用的离线预览

* `tools/cldstyles.py` —— 云影风格: `python tools/cldstyles.py tiles` / `sheet`,
  输出 `obj/wthpreview/cld_tiles.bmp`(六种风格 3x2 的云图) 与 `cld_sheet.bmp`(合成到地图)。
  它是 C 版的**逐行复刻** (同一个 perm 表 / 同一个 remap / 同一个整数开方)。

  表内平移 —— 复刻时把这两件事混在一起 (每次调用都重打表), 会得到"分布一样但排列
  完全不同"的图, 阈值校验还看不出问题。
* `tools/cldextract.py` —— 从 `Weather.cpp` 里直接切出云影函数, 编成 `obj/cldgen.exe`,
  导出一张 PGM。这是"预览 == 实机"的硬验证: 两者逐字节比对, 差异只剩 float32 vs
  float64 的舍入 (均值 1.4/255), 出现成片差异就说明哪边改漏了。
* `tools/cldcmp.py` —— 整屏对比几个候选参数 (`python tools/cldcmp.py 0 1`)。
* `tools/fogcheck.py` —— **编译真源码**量雾气场: 底浓度是否真的等于 `CloudFogFloor`、
  1752x1048 屏上逐像素 alpha 梯度 (现在 max=2, 旧做法 4, 也就是不可能看出边)。
  改雾气的烘焙段就跑它。
* `tools/cldwhitecheck.py` —— 云层落笔的标量/SSE2 逐位比对: 两种口径 × 四种雾色
  (纯白 / 夜里偏暗 / 三通道差 3 级 / lightMix=0) × 565/555 × 裁切偏移, 共 2880 组,
  顺带验"压暗只减、雾气朝目标色收敛、不越通道满值"。它只验**落笔**, 浓度场归
  `fogcheck.py`。
* `tools/wthpreview.py` —— 粒子档的早期近似脚本, 粒子合并成统一系统后**没有跟着改**,
  只能当粗看; 粒子观感以实机为准。

以上脚本都用 8 位色代替 565 混合, 只作观感参考。

## 4. 雷电 (闪电 / 打雷) 与雨声

开关在 ESC 菜单「天气」那一行的第四段 (雨/雪/火雨/雷电 并排), 与降水开关一样
**只在本次运行有效** —— 不落盘, 免得下次进游戏"晴天一直打雷"。雷电是**独立开关**,
不下雨也能打 (光开雷电就是干雷暴)。雨声 (RainLoop) 跟着"下雨"本身走, 不受雷电
开关影响 (ini 有 `RainSoundEnable=0` 可以要"安静的雨")。四段放不下时按控件流折行,
见 `notes/ESC菜单.md` §3。

### 4.1 声音怎么发出去 (src/misc/SoundFx.cpp)

| 事实 | 出处 / 实证 |
|---|---|
| 音效表 `VocClass::Array` = `0xB1D378`, 下标就是 sound.ini `[SoundList]` 的序号 | `0x750939` 读 `[0xB1D388]` 当上界、`[0xB1D37C]` 当表 |
| 名字 -> 下标: `VocClass::FindIndex` `0x7514D0`, fastcall(ecx=名字), 大小写不敏感, 找不到 -1 | 内部逐个 `_strcmpi` (`0x7C8D20`) |
| 播放: `VocClass::PlayGlobal` `0x750920`, fastcall(ecx=idx, edx=pan 0..0x4000, 栈=音量 float, 栈=控制器), `ret 8` | 函数自己读音效总开关 `0x8464AC`, 自己夹下标 |
| **音量参数是倍率不是绝对值** | `0x4061D0`: `(voc->Volume>>16) * 传入 >> 14`, 传 1.0 = sound.ini 原音量 |
| 循环音要能停, 必须自己持有一条 `AudioController` | PlayGlobal 末尾 `SetEvent(ctrl, event, voc)` |
| 控制器里 `AudioIndex` 必须 = `0x87E294` | End/Stop 拿 `[ctrl+0xC]==0x87e294` 当魔数, 不设就整只函数空转 (`0x405FDE`) |

* 不用 `PlayAt` (要世界坐标): 天气是屏幕层的东西, 没有"声源在世界里"这回事,
  距离感直接由音量与 pan 表达。声像跟着**落点的横向位置**走 —— 看得见的那道就是
  听见的那道, 落点在屏外时同样指向那一侧。
* `AudioController` 布局 (YRpp Audio.h): `{Event, Stamp, EventType, AudioIndex, Unused}`,
  20 字节。本模块在 SoundFx.cpp 里逐字段复制, 不放进 EngineAddr.h (那里只放地址与
  成员偏移, 这里要的是完整布局)。
* **补一次 End 是安全的**: `End` (`0x405FD0`) 入口按 `(Stamp, EventType)` 核对事件
  是否还活着, 事件已被引擎销毁时自己什么都不做, 所以退局/读档后补 End 不会踩空。
  它末尾还会把 `ctrl->Event / ctrl->EventType` 清零 (`0x406039`/`0x40603B`)。
* 名字写错 = 静默不发声 (不是崩溃)。`Weather` 自检行
  `weather: sound RainLoop=139 _Amb_WindCold=1985 WeatherIntro=177 ...` (另有装载时的 `weather: cfg ...` 参数自检行)
  里出现 -1 就说明那个键写错了。SoundFx 只缓存**成功**的解析, 失败的每 2 秒重试
  一次 (不能每帧扫几千条的音效表)。
* **字符串键必须走 `OU_ReadString`**: Profile API 只裁首尾空白、不剥行内注释,
  `RainSound=RainLoop\t;雨声循环` 会原样返回, 拿去查表恒为 -1。整数键不受影响
  (`atoi` 遇到 tab 就停)。

### 4.2 时间线 (逻辑帧)

雷电开 → 2 秒后第一道闪电 → 之后每 `ThunderFrames` (最小,最大) 帧一道。
每道闪电先见光, 雷声延迟 6~36 帧 (距离 + 屏外补偿), 同时按距离把音量压到
65%~100%, 屏外那道再压 35%。雷声从 `ThunderSound` (逗号分隔) 里**随机挑**, 没有前奏/
过门 —— 那几条本身就是不同的雷, 用来换听感, 不是"开场/过门"的时序点。

用**逻辑帧**的理由: 这游戏的速度与帧号绑定 (`ADDR_FRAME`), 用墙钟会出现"游戏变慢
雷照打", 与玩家的时间感对不上。副作用是暂停安全 —— 帧不动, 状态机也就不推进。

**`GtTickNow()` 的单位不是毫秒**: 它是 `timeGetTime() >> 4`, 一个 tick = 16ms
(`0x6C8C40`)。只有雨声的 2 秒重试退避还在用它 (`now = GtTickNow() * 16u`), 雷雨
时间线一律走 `g_Tick`; 两者混用会把时间线拉长 16 倍。

### 4.3 画面

* **电弧**: 自绘折线, 主折线 9 个节点从视图上方 (可以更高, 从云外) 扎到视图
  55%~110% 处, 每段左右甩 ±54 (归一化 0..1023, 绘制时按视图尺寸展开 —— 换分辨率
  不用重生成); 再从第 2、4、6 节点各甩出一条 4 节点分叉。
* **粗细**: 每个线像素铺一个"白芯 + 三层蓝光晕"的点 (`Wth_BltDot`, 最多 13 笔),
  半径 1 时 alpha 62%/45%, 半径 2 时 14%。单像素芯在 1024×768 的贴图上细得像发丝,
  光晕才是让它"变大"的东西。分叉只有主干 3/4 亮度。
* **落点可以在屏外**: 归一化坐标不夹到 0..1023, 一半落点在视图附近, 三分之一直接
  甩到 ±半屏外。屏外那道看不见电弧, 提亮按 `g_Bolt.prox` 压到三成, 声像仍指向它 ——
  `pan = 0x2000 + (x-512)*0x4000/1023`, 夹到 0..0x4000。
* **整屏提亮**: `Wth_FlashFill`, 从视图顶到底线性衰减 (aTop → 45%), 552 档色阶
  用 SSE2 一次 8 像素拆通道加法 (逐像素算要十几毫秒, 而闪电正好落在最需要帧率的
  时候); 555 与老 CPU 走标量, 同一套算法。
* **闪两下**: `kFlashA` / `kBoltA` 一条 10 帧的曲线, 第 4 帧的第二个峰是**回击**
  (return stroke)。单峰看着像闪光灯, 两下才像雷。
* 画在**所有天气之后** (闪电是整屏的一次曝光, 压在雨丝下面像在雨幕后面打手电)。
* 电弧/提亮都只画在视图区原图面 (`SB_RawView`) 上: 缩放、无UI截图、存档缩略图一致。

### 4.4 参数 (全在 `[Environment]`)

| 键 | 含义 | 默认 |
|---|---|---|
| `ThunderFlash` | 提亮峰值 0~255, 0 = 只画电弧 | 110 |
| `ThunderBolt` | 1 = 画电弧 | 1 |
| `ThunderColor` | 闪电色 (加法), `RRGGBB` / `R,G,B` 都认 | 176,194,228 |
| `ThunderFrames` | 两道闪电的间隔 (游戏帧, 最小,最大) | 300,900 |
| `ThunderVolume` | 打雷音量倍率 (%) | 100 |
| `ThunderSound` | 雷声候选, 逗号分隔 (每次打闪随机挑一条) | WeatherIntro,WeatherStart,WeatherStrike |
| `RainSoundEnable` / `RainSound` / `RainVolume` | 雨声循环 | 1 / RainLoop / 100 |
| `SnowSoundEnable` / `SnowSound` / `SnowVolume` | 雪天的风声循环 (跟雪开关走, 与雨声各占一条通道, 雨夹雪时一起响)。**条目自带 Delay=5~10 秒**: 开雪后要等几秒才有第一声, 且一阵一阵吹 | 1 / _Amb_WindCold / 100 |
| `SnowPowderLife` | 雪粉寿命范围 (逻辑帧, 60=1秒), 首颗在区间上半段抽 (多亮一会儿) | 30,60 |

### 4.5 收尾

退出对局时引擎会清掉全部声音, 我们的 `End` 在那之后安全空转; 没有为"退局"挂钩子。
菜单里关雨/关雷电要走 `Weather_SetRain/SetThunder` 里的即时 `Wth_SndReset`, 因为
主循环在菜单打开时是停的。声音纯本地, 不碰模拟状态, 联机安全。

## 5. 自检线索

* 图像档加载时一行: `weather: RAIN frames=31 loop=0-18 size=768x576 step=2`
* 图像档画满 120 帧时一行: `weather: RAIN 120 draws -> N anim frames`
  (60 帧游戏下 N 应该在 60 上下; 如果是 0, 说明逻辑帧号没动)。
* 粒子档布点一行: `weather: particles view=1752x1048 rain=640 snow=640 fire=96`
* 云图烘焙一行: `weather: cloud tex th=131 span=31 opacity=70`
* 全量账 `Perf=1` 里看 `dWTH` (us/帧, 整个天气层) 与 `dCLD` (其中云影那一段)。
* 云影形状: `python tools/cldpreview.py 400 70` 后看 `obj/wthpreview/cloud_scene.bmp`。
* 音效解析: `weather: sound RainLoop=139 _Amb_WindCold=1985 WeatherIntro=177 ...` (另有装载时的 `weather: cfg ...` 参数自检行)
  (-1 = 那个 `[Environment]` 键写的名字在 sound.ini 里不存在 / 行内注释没截掉)。
* 天气那一行的宽度: `esc: trio seg=4 segs=.. labelW=.. rowW=..` (首次绘制时一行)。
* **`Wth_LogicDelta` 一帧只能调一次**: 它会更新帧号基准, 第二次必返回 0, 于是
  `Wth_Advance(l, 0)` + `dp = 0`, 雨雪完全静止 (日志里的 `120 draws -> 0 anim frames`)。
