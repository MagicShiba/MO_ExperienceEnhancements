# 天气覆盖层 (图像档 / 粒子档)

目标: 在单机/联机里给整屏加雨雪, 速度与引擎自身的动画一致, 且不在配置文件里留
"恒定天气"。

## 1. 两种画法 + 三个降水开关 + 云影

* **画法**: `WEATHER_DRAW_IMAGE`(0) 用 art 里的 `RAIN`/`SNOW.SHP` 整屏帧;
  `WEATHER_DRAW_PARTICLE`(1) 自绘粒子。ESC 设置页「杂项 → 画法」一段两选。
* **开关**: 雨 / 雪 / 火雨 三个互不影响的开关 (雨 + 雪 = 雨夹雪, 没有单独的雨夹雪档),
  加一个独立的云影。火雨只有粒子形态, 与画法无关; 云影与降水无关, 可以单独开。
* **落盘策略 (两类开关不一样)**:
  | 项 | 落盘? | 键 |
  |---|---|---|
  | 画法 | **是** (长期设置) | `[Weather] DrawMode=image/particle` |
  | 云影 | **是** (长期设置) | `[Weather] CloudEnable=0/1` |
  | 雨 / 雪 / 火雨 | 否 (只在本次运行) | — (s_Toggle 里 `section=NULL`) |
  降水开关不落盘的原因: 上次开了雨, 下次启动就一直在下, 变成"恒定天气"。
  画法与云影是"我偏好这种显示方式", 属于长期设置, 由 ESC 菜单写回 ini, 模块装载时
  用 `Wth_LoadState()` 读回来。
* 表驱动: `s_Toggle` 五行 (云影带 section/key); `s_Choice` 两行 —— 画法
  (`EscChoiceWthMode`) 与**云影风格** (`EscChoiceWthStyle`, 落盘 `CloudStyle`)。
  两者都在处理函数里顺手 `Esc_QueueRaw`/`Esc_QueueValue`。

## 2. 图像档

### 2.1 资源

`AnimTypeClass::Array` (`0x8B4150` = `DynamicVectorClass<AnimTypeClass*>`, `+0x04` 数据指针,
`+0x10` 个数) 里按 ID 找 `RAIN` / `SNOW`, 再走 `ObjectTypeClass` 虚表槽 39 (`LoadImage`)
拿 `SHPStruct*`。实测 (日志):

| ID | SHP 尺寸 | SHP 帧数 | LoopStart/LoopEnd |
|---|---|---|---|
| RAIN | 768x576 | 31 | 0 / 19 |
| SNOW | 800x600 | 20 | 0 / 19 |

SHP 帧数比循环段多, 所以必须按类型里的 LoopStart/LoopEnd 截断 (LoopEnd 是开区间,
可见末帧 = LoopEnd-1)。

### 2.2 播放速度: 类型里的 +0x2B0 已经是"间隔", 不是 art 里的 Rate

`artmo.ini` 里 `[RAIN]`/`[SNOW]` 都写 `Rate=400`, 但活进程里 `+0x2B0` 读出来是 **2**
(`tools/animdump.c`)。也就是说引擎在读 ini 时就把 Rate 换算成了"每动画帧要过几个
逻辑帧" = `900/Rate` 截断 (ModEnc `Rate`: playback delay = 900/Rate ticks, tick 即逻辑帧)。

⇒ 直接用这个值当间隔, **不要**再拿 art 的原始 Rate 算一遍 `900/Rate`
(算成 900/2 = 450 就冻住了, 一帧停在屏上 7.5 秒, 看起来就是静止)。

逻辑帧计数用 `0xA8ED84` (每帧 +1, 暂停/进菜单时不动), 每次渲染取增量。

### 2.3 绘制: 直接 blit 到 Composite, 没有中间面

早期做法是"渲进自有 16bpp 缓冲 → 逐像素跳过 0 拷到 Composite"。这是绕路:

* 引擎 `CC_Draw_Shape` (`0x4AED70`) 本身就会跳过 SHP 的透明像素 (RLE 的 skip 段),
  目标面没被写的像素原样保留, 所以根本不需要自己判 0;
* `Bounds` 参数就是**裁剪框**, 平铺时每格把视图区当裁剪框传进去, 侧栏/底栏自动裁掉;
* 于是每帧只剩"视图区/格子数"次引擎 blit, 没有零填充、没有逐像素循环、没有 `LocalAlloc`。

**平铺格距要比图小 4 像素** (`WTH_IMG_OVERLAP`)。这张图不是可无缝平铺的贴图 ——
它最外一两列/行是空的或者被裁掉了笔画, 按整图尺寸铺, 沿格线就露出一条透明的缝
(画面中间那道十字形的"缝隙" 就是格线)。让相邻两格重叠几个像素把缝压住: 重叠区只占
4/768 ≈ 0.5%, 密度差看不出来。

## 3. 粒子档

### 3.1 一个粒子系统, 三份参数

雨 / 雪 / 火雨 **是同一套粒子**: 一个池子 (`g_Px[WTH_PX_MAX]`, 按 kind 顺序排)、
一套推进 (`Wth_PxStep`)、一个落笔循环 (`Wth_PxDraw`)。差别全在 `g_Kind[]` 的
`WthKind` 表里 (数量/速度/长度/颜色/头部画法/烟)。

* 加一种天气 = 加一行参数 + 一个 `WTH_HEAD_*`; 不再复制 spawn/step/draw 三份代码。
* 头部画法只有三种: `WTH_HEAD_LINE` (有宽度的线 = 雨丝) / `WTH_HEAD_FLAKE`
  (十字 + 下沿暗影 = 雪花) / `WTH_HEAD_GLOW` (加法光斑 + 烟柱 = 火球)。
  拖尾是共用的一段 (`Wth_PxTrail`): 颜色由 `colA → colB` 渐变, alpha 按 `fade` 衰减,
  `tailSmoke/plume` 非 0 时后段并进烟色再接烟柱。雨把 colB 设成等于 colA 就成了单色雨丝。
* 只推进 / 只画本帧 `mask` 里的 kind (图像档时雨雪交给 SHP, 粒子原地待命)。
* 位置/速度全是 **1/16 像素定点整数**, 速度单位是"每**逻辑帧**"—— 与图像档、引擎
  动画同一把尺子: 60 帧下 10~17px/帧的雨, 游戏降到 15 帧就跟着慢。
* 粒子活在**视图区局部坐标系**里, 相机位移每帧整批反向平移 (`Wth_CamStep`),
  看起来钉在世界里; 位移超过 ±64px 视为切镜头/读档, 不搬 (否则整屏雨瞬移)。
* 掉出下边界从上面回来用**取模**, 不重新布点 —— 密度天然守恒, 也不用每帧算几百个随机数。
* 雪花左右摇摆用三角形波 (`g_Tick` 相位), 不摆幅用每 kind 的 `sway` 控制。

### 3.2 参数全在 ini 的 [Weather] 段

`Weather.cpp` 的 `Wth_Defaults()` 是缺省值, `Wth_ReadCfg()` 用
`GetPrivateProfileIntA/StringA` 覆盖 (装载时读一次, 改 ini 要重启游戏)。
三种天气的键名只差前缀, 读取表用 `WTH_KCFG("Rain"/"Snow"/"Fire", kind)` 宏展开。

| 组 | 键 | 含义 |
|---|---|---|
| 开关 | `CloudEnable` / `DrawMode` | 只有这两项落盘 (长期设置) |
| 通用 | `XxxCount` / `XxxCountMin` / `XxxCountMax` | 数量 = 视图面积/Count, 再夹到 [Min,Max] |
| 通用 | `SpeedScale` | **粒子速度统一百分比倍率** (100=配置原速), 一次改三类粒子的快慢 |
| 通用 | `ImageSpeed` | 图像档播放速度百分比 (100=引擎原速), 只影响 SHP 动画 |
| 速度 | `XxxSpeedMin/Max` | **60 帧基准下的像素/秒**, 内部换算 `×4/15` 成 1/16px/逻辑帧 |
| 浓淡 | `XxxAlphaMin/Max` | 0~255 |
| 长度 | `XxxLenMin/Max` | 拖尾像素长度 (雪为 0 = 没拖尾) |
| 大小 | `XxxSize` | 雨丝宽 / 雪臂长 (1~4) / 火头半径 (1~3) |
| 风 | `RainWind` | 水平速度 = 下落速度 × wind/100, 负=向左; 拖尾方向由 `sx` 自动跟随 |
| 溅射 | `XxxSplash`(每注几颗) / `XxxSplashRate`(每秒落点数, 0=按数量自动) | 落地溅开的水花/火星, 落点铺满整个画面 |
| 颜色 | `RainColor` / `SnowColor` / `FireHeadColor`(头) / `FireMidColor`(拖尾根) / `FireEndColor`(尾端) / `SmokeLightColor` / `SmokeDarkColor` | `RRGGBB` / `#RRGGBB` / `R,G,B` 都认 |
| 火雨 | `FireSmokeMin/Max` | 每隔多少逻辑帧冒一团烟 |
| 火雨 | `FireTailSmoke` | 尾迹后段并入烟色的程度 (0=不并, 255=末端全变烟色) |
| 火雨 | `FirePlume` | 火舌之上的烟柱长度 (像素, 0=不画) |
| 烟 | `SmokeLifeMin/Max`、`SmokeAlphaMin/Max`、`SmokeRadius`(≤8)、`SmokeGrowMin/Max` | 寿命/浓淡/最大半径/每帧变大 |
| 雪 | `SnowBigRate` | 大片概率 1/N, 0=全小片 (大片臂长再 +1) |
| 云影 | `CloudOpacity`(云心压暗 0~255)、`CloudScale`(云块尺度 px)、`CloudStyle`(风格名) | 见 3.5 |

`Wth_ReadCfg` 末尾按 kind 循环夹一遍 (count/size/len/splash/smoke…), 手改配置写飞了
也不会越界; `count` 是除数, 有下限。

### 3.3 显眼度

* 雨: 头部 4 像素做成 **2px 宽** + 亮蓝白 + alpha 150~220。之前 1px 半透线在亮地形上基本看不见。
* 雪: **必须比雨慢一个量级** (22~67px/s vs 600~1020px/s), 否则是"白色的雨";
  画法用"十字亮点 + 下方一像素压暗影"—— 纯白在雪原/沙地上会糊掉, 有暗边才看得见。
* 火雨: 白热头 (3x3 加法光斑) + **上粗下细的火舌** + 火舌之上的**烟柱**。
  火舌/烟柱走普通混合 (亮地形上才看得出暗红), 只有头走加法 (有发光感)。
* 烟: 两套 —— ① 跟着火球走的**烟柱** (顺火舌延长线, 越远越宽越淡); ② 会飘会散的
  **烟团** (`WthSmoke` 环形缓冲, 192 上限)。
* **尾迹"断成一节一节"的两个真因** (都修掉了, 改这块前先看这两条):
  1) 每行的 x 是按拖尾斜率跳的 (`xoff -= sx`), 风大时一行能跳好几个像素, 中间空一格
     → 用 `Wth_HFill` 把上一行到这一行的水平空隙补上;
  2) 旧的烟柱每行 alpha 乘了一个哈希随机数 `(4~7)/6` —— 相邻行差 75%, 看着就是断的
     → 改成慢周期平滑包络 (每 32 行一个三角波起伏), 一行一行是连续的。
* 另外尾迹后段按 `FireTailSmoke` 并入烟色, 火舌末端与烟柱起点 alpha 直接接上
  (`a0/4`), 所以"白尾"是**渐变成烟**, 不是一个硬切换, 也没有突然截断的头。
* **火头最后画**: 它走加法混, 先画会被火舌的普通混合盖成橙色, 白热芯就没了。
* **烟色按背景亮度选**: 每团/每根烟先读一次头顶像素的绿通道, 亮底用暗烟
  (70,66,62)、暗底用亮烟 (178,176,172)。固定灰必然在某一半地形上看不见, 或在亮地形
  上显得像土。

### 3.4 落地溅射与烟的生灭

* **落点铺满整个画面** (只留 8px 边距), 不取地形高度, 更不拿视图底边当地面 ——
  底边是屏幕边界, 按底边溅会在最下沿堆出一条"水墙"。这是正交俯视, 屏幕上方同样是
  地面, 只在下半屏落会像"半空里炸开"; 也正因为铺满, 这些水花本身就充当了不挂在雨丝
  上的**纯溅射**, 不会出现"上密下疏"的错觉。
* 节拍由粒子数推出来 (`Wth_LandTick`: 每种 `count/5` 次/秒), 雨越密落得越勤;
  ini 里给了 `XxxSplashRate` 就用定值 (0 = 自动)。`WthDrop` 环形缓冲, 有自己的重力
  (`WTH_DROP_GRAV`) 与寿命, 一颗溅珠一半向上崩、一半横向甩出去; 颜色取该种天气的 `colA`。
* **烟"凭空出现 / 突然消失"是 alpha 曲线的问题**: 旧版线性淡出, 半径已经很大时还剩一格
  可见的圆。现在用抛物线 `a = a0*4*age*(life-age)/life²`, 两头都贴着 0; 起始半径也
  缩到 2~7 (1/16 像素), 长起来靠 `grow`。

### 3.5 云影 (低频定形 + 高频侵蚀)

* **算法来源**: Guerilla Games 的体积云 (wedesoft.de "Procedural Volumetric Clouds" 里
  引述的那段代码), 只留二维部分:

  ```
  base    = 低频 fBm       -> 云在哪、有多厚
  detail  = 高频 fBm       -> 只在云内部起作用
  density = clamp((detail - (1 - base)) / base)
  ```

  云心 `base≈1` 时阈值 `1-base≈0`, detail 整个被填满 => **实心**; 云边 base 小、阈值高,
  只有 detail 的尖峰能过 => 边被"侵蚀"成絮状。**云心实心 + 边缘絮状**才是"云"; 之前
  整张图都是渐变噪声、按百分位切一刀, 云心也是渐变的, 看着就是一层雾。
* **"图像太碎"的真因**: 旧版轮廓由最细那层 + 域扭曲决定, 而最细一层只有 3 个纹素
  (= 像素噪声), 切出来一圈碎屑。现在的硬约束是**最细一层格子 >= 6 个纹素**:
  `per0 * 2^(oct-1) <= 42` (256 纹理)。超过就一定碎, 调覆盖率/浓度都救不回来。
* **为什么要二分校准覆盖率**: 上面的 remap 会把面积再缩一次 (云心要求 detail 也过阈值),
  直接拿 45% 当阈值时实际只剩 5%。烘焙后按 `Wth_CldFill` 的计数二分 12 次, 覆盖率对
  阈值单调, 收敛到 1/4096 级, 于是 `cover` 参数是准的。
* **开方**: remap 的中性值落在 0.5, 直接当 alpha 整屏偏淡; 开一次方把中段抬起来, 云心
  才"实"。用逐位整数开方 (`Wth_ISqrt`), 不引 libm。
* **模糊**: 烘焙后跑 `blur` 次 `[1,2,1]` 分离模糊 (环面), 抹掉纹素级锯齿。
* **无缝平铺**: 每层噪声的格点索引按自己的周期取模 (`x0 = ix % per`), 第 o 层周期取
  `per0 * 2^o` —— 每层都正好铺满整张图一遍, 整张图首尾天然衔接。
* **风格必须换置换表, 不能只换阈值**: 同一张 perm 表下, 整屏云块是**同一条噪声脊**
  的不同截断 —— 相邻团总是互为两端, 换个阈值只是改浓淡, "哪里长云"动不了, 于是
  所有风格看着都像同一张图的明暗版本。现在每种风格自带 `perm` 种子, 烘焙前
  `Wth_PermInit(st->perm)` 重打一张表, 云形之间没有共同骨架。
  `Wth_Perlin` 的 `seed` 参数只取低 8 位当**表内平移**, 用来错开各倍频层, 不换表。
* **y 压要烘进纹理, 不能在采样端压**: 这是 2:1 的等距视图, 地面是扁的, 云块也得扁。
  做法是在**烘焙时**把 y 方向的噪声格数乘 `100/squash%` (`Wth_PeryOf`, 于是
  `Wth_Perlin` 两轴各自取模, `perY > perX` 不影响无缝平铺)。纹理仍是 256², 采样和
  绘制都是 1:1 正方形, 两轴平铺周期一样长。
  * 为什么不能改到采样端: 那样纹理里还是圆团, 只能靠 `tileY = tile*squash%` 把 y 周期
    砍半 —— 云影在屏幕上确实扁了, 但**一屏的重复次数翻倍**, 而且纹理里 y 方向一点
    新内容都没有 (同一团云的拉伸)。烘进纹理等于把这块面积换成"更多、更扁的云"。
  * 顺带的观感维度: `squash` 各风格不同 —— 压得狠像贴地薄云带, 压得少像高空大团。
  * 代价是 y 的格数翻倍, 最细一层会变成 3~4 个纹素的噪声 (云边啃成锯末), 所以
    `CLD_YMAX = CLD_TEX/8` 兜底: 每层 `perY` 最多 32 格 (8 纹素)。
  * 域扭曲的 y 位移要按 `squash%` 缩小 (`wy = warp*sq/100`) —— 位移是"域"单位, y 的
    域压过之后同样的位移会落到两倍的格数上, 不缩云边在 y 方向就拧成波浪。
* **风格表** (`kCldStyle`, ESC 菜单里选, 落盘 `CloudStyle`):

  | 序号 | 名字 | perm | 低频 bPer,bOct,bAmp | 高频 dPer,dOct,dAmp | warp/clump | squash | 覆盖率/软边 | 效果 |
  |---|---|---|---|---|---|---|---|---|
  | 0 | cumulus | 01234567 | 6,3,50 | 14,3,52 | 90 / 0 | 50 | 46% / 30 | 团状积云, 全屏均匀 (默认) |
  | 1 | big | 2F8A31C5 | 3,3,55 | 9,3,45 | 85 / 22 | 54 | 32% / 26 | 大团稀疏, 团间大片晴空 |
  | 2 | small | 51D0B473 | 11,3,62 | 26,3,62 | 80 / 0 | 48 | 42% / 30 | 细碎, 高频压过低频, 边全是絮 |
  | 3 | sheet | 7C31F09B | 5,2,40 | 9,2,38 | 0 / 20 | 40 | 70% / 55 | 平滑层云, 无扭曲, 一大片纱 |
  | 4 | overcast | 9E5A2D03 | 6,3,42 | 10,3,28 | 60 / 35 | 58 | 88% / 58 | 阴天, 几乎整屏在影里 |
  | 5 | patchy | B4C7E119 | 4,3,52 | 16,3,55 | 100 / 55 | 47 | 42% / 18 | 疏密不均, 硬边, 一半晴朗 |
  | 6 | streak | C3E5D7A2 | 5,3,50 | 14,3,50 | 60 / 25 | 30 | 40% / 34 | 条状云带: 大团 + 3.3:1 压缩 = 被风吹开的横带 |

  * `bAmp/dAmp` 是**每层幅度衰减 (%)**, 50 = 经典 fBm。调小让低频独占 => 大团平滑;
    调大让高频顶上来 => 絮多、轮廓碎。这是"平滑 vs 细碎"的主旋钮, 比改层数稳。
  * `warp` 是域扭曲千分数, 0 = 边不起浪 (层云/薄云那种一整片的感觉)。
  * `clump` 叠一层 per=2 的单层噪声当**大区域疏密**: 这一片云多、那一片几乎空。
    覆盖总量由二分校准补回, 所以它只改分布形状, 不改总量。
  * `squash` 参与烘焙 (改它要重烘; 换风格本来就会重烘, 所以没有额外代价)。
  * 加一种风格 = 在表里加一行 (`per0 * 2^(oct-1) <= 42`, 且 `per0*100/squash` 再乘
    `2^(oct-1)` 也不会超过 `CLD_YMAX`) + Weather.h 的
    `WEATHER_CLOUD_STYLE_N` + EscMenu 的 `kCldStyleKey` + 4 份语言文件的 `GuiWthStyleN`。
* **只留两个 ini 参数** (覆盖率和软边由预设定, 手调只会得到"调了没反应"或"整屏均匀
  压暗" —— 那是旧版一个参数兼任阈值与浓度的老毛病):
  | 参数 | 作用 | 默认 |
  |---|---|---|
  | `CloudOpacity` | 云心最大压暗 alpha (70 ≈ 压暗 27%) | 70 |
  | `CloudScale` | 云块尺度 (像素, 两轴相同); `CLD_TILE_MUL=6`, 默认 `bPer=6` 时一团云 ≈ 就是它, 平铺周期 = 它*6 | 400 |
  | `CloudStyle` | 风格名或序号 | cumulus |
* 压暗是**乘法** (`(c*m8+dith)>>8`), 不会出现"盖一层灰"。但乘法**不等于**色相不变 ——
  16bpp 的 5/6/5 在暗色上只有几档, 各通道各自取整就会把色比撕开:
  * 实测 (深蓝水 5 位 R=6, 6 位 G=12, 5 位 B=8, CloudOpacity=70): 整条 alpha 0..70
    **只产生 8 种颜色**。于是平滑的云影在水面上被切成一圈圈硬边台阶 ("断层"),
    而且 R/B 在 0.71~0.86 之间来回跳 (深蓝发紫红就是这么来的), 低 alpha 段
    (0..12) 还完全不变 —— 云影外圈有个"死区"。
  * 修法: 把固定的 `+128` 换成 **4x4 有序抖动 (Bayer) 的 8..248**。取整变成邻域里的
    比例混合, 均值不变 => 色相比不变; 台阶变成细噪点 (1 个 5 位 LSB ≈ 3% 亮度)。
    实测同样条件下 4x4 均值从 (49,49,66) 平滑走到 (36,35,47.5), R/B 稳定在 0.74。
  * `kBayer` 的相位跟着屏幕走 (块起点恒为 8 的倍数, 所以块内相位恒为 `i&3`),
    三个通道用同一相位 —— 用不同相位会变成彩色噪点, 只在亮度上抖动才是对的。
* **两条路必须逐位一致**: `Wth_CloudFillScalar` 与 `Wth_CloudFillSse2` 用同一张
  `kCldW`、同一条抖动公式。实机第一帧跑一次 `Wth_CloudVerify` (小窗口随机底图,
  两条路各跑一遍逐字节比), 不一致才写 `weather: cloud sse2 mismatch=N`;
  命令行里用 `python tools/cldfilltest.py` (200 组随机 alpha 场)。
* **场必须按实际视图尺寸分配**: 旧版是固定 `128x96` 静态数组, 1752x1048 时 rows=131
  就越界, 读到后面的全局变量 (颜色值) 当 alpha, 画面下部出现成片黑块。现在
  `Wth_CloudAlloc` 建在堆上, 落笔用的行列数直接用 `g_CldCols/g_CldRows`。
* **块内插值必须 smoothstep**: 线性权重只有 C0 连续, 云边陡 (alpha 每 8 像素跳十几级)
  的地方会留一圈 Mach 带, 看着像一张 8x8 马赛克网。`kCldW[8]` 是 8 个像素中心
  (0.5/8 … 7.5/8) 过 smoothstep 再放大到 256 的权重表; 标量与 SSE2 用同一张表。
* 漂移固定 2/1 px/s (`CLD_DRIFT_X/Y`), 不开放参数: 云影是慢变量, 调它没有意义。
* 开销: 烘焙一次 (256², 实际几毫秒, 日志打 `weather: cloud style=... bake=Nms`); 场只在
  镜头/漂移走了 4 像素或**换了风格**时重算; 逐像素压暗走 SSE2 (`Wth_CloudFillSse2`)。
  `Perf=1` 里看 `dCLD`。

### 3.6 调参用的离线预览

* `tools/cldstyles.py` —— 云影风格: `python tools/cldstyles.py tiles` / `sheet`,
  输出 `obj/wthpreview/cld_tiles.bmp`(六种风格 3x2 的云图) 与 `cld_sheet.bmp`(合成到地图)。
  它是 C 版的**逐行复刻** (同一个 perm 表 / 同一个 remap / 同一个整数开方)。
  `set_table(pm)` 对应 `Wth_PermInit`: **一张表用整个风格**, `hh()` 里的 seed 只当
  表内平移 —— 复刻时把这两件事混在一起 (每次调用都重打表), 会得到"分布一样但排列
  完全不同"的图, 阈值校验还看不出问题。
* `tools/cldextract.py` —— 从 `Weather.cpp` 里直接切出云影函数, 编成 `obj/cldgen.exe`,
  导出一张 PGM。这是"预览 == 实机"的硬验证: 两者逐字节比对, 差异只剩 float32 vs
  float64 的舍入 (均值 1.4/255), 出现成片差异就说明哪边改漏了。
* `tools/cldcmp.py` —— 整屏对比几个候选参数 (`python tools/cldcmp.py 0 1`)。
* `tools/wthpreview.py` —— 粒子档的早期近似脚本, 粒子合并成统一系统后**没有跟着改**,
  只能当粗看; 粒子观感以实机为准。

以上脚本都用 8 位色代替 565 混合, 只作观感参考。

## 4. 自检线索

* 图像档加载时一行: `weather: RAIN frames=31 loop=0-18 size=768x576 step=2`
* 图像档画满 120 帧时一行: `weather: RAIN 120 draws -> N anim frames`
  (60 帧游戏下 N 应该在 60 上下; 如果是 0, 说明逻辑帧号没动)。
* 粒子档布点一行: `weather: particles view=1752x1048 rain=640 snow=640 fire=96`
* 云图烘焙一行: `weather: cloud tex th=131 span=31 opacity=70`
* 全量账 `Perf=1` 里看 `dWTH` (us/帧, 整个天气层) 与 `dCLD` (其中云影那一段)。
* 云影形状: `python tools/cldpreview.py 400 70` 后看 `obj/wthpreview/cloud_scene.bmp`。
