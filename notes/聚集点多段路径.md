# 聚集点多段路径 (RallyPath)

实现见 `src/order/RallyPath.cpp`, 配置见 `dist/MOExperience.ini` 的 `[RallyPath]`。

## 交互

| 操作 | 效果 |
|---|---|
| 左键点空地 (选中工厂) | 引擎设聚集点并自己画那条线; 本模块记成第一段起点, 旧尾巴作废 |
| 按住 Z + 左键点图 | 追加一段尾巴, 起点不动 |
| 松开 Z | 尾巴保留, 之后出厂的单位继续用 |
| 右键 | 本模块不做事 (原版取消令 / 拖镜头) |
| 换家 / 读档 / 观战切换 | 清折线表并丢弃在追队列 |
| 建筑被卖/摧毁/占领 | 每轮验活后自动删表项 |
| 多选工厂一起 Z 画线 | 每家各记一份, 出厂各走各的; 画线时建议只选一家 |

## 自己工厂只走自己的线

1. **登记真正出厂的建筑**。出厂钩按指针查表。引擎可能对同一单位连续回调多次
   (出口忙时改派给另一栋同类建筑), 真正出厂的是最后一次, 故同一单位以最后一次
   的 `bld` 为准, 同建筑重试时保持原记录。
2. **只认本家选中建筑**。门里先验 `Owner (+0x21C) == CurrentPlayer`, 再验 ESI 在选中表内,
   单发调用 (AI/触发器等) 一律放行。非本家 (AI/其它玩家/盟友) 建筑即使被选中也不设折线,
   也不吞掉它的原生聚集点行为; 建筑被击破占领后 `Owner` 变非本家, 每轮 `RP_DropDead`
   顺带清掉该表项。
3. **追单绑定单位 ID**。出厂瞬间抓 `Fetch_ID`, 每轮 `OU_PtrAlive` 验活, 对不上就丢。
   节点事件带真实 ID 进 `OT_Fire`。
4. **主厂改派**。生产集中到主厂, 主厂出口忙时会改派到空闲同类厂出厂, 线是否生效
   取决于实际从哪栋出厂。

## 支持哪些建筑

只有 ini `[RallyPath] Types=` 里列出的建筑 ID (逗号分隔), 留空 = 不限类型。
默认值取自 mod rules:

| 用途 | rules 键 | 默认 ID |
|---|---|---|
| 战车工厂 | `PrerequisiteFactory=` | GAWEAP, NAWEAP, YAWEAP, FAWEAP |
| 兵营 | `PrerequisiteBarracks=` | GAPILE, NAHAND, YABRCK, FABARR |
| 船厂 | `[GenericPrerequisites] SHIPYARD=` | GAYARD, NAYARD, YAYARD, FAYARD |

不列结尾 `B` 的附属版和船厂 `AI` 附属版, 只认主建筑。`GACNST` 等是基地, 不是兵营。

`BuildingType` 的 ID 是 `BuildingTypeClass + 0x24` 处的内联 `char[0x18]`, 不是指针。

## 第一段起点

第一段起点 = **玩家自己左键设的那个聚集点格** (`sx/sy`, 在 `RP_SetRally` 里记下, 就是引擎
同一次点击设的聚集点)。尾巴接在引擎那条聚集点线末端续画。
没设过 (`sx<0`) 时绘制从建筑本体坐标起笔, 补上"建筑→首段"。

> **不要读引擎 `ArchiveTarget` 的坐标**。`BuildingClass` 的 `ArchiveTarget` @ `+0x218`
> 是引擎画聚集点线读的目标指针, 但只有当前玩家选中的工厂才保证有效;
> 失效条目读到的可能是脏指针, 解引用虚表会崩。故本模块**只判空、绝不解引用**。

**聚集点由有变无** (按 S 清聚集点 / 点建筑自身取消): `+0x218` 变 NULL, `had` 由 1→0,
折线一并作废。只读一遍指针, 安全。

本模块永远不写引擎的聚集点, 只改本机内存/渲染面。

**绘制风格**: 折线用虚线 (`OU_PrevDrawDash`, 每 6 像素实 / 4 像素空), 与引擎聚集点线的
虚线风格一致。

Poll 里维护 `g_RpZRecent`: 按住 Z 期间恒为 15 帧, 这期间任何左键都不清尾巴,
防钩子漏读 Z 误删。清除只发生在左键重设聚集点, 不用右键清 (右键是原生取消/拖镜头)。

## 钩点

| 钩 | 地址 / 长度 | 说明 |
|---|---|---|
| 聚集点门 | `0x44377E` / 6 B | `CellClickedAction` 内设聚集点判定入口。ESI = 建筑。回 1 吞掉原生聚集点 |
| 出厂 | `0x443C81` / 7 B | `BuildingClass::ExitObject` (`0x443C60`) 内分派前。ESI = 建筑, EDI = 单位。**同址同长**于 Phobos `BuildingClass_ExitObject_InitialClonedHealth`（`0x443C81`/7B），供 Syringe 链式共挂；勿改回 `0x443C7D`/13B（会与 Phobos 区间嵌套互毁） |

落点格不取栈参, 直接问 `OU_MouseCell` (与引擎同条 `ProcessClickCoords` 路径)。
出厂钩被偷字节只读 EDI, 无须还原寄存器。

## 出厂延迟

出厂瞬间载具还卡在出口格上, 立刻发节点会判不可达而整条放弃, 故等 `DelayFrames`
个逻辑帧再发。读 `0xA8ED84` 逻辑帧号, 不数轮询次数 (Poll 一帧可被调多次)。
游戏逻辑 30 帧/游戏秒, 60 帧 = 2 秒。

## 规划点下发: 两阶段

事件形状 (与 PatrolCircle 同): 每点每单位一条 MegaMission, `Mission=Move(2)`,
`Target=空`, `Destination=格`, `Follow=同格`, `IsPlanningEvent=1`; 最后补一条
PlanCommit (`Type 0x2B`)。

规划点先进队列 (主循环每帧只搬 2 条), PlanCommit 直进 DoList, 同批齐发则提交先落地
而被按无节点丢弃。所以先发全部节点 → 轮询 token 确认数够 → 再发提交。
不逐段推进, 发完即交引擎自己走, 随即释放槽位。

## 别抢玩家的规划

PlanCommit 是房屋级的, 我方提交会连带启动玩家画到一半的路径。故玩家还有没提交的
路径就一直压着不发, 不设超时。纯只读扫规划开关 (`0xAC4CF4`) 与 token 数组
(`0xAC4C7C` items / `0xAC4C88` count)。`0xAC4C78` 处是 `DynamicVectorClass`,
成员为 items@+0x4 / capacity@+0x8 / count@+0x10; 用成 `+0x8` 会按 capacity 越界
读到未初始化槽位而崩。

只把 `count>0 且游标 (token+0x8C) ==0 且标记 (token+0x1C) ==0` 且不属于本模块的
token 当作别人的待提交路径。已在走/已提交的 token 会被提交跳过, 不算进来,
否则我们自己刚提交的单位会挡住后面几家工厂。

## 折线颜色

```
方案下标 = *(CurrentPlayer(0xA83D4C) + 0x16054)
方案指针 = ColorScheme::Array.items(0xB054D4)[下标]
主色阶   = *(方案 + 0x330)
R,G,B    = 方案->Colors[主色阶*3]   // Colors @ +0x04
```

不用 `BaseColor` (不是玩家色)。取不到回退黄色, 线宽 2 像素。

## 注意事项

别按指针扫对象验类型 ID (ID 是内联数组, 扫指针找不到; 野指针解引用直接崩)。
探内存只用 `IsPlausiblePtr` 守卫加 `VirtualQuery` 思路, 详见实现。
