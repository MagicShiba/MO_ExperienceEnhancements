# 崩溃定位

## 一、最常见的一类：钩子副本里的 rel32 没有重定位

Syringe 把站点前 N 字节**原样**抄进钩子桩池当"原指令副本"，不做重定位。副本里只要有
相对分支（`E8/E9/EB/7x/0F8x`），换地址执行后目标也跟着平移：

```
target' = target + (副本地址 - 站点)
```

`SU_PopOne` 挂在 `0x73D8CD`，那 5 字节就是 `call 0x004DE710`，而处理函数在"没有单卸
记录"时 `return 0` —— 于是落到副本上执行这句 call。验算（池基址 `P=0x086E0000`，
副本从 `P+0x21` 开始）：

| 量 | 值 | 日志 |
|---|---|---|
| 副本首指令地址 | `P+0x21` = `0x086E0021` | — |
| call 的返回地址 | `0x086E0026` | `MOE: esp=` 第一字 `086E0026` |
| 实际跳到的目标 | `0x086E0026 - 0x25F1C2` = `0x08480E64` | `CRASH: eip=` 同上 |

落地页是**另一块**钩子桩池（页首正好是 Ares 在 `0x736E8E` 的桩），`+0xE64` 处是没用
到的零填充 → `00 00` = `add [eax],al`，`eax=0` → 写地址 0。`eipmem +偏移` 恒为 `0xE64`
也由此解释：`target = P - 0x25F19C`，P 页对齐，低 12 位必然恒为 `0xE64`；页基址随进程
分配变，所以出现 `0x848/0x85A/0x85C` 三种。

`edx=0x7F5C70` 是 **UnitClass 的虚表**（`vtbl-4` 的 RTTI → `.?AVUnitClass@@`），不是
"某个全局"；`ecx` 是 UnitClass 实例，路径上 `mov edx,[esi] / mov ecx,esi` 留下的。
崩溃与虚表无关。

**修法**（`src/misc/SingleUnload.cpp`）：没有记录时不能 `return 0`，改成自己 `thiscall`
调 `0x4DE710`（只有 `ECX=this`、无栈参），把返回值写进 `REG_OFF_EAX`，再返回
`0x73D8D2`（原 call 的下一句 `mov edi,eax`）。

**同类风险**：`BQ_PausePeel (0x6AB0C1 jne)` / `BQ_DarkDispatchPeel (0x6AAE44 je)` 的副本
也是 rel32，目前所有分支都返回绝对地址（永不返回 0）所以安全，已就地注明。
**新增钩子前先跑 `python tools/hookaudit.py`**：它列出"副本含相对分支"与"长度切半条
指令"两类问题（当前 67 条里 9 条带 rel）。

## 二、日志能给出的信息

1. `CRASH: ==== <版本> pid= fr= up= ====` —— 块首（版本、进程、帧号、运行毫秒）。轮转时
   靠这一行的标记把整段现场留住，见下面"崩溃记录存在哪"。
2. `CRASH: code=… addr=… (write) tgt=…` —— 异常码、EIP、访问方向、出错地址。
3. `CRASH: eax… esi=… edi=… eip… fr=…` —— 寄存器现场 + 帧号。
4. `MOE: phase=<当前> hist <名>@<ms>…` + `MOE: esp=…` —— 阶段名、最近 8 次阶段历史
   （`@` 后是距崩溃的毫秒）、esp 起 24 个 dword 原始窗口。
5. `MOE: surf sb=… comp=…` + `MOE: buf sb=… comp=… tgtin=` + `MOE: own=` —— 崩溃现场的
   面指针、各面缓冲区间、出错地址落在哪张面里（`sb` / `comp` / `none`）、是否落在我们
   自有的侧栏缓冲。
6. `CRASH: mod=… off=… at …` —— EIP 所在模块与模块内偏移 + 该处 8 字节原文。
7. `CRASH: eipin / eip near` —— **只在 `mod=` 认不出模块时出现**：模块表认得出而
   `GetModuleHandleExA` 不认（自建映像），或谁都不在时报最近的模块 + 间隙。
8. `CRASH: eipmem ty=… pr=… alloc=… +off reg=…` —— EIP 不在任何模块时的内存归属，
   `ty=priv pr=rwx` 就是代码池；`alloc` 未对齐 64K 时多半是线程栈。
9. `CRASH: eipcode <16 字节>` —— 崩溃指令原文，可离线反汇编确认写的是哪个偏移。
10. `CRASH: mods exe= self= ares= al=` + `CRASH: ebp[…]` + `CRASH: stk …` —— 栈回溯，
    两条链：`ebp` 是精确帧（每帧取 `[ebp+4]`，逐帧验可读/单调/落模块），`stk` 是
    ESP 起 0x800 字节的原始扫描（ebp 被写坏时只剩这条）。
11. `CRASH: pre …` —— 崩前 12 行日志（`LogLine` 维护的环，崩溃处理写第一个字节前冻结）。
12. `CRASH: obj <reg>=… vt=… <模块+off> ty=… alloc=…` + `CRASH:   hdr <reg> …` ——
    把寄存器当对象指针看：虚表归属 + 头 8 个 dword。`vt` 落在模块里 = 活对象（坏的是
    某个字段）；`unaligned` / `vt-nomod` / `ty=priv` 无虚表 = 这块已被回收复用。
13. `MOE: eng mode= scen= plan= house=` + `MOE: ppath <12 个槽>` —— 引擎状态与
    `HouseClass::PlanningPaths[12]`（`0x5023B0` 遍历它）。未对齐的槽后面带 `!`。

### 崩溃记录存在哪
只有 `MOExperience.log` 一个文件，不另开 `moe-crash-*.txt`。

崩溃块的**第一行**是块首标记 `CRASH: ==== <版本> pid= fr= up= ====`，块内每行都以
`CRASH:` / `MOE:` 开头 —— 轮转（`[Log] MaxKB`）靠这两条认出整段现场：截断前
`GtKeepCrash` 全文扫出最后一个标记，只抄到块尾（第一个非 `CRASH:`/`MOE:` 行首为止），
截断后原样写到新日志开头。所以**一次崩溃现场至少跨过一次轮转**，再下一次才丢。

不能只看文件末尾：崩完的日志往往还没到 MaxKB，之后接着有别的会话往里写，块早被推到
中段去了。轮转只由游戏宿主做（`MOE_HostIsGame`），Syringe 进程跟着截断会把刚写回的
现场抹掉。


### 阶段名别当证据用
`g_MoePhase` 帧末会被清成 `MP_NONE`（不进历史环），所以崩在我们没标注的地方时它
就是 `-` —— 真正有信息量的是 `hist` 那串"阶段@毫秒"。

`obj/MOExperience.map` 只有 ~387 个全局符号，本 DLL 内的栈帧只能定位到函数级
（例：`MOE+0x4251B` = `SB_Poll()+0x11B`）。产物用 `-s` 链接，DLL 里既没有 COFF
符号表也没有 `.debug_*`，`nm`/`objdump` 查不到任何东西 —— map 是唯一的反查依据
（细节见 `构建体积.md`）。

## 三、Syringe 钩子桩池的结构

EIP 报成 `priv/rwx/4096` 的野地址**不是跑飞**，是 Syringe 在游戏进程里 `VirtualAlloc`
出来的钩子桩池。桩模板在 `Syringe.exe` 文件偏移 `0x3B7E4`（`.rdata`，VA `0x43C5E4`），
写入例程 `0x42C160`：

```
60              pushad
9C              pushfd
68 <site>       push 站点地址        ; 被挂钩的 gamemd 地址
54              push esp             ; REGISTERS*
E8 <handler>    call 处理函数        ; 钩子 DLL 里的函数, 返回"接着跳哪"
83 C4 08        add esp,8
89 44 24 FC     mov [esp-4],eax
9D              popfd
61              popad
83 7C 24 D8 00  cmp [esp-0x28],0
74 04           jz  +4
FF 64 24 D8     jmp [esp-0x28]       ; 处理函数给了地址 → 直接跳
```

处理函数返回 0 = **交给链上的下一个桩**。同一站点被多家 DLL 挂钩时，Syringe 把它们的
桩依次排开，桩尾再跟一段"原指令副本 + `E9 jmp 回 站点+max(len,5)`"：

```
[ 33 字节桩 ×k ][ 原指令副本 (maxlen 字节) ][ E9 rel32 ]
```

每个站点一段独立分配（`33k + maxlen + 5`，按页圆整到 4096），所以一页里通常只有一个
站点的桩、其余全是零填充 —— 撞进零填充就会执行 `00 00`。

桩里的 `site`(+3) 与 `E8` 后 rel32(+9) 可解出站点的处理函数归属。实例：`alloc=0x8480000`
那页的桩 `site=0x00736E8E`、处理函数 `0x6821E6E0` = **Ares.dll+0x4E6E0**
（`0x736E6E` 的 `jmp [ebp*4+0x737148]` 跳表的某条分支）。
